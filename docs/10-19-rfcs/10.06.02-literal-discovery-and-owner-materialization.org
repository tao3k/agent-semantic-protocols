#+TITLE: RFC 10.06.02 — Literal Discovery and Owner Materialization
#+STATUS: Draft

* Problem

The registered search flow cannot currently carry an unknown string literal,
error code, CLI spelling, or diagnostic reason from discovery to an exact
owner selector.

The failing production path is:

#+begin_example
search pipe "item-not-in-live-owner"
  -> query-bundle-required / package-drift
  -> declaration-name Tree-sitter query
  -> no owner
#+end_example

A string literal is not a declaration name.  Reclassifying it as a symbol
produces an impossible parser query.  Falling back to raw filesystem, Git,
=rg=, or a guessed owner is forbidden.

* V1 Contract

The shared v1 query-pack contract MUST distinguish these language-neutral term
roles:

- =context=
- =concept=
- =symbol=
- =literal=
- =diagnostic-code=

Providers and language harnesses own the mapping from a typed role to parser
captures.  Rust may map =literal= to string literal nodes and
=diagnostic-code= to string, attribute, enum, or constant facts, but the
shared search crate MUST NOT embed Rust node kinds.

The shared query grammar exposes explicit, language-neutral anchors:

#+begin_example
literal:<exact-value>
diagnostic:<exact-code-or-reason>
#+end_example

The prefix is transport syntax and is not part of the lookup value.  It avoids
punctuation heuristics and lets every registered provider consume the same
typed request.

A single =literal= or =diagnostic-code= term is a complete typed anchor.  It
MUST NOT be rejected by the broad-query budget and MUST NOT require a second
clause.

* Discovery Flow

The only valid unknown-owner flow is:

#+begin_example
typed query term
  -> registered provider query-pack recipe
  -> provider/source-index candidate facts
  -> owner selector with workspace package identity
  -> exact query projection
#+end_example

The public =search= surface MUST expose provider-backed discovery without
requiring the caller to know a source file first.  =search owner= remains an
owner-local refinement surface; a directory MUST NOT be passed to the provider
as though it were a source file.

When an owner belongs to a nested registered workspace, every candidate
selector MUST preserve enough workspace package identity to be executable from
the original workspace root.  Returning =rust://src/...= when the request was
rooted at =rust://crates/<package>/src/...= is invalid.

* Query-Pack Responsibilities

The shared v1 schema owns the role vocabulary and typed recipe shape.
Each registered language harness owns:

- literal and diagnostic capture queries
- language-specific escaping and case sensitivity
- package/workspace-root attribution
- conversion from parser facts to the canonical selector identity

The protocol router consumes these typed facts.  It MUST NOT infer literals
from punctuation, synthesize declaration-name queries, or maintain a
language-specific allowlist.

* Projection and Failure Receipts

Successful discovery returns a canonical owner selector and the typed capture
role that produced it.

Failure is typed and terminal for that route:

- =literal-capture-unavailable=
- =diagnostic-capture-unavailable=
- =workspace-owner-identity-missing=
- =owner-not-in-live-snapshot=

The failure receipt MUST NOT recommend a Tree-sitter declaration query for a
literal and MUST NOT recommend raw source search.

* Performance Gate

The registered-language gate MUST exercise every provider query pack with:

1. one exact symbol
2. one string literal
3. one diagnostic code when the language declares that capability
4. one nested-workspace owner

Warm discovery MUST use the active snapshot and provider memory/index facts
without subprocess, database reopen, manifest rewrite, or binary reread.
The benchmark records parse, candidate lookup, owner attribution, and
projection separately in milliseconds.

* Acceptance Evidence

Closure requires all of the following:

- the shared v1 schema accepts =literal= and =diagnostic-code=
- every registered capable harness supplies its parser-owned capture recipe
- a single typed literal bypasses the broad-query budget
- root-workspace discovery returns an executable nested-workspace selector
- the exact selector succeeds without =--term=
- no raw-search, Git, filesystem scan, or declaration-name fallback exists
- cold and warm receipts satisfy the registered performance gate
