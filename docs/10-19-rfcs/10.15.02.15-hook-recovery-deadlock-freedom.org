#+title: Hook Recovery Override and Recursive-Dispatch Deadlock Freedom
#+property: schemaId agent.semantic-protocols.rfc.hook-recovery-deadlock-freedom
#+property: schemaVersion 1
#+property: rfcClauseId ASP-RFC-10.15-HOOK-RECOVERY-DEADLOCK-FREEDOM

* Status

Normative P0 refinement of the local Hook execution plane.

* Failure counterexample

A dispatch rule that denies both the calling Agent and the configured target
Agent creates a recursive fixed point: the target is instructed to delegate the
same command to itself.  If building or installing the repaired ASP binary is
also subject to that rule, no in-band repair transition exists.

This is a control-plane deadlock, not evidence that ASP, Cargo, or the target
Agent is globally unavailable.  A deny message MUST distinguish the current
Agent boundary from system availability and MUST name the exact ChoicePlane,
typed target/lane, and scoped command that advances the state.

* Architecture

=ASP_NO_AGENT=1= has two inherited-process projections with absolute
pre-bootstrap precedence:

#+begin_example
Plugin launcher: detect inherited ASP_NO_AGENT=1 -> {} -> stop
Hook evaluator process entry: detect inherited ASP_NO_AGENT=1 -> {} -> stop
#+end_example

The launcher branch MUST execute before State Home/current/binary resolution
or stdin.  The evaluator branch MUST execute before runtime construction,
workspace discovery, configuration or provider projection, mmap/file locks,
Runtime or ASP Server access, lifecycle observation, stdin, and telemetry. The
inherited value must be exactly =1=. These two layer-zero paths perform no
payload parsing and MUST satisfy
=hookDecisionCpuMicros < 1000=. This exclusive
hard boundary measures work owned by Hook; =hookDecisionElapsedMicros= remains
an observed wall receipt and MUST NOT be relabeled as deterministic algorithm
work because Host scheduling delay is external to the decision function.
The CPU hard boundary is not the operating target. At least 75% of a 32-process
concurrent pressure sample MUST satisfy wall =elapsedMicros <= 500=. Thus a result
such as 823us is still admitted by the fail-closed boundary but is a performance
regression because it lacks sufficient scheduling and filesystem headroom.

Codex Bash PreTool additionally has one command-local projection in the Rust
=asp-hook= process boundary. Before loading the embedded policy bundle, the Shell Parser
proves that =ASP_NO_AGENT=1= reaches the requested process through
exactly one of =NAME=VALUE command=, =env NAME=VALUE command=, or
=export NAME=VALUE; command=. This is bootstrap authority, not a Config rule:
Config V1 MUST NOT contain an =ASP_NO_AGENT= matcher, allow decision, or
policy witness. Raw JSON text, quoted text,
unrelated earlier stages and quoted assignment text do not establish
authority. This command-local path parses the Host payload but terminates
before the policy bundle, Reader Probe, Agent dispatch, Runtime, or any other
policy rule. Any generation that embeds a policy rule for this escape is a
failed publication candidate because policy cannot authorize its own bypass.

For an ordinary =asp= CLI invocation, inherited =ASP_NO_AGENT=1= selects the
=agent-semantic-client= single-thread server-first IPC lane.  That lane creates no Tokio
worker pool and registers no Ctrl-C signal listener; it retains only the I/O
driver required to reach or recover the resident ASP Server.  When the owner is
dead or missing, the lane consumes the event-bound immutable candidate from the
durable pending-or-applied V1 activation and performs exactly one typed
supervisor recovery before continuing the original client request.  It is not
a local parser/provider fallback, does not read a legacy mutable artifact
identity projection, and cannot override operator-stop or endpoint/candidate
identity denial.  Such denial remains a V1 typed CLI failure.

Hook invocation is one-shot but not low-concurrency. Concurrent Host actions
MUST resolve the stable =ASP_STATE_HOME/runtime/bin/asp-hook= launcher and
evaluate the policy bundle embedded in that exact executable. There is no
second =hooks/current= pointer and no separately published Hook generation.
The executable content digest binds the evaluator, Config schema-version-1
bytes, compiled matcher/policy, Agent registry, and typed policy receipt. The
read path MUST NOT serialize behind a writer, queue for Runtime capacity,
compile mutable source, or publish policy. The Developer installer validates an
=asp-hook= candidate and atomically replaces the stable Runtime tool launcher;
each invocation observes either the prior complete executable or the next
complete executable.

Editing mutable Config or registry source MUST NOT affect the installed Hook
policy. Parse, compile, validation, immutable materialization, or launcher
publication failure MUST leave the prior =runtime/bin/asp-hook= unchanged.
Immutable materialization may use Tokio blocking tasks; the stable-launcher
transaction is a bounded synchronous =fs2= lock, atomic symlink rename, and
directory =fsync= with no =await= inside the lock.

Hook executable publication and Runtime serving activation are distinct
authorities. Hook publication MUST NOT wait for, inspect, or depend on Runtime
activation. Runtime states
=stopped=, =pending=, =failed=, and =ready= cannot change Hook policy
availability. The fixed Plugin launcher resolves only
=runtime/bin/asp-hook= and MUST NOT read =runtime/bin/asp=, Runtime
active/healthy slots, endpoint state, or Runtime publication identity.

Runtime binary publication has a separate dual-authority invariant.  Inside
the sole =artifact-mutation.lock= transaction, Artifacts MUST allocate the next
generation from current pending/applied V1 receipts, publish the event-bound
immutable candidate, and atomically switch only =runtime/bin/asp= to that
candidate.  Resident =active=, =healthy=, and all serving aliases remain the
previous applied generation until the actor publishes ready/applied commit.
Protocol/client packages MUST NOT perform a second launcher transaction.

The retired single-switch design deadlocks when applied generation 21 owns a
dead resident owner while generation 28 contains the only stale-endpoint and
no-owner recovery implementation: the old client cannot reach the code needed
to replace its own owner.  Dual authority breaks that cycle because the next
ordinary client executes generation 28 while serving stays 21. Candidate,
event, malformed-state, or launcher failure preserves both previous client and
serving authorities. Actor commit must compare the current pending generation
under the same mutation guard; an older actor can neither retire nor overwrite
a newer pending event.

Each installed =asp-hook= executable contains one immutable policy bundle. Its fixed header
carries deterministic config and agent content identities plus the compiler
generation digest; its body carries the compiled matcher.
The complete matcher and policy-derived direct-read decision-template shards
share the same policy digest and owner stamps. A direct-read shard is rendered by
the complete composed policy compiler and contains the winning typed decision
with a safely substituted source-path placeholder; the one-shot reader does not
rehydrate the complete config, project providers, or rule graph. Shard identities are derived from normalized
ToolAction facts plus provider-owned extensions, never raw Host tool names or
hard-coded rule ids. The reader performs one read-only mmap and never discovers
Git/Runtime workspace identity. The cache key is derived directly from the
normalized Host workspace path. A serialized-reader implementation is
non-conforming even when its
single-reader median is below budget: queue delay from sibling readers is not
part of the local decision and can violate the strict boundary.

Without the override, dispatch is a typed identity state machine.  When the
current =agent_type= and non-empty =agent_id= identify the configured target,
the dispatch obligation is satisfied and the decision is terminal allow.
Only a different or unproven identity may receive the dispatch deny.

* Formal obligations

=ASPProof.HookRecoveryDeadlockFreedom= and
=ASPProof.RuntimeClientServingPublication= must prove:

- the legacy recursive dispatcher admits a target-self-dispatch counterexample;
- the recovery override dominates every policy and identity state;
- target identity is an allow fixed point when recovery is not active;
- recovery evaluation has no Runtime, configuration, lock, or telemetry
  dependency;
- a broken-binary recursive-deny state is not repairable under the legacy
  transition but becomes repairable when the recovery override is present.
- a serialized reader queue has a concrete budget-violation counterexample;
- lock-free reader latency and policy outcomes are invariant under reader count;
- atomic publication exposes only the prior or next complete Hook executable, never
  a torn matcher state.
- mutable Config source edits preserve the installed Hook executable;
- every candidate-stage failure preserves the previous Hook executable;
- Hook commit is invariant under Runtime activation state;
- Plugin-launcher and evaluator-process inherited overrides each break the
  legacy recovery cycle, while shell command assignment has no recovery
  authority.
- the old applied-client/single-switch design has a concrete dead-owner plus
  newer-pending bootstrap deadlock;
- dual client/serving publication is atomic and monotone, reaches recovery
  without the old owner, converges after current actor commit, and preserves a
  newer pending generation under stale concurrent commit;
- 823us of Hook CPU is a concrete counterexample that satisfies the 1ms hard boundary but
  violates the 500us operating target, and 24/32 is the minimum typical quorum.
- a decision with 240us of Hook CPU and 6000us of external scheduler delay
  satisfies the algorithm boundary while its observed wall time exceeds 1ms;
  therefore a universal wall-max assertion is not a valid refinement theorem.

* Executable refinement gates

Rust tests MUST cover both process-environment bypass layers with missing
Hook executable/state/config,
direct and arbitrarily wrapped command assignments, a similarly named variable
that cannot bypass policy, mutable source edits without publication, ten
consecutive Developer generations, parse/compile/validate/publication failure
retaining previous, 32 concurrent launcher calls observing only =N= or =N+1=,
all four independent Runtime states, target-Agent dispatch idempotence,
non-target deny guidance, and absence of Runtime Server dependencies. The final
acceptance matrix must run through the installed plugin Hook in a normal Codex
task after the user enables it.

Artifacts tests additionally MUST cover production-shaped previous/pending
authority, candidate and launcher failure, malformed V1 receipts, publication
versus actor-commit ordering, and stale generation rejection. =agent-semantic-client=
tests MUST prove the ordinary =ASP_NO_AGENT= lane avoids worker-pool and signal
registration, recovers one dead applied owner before dispatching the original
request, and preserves typed operator-stop denial while still using resident
Server IPC.
