* Status

Draft implementation contract. This module refines RFC 10.15.02.09 without
changing its bootstrap repair and failure-plane guarantees.

* Design correction found by formalization

Caching only a compiled matcher in ASP Server is not a closed architecture.
=ClientHookConfig= is an in-process semantic object containing compiled rules,
and the hook pipeline consumes the same object after classification for
resident dispatch, source-access materialization, and session policy. Sending
the object back through IPC would either discard compiled semantics or invent a
second serialization ABI.

The resident unit MUST therefore be a complete hook evaluator generation. The
bootstrap sends the bounded event envelope to ASP Server and receives the final
platform response. A generation-keyed evaluator owns the compiled matcher and
all consumers of that matcher in one process.

* Generation identity

Let

- =A= be the Runtime Server artifact digest;
- =W= be the canonical workspace identity;
- =C= be the managed hook-config content digest;
- =P= be the project hook-overlay content digest;
- =F= be the embedded contract fingerprint.
- =R= be the activation/runtime projection generation.

The evaluator key is =K = (A, W, C, P, F, R)=. A response is admissible only when
the key observed before evaluation equals the generation key that produced the
response. Workspace identity is part of the key, so equal configuration bytes
in two workspaces cannot alias lifecycle state.

* Warm and fallback paths

#+begin_src mermaid
stateDiagram-v2
    [*] --> Bootstrap
    Bootstrap --> ServerProbe: bounded event
    ServerProbe --> ResidentHit: K already resident
    ServerProbe --> ResidentBuild: K absent
    ResidentBuild --> ResidentHit: compile and publish K
    ResidentHit --> Evaluate: lease K
    Evaluate --> KeyRecheck: platform response
    KeyRecheck --> Emit: observed K equals response K
    KeyRecheck --> RetryOnce: generation advanced
    RetryOnce --> ServerProbe: one bounded retry
    ServerProbe --> LocalFallback: server unavailable or old transport
    LocalFallback --> RepairGate: typed contract drift
    LocalFallback --> Emit: coherent local evaluation
    RepairGate --> Emit: repaired replay or plane policy
    Emit --> [*]
#+end_src

The warm path performs one local socket round trip and zero matcher
compilations. Server absence, an older data-plane schema, or server restart is
an optimization miss rather than an authorization fact: the bootstrap falls
back to the existing local evaluator. The RFC 10.15.02.09 enforcement and
observational failure policies remain authoritative.

* Stateful cache requirements

1. Publication MUST be atomic: readers observe either the old complete
   generation or the new complete generation.
2. At most one compiler owns a missing key; concurrent requests join that
   generation rather than compile duplicates.
3. A lease pins the generation until the response has been produced.
4. A response generated under a stale key MUST NOT be admitted under a newer
   observed key.
5. Eviction MAY remove an unleased generation, but MUST NOT affect the result
   of an in-flight evaluation.
6. Server restart clears the in-memory cache safely because =A= and the server
   binding are re-established before evaluation.
7. The decision receipt MUST expose =hookMatcherGeneration= as =compiled= or
   =resident-hit= so installed-path validation can distinguish reuse from mere
   server health.

* Lean correspondence

| RFC obligation | Lean theorem |
|-
| workspace generations cannot alias | =workspace_identity_prevents_alias= |
| activation generations cannot alias | =activation_generation_prevents_alias= |
| equal keys reuse one compilation | =same_key_compiles_once= |
| stale responses are rejected | =stale_generation_is_not_admissible= |
| a leased generation cannot be evicted | =leased_generation_is_not_evictable= |
| the warm path uses one round trip | =warm_path_is_one_round_trip= |
| server failure preserves local fallback | =server_failure_selects_local_fallback= |

* Rust ownership boundary

| Responsibility | Owner |
|-
| stable public command and bounded server-first forwarding | =asp hook= entrypoint |
| local fallback and cold repair | internal bootstrap module of the same =asp= artifact |
| typed evaluator request and response | Runtime Server data-plane protocol |
| evaluator callback and compiled-generation cache | protocol daemon process |
| config compilation and classification semantics | =agent-semantic-hook= |
| artifact/config drift repair | RFC 10.15.02.09 bootstrap repair |

This design intentionally does not serialize =ClientHookConfig=. The final
platform response is the only semantic result crossing the evaluator IPC
boundary.
