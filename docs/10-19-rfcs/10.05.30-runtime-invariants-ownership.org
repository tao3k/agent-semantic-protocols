* Global invariants

** One lifecycle authority

ASP Runtime Server owns workspace identity, provider admission, lazy resident
activation, generation publication, bounded concurrency, cancellation, drain,
and lifecycle receipts.  A request client owns none of this mutable state.

Query handling never starts, repairs, restarts, or locally executes a provider.
Runtime absence and provider unavailability are typed terminal evidence, not
permission to construct an alternate route.

Content-addressed parser artifacts bind both the declarative registration
digest and the exact provider executable artifact digest.  Owner bytes alone
cannot prove reusable parser output: changing provider code while retaining a
V1 descriptor MUST invalidate the old parser product.  Unchanged executable,
parser/query-pack identity, auxiliary inputs, owner path, and owner content may
still be reused across workspace generations; generation proof is rebound
separately.

Every Search/Query request and terminal binds the same =ProjectId= and
=WorkspaceId=.  The binding is present in both the ClientFrame envelope and
the persisted operation terminal so detached receipts remain attributable.
=workspaceIdentity=, =projectRoot=, an endpoint path, or an activation counter
MUST NOT appear as an alternate partition key.  Stage, publication, resident
lease, search fan-in, and exact-query projection all reject a project or
workspace mismatch before observing or mutating active generation state.
Live Corpus cold/warm/release receipts use the same pair and never expose a
mutable =globalCacheMutationCount=: there is no global cache partition or
global mutation authority.  A cold/release action can only compare-and-mutate
the exact project/workspace resident generation named by the request.

Every public operation that measures or consumes Search/Query semantics enters
the same Runtime activation admission before opening the data plane.  This
includes language facades and formal Live Corpus qualification.  Qualification
MUST NOT construct =AspClient= directly against an endpoint path and thereby
bypass supervisor admission.  It may wait for a newly admitted Runtime to
publish =Healthy= before the measurement phase begins; that bounded startup
wait is recorded separately and is never counted as a Ready-query latency.
Once measurement begins, the benchmark uses the identical resident gRPC
service, catalog, generation lease, cancellation registry, and terminal rules
as =asp <language> search/query=.  A benchmark-only daemon, socket, or recovery
path is a second lifecycle authority and is forbidden.

Live Corpus Search/Query coverage is a V1 TOML Scheme scenario suite, not an
argv playbook generator.  Every locked large-library resource names its
language/provider identity and stores the complete public =(search ...)=,
zero-match =(search ...)=, source =(query ...)=, and callable-skeleton
=(query ...)= forms.  Query forms contain exactly one typed ={{selector}}=
slot because the parser-owned selector is discovered by the preceding Search;
the runner JSON-encodes that value, lowers the resulting complete Scheme form,
and rejects producer, selector, or projection drift before dispatch.  Test
budgets and cache-state schedules remain suite metadata.  They MUST NOT be
translated into public Search flags or used to synthesize the semantic form.
The suite digest binds the exact TOML bytes into the qualification receipt, so
scenario edits are executable benchmark history rather than prose examples.

When qualification declares =first-ranked-parser-owned=, it preserves the
server settlement order while removing later duplicate selectors.  It MUST NOT
sort selector text before choosing the Query target: lexical sorting destroys
rank evidence and can replace a callable result with an unrelated structural
owner.  Derived owner-path lists preserve the same first-observed order.

Live Corpus Merkle qualification is a test-only resident read on that same
ClientFrame session.  Its V1 qualification request binds the request root to
the session's admitted workspace; Runtime reads the already-published resident
projection and returns the existing V1 proof-qualification receipt.  The
sub-millisecond mmap/kernel budget measures inside Runtime, while ClientFrame
transport wall time remains a separate observation.  It MUST NOT open a WorkspaceDb IPC
session, write the legacy length-framed protocol to the gRPC data endpoint,
scan source files, or expose a CLI/Search/Query flag surface.  The proof read
does not admit, build, or repair a generation; absence or identity drift is a
typed failure of the qualification run.

=Healthy endpoint= and =committed resident transaction= are not synonyms.  A
new owner can publish a reachable endpoint before its applied activation
receipt becomes atomically visible.  Supervisor admission MUST therefore wait
until the reachable endpoint, owner-spawn receipt, applied activation receipt,
publication nonce, artifact path, and content digest all describe the same
transaction.  Endpoint health without that identity closure remains
=Starting=; it is never returned as Ready and is not repaired by client retry.
This rule closes the same initialization race that LSP clients commonly paper
over with reconnect loops, while preserving a single Runtime authority.

Tokio task ownership, generation-attempt terminalization, and telemetry
isolation are owned by
[[file:10.05.11.05-runtime-server-tokio-task-lifecycle.org][10.05.11.05 Runtime Server Tokio Task Lifecycle]].

** Language-scoped lazy admission

A language facade resolves through the registered provider catalog to exactly
one provider identity.  A language-scoped search, query, check, or cache
operation does not widen to a complete-generation or all-provider operation
when an index-owner argument is absent.

Only an explicitly unscoped operation may request global coverage.  Runtime
evidence for a language-scoped operation therefore reports no unrelated
provider process or preparation work.

The same boundary applies before a generation exists.  A targeted demand
constructs =requiredLanguages= from the selected provider identity alone; it
does not enumerate every language detected in the repository.  An absent,
cold, or uninstalled provider for another language cannot turn the selected
request into =query-not-ready=.  Only an explicit =CompleteGeneration=
transaction may fan in the repository-wide provider set.

Provider package, registration, and server authority are owned by
[[file:10.05.61-language-provider-server-authority.org][10.05.61 Language Provider Server Authority]].

** Typed topology before rendering

Every SearchLoop entry constructs stable nodes, directed typed relations, and
typed action-frontier entries before compact rendering.  Canonical selector
validation precedes any =owns_item= or =targets_item= relation.

Presentation ordinals are not durable node identities.  A malformed or
cross-language selector may remain as unresolved input evidence, but it
produces neither an owner/item relation nor grounded selector evidence.

Evidence topology and route selection are owned by
[[file:10.05-interactive-graph-first-progressive-searchloop/10.05.20-evidence-graph-routing/00-overview.org][10.05.20 Evidence Graph and Routing]].

** Active-generation authority

A search or exact query reads one admitted immutable generation.  =Ready=
means coverage is proven for the requested workspace owner and provider; an
empty or uncovered generation is not a successful =no-matches= result.

The active generation is the sole membership authority.  Provider fingerprint
storage and retained bytes are caches, not membership truth.  Concurrent
generation demand is single-flight and attempt-bound.

Before a language Search or Query reads =Ready= state, Runtime discovers the
current workspace candidate and submits or coalesces that exact candidate at
the server-owned admission authority.  A previously =Ready= resident whose
candidate or policy identity differs is never read.  =Queued=, =Building=, or
publication lag is observed through the attempt's retained terminal event.
The first admitted caller may wait once, within its absolute first-computation
deadline, for that same attempt to become =Ready= or terminal.  It does not
poll, retry, submit a second attempt, or report =materializing= as a usable
result.  A ready resident read remains governed by the independent 1ms server
budget.

The Runtime resident generation, parser-owned source/materialization generation,
workspace source-snapshot root, and projected owner-Merkle root are distinct
identity domains.  Cache-state admission binds the Runtime generation and
source-snapshot root; Query receipts bind the parser generation and source root;
Merkle inclusion binds the owner-Merkle root.  Qualification MUST retain these
identities and MUST NOT compare, substitute, or normalize one into another.

A multi-request client session performs lifecycle admission exactly once and
pins the returned content-bound Runtime handoff.  Repeated or concurrent Search
and Query dispatches reuse the same multiplexed ClientFrame session; they MUST
NOT re-enter activation, endpoint discovery, or workspace admission per request.

A generation reopened from its durable mmap owns immutable exact and Search
projection reads, but it does not own the process-resident parser-overlay
membership state.  Runtime MUST represent that capability boundary explicitly.
When Search cannot prove a candidate scope materialized from the reopened mmap,
it falls through to the workspace registry's exact content-bound resident lease
and its single-flight candidate materializer.  Capability absence is neither
generation corruption nor permission to rebuild the full workspace.
The same reopen transaction MUST load and admit the durable workspace execution
publication named beside the generation pointer.  A missing, corrupt, or
generation/source-mismatched execution sidecar rejects cold reuse; reopening a
QueryGeneration with =executionPublication=None= is not a valid cold-load.
When the publication observer upgrades an already admitted object to the exact
execution-bound product without changing its content generation digest, the
old and upgraded objects MUST share the same Search and Query single-flight and
terminal maps.  An in-flight parser-overlay task may finish through the old
object reference; replacing those maps would lose its terminal and force the
same normalized Scheme plan to recompute against a later overlay state.

Resident-hit observability is emitted once by the outer request-plane boundary
after the strict request clock is captured.  A Query cache hit MUST NOT perform
a second synchronous per-route telemetry publication inside that clock; doing
so makes queue contention part of the read kernel and duplicates the terminal.

A completed Search materialization is also the response payload authority.
The generation, dispatcher, ClientFrame service, and gRPC encoder MUST retain a
shared immutable payload handle through serialization; a resident hit MUST NOT
deep-clone the complete JSON projection merely to cross an in-process layer.
The shared representation is wire-transparent and does not change the V1 frame
schema.
Query materializations use the same ownership rule.  Request identity, request
profile, and request-plane elapsed time are a three-field serialization overlay
over the generation-owned immutable template.  A resident Query MUST NOT clone
or rebuild the nested materialization tree merely to rebind those request-local
fields.  The client receives an ordinary V1 JSON object; only the Runtime-side
ownership and serialization strategy changes.
The Search topology attachment is derived only from the immutable Search-core
projection.  Candidate-scoped parser overlays may enrich exact Query and
native graph reasoning, but MUST NOT change =topologyGenerationDigest= for a
lexical Search over the same source generation.  Overlay topology has its own
bounded attachment/proof identity; folding it back into the global Search
attachment would make Search identity depend on which Query happened first.

Agent-produced summaries and their Org rendering obey the same separation.
Search returns a content-bound candidate owner/selector frontier; exact Query
materializes the parser-owned scope; only then may an Agent summarize that
bounded evidence.  The admitted summary artifact binds the source generation,
selector, Agent/model identity, prompt identity, summary digest, and Org AST
digest.  The Org document is a durable evidence projection of that artifact,
not unbound prose and not an implicit Search side effect.  Its topology edges
form a separately identified semantic overlay that may be requested by a
later projection, but neither summary publication nor Org rendering may
rewrite Search Core or change the base Search topology digest.

The executable model
=ASPProof.SearchTopologySemanticOverlayIndependence= proves three V1
properties: exact Query publication preserves Search topology identity,
Agent/Org summary publication preserves it, and the two independent overlay
publications commute.  A summary with a stale content generation or a missing
Org AST digest is rejected.  These are admission properties, not claims that
the currently available Agent/Org production path is complete.

Memory ownership and capability-lazy indexes are owned by
[[file:10.05.11.09-runtime-generation-memory-authority.org][10.05.11.09 Runtime Generation Memory Authority]].
Generation publication and readiness are indexed by
[[file:10.05-interactive-graph-first-progressive-searchloop/10.05.20-server-resident-search-generation/00-overview.org][10.05.20 Server-Resident Search Generation]].

** Exact selector and source authority

Exact source materialization accepts one parser-owned structural selector and
returns only the projection declared by the typed operation.  Search-derived
projection and exact source are distinct operations and cannot reinterpret one
another after failure.

Owner discovery is not exact projection.  It may return canonical item
selectors without creating a workspace generation, but it cannot manufacture
source bytes or an exact-query success.

The selector chain is owned by:

- [[file:10.05.12-exact-selector-provider-generation-authority.org][10.05.12 Exact Selector Provider Generation Authority]]; and
- [[file:10.05.17-resident-exact-query-authority.org][10.05.17 Resident Exact Query Authority]].

** Request-independent generation work

Public requests submit or coalesce generation demand and observe the current
typed phase.  A first-computation request may await the retained terminal event
for the one admitted attempt; the work itself remains Runtime-owned rather
than transport-owned.  Dropping or timing out a waiter never detaches or
silently cancels shared admitted work.

Every accepted attempt owns exactly one terminal publisher.  =Queued=,
=Building=, =Ready=, =Failed=, and =Cancelled= are Runtime states; client
timeouts, sleeps, polling, and elapsed-time repair cannot create transitions.

Incremental cache and mutation ownership are specified by
[[file:10.05-interactive-graph-first-progressive-searchloop/10.05.70-runtime-owned-incremental-cache-v1.org][10.05.70 Runtime-Owned Incremental Search Cache]].

** Atomic publication

Candidate generation, source root, provider/schema identity, projection
capability, and resident locator advance as one validated publication.  Readers
observe either the previous complete generation or the successor complete
generation.

V1 has four internal readiness tiers even though its public wire version does
not change:

1. =ContentSnapshotReady= owns canonical paths, exact source bytes and
   content/provider/scope identity.
2. =SearchCoreReady= owns the immutable owner directory and complete lexical
   candidate coverage required to run exact byte verification.  Its in-memory
   atomic publication is the first-Search linearization point.
3. =SemanticOwnerReady(owner, artifactKey)= owns parser selectors, callable
   projections and Relations for one content-addressed owner.  Search grounds
   only candidate owners; exact Query waits for only the selectors it names.
4. =DurableReady= owns restart media.  It is required for restore admission,
   not for reads from an already validated process-resident Search Core.

The following work is forbidden before =SearchCoreReady=: full-workspace
provider projection, full Project Topology closure, optional graph attachment,
serialization of complete/exact/search copies, mmap reopen, execution-sidecar
fsync, and Turso attachment.  Those are independently observable attachments.
A failed durability attachment marks restart recovery unavailable for that
generation but cannot revoke an already validated resident generation.

Logical and physical identities are distinct.  The Runtime provider execution
binding's =sourceIndexDigest= binds the logical source-index/import product.
A segment or database commit digest authenticates recovery media only; it must
not be substituted into the logical execution identity.  Parser artifact keys
bind provider, parser, query-pack and owner-content digests.  Generation proof
then binds that reusable artifact to current owner path, source root, scope and
execution identity.  While providers emit path-qualified selectors, the key
also includes canonical owner path and the digest of parser-visible auxiliary
inputs.  Changing content, path, auxiliary inputs or parser identity rejects
reuse; changing only the generation proof does not require reparsing the same
bytes.

Candidate materialization is cache-first.  A content-addressed hit MUST be
validated and rebound without starting a provider process.  Only the typed
=provider-parser-runtime-required= miss may cross the provider lifecycle
boundary, await that single resident actor, and compute the owner once.
Concurrent Search or Query requests coalesce by workspace generation, owner
path and owner content digest; client cancellation removes a waiter, not the
shared materialization.

The generic ASP client and Runtime data plane depend on shared protocol,
transport, registry and resident-index crates only.  They MUST NOT link a
language implementation such as =asp-rust= or embed one provider server as an
optimization.  The prohibition includes normal, build and test dependency
graphs; provider-specific tests remain provider-owned and generic integration
tests use protocol fixtures or an external provider binary.  Rust, Python,
Gerbil Scheme and every later language remain separate provider servers behind
the same transport boundary.  Provider
process bootstrap and warm-up are lifecycle observations reported separately;
they are not Search or Query engine time.  A first-computation receipt still
accounts for the provider's actual candidate parse/projection work after the
server is Ready, so excluding bootstrap cannot hide parser cost.

Timing receipts use disjoint names.  =requestWallMicros= is end-to-end waiting
and may include provider lifecycle.  =providerLifecycleWorkMicros= contains
provider start plus readiness work only.  =runtimeEngineWorkMicros= contains
resident/cache lookup, provider projection, validation and publication, but
never provider start or readiness.  A receipt that exposes only an undivided
=elapsedMicros= MUST NOT be used as Search or Query engine evidence.

Query does not perform acquisition.  Each canonical selector determines its
owner path before projection.  Generation admission builds an owner-path hash
index and an exact-selector hash index once; a resident Query resolves through
those indexes directly and then copies only the selected byte range or derived
projection.  It MUST NOT enumerate workspace owners, invoke rg or Tantivy,
walk the filesystem, or use a language-provider dependency in the client.
When an owner is present only in the candidate semantic overlay, lookup remains
bounded by that one owner until its selectors are promoted into the resident
exact index.  Therefore unrelated workspace owner count is not a Query work
term.

Semantic owner publication is an in-memory compare-and-set in the workspace
writer lane.  It retains the canonical base digest and publishes a new resident
overlay revision; it MUST NOT call the complete-generation publisher, update the
durable pointer, advance the canonical epoch, or serialize unrelated owners.
Because parser materialization attaches semantic projections to an already
indexed owner, admission MUST verify that owner path, content digest and source
bytes equal the currently visible canonical content identity.  Semantic
publication MUST reject tombstones and new or content-changed owners; those are
content-generation mutations.  It MUST NOT rebuild or incrementally update the
workspace content Merkle tree.  One admitted semantic batch produces exactly
one atomic overlay revision and one derived overlay digest, rather than routing
through a content-delta revision and then advancing a second time.
The overlay is a read-through delta over the immutable generation lease: it
MUST NOT clone canonical owner bytes or canonical Relations into overlay state.
Only changed owners, tombstones, Relation deltas, selector deltas and semantic
membership deltas are overlay-owned.  Canonical semantic owners remain visible
through base read-through after any later delta, and the workspace snapshot is
shared by reference until a path delta derives its successor.  Naming a second
full-base in-memory copy an overlay does not satisfy this requirement.
Restart recovery revalidates the already durable parser artifact and reattaches
it on demand.  Therefore one candidate miss has work proportional to that
candidate artifact, never to total workspace bytes.

After a durable parser artifact has passed that validation, the Runtime Search
Service MAY retain its immutable projected owner in a process-resident hot set.
The hot set is keyed by the complete V1 parser-artifact identity, including
provider, parser, query-pack, auxiliary-input, owner-path and owner-content
digests.  It is an acceleration layer, not a second recovery authority: a
process restart repopulates it only from a validated durable artifact or a
successfully published provider result.  A hit MUST recheck the requested full
identity and owner content binding without reopening or decoding the artifact
file.  Entries are bounded by both bytes and count, derive their byte budget
from the Runtime Server process memory authority, use deterministic recency
eviction, and disappear with the Runtime Search Service lifecycle.  Eviction
changes only latency; it cannot change Search or Query semantics.  A miss or
identity drift returns to durable validation/provider projection and MUST NOT
silently reuse an owner-path-only entry.
Performance receipts MUST distinguish resident hits, durable-file hits, misses,
and rejected artifacts so a fast semantic-overlay hit cannot be misreported as
proof that the parser-artifact hot set was exercised.

For every admitted workspace/provider target restored during daemon startup,
the same startup barrier also attempts and terminalizes establishment of the
Runtime-owned resident provider actor before public health becomes Ready.  A
successful cache-complete generation restore MUST NOT leave provider process
creation as hidden work in the first Search materialization.  Search may
consume the already resident actor, but it does not own provider process
startup for a successfully warmed workspace.  A target that fails warmup is
not reported provider-ready; its typed startup-recovery diagnostic remains
visible without revoking independent resident languages.

Graph and Project Topology are request-scoped refinements over the admitted
candidate owner set.  A graph clause may add a bounded one-hop Relation
neighbourhood, but it MUST NOT force parser projection for every indexed
owner.  The request-local graph contains only endpoints admitted by that
bounded owner cut; cross-cut Relations remain outside the evaluated frontier.
Each subsequent Search may construct its own candidate cut, so the first
Search cannot freeze an incomplete generation-global topology.

A Search containing Tantivy waits only for the generation-bound lexical
attachment terminal.  Graph readiness is not part of that completion signal:
the request graph is created only after retrieval and semantic owner admission.
Generation publication MUST NOT start a global graph build that competes with
the lexical attachment or delays its waiter.

A request's language/provider target narrows construction work, never the
published authority.  The single-flight builder starts only that provider and
collects its complete current owner, relation, and ProjectResolution
membership.  It then replaces the previous membership for the exact
language/provider authority in the active immutable base and publishes the
result as one =CompleteGeneration=.  Unselected providers, their source blobs,
relations, and ProjectResolution receipts are carried forward byte-for-byte.
Generation readiness is target-relative: an already resident generation that
lacks any provider authority selected by the request is not Ready for that
request.  Runtime MUST submit the missing targeted successor and await the
first published generation containing every requested =(language, provider)=
authority; it MUST NOT dispatch Search against the stale resident generation
or require a second client call.
The first targeted demand on a cold workspace is the initial complete member
set.  Publishing the target-only candidate directly, or rescanning every
registered provider for one language demand, is forbidden: the former erases
active languages and the latter destroys lazy provider isolation.

Provider coverage ranges only over programming-language registrations.  Org
and Markdown are embedded document surfaces and therefore contribute document
owners to the workspace generation without contributing provider identities,
provider artifacts, or provider processes.  A missing =asp-org= or =asp-md=
artifact can never be a legal =query-not-ready= cause because those artifact
authorities do not exist in the server-first architecture.

Runtime admission MUST therefore join two disjoint catalogs without converting
one into the other: installed programming-language providers come from the
active provider projection, while embedded document producers come from the
ASP binary's Orgize-owned document catalog and their admitted schema profiles.
A =(documents ...)= atom MUST be checked against the latter catalog and MUST
NOT be checked against installed provider receipts.  Its generation demand may
name the document language but carries no external provider id; source owners
are collected by the embedded document projection and no provider process is
started.  The mixed =(language ...)= plus =(documents ...)= case must preserve
both authorities in one generation-bound Search plan.  Acceptance requires a
freshly published ASP binary with no Org/Markdown provider receipt to execute
that mixed request successfully; a test that pre-seeds a synthetic =asp-org=
installed provider is invalid evidence.

Process-cold Runtime recovery MUST inventory the workspace once and publish one
complete generation containing every discovered programming language and every
embedded Orgize document language.  It MUST NOT publish one recovery generation
per installed provider: that N-generation sequence races durability attachment,
allows a successor to overlay a stale base, and turns the first Search into a
coverage-repair loop.  Startup construction remains outside the Search/Query
latency interval; after startup readiness, mixed producer admission is a
resident generation coverage check and performs no provider construction.

For a complete source-index successor, every non-=@scope/= file-hash record
belongs to exactly one admitted owner.  Overlay construction derives that
membership from the successor owner set and removes orphan hashes from the
active base before computing the content Merkle root.  Projection evidence may
remain under =@scope/=, but it is never a workspace source leaf.

No install client, provider, request handler, or cache command may repair or
advance persisted Runtime authority directly.  Publication and serving
activation remain separate transactions with explicit Ready evidence.

** Bounded streams and cancellation

All request fan-out/fan-in uses the workspace Tokio runtime, bounded channels,
deterministic ordering, and one cancellation-aware request scope.  Pure
in-memory graph, rank, Merkle, and route-cost kernels remain synchronous value
functions inside that task tree.

No SearchLoop path creates a private runtime, unmanaged OS thread, nested
=block_on= bridge, unbounded queue, polling loop, or request-time provider
process.

** Receipts are evidence, not lifecycle repair

Every admitted phase emits an attempt-bound start and exactly one completed,
failed, or cancelled terminal.  Receipts bind workspace, provider, generation,
operation, schema, and relevant content identities.

Telemetry may observe lifecycle but cannot authorize it.  A timeout, missing
event, or old receipt never repairs a state transition.  Search-result reuse
and model prefix-cache reuse remain distinct and separately observable.

Receipt, cache identity, replay, and recovery ownership is indexed by
[[file:10.05-interactive-graph-first-progressive-searchloop/10.05.40-receipts-cache-identity/00-overview.org][10.05.40 Receipts, Cache, and Semantic Identity]].

** Hard cut

Replacing a public operation, endpoint, schema projection, or transport deletes
its old parser branch, implementation, fixture, test, dependency, help,
guidance, and document locator in the same architecture change.

There is no compatibility toggle, legacy executor, fallback route, dual serve,
or version-suffixed Rust namespace.  Shared wire identity remains
=schemaVersion: 1= until a genuinely breaking shared schema requires a new
versioned schema artifact.

Typed resident dispatch removal is owned by
[[file:10.05.70-typed-resident-search-dispatch.org][10.05.70 Typed Resident Search Dispatch]].
