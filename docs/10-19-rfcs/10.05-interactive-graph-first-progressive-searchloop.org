* Global architecture invariant

ASP Server-First Agent Search Architecture.
The public gRPC ClientFrame is the sole public search/query route; the command entry is a thin typed CLI adapter.
Git history is the only historical architecture archive; this working tree describes only the current server-first design.

* Status

Normative architectural root for RFC 10.05.

This file is intentionally a compact index.  Detailed state machines,
algorithms, receipts, proofs, provider rules, and acceptance gates live in the

The governing principles are:

- server-first;
- agent-first;
- graph-first; and
- progressive-first.

* Decision

ASP exposes one SearchLoop data plane:

#+begin_example
typed request client
  -> shared agent-semantic-client
  -> ClientFrame gRPC/Tokio stream
  -> Runtime-owned bounded Unix data socket
  -> ASP Runtime Server admission
  -> resident provider/generation/search authority
  -> typed terminal receipt and client presentation
#+end_example

The CLI, Hook, Live Corpus, native integrations, and language clients are equal
clients of this route.  They do not own provider execution, workspace
generation, cache construction, projection truth, lifecycle recovery, or a
semantic fast path.

The Runtime daemon mounts the public =AspClientFrameService= through both the
=AspClientGrpcService= gRPC adapter and the =serve_http_json= HTTP/JSON
adapter.  Both adapters consume the same transport-neutral =ClientFrame=
schema, method catalog, lifecycle admission, and dispatcher; neither adapter
may parse a method into a second route or provide a fallback.  Runtime audits
the existing =data_socket= before endpoint allocation; it does not create a
fourth semantic authority.

The current endpoint field is the Runtime-owned bounded UDS
=client_endpoint=.  A v1 =client_http_endpoint= record may be consumed only as
authoritative input to one-way endpoint migration.  It never authorizes a
second current endpoint or semantic dispatcher.  When an HTTP endpoint is
advertised, its one canonical frame path is only a transport adapter over the
same =AspClientFrameService=; gRPC and HTTP/JSON round trips therefore produce
identical typed responses, including admission failures.

The package and route contract is owned by
[[file:10.05-interactive-graph-first-progressive-searchloop/10.05.01-server-client-package-responsibility.org][10.05.01 Server/Client Package Responsibility]].
Atomic resident activation is owned by
[[file:10.05-interactive-graph-first-progressive-searchloop/10.05.02-atomic-resident-publication.org][10.05.02 Atomic Resident Publication]].

* Naming

The canonical short name is =SearchLoop=.

=Interactive= means each agent turn observes a typed evidence state, chooses a
bounded action, receives a compact receipt, and advances a session frontier.
It does not mean a terminal prompt or human menu.

=Graph-first= means semantic owners, items, dependencies, capabilities, and
proof obligations are typed nodes and edges.  Commands transport graph
operations; command strings are not the ontology.

=Progressive= means each turn expands only the evidence needed for the next
decision.  It never weakens fail-closed authority or permits best-effort source
claims.

* Primary loop

The canonical state transition is:

#+begin_example
intent
  -> admitted workspace/provider authority
  -> typed seed topology
  -> bounded evidence route
  -> compact inspection
  -> focused expansion or exact materialization
  -> receipt-backed conclusion, reroute, or stop
#+end_example

Loop state, rather than a command transcript, is the durable protocol object.
A user-supplied exact selector enters the same topology as any other seed.  It
does not create a second text protocol.

Interactive transition semantics are owned by
[[file:10.05-interactive-graph-first-progressive-searchloop/10.05.10-interactive-searchloop/00-overview.org][10.05.10 Interactive SearchLoop]].

* Search/query wire and replay contract

Search and exact query are two operations on one public =ClientFrame= data
plane. The language CLI is only a typed adapter: it selects =search= or
=query=, supplies the schema-owned parameters, and renders the returned frame.
It does not create a provider route or interpret a URL/string heuristic.

Every successful or terminal frame carries the same workspace identity,
provider identity, generation identity, source-snapshot identity, request
identity, and schema references. Search results carry the typed =routeGraph=,
=actionFrontier=, and =recommendedNext= fields; query carries the canonical
structural selector and the declared source or projection kind. A query may
consume a selector produced by search only after the Runtime Server validates
that selector against the active immutable generation and source snapshot.

Admission is server-owned and precedes provider work. A cold search/query
request first reaches a single-flight generation admission, observes its
queued/building transition, and waits for one terminal receipt before reading
or dispatching a provider. =Queued= and =Building= are intermediate states,
never query results and never successful no-match evidence. A failed,
cancelled, stale, torn, or cross-generation admission is a typed terminal
error; it cannot fall back to a local provider or cached source.

Replay is identity-bound: replaying the same request against the same
workspace, provider, generation, source snapshot, selector, and schema
references is deterministic; a changed request nonce or any changed identity
must produce a new request and cannot reuse the prior terminal. Search and
query terminals therefore preserve the original request identity and expose
the server-owned error reason and next action without silent retry.

* Global invariants

** One lifecycle authority

ASP Runtime Server owns workspace identity, provider admission, lazy resident
activation, generation publication, bounded concurrency, cancellation, drain,
and lifecycle receipts.  A request client owns none of this mutable state.

Query handling never starts, repairs, restarts, or locally executes a provider.
Runtime absence and provider unavailability are typed terminal evidence, not
permission to construct an alternate route.

Tokio task ownership, generation-attempt terminalization, and telemetry
isolation are owned by
[[file:10.05.11.05-runtime-server-tokio-task-lifecycle.org][10.05.11.05 Runtime Server Tokio Task Lifecycle]].

** Language-scoped lazy admission

A language facade resolves through the registered provider catalog to exactly
one provider identity.  A language-scoped search, query, check, or cache
operation does not widen to a complete-generation or all-provider operation
when an index-owner argument is absent.

Only an explicitly unscoped operation may request global coverage.  Runtime
evidence for a language-scoped operation therefore reports no unrelated
provider process or preparation work.

Provider package, registration, and server authority are owned by
[[file:10.05.61-language-provider-server-authority.org][10.05.61 Language Provider Server Authority]].

** Typed topology before rendering

Every SearchLoop entry constructs stable nodes, directed typed relations, and
typed action-frontier entries before compact rendering.  Canonical selector
validation precedes any =owns_item= or =targets_item= relation.

Presentation ordinals and rendered =recommendedNext= text are not durable node
identities.  A malformed or cross-language selector may remain as unresolved
input evidence, but it produces neither an owner/item relation nor an
executable exact-query action.

Evidence topology and route selection are owned by
[[file:10.05-interactive-graph-first-progressive-searchloop/10.05.20-evidence-graph-routing/00-overview.org][10.05.20 Evidence Graph and Routing]].

** Active-generation authority

A search or exact query reads one admitted immutable generation.  =Ready=
means coverage is proven for the requested workspace owner and provider; an
empty or uncovered generation is not a successful =no-matches= result.

The active generation is the sole membership authority.  Provider fingerprint
storage and retained bytes are caches, not membership truth.  Concurrent
generation demand is single-flight and attempt-bound.

Memory ownership and capability-lazy indexes are owned by
[[file:10.05.11.09-runtime-generation-memory-authority.org][10.05.11.09 Runtime Generation Memory Authority]].
Generation publication and readiness are indexed by
[[file:10.05-interactive-graph-first-progressive-searchloop/10.05.20-server-resident-search-generation/00-overview.org][10.05.20 Server-Resident Search Generation]].

** Exact selector and source authority

Exact source materialization accepts one parser-owned structural selector and
returns only the projection declared by the typed operation.  Search-derived
projection and exact source are distinct operations and cannot reinterpret one
another after failure.

Owner discovery is not exact projection.  It may return canonical item
selectors without creating a workspace generation, but it cannot manufacture
source bytes or an exact-query success.

The selector chain is owned by:

- [[file:10.05.11-canonical-item-query-authority.org][10.05.11 Canonical Item Query Authority]];
- [[file:10.05.12-exact-selector-provider-generation-authority.org][10.05.12 Exact Selector Provider Generation Authority]]; and
- [[file:10.05.17-resident-exact-query-authority.org][10.05.17 Resident Exact Query Authority]].

** Request-independent generation work

Public requests submit or coalesce generation demand and observe the current
typed phase.  They do not wait inside the transport future for construction to
finish.  Dropping a request never detaches or silently cancels admitted work.

Every accepted attempt owns exactly one terminal publisher.  =Queued=,
=Building=, =Ready=, =Failed=, and =Cancelled= are Runtime states; client
timeouts, sleeps, polling, and elapsed-time repair cannot create transitions.

Incremental cache and mutation ownership are specified by
[[file:10.05-interactive-graph-first-progressive-searchloop/10.05.70-runtime-owned-incremental-cache-v1.org][10.05.70 Runtime-Owned Incremental Search Cache]].

** Atomic publication

Candidate generation, source root, provider/schema identity, projection
capability, and resident locator advance as one validated publication.  Readers
observe either the previous complete generation or the successor complete
generation.

No install client, provider, request handler, or cache command may repair or
advance persisted Runtime authority directly.  Publication and serving
activation remain separate transactions with explicit Ready evidence.

** Bounded streams and cancellation

All request fan-out/fan-in uses the workspace Tokio runtime, bounded channels,
deterministic ordering, and one cancellation-aware request scope.  Pure
in-memory graph, rank, Merkle, and route-cost kernels remain synchronous value
functions inside that task tree.

No SearchLoop path creates a private runtime, unmanaged OS thread, nested
=block_on= bridge, unbounded queue, polling loop, or request-time provider
process.

** Receipts are evidence, not lifecycle repair

Every admitted phase emits an attempt-bound start and exactly one completed,
failed, or cancelled terminal.  Receipts bind workspace, provider, generation,
operation, schema, and relevant content identities.

Telemetry may observe lifecycle but cannot authorize it.  A timeout, missing
event, or old receipt never repairs a state transition.  Search-result reuse
and model prefix-cache reuse remain distinct and separately observable.

Receipt, cache identity, replay, and recovery ownership is indexed by
[[file:10.05-interactive-graph-first-progressive-searchloop/10.05.40-receipts-cache-identity/00-overview.org][10.05.40 Receipts, Cache, and Semantic Identity]].

** Hard cut

Replacing a public operation, endpoint, schema projection, or transport deletes
its old parser branch, implementation, fixture, test, dependency, help,
guidance, and document locator in the same architecture change.

There is no compatibility toggle, legacy executor, fallback route, dual serve,
or version-suffixed Rust namespace.  Shared wire identity remains
=schemaVersion: 1= until a genuinely breaking shared schema requires a new
versioned schema artifact.

Typed resident dispatch removal is owned by
[[file:10.05.70-typed-resident-search-dispatch.org][10.05.70 Typed Resident Search Dispatch]].

* Projection boundary

SearchLoop constructs typed evidence and action-frontier state.  The rendering,
ranking projection, token/byte cost, compact packet shape, and other
agent-facing projection semantics are owned exclusively by
[[file:10.06-agent-search-projection.org][RFC 10.06 Agent Search Projection]].

RFC 10.05 does not duplicate projection syntax or cost formulas.  A compact
renderer consumes typed topology and cannot parse selectors again, invent
owner facts, or choose an action independently.

* Qualification gates

The architecture is qualified only when all applicable owner gates pass
together:

1. the current endpoint record resolves one bounded Runtime UDS and one public
   ClientFrame gRPC service;
2. production and public-route tests contain no HTTP/JSON or TCP fallback and
   no fourth client socket;
3. language clients, CLI, Hook, and Live Corpus use the shared typed client;
4. concurrent requests coalesce one admitted generation attempt and every
   attempt reaches exactly one terminal;
5. exact source, callable-skeleton, resident search, zero-match, cancellation,
   backpressure, and payload failure cases retain typed identity evidence;
6. warm resident operations perform zero provider launch, filesystem scan,
   database open, publication lock, retry, polling, or lifecycle mutation;
7. OpenTelemetry and Live Corpus expose phase, service, transport, wall,
   memory, work-counter, and terminal evidence without turning thresholds into
   lifecycle correctness;
8. Lean/AXLE audits refine the same single-route, bounded-stream,
   cancellation, publication, and receipt invariants; and
9. Org links resolve, each normative concern has one canonical owner, and the
   root remains a compact dependency map rather than a second specification.

Performance budgets are defined by the relevant child owner and executable
qualification.  Compilation, installation, daemon startup, provider warmup,
generation construction, transport time, service time, and whole-command wall
time are reported separately.
