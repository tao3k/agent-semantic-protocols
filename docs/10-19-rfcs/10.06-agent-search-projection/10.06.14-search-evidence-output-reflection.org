** Purpose And Non-Goals

This RFC owns reflection questions and counterexamples. It does not own CLI
grammar, output layout, topology storage, topology settlement, or an
implementation ledger. Those responsibilities are split into:

- [[file:10.06.15-search-query-playbook-contract.org][RFC 10.06.15]]: Search and Query Playbook contract.
- [[file:10.06.16-project-topology-reasoning-library.org][RFC 10.06.16]]: reusable project topology library.
- [[file:10.06.17-gql-ascent-search-reasoning.org][RFC 10.06.17]]: reusable Project Topology, internal logical inference, and single-GQL settlement.

Git is the history. This document must not become an append-only change diary.

** System Boundary

This SDD governs the shared Agent-facing evidence semantics. Provider parsing,
runtime storage, and UI rendering are dependencies, not alternate authorities.

** Stakeholders And Consumers

Consumers are search Agents, provider maintainers, Runtime admission owners,
schema authors, proof authors, and reviewers of source-owned Org contracts.

** Requirements And Constraints

Evidence is content-bound, language-neutral, replayable, compact, and
fail-closed. No presentation shortcut may mint authority or completeness.

** Quality Attributes

Primary qualities are decision sufficiency, epistemic precision, bounded
context, deterministic replay, cross-language symmetry, and drift safety.

** Design Concerns

The design separates facts from proposals, content identity from transaction
generation, complete evidence from bounded rendering, and Search from Query.

** Architecture Views

*** Runtime View

Runtime admits acquisition receipts, provider projections, topology identity,
derivation, ranking, and one typed terminal before rendering.

*** Data And State View

Durable state consists of source-owned contracts and content-addressed facts.
Packet-local aliases and display order are derived state.

*** Dependency And Integration View

RFC 10.06.15 owns operations, RFC 10.06.16 owns reusable topology, RFC 10.06.17
owns reasoning projection, and the Lean model supplies counterexamples.

** Interfaces And Contracts

The public interface is defined by the three child RFCs and their future shared
schemas. This parent defines the constraints all child contracts must satisfy.

** Decisions And Competing Candidates

The accepted decomposition replaces one cumulative RFC. Rejected alternatives
are one monolithic document, duplicated full SDD templates, and implementation
notes appended to the reflection owner.

** Data Model And Invariants

Facts, witnesses, coverage, topology, derivations, frontiers, selectors, and
source excerpts are distinct typed values. Rendering cannot change support.

** Accepted Boundary

A successful Search gives the Agent enough bound knowledge to Query an exact
selector, refine Search, or stop. It does not force an owner/member/Query
sequence when a direct selector is already admitted. Exact Query alone
materializes selector-owned source.

** Reflection Dimensions

1. =Decision sufficiency=: can the Agent choose a justified next operation?
2. =Epistemic typing=: is each claim a parser fact, declared meaning, accepted
   synthesis, proposal, retrieval witness, or derived conclusion?
3. =Non-redundancy=: is each fact rendered at one owning layer?
4. =Concision=: is presentation small without deleting required support?
5. =Replay value=: can a later turn recover identities and witnesses?
6. =Drift safety=: can changed source or interpretation invalidate reuse?

Redundancy, concision, and cost are separate properties.

** Fixed Decisions

- The evidence graph is the default; there is no =--evidence-skeleton= switch.
- fd, rg, and Tantivy are independent acquisition routes.
- Runtime adds no implicit extension filter.
- Native enrichment is provider-owned and automatic.
- =--native-syntax= accepts canonical selectors only.
- GQL is the sole default Agent-facing graph and owns direct facts, settled
  derivations, frontiers, semantic annotations, and Query handles.
- Ascent runs an internal, versioned topology-inference program. Runtime settles derived
  knowledge and coverage-sensitive frontiers into GQL with explicit modality,
  proof, and program provenance.
- Python Graphs ranks after derivation; Runtime then certifies topology witness closure,
  compatibility, coverage, and minimality before rendering.
- A source excerpt is not selector-failure recovery.
- Query returns the complete selector-owned scope without generated ellipses.
- Natural-language annotations remain premise-bound proposals until human or
  source-owned Org contract admission. They may guide Search but cannot prove
  structure, behavior, completeness, or absence.

** Open Questions And Fixed Invariants

Open: the production GQL grammar, typed topology-inference bridge schema, lattice join,
retraction strategy, ranking calibration, proof retention, and measured context
budget remain to be validated. Fixed invariants are listed
above and may change only through a new reviewed RFC decision.

** Fitness Criteria

Measure commands to the correct edit boundary, packet size, first-selector
latency, witness closure, repeated searches, false absence, cross-language
coverage, and stale-binding rejection.

** Evidence Loop

Run the Lean executable, Org lint, schema tests, provider round trips, sandtable
scenarios, and real-project trials. Feed observed ambiguity back to the owning
child RFC, then rerun this adversarial catalogue.

** Failure Modes And Recovery

Missing ownership, stale identity, incompatible premises, incomplete coverage,
or invalid witnesses fail closed. Recovery rebuilds the responsible derived
artifact from source-owned contracts; it never guesses selectors or ranges.

** Rollout And Migration

Adopt the split RFCs before shared schemas. Then align providers, implement the
Rust path, validate sandtables, and measure a real project. Old monolithic
sections are replaced by Git history and these responsibility links.

** Adversarial Review

R01 through R27 remain the required review suite. A child contract cannot claim
closure merely because its syntax lints or one provider renders it.
