#+title: RFC 10.15.02.01 — Agent Session Transactional Generation Lifecycle

* Status
Focused formal verification is complete. This RFC refines [[file:10.15.02-codex-resident-agent-lifecycle-v1.org][RFC 10.15.02]] from an evidence classifier into a transactional generation lifecycle. The Lean source, compiled module, direct audit, and runner pass; all 22 theorem declarations are axiom-free. No Rust implementation is authorized in this session.

* Observed counterexample
Both configured residents are =idle-resumable= but =routable=false= and =messageTargetStatus=unbound=. Their canonical paths remain occupied. The expected model is =gpt-5.6-luna= while host evidence identifies =gpt-5.4-mini=. Host-tree presence and follow-up acknowledgement exist, but neither commits a binding lease. =reconcile= reports =affected: 0=; child bootstrap is correctly rejected; the main session cannot retire and release the occupied path.

The legacy classifier can therefore revisit =RebindExistingChildTarget= forever. Presence selects a branch, but no authorized transaction changes generation, binding, or path ownership.

* Fundamental separation
The lifecycle has five orthogonal durable dimensions:

1. =ResidentSlot=: logical identity =(projectId, rootSessionId, residentName)=.
2. =PhysicalGeneration=: one concrete typed child and monotone generation.
3. =BindingLease=: verified child, root, target, and generation binding.
4. =LifecycleTransaction=: reservation, intent, host receipt, retirement, release, and replacement.
5. =DispatchLedger=: stable command identity, delivery generation, and terminal receipt.

Host-tree presence and follow-up acknowledgement are observations, not registration authority.

* Generation registration law
A generation becomes registrable only from a typed host-start receipt indexed by the durable spawn intent. It binds slot, generation, stable intent key, expected profile, child identity, and canonical target.

#+name: agent-session-valid-start-binding
#+begin_src typst
#let ValidStart(r, h) = $upright("ValidHostStart")(r, h)$
#let Slot(x) = $upright("slot")(x)$
#let Gen(x) = $upright("generation")(x)$
#let Intent(x) = $upright("intentKey")(x)$
#let Profile(x) = $upright("profile")(x)$
$
  forall r, h,
  ValidStart(r, h) => Slot(h) = Slot(r) and Gen(h) = Gen(r) and
  Intent(h) = Intent(r) and Profile(h) = Profile(r).
$
#+end_src

Stale generation, profile drift, generic child, path-only observation, and acknowledgement-only evidence cannot register a generation.

* Transactional repair decision
An occupied, unbound, profile-drifted slot has two safe classifications: commit a durable retirement intent when retirement exists, or return =BlockedHostCapability=. It never returns =Ready= or repeats rebind. Canonical-path release is a distinct intent after retirement, and replacement is legal only after a release receipt.

#+name: agent-session-repair-classification
#+begin_src typst
#let Classify(c, o) = $upright("classifyRepair")(c, o)$
#let Retire(c) = $upright("canRetire")(c)$
#let Drifted = $upright("OccupiedUnboundDrift")$
$
  forall c,
  Classify(c, Drifted) =
  cases(
    upright("CommitRetirementIntent") & "if " Retire(c),
    upright("BlockedHostCapability") & "otherwise",
  ).
$
#+end_src

* Monotone repair law
Every committed transition strictly decreases a finite phase rank. =Ready= and =BlockedHostCapability= are terminal rank-zero outcomes. This excludes self-loops and two-cycles without assuming every host capability exists.

#+name: agent-session-monotone-repair
#+begin_src typst
#let Step(x, y) = $upright("TransactionalRepairStep")(x, y)$
#let Rank(x) = $upright("phaseRank")(x)$
$ forall x, y, Step(x, y) => Rank(y) < Rank(x). $
$
  not exists x, Step(x, x)
  and not exists x, y, Step(x, y) and Step(y, x).
$
#+end_src

* Lean-discovered corrections
1. Presence and acknowledgement cannot construct =ValidBinding=.
2. A start receipt binds slot, generation, intent key, expected profile, and typed-start evidence.
3. Stale generation, profile drift, and untyped start are independently rejected.
4. Occupied/unbound drift never returns =Ready=.
5. Missing retire or release becomes a terminal blocker instead of another rebind iteration.
6. Strict phase-rank decrease excludes repair self-loops and two-cycles.
7. Dispatch acceptance remains indexed by generation, stable key, and command digest.

def ValidHostStart (reservation : GenerationReservation)

  receipt.slot = reservation.slot ∧
  receipt.generation = reservation.generation ∧
  receipt.intentKey = reservation.intentKey ∧
  receipt.observedProfile = reservation.profile ∧

  next : TransactionPhase
