#+startup: overview

Parent architecture: [[file:../../10.05-interactive-graph-first-progressive-searchloop.org][RFC 10.05 SearchLoop]].

* Status

Draft. The architecture and Lean statements are proposed. The failure
observations in this document were reproduced locally; they do not imply that
the proposed Rust server transaction is implemented.

* Decision

The normative principal is the =ASP Runtime Server=.  ASP Agent Session and Resident Subagent
authority is specified separately by
[[file:../10.05.22-agent-session-runtime-server-boundary/00-overview.org][RFC 10.05.22]].

=ASP-RFC-10.05-SRSG-AUTHORITY=: The Runtime Server workspace entry is the only
writer of search-index state.

=ASP-RFC-10.05-SRSG-READ-WRITE=: Reader readiness and writer readiness are
independent.  A failed or paused
writer lane MUST reject staging and publication, but it MUST NOT make the last
committed immutable generation unreadable.  SearchLoop availability depends on
the resident read plane and at least one ready provider partition, not on the
writer lane being online.

=ASP-RFC-10.05-SRSG-AVAILABILITY=: SearchLoop remains available exactly when
the resident read plane is online and at least one provider partition is ready.

The CLI, hooks, providers, SearchLoop, and agents may:

- submit source observations or provider deltas;
- request a generation lease;
- query a server-pinned generation;
- release a lease;
- inspect receipts.

They may not independently rebuild, activate, invalidate, or publish a search
generation.

This replaces the accidental multi-writer design in which the CLI source-index
cache, provider incremental owner cache, resident query generation, and
workspace-owner endpoint can advance independently.

* Observed counterexample

The local audit produced three simultaneous identities:

- a CLI rebuild published =source-index-6f7d...=;
- provider owner ingestion remained warm on =b4e0...=;
- exact query remained pinned to root =e5d9...=.

The rebuild reported =files=1633=, =owners=1633=, and =selectors=0=. A later
owner ingestion could discover a canonical selector, while exact query still
reported that the item was missing from its live owner generation.

This is not a cache-eviction problem. It is a missing single-writer and atomic
publication boundary.

The same audit also exposed adjacent lifecycle faults:

- =asp-explore=, =/root/asp_explore=, and =/root/asp_explorer= denoted
  different names or targets;
- a provider manifest containing =workspaceScope= was rejected by an older
  activation DTO;
- a project-resolution request and reader disagreed about a required
  =algorithm= field;
- a valid native child could be reachable while the ASP registry retained an
  unbound or stale target.

These observations motivate strict separation between host-native agent
addressing and server-owned search generation.

* Authority model

** Workspace server

For each canonical workspace identity, the server owns:

- the active generation;
- at most one staged generation per publication transaction;
- source-snapshot and provider-delta ingestion;
- parser and structural-selector materialization;
- generation compare-and-swap;
- retained-generation leases;
- publication, recovery, and garbage-collection receipts.

The server must persist the publication record before exposing a new active
generation.

** Source Index package boundary

=ASP-RFC-10.05-SRSG-DB-OWNER=: Source Index materialization is a DB Engine
responsibility inside the ASP Server.  The =agent-semantic-client-db= package
owns Turso tables, Merkle roots, source blobs, provider projections, generation
publication, active-generation reads, and their typed receipts.  The server
runtime calls this package through its bounded Tokio writer/read lanes.

The =agent-semantic-client= package is not a Source Index owner.  It may contain
only a typed server/IPC adapter when a command surface needs to ask the ASP
Server for a lookup or an admission operation.  It MUST NOT collect workspace
files, build Merkle state, open Turso, publish envelopes, or maintain a second
generation cache.  Gerbil remains a parser-fact provider; it does not build or
query the Source Index.

Turso is the durable canonical store and the resident MemoryBackend/mmap
projection is a server-managed read acceleration layer.  Merkle identities bind
source bytes, selectors, workspace generation, and publication receipts; they
do not create a client-side authority.  Any older client-local Source Index
implementation is retired by this package boundary rather than exposed as a
compatibility alias.

** Provider

A provider parses language-owned input and returns a typed delta plus its
source-snapshot evidence. A provider does not choose the active generation.

A failed provider marks only its provider partition unavailable. It must not
invalidate unrelated ready partitions or the server generation itself.

** CLI and SearchLoop

The CLI is a thin adapter. SearchLoop sends clauses and consumes a lease-bound
evidence graph. Neither surface owns an index cache.

Commands such as =cache source-index rebuild= may remain as operator repair
tools, but they must submit a server rebuild transaction. They must not write a
parallel local generation.

** Host-native agent route

A registered subagent name is resolved by the host to a live DeepLink or native
message target. ASP records and verifies the host attestation; it must not
derive a target path from punctuation or role spelling.

An =@registeredSubagentName= dispatch therefore takes one host routing hop:

The same local run produced four hook/router counterexamples:

- a live registered =asp_explorer= resident was replaced by a legacy
  =asp-explore bootstrap= instruction instead of receiving a native follow-up;
- =asp query playbook --documents org= emitted a lexical =recommendedNext= that the Org facade
  rejected as =unsupported view lexical=;
- a Rust owner route was recommended for an Org owner and then failed with
  =owner-language-mismatch=; and
- an exact named =orgize eval plan= piped to =typst eval --in -=, and a bounded
  JSON receipt projection, were misclassified as =bulk-source-dump=.

=ASP-RFC-10.05-SRSG-HOOK-ROUTE= is deleted.  Its authority and proof are
=ASP-RFC-10.05-ASRS-ROUTE= in RFC
10.05.22.  The Agent Session hook MUST preserve parser-owner identity, exact
block/receipt boundedness,

of the protocol contract and MUST be grammar-checked against the selected

* Server transaction

Let server state be:

#+name: server-generation-state
#+begin_src typst
$ S = (r, g_a, g_s, d_a, R, W) $

#table(
  columns: 2,
  [Field], [Meaning],
  [$r$], [authority revision],
  [$g_a$], [active generation],
  [$g_s$], [optional staged generation],
  [$d_a$], [active snapshot digest],
  [$R$], [resident read plane is online],
  [$W$], [single writer lane is online],
)

"ok"
#+end_src

Publication is a compare-and-swap transaction:

=ASP-RFC-10.05-SRSG-CAS=: publication is a writer-online,
revision-matching, monotone compare-and-swap.

#+name: server-generation-cas
#+begin_src typst
$ "PublishCAS"(S, r_e, g_n, d_n)
:=
W
and (r_e = r)
and (g_a < g_n)
and "Validated"(g_n, d_n) $

$ "commit"(S, g_n, d_n)
=
(r + 1, g_n, "none", d_n, R, W) $

$ r_e != r
arrow.r.double
"PublishCAS"(S, r_e, g_n, d_n) = "none" $

$ not W
arrow.r.double
"PublishCAS"(S, r_e, g_n, d_n) = "none" $

"ok"
#+end_src

A staged generation is never query-visible. A query is valid only with a
server-issued lease:

=ASP-RFC-10.05-SRSG-LEASE=: every query is bound to one published generation
and authority revision.

#+name: server-generation-lease
#+begin_src typst
$ L = (w, g_l, r_l) $

$ "CanQuery"(S, L)
:=
R
and (g_l = g_a)
and (r_l <= r) $

$ g_s = "some"(g_n)
arrow.r.double
not "CanQueryGeneration"(S, g_n) $

$ R and not W
arrow.r.double
"CanQuery"(S, (w, g_a, r)) $

"ok"
#+end_src

Retained generations may be queried only by an unexpired lease. They cannot
receive new writes. Garbage collection must preserve every leased generation.

* Safety requirements

1. Single writer: only the workspace server changes active generation.
2. Unique active generation: one workspace has at most one active generation.
3. =ASP-RFC-10.05-SRSG-STAGING=: Staged invisibility: staged data cannot answer queries.
4. CAS publication: a stale authority revision cannot publish.
5. Monotone generation: successful publication strictly increases generation.
6. Lease consistency: every answer identifies the exact generation and
   revision used.
7. Provider isolation: one failed provider cannot erase unrelated ready
   partitions.
8. Crash safety: recovery exposes the last committed active generation, never
   a partially staged generation.
9. No inferred native target: ASP accepts only a host-attested DeepLink or
   message target.

* Recovery

Recovery order is:

1. identify the canonical workspace server;
2. load the last committed publication record;
3. discard or resume an uncommitted staged transaction;
4. restore provider partitions independently;
5. publish a fresh generation only after selector and snapshot validation;
6. issue new leases;
7. resume SearchLoop.

CLI cache deletion is not a recovery primitive.

The platform supervisor definition MUST pin the immutable, digest-addressed
runtime artifact, not the mutable =runtime/bin/asp= entry. Publishing a new
stable entry therefore changes the supervisor definition and forces an atomic
service replacement. A healthy receipt from the previous digest is not a
successful reconciliation.

Supervisor replacement is ordered.  It first observes the running endpoint with
a read-only =Status= request, then atomically publishes and loads the definition
that pins the canonical artifact, and only then asks an older generation to
drain.  A health probe MUST NOT drain the old generation before the replacement
definition is loaded: doing so permits the still-old supervisor definition to
restart the stale binary.  Reconciliation completes only after the endpoint
receipt proves the canonical artifact digest and transport contract.

Daemon bootstrap is Global and workspace-neutral.  It opens the catalog,
registry, election, and Tokio control/data-plane listeners without requiring a
Git candidate snapshot or an active workspace generation.  Workspace identity
and candidate evidence enter only through the first typed workspace admission;
one malformed or stale workspace receipt cannot prevent the Global daemon from
publishing its endpoint.

Exact-selector relocation is projection-independent.  The active generation
first resolves the parser-minted canonical item identity (=languageId + kind +
symbol + implementationOwner + traitOwner=) to zero, one, or many live
selectors.  Only after a unique live selector is chosen may the reader resolve
the requested projection.  A unique relocation is a successful exact read when
that projection exists; the consumer MUST NOT reject it merely because the
owner path changed.  When the item relocated but the projection is absent, the
result is =projection-mode-not-in-active-generation= with the resolved selector,
never =selector-not-in-active-generation=.  Ambiguous identity and genuinely
retired identity remain distinct terminal states.  Query execution is read-only
and cannot rebuild or publish a generation to repair either state.
An explicit ASP workspace command therefore has a control-plane readiness edge
before query dispatch.  The hook asks the Runtime Server to validate the
published project-root locator and waits for a terminal =Ready= admission
receipt.  A missing or incompatible locator forces a new single-flight writer
attempt even when the candidate digest equals the last admitted candidate;
returning a cached =Ready= receipt for an unreadable mmap is forbidden.  The
writer restores the last canonical Turso materialization or builds and commits
a new generation, then atomically publishes the locator.  Session-start and
ordinary prompt admission remain non-terminal scheduling operations, so one
cold workspace cannot block the Global daemon or unrelated workspaces.
The projection-independent identity table is the only v1 exact-segment format;
readers reject earlier projection-keyed mmap bytes and the workspace writer
re-materializes them from the last canonical Turso generation before exposure.

* Implementation calibration

| Surface | Current evidence | Required state |
|-
| Rust provider manifest | =workspaceScope= can be emitted | reader and generator share one versioned DTO |
| Project resolution | request/reader =algorithm= drift observed | versioned request with compatible defaults |
| Source-index rebuild | rebuilt owners with zero selectors | server transaction validates non-vacuous selector coverage |
| Provider incremental owner | independent warm generation observed | delta commits into server staging generation |
| Exact query | stale active root observed | server lease pins the published generation |
| Exact relocation | projection-keyed relocation hides moved items | canonical item identity resolves before projection availability |
| Native subagent dispatch | host follow-up is routable | registered name resolves to host-attested DeepLink |
| ASP session | bootstrap/claim loop adds foreground rounds | verify native receipt; do not duplicate host routing |

* Lean correspondence

The Lean model =ASPProof.RuntimeServerSearchGeneration= proves:

- CLI write authority is empty;
- staged generations are not queryable;
- stale revision publication is rejected;
- successful publication is monotone and clears staging;
- an offline writer cannot publish;
- stopping the writer preserves a lease-bound read of the active generation;
- a lease-bound query uses the active generation;
- loading the canonical supervisor definition before drain makes the restarted
  process canonical, while drain-before-load can restart the stale digest;
- Global daemon bootstrap does not require a workspace identity;
- canonical relocation is independent of projection availability;
- a uniquely relocated item with an available projection is an exact hit;
- one ready provider preserves partial SearchLoop availability;
- declared server cost strictly dominates the CLI rebuild path.

The Lean model does not prove parser correctness, storage durability, operating
system liveness, or the measured cost constants.

* Non-goals

- preserving the existing complex cache CLI as an agent-facing API;
- making provider activation a global all-or-nothing gate;
- deriving a native agent target from a normalized string;
- treating a successful build, manifest parse, or =Ready= pane as end-to-end
  search closure.
