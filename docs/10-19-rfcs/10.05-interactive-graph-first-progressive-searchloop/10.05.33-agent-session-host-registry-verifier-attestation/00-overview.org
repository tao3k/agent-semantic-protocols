#+title: RFC 10.05.33 — Agent Session Registry Verifier Attestation
#+startup: overview

* Status

Focused formal attestation verification is complete. This RFC refines
[[file:../10.05.32-agent-session-host-registry-merkle-path-conformance/00-overview.org][RFC 10.05.32 — Agent Session Registry Merkle Path Conformance]]. It defines
byte-level verifier attestation, Lean audit, and AXLE receipt identity. The
source module and direct audit compile, all 23 declarations are axiom-free, the
Lean JSON audit is admitted by the repository AXLE consumer across five scoped
theorem families and five RFC clauses, and the module is imported by the
proof-package root. It does not authorize Rust implementation.

This closure validates the formal attestation contract and its audit inventory.
It does not claim that an installed runtime verifier artifact has already been
replayed. Runtime artifact execution remains the next boundary.

The aggregate =lake build ASPProof= gate remains outside this focused claim;
unrelated proof modules retain the previously recorded =Mathlib= and
=Decidable= failures.

* Problem

RFC 10.05.32 proves the abstract path fold and semantic bridge. It does not bind
that proof to the bytes, decoder, executable verifier artifact, or test-vector
suite used at runtime.

Five gaps remain:

- naive concatenation is ambiguous before hashing;
- a decoder may accept a wrong domain, inconsistent length, invalid direction,
  truncation, or trailing bytes;
- a digest implementation may ignore its domain or disagree with golden vectors;
- an otherwise conforming verifier result may come from a different executable;
- an AXLE receipt may say “pass” without binding the Lean module, Lean audit,
  verifier artifact, and vector-suite identities.

The attestation chain is complete only when all five identities agree.

* Evidence alignment

Existing contracts already require domain-separated length-prefixed Merkle
parts, exact artifact identity, malformed-packet fail-closed behavior, and
scoped Lean/AXLE receipts. RFC33 composes those requirements into one verifier
attestation boundary. It does not replace the source-snapshot Merkle authority
or claim mathematical injectivity for a runtime digest.

* Lean-discovered obligations

The model separates transport and identity data in =Type= from attestation
evidence in =Prop=. It constructs four unsafe alternatives:

- two different field partitions with the same naive concatenation;
- an always-decode implementation that returns a packet for malformed input;
- an always-zero digest that fails a non-zero vector;
- an unbound AXLE receipt carrying only a pass bit and note digest.

The admitted receipt binds module, audit, artifact, and vector-suite identities
independently. One aggregate “passed” value cannot substitute for those fields.

Lean decoder totality is not executable termination evidence by itself. The
runtime artifact must be replayed against malformed classes and golden vectors;
the resulting evidence must be admitted by AXLE without granting undeclared
axioms to the Lean theorem family.
