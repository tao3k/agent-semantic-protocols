* Status

This document is the cache-identity refinement of the SearchLoop mathematical
model in [[file:00.11-clause-first-mathematical-model.org][00.11]].  It is normative for semantic cache reuse and invalidation.

The mathematical source is the named Typst Org Babel block
=searchloop-cache-invalidation-model= in this RFC.  There is intentionally no
detached authoritative =.typ= file and no =:file= header argument.  Org is the
single durable source; =asp org= extracts the parser-owned block and Typst
receives it on stdin.  A generated PDF is a validation artifact, not a second
source of truth.

The executable proof authority is split across:

- [[file:../../../../packages/proofs/ASPProof/SearchLoopCacheIdentity.lean][ASPProof.SearchLoopCacheIdentity]] for complete identity, generation, tier, and reconciliation laws;
- [[file:../../../../packages/proofs/ASPProof/SearchLoopCacheRelocation.lean][ASPProof.SearchLoopCacheRelocation]] for explicit selector relocation; and
- [[file:../../../../packages/proofs/ASPProof/SearchLoopCacheDiagnostics.lean][ASPProof.SearchLoopCacheDiagnostics]] for typed invalidation diagnostics.

The Lean model is not a transcription target after the RFC is finished.  It is
an adversarial model checker for the RFC: counterexamples and type distinctions
found while proving the laws MUST be fed back into this document and its Typst
block.

* Problem

SearchLoop should reduce the agent-facing complexity of search.  A semantic
cache can avoid repeating discovery, but only if a cache hit means that every
authority-bearing input needed by the cached conclusion is unchanged.

Three tempting simplifications are unsound:

1. A workspace generation is not a semantic witness.  Unrelated workspace
   changes may advance the generation while the minimal witness remains valid.
2. A witness set is not a source snapshot.  The witness identifies evidence
   consumed by an obligation; the snapshot belongs to the validation domain
   used to judge that evidence.
3. Model and prompt identity do not belong in every semantic key.  They affect
   model-produced L4 judgments, but needlessly invalidate parser-owned semantic
   receipts.

The earlier eleven-component sketch collapsed the first two identities and the
earlier fourteen-theorem audit collapsed five different proof-admission scopes.
Lean exposed both errors.  This RFC corrects them rather than encoding them as
implementation accidents.

* Design goals

- Make semantic reuse an exact, provider-neutral relation.
- Keep cache-hit authority separate from human-readable invalidation reasons.
- Prove that omitting provider, provider artifact, policy, or RFC identity can
  produce false reuse.
- Permit selector relocation only through an explicit rekey operation.
- Keep whole-workspace generation out of the semantic equality key.
- Scope model and prompt identity to model-output tiers.
- Admit Lean JSON into AXLE by actual axiom closure, never by a broad aggregate
  inventory.
- Keep the complete mathematical explanation executable inside Org Babel.

* Non-goals

- This RFC does not define a Rust command or add Rust implementation.
- It does not require agents to construct cache keys manually at the CLI.
- It does not make invalidation-reason precedence part of cache authority.
- It does not claim that an aggregate Lean JSON inventory is an AXLE admission
  receipt.
- It does not turn a generated PDF into an independently edited specification.

* Normative type projection

** Validation identity

Lean =ValidationIdentity= contains four independent fields:

| Lean field | Mathematical symbol | Meaning |
|-
| =sourceSnapshot= | \(s\) | content identity of the source snapshot |
| =provider= | \(p\) | provider contract identity |
| =schema= | \(\sigma\) | shared schema identity |
| =policy= | \(\pi\) | policy identity |

Define

\[
  D = (s,p,\sigma,\pi).
\]

The source snapshot field \(s\) is deliberately not the witness-set field
\(v\).  This is a distinction of semantic role and tuple position, not a claim
that their underlying encodings can never be numerically equal.  A witness set
can remain minimal while the containing source snapshot or validation
authority changes.

** Semantic key

Lean =SemanticKey= has the following top-level fields:

| Lean field | Mathematical symbol | Meaning |
|-
| =obligation= | \(o\) | proof/search obligation |
| =workspace= | \(w\) | canonical workspace identity |
| =witnessSet= | \(v\) | minimal evidence identity |
| =domain= | \(D\) | validation identity |
| =providerArtifact= | \(a\) | executable/provider artifact identity |
| =selector= | \(q\) | structural selector identity |
| =rfc= | \(r\) | governing RFC identity |
| =projection= | \(\rho\) | projection/rendering contract |
| =budgetClass= | \(b\) | bounded search budget class |

Flattening \(D\) gives the complete twelve-component semantic identity:

\[
  K_s=(o,w,v,s,p,\sigma,\pi,a,q,r,\rho,b).
\]

No public CLI needs to expose this tuple.  SearchLoop and its providers derive
it from parser-owned facts, installed artifact identities, schemas, policies,
and the governing RFC.

** Workspace generation is reconciliation state

Lean =CacheState= stores a =SemanticKey= together with
=workspaceGeneration=.  Let that generation be \(g\):

\[
  C=(K_s,g).
\]

Semantic reuse depends on \(K_s\), not on equality of \(g\).  A generation
comparison is a reconciliation trigger:

\[
  g_c \ne g_n \;\not\Rightarrow\; K_{s,c}\ne K_{s,n}.
\]

Therefore whole-generation invalidation is conservative but incomplete: it can
reject a valid semantic receipt after an unrelated workspace change.  After a
generation drift, SearchLoop MUST recompute the current semantic identity from
the minimal witness and authorities; it MUST NOT treat generation equality as
proof of semantic compatibility.

** Model judgment key

Lean =ModelJudgmentKey= extends the semantic key with model and prompt
identities:

\[
  K_{L4}=(K_s,m,h).
\]

Here \(m\) is model identity and \(h\) is prompt identity.  They are required
for model-produced L4 output and excluded from parser-owned semantic receipt
reuse.

* Normative laws

** Exact semantic reuse
:PROPERTIES:
:RFC_CLAUSE_ID: ASP-RFC-10.05-SCI-KEY-IDENTITY
:END:

For cached and current semantic keys \(k_c,k_n\):

\[
  \operatorname{reuse}(k_c,k_n)\iff k_c=k_n.
\]

Consequently:

- exact key equality is sufficient for reuse;
- any complete-key drift invalidates semantic reuse; and
- a successful reconciled state implies exact semantic-key equality.

This is the authority relation.  It is intentionally simpler than diagnostic
classification.

** Omission countermodels

For a field \(x\), let \(P_{-x}\) project a key while omitting \(x\).  Lean
constructs unequal keys that collide under the following projections:

\[
\begin{aligned}
  k_1\ne k_2 &\land P_{-p}(k_1)=P_{-p}(k_2),\\
  k_1\ne k_2 &\land P_{-a}(k_1)=P_{-a}(k_2),\\
  k_1\ne k_2 &\land P_{-\pi}(k_1)=P_{-\pi}(k_2),\\
  k_1\ne k_2 &\land P_{-r}(k_1)=P_{-r}(k_2).
\end{aligned}
\]

Thus provider, provider artifact, policy, and RFC identity are not optional
metadata.  Omitting any one admits a false hit.

** Typed invalidation is diagnostic
:PROPERTIES:
:RFC_CLAUSE_ID: ASP-RFC-10.05-SCI-TYPED-INVALIDATION
:END:

Let =diagnoseSemantic= return a list of typed =InvalidationReason= values.
The diagnostic layer obeys:

\[
  \operatorname{diagnose}(k_c,k_n)=\varnothing
  \iff k_c=k_n,
\]

and

\[
  \operatorname{diagnose}(k_c,k_n)\ne\varnothing
  \Rightarrow \neg\operatorname{reuse}(k_c,k_n).
\]

Typed reasons make provider-artifact drift, policy drift, and future mismatches
auditable.  Their ordering or presentation MUST NOT decide reuse.  This
separation prevents a diagnostic-precedence change from silently changing cache
authority.

** Selector relocation
:PROPERTIES:
:RFC_CLAUSE_ID: ASP-RFC-10.05-SCI-SELECTOR-RELOCATION
:END:

Selector drift is stale by default:

\[
  q_c\ne q_n \Rightarrow
  \neg\operatorname{reuse}(K_s[q:=q_c],K_s[q:=q_n]).
\]

A provider may prove relocation and explicitly rekey the cached identity:

\[
  \operatorname{relocate}(k_c,q_n)=k_n
  \Rightarrow
  \operatorname{reuse}(\operatorname{relocate}(k_c,q_n),k_n).
\]

Relocation is therefore neither string fallback nor implicit selector
normalization.  It is an explicit transition whose result is checked by the
same complete equality law.

** Tier-sensitive model drift
:PROPERTIES:
:RFC_CLAUSE_ID: ASP-RFC-10.05-SCI-TIER-SCOPE
:END:

For a fixed \(K_s\) and different model/prompt pairs:

\[
  (m_1,h_1)\ne(m_2,h_2),
\]

semantic reuse is preserved:

\[
  K_s=K_s,
\]

while L4 reuse is invalid:

\[
  (K_s,m_1,h_1)\ne(K_s,m_2,h_2).
\]

This avoids invalidating parser-owned results whenever the calling model or
prompt changes, while still preventing reuse of stale model judgments.

* SearchLoop interaction

The agent does not issue a large cache-aware search command.  SearchLoop owns
the progressive interaction:

1. derive the current obligation and minimal witness;
2. derive the complete semantic key from parser/provider authority;
3. compare exact semantic identity;
4. if generations differ, reconcile rather than blanket-invalidate;
5. if keys differ, emit typed reasons and a focused next action;
6. if selector relocation is available, prove and rekey it explicitly;
7. include model/prompt identity only for the L4 model-output tier.

The CLI remains a transport for traditional human use.  It is not the public
representation of the proof key and does not need a combinatorial family of
cache flags.

== Complete semantic identity

Let

$ D = (s, p, sigma, pi), $

where $s$ is the source snapshot, $p$ the provider, $sigma$ the schema, and
$pi$ the policy. The flattened semantic key is

$ K_s = (o, w, v, s, p, sigma, pi, a, q, r, rho, b). $

The components are obligation, workspace, witness set, source snapshot,
provider, schema, policy, provider artifact, selector, RFC, projection, and
budget class. Their roles remain distinct:

$ "role"(v) = "witness-set", quad
  "role"(s) = "source-snapshot". $

Even if their underlying encodings happen to be equal, the two tuple positions
cannot be projected into one field: a minimal witness is not the validation
source snapshot.

== Exact authority and typed diagnostics

Cache authority is complete equality:

$ reuse(k_c, k_n) <=> k_c = k_n. $

Typed diagnostics are derived only after comparison:

$ diagnose(k_c, k_n) = emptyset <=> k_c = k_n, $

$ diagnose(k_c, k_n) != emptyset
  => not reuse(k_c, k_n). $

Diagnostic ordering cannot turn a stale key into a hit.

== Omission countermodels

For $x in {p, a, pi, r}$, let $P_(-x)$ omit field $x$. Lean constructs
countermodels satisfying

$ k_1 != k_2 quad "and" quad P_(-x)(k_1) = P_(-x)(k_2). $

Therefore provider, provider artifact, policy, and RFC identities all belong to
the semantic authority key.

== Workspace generation is not the witness

A cache state is

$ C = (K_s, g). $

Generation drift does not imply semantic drift:

$ g_c != g_n quad "does not imply" quad K_(s,c) != K_(s,n). $

Consequently a whole-generation predicate can reject reuse while exact
semantic equality still proves

$ reuse(K_(s,c), K_(s,n)). $

Generation drift triggers reconciliation; it does not replace witness-based
validation.

== Selector relocation

Selector drift is stale by default:

$ q_c != q_n => not reuse(K_s[q := q_c], K_s[q := q_n]). $

Explicit relocation is valid only when rekeying produces the complete current
identity:

$ relocate(k_c, q_n) = k_n
  => reuse(relocate(k_c, q_n), k_n). $

== Tier-sensitive model identity

Parser-owned semantic receipts use

$ K_"semantic" = K_s. $

L4 model-output entries use

$ K_"L4" = (K_s, m, h). $

For fixed $K_s$ and changed model/prompt identity,

$ (m_1, h_1) != (m_2, h_2), $

semantic reuse remains valid, while

$ (K_s, m_1, h_1) != (K_s, m_2, h_2). $

* Verification contract

The cache proof slice is valid only when all of the following hold:

1. the three focused Lean modules compile;
2. =ASPProof.Audit= compiles and emits all seven deterministic Lean JSON files;
3. each JSON file validates against =lean-proof-audit.v1=;
4. AXLE admits the five scopes with the exact allowed axiom closure;
5. omitting =--allow-axiom propext= rejects an equality scope;
6. all five AXLE receipts validate against =axle-lean-audit-receipt.v1=;
7. =asp org= extracts the named Typst block and =typst compile -= succeeds; and
8. the proof receipt records exact hashes, counts, and any broader build
   blocker without treating focused success as full-package completion.

* Consequences for future implementation

- Providers derive keys; agents do not spell twelve-component tuples.
- Cache hits are exact semantic claims with auditable authorities.
- Typed reasons guide the next SearchLoop action without becoming authority.
- Generation changes lead to focused reconciliation instead of blanket cache
  destruction.
- Explicit relocation is a proof-carrying rekey operation.
- Model churn does not invalidate parser-owned semantic evidence.
- Any future key-field removal requires a Lean countermodel attempt before the
  RFC can be weakened.
