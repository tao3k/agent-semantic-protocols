#+property: header-args:typst :lint typst-eval :runtime typst :format typst

* Status

This module closes the finite reference boundary left by 01.34.  A single
package-owned generator executes the reference GQL path and positive Logic
join, then emits two committed views of the same trace: canonical JSON for
schema and digest checks, and Lean constants for theorem replay.

This is a proof-oriented reference contract.  It does not implement the Rust
provider, claim production latency, or prove every future GQL or Ascent
program.  Its purpose is to make semantic and artifact drift observable before
the provider architecture is accepted as a replacement for the legacy search
surface.

* Artifact identity contract

The generator binds the trace to the schema version, generator identity,
source snapshot, provider artifact, runtime artifact, GQL source and AST,
Logic source and AST, relation registry, graph snapshot, execution binding,
row multiplicity policy, and canonical ordering policy.  The payload digest is
computed after all semantic fields are present and before it is inserted into
the JSON object.

#+begin_src typst
#{
  $d_p = H("canonical-payload-bytes")$
  $"Generate"(x) = (J_x, L_x)$
  $"Stable"(x) = (J_x = J_"committed") and (L_x = L_"committed")$
  $"Bound"(x) = (d_p = d_"claimed") and "Stable"(x)$
}
#+end_src

Canonical JSON uses sorted keys, compact separators, UTF-8, and exactly one
terminal LF.  Generated Lean uses a deterministic declaration order and also
ends in exactly one LF.  Tests compare both generated byte strings with their
committed artifacts; semantic equality alone is insufficient.

* Stateful replay protocol

#+begin_src mermaid
stateDiagram-v2
  [*] --> InputsBound
  InputsBound --> SemanticsExecuted: parse and bind GQL plus Logic
  SemanticsExecuted --> TraceGenerated: evaluate graph and relations
  TraceGenerated --> JsonValidated: validate schema and recompute payload digest
  TraceGenerated --> LeanGenerated: render deterministic Lean constants
  JsonValidated --> BytesMatched: JSON bytes equal committed fixture
  LeanGenerated --> BytesMatched: Lean bytes equal committed fixture
  BytesMatched --> LeanReplayed: replay rows, multiplicity, policy, and read-only graph
  LeanReplayed --> AxleAdmitted: all named declarations are axiom-free
  AxleAdmitted --> Accepted
  InputsBound --> Rejected: identity missing or malformed
  JsonValidated --> Rejected: digest mismatch
  LeanGenerated --> Rejected: generated bytes drift
  LeanReplayed --> Rejected: semantic rows drift
  Rejected --> [*]
  Accepted --> [*]
#+end_src

The transition is fail closed.  A valid schema shape is not enough: changing a
row while retaining the old payload digest, changing the graph while retaining
the query, or regenerating only one of the JSON and Lean views must prevent
admission.

* Semantic replay obligations

The normative clause identifier is
=ASP-RFC-10.05.01.35-ARTIFACT-REPLAY=.  Every declaration in the AXLE audit
maps to this clause; adding an unrelated theorem without an RFC mapping does
not increase the admitted coverage.

#+begin_src typst
#{
  $"Replay"(L_x) = (R_G^x = R_G^"reference") and
    (R_L^x = R_L^"reference")$
  $"ReadOnly"(x) = D_G^"before" = D_G^"after"$
  $"Admit"(x) = "Bound"(x) and "Replay"(L_x) and "ReadOnly"(x)$
}
#+end_src

The committed trace contains two distinct =OWNED_BY= witness edges with the
same endpoints.  Both GQL and Logic results therefore contain duplicate
projected rows.  The Lean replay proves that three rows remain present and that
the first two projected rows are equal; deduplicating them would violate the
=bag-by-witness-edge= contract.

* Honest proof boundary

Python owns canonical JSON serialization, SHA-256 recomputation, JSON Schema
validation, and byte comparison with both committed artifacts.  Lean imports
the generated constants and proves finite semantic replay, graph read-only
identity, policy identity, and fail-closed rejection of a changed payload
digest.  Lean does not implement SHA-256 in this module and therefore does not
independently prove the cryptographic algorithm or the Python generator for all
possible inputs.

The combined claim is deliberately narrower:

1. the packaged generator deterministically emits the committed JSON and Lean
   bytes for the reference input;
2. the JSON payload validates and its claimed payload digest recomputes;
3. the imported Lean rows equal the independently stated finite reference
   semantics;
4. all named replay declarations are admitted without axioms;
5. runtime performance and production-provider equivalence remain empirical
   gates after implementation.

* Acceptance evidence

The focused Python artifact suite passes 7 tests.  The Lean replay and audit
targets compile, and the audit inventory must report no axiom dependencies for
every named declaration.  AXLE must admit the corresponding audit JSON and
produce the versioned receipt before this module is considered closed.

* Next boundary

The qualification contract is continued by
[[file:01.36-polyglot-search-empirical-qualification.org][01.36 Polyglot Search Empirical Qualification]].

The next implementation phase may connect the shared trace contract to real
provider artifacts and representative projects.  It must preserve the same
identity fields and progressive-search semantics, while adding empirical
receipts for token cost, graph-hop count, interaction turns, latency, cache-hit
behavior, and answer quality.  Those measurements cannot be substituted by
the finite Lean replay.
