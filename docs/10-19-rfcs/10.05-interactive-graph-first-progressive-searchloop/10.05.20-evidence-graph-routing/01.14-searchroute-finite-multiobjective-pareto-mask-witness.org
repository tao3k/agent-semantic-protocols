#+title: SearchRoute Finite Multiobjective Pareto Mask and Dominance Witness
#+startup: overview
#+options: toc:3 num:nil

* Status

This RFC discharges the certified keep-mask assumption introduced by
=01.13-searchroute-certified-normalized-union-sequential-equivalence.org= for a
finite committed candidate universe.

It defines an executable multiobjective dominance relation, derives the
keep-mask by finite dominator search, proves soundness and completeness, and
requires a dominating witness for every removed route.

This RFC changes no Rust or Python runtime code.

* Cost vector

Each canonical route has the cost vector:

#+begin_example
(graphHops,
 projectedTokens,
 interactionRounds,
 searchCacheMisses,
 modelCacheMisses)
#+end_example

The two cache dimensions are intentionally distinct:

- =searchCacheMisses= measures failure to reuse parser/search graph state;
- =modelCacheMisses= measures failure to reuse model-side prompt-prefix state.

One cache hit does not compensate for a miss in the other dimension. They may
be weighted or constrained by a later policy, but the canonical vector keeps
their evidence separate.

* Strict dominance

Route =a= strictly dominates route =b= when =a= is no worse in all five
dimensions and strictly better in at least one:

#+name: finite-multiobjective-strict-dominance
#+begin_src typst :lint typst-eval-stdin :runtime typst
$ a prec b
  quad "iff" quad
  forall i in D, c_i(a) <= c_i(b)
  quad "and" quad
  exists j in D, c_j(a) < c_j(b) $

$ D = { "hops", "tokens", "rounds",
  "search-cache misses", "model-cache misses" } $

$ c(a) = c(b)
  quad "implies" quad
  not (a prec b) and not (b prec a) $
#+end_src

Equal cost therefore does not imply duplicate identity and does not create
strict dominance. Two distinct canonical routes with equal cost remain in the
frontier.

* Finite keep-mask construction

For each candidate =r= in committed universe =U=:

#+begin_example
findDominator(U, r):
  return the first d in the enumeration for which d strictly dominates r
  return none when no such d exists

keep(U, r):
  true  when findDominator(U, r) = none
  false when findDominator(U, r) = some(d)
#+end_example

Enumeration order may choose a different valid witness, but it MUST NOT change
keep-mask membership.

The proof establishes:

- =findDominator = some(d)= implies =d in U= and =d= strictly dominates =r=;
- =findDominator = none= implies no member of =U= strictly dominates =r=;
- every kept route is undominated;
- every undominated route is kept;
- every removed route has a concrete dominating witness.

* Permutation determinism

#+name: pareto-mask-permutation-and-witness
#+begin_src typst :lint typst-eval-stdin :runtime typst
$ "members"(U_1) = "members"(U_2)
  quad "implies" quad
  forall r, "keep"(U_1, r) = "keep"(U_2, r) $

$ "keep"(a, b, R; r) = "keep"(b, a, R; r) $

$ not "keep"(U, r)
  quad "implies" quad
  exists d in U, d prec r $
#+end_src

Lean defines a constructive permutation relation generated by adjacent swap,
list-prefix preservation, and transitivity. It proves keep-mask invariance for
that relation, rather than relying on quotient-based list permutation.

Witness identity itself is not required to be permutation invariant when
several dominators exist. The semantic mask is deterministic; witness
selection becomes deterministic only after a separate canonical witness-order
policy is bound into the normalization identity.

** Direct witness is not necessarily retained

The finite search returns the first direct dominator in the enumeration. That
witness can itself be dominated and absent from the visible frontier.

Lean constructs the chain:

#+begin_example
slowest <- slower <- faster
#+end_example

where =findDominator(slowest) = slower= but =keep(slower) = false=. Therefore
the current theorem guarantees a candidate-universe witness, not yet a retained
frontier witness.

A production dominance certificate must either:

- include a witness chain terminating at a kept undominated route; or
- include a separately proved transitive shortcut to a kept dominator.

* Evidence-graph interpretation

The cost dimensions correspond directly to the graph-first SearchLoop goal:

- fewer graph hops reach decisive evidence through a shorter semantic path;
- fewer projected tokens reduce agent context consumption;
- fewer interaction rounds reduce SearchLoop latency and tool-call overhead;
- fewer search-cache misses reuse graph/parser results;
- fewer model-cache misses preserve prompt-prefix cache hits.

The Pareto mask avoids collapsing these objectives into one unjustified scalar.
A one-hop route is not automatically preferred if it emits substantially more
tokens or destroys both cache-hit opportunities.

The RFC includes a concrete certified example in which a route with one graph
hop, 64 projected tokens, one interaction round, and zero cache misses strictly
dominates a route with two hops, 128 tokens, two rounds, and one miss in each
cache layer.

* Dominance-witness receipt

The compact receipt MUST contain:

- candidate-universe root;
- canonical cost-vector root;
- dominance-policy identifier;
- keep-mask root;
- kept and removed counts;
- dominance-witness root;
- candidate capacity;
- optional continuation for removed-route witness inspection.

For each removed route, detailed inspect MUST return at least:

- removed canonical route identity and cost vector;
- dominating canonical route identity and cost vector;
- componentwise no-worse evidence;
- at least one strict-improvement dimension;
- whether the direct witness is itself kept;
- a continuation to the next witness when the direct witness is removed;
- snapshot and policy identity.

An explicit witness disclosure is bounded by:

#+begin_example
fixedBytes + bytesPerCandidate * candidateCapacity
#+end_example

The default root-and-count summary remains independent of removed-route count.

* Proof-discovered design corrections

1. A removal bit without a dominating witness is not a completeness proof.
2. A direct witness may itself be removed; direct-witness existence is weaker
   than a retained-frontier certificate.
3. Witness choice and keep-mask membership have different determinism
   requirements.
4. Equal cost is not strict dominance and is not canonical route identity.
5. Search-cache reuse and model-cache reuse are orthogonal cost dimensions.
6. Candidate enumeration order may affect which witness is returned, but must
   not affect frontier membership.
7. A scalar score would hide trade-offs that the Pareto frontier must preserve.

* Protocol requirements

1. The keep-mask MUST be derived from the complete finite candidate universe.
2. Strict dominance MUST mean no worse in every canonical dimension and better
   in at least one.
3. Every removed route MUST have a direct candidate-universe witness; a
   completed frontier certificate MUST extend it to a retained endpoint.
4. Equal-cost distinct canonical routes MUST both survive unless another route
   strictly dominates them.
5. Candidate permutation MUST NOT change keep-mask membership.
6. Search-cache and model-cache outcomes MUST remain separately evidenced.
7. Detailed witness disclosure MUST be capacity-bounded and progressively
   inspectable.

* Next proof boundary

The next refinement must construct a finite dominance-witness chain and prove
that it terminates at a retained undominated route. It should establish strict
cost descent, prohibit witness cycles, bound chain length by candidate
capacity, and allow a transitive shortcut to the retained endpoint.

Only after retained-endpoint completeness is proved should a later refinement
canonicalize witness selection and make witness roots invariant under candidate
permutation.
