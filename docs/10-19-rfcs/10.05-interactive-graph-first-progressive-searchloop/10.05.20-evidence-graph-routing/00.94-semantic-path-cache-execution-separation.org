* Lean-discovered design gap

The cache-credit model previously used one field named =graphHops= both for
route cost and for work removed by a search-cache hit.  Those meanings are not
interchangeable.

A semantic graph hop belongs to the evidence certificate.  It states how many
evidence relations connect the query obligation to the accepted witness.  A
cache hit does not alter that proof object.

An executed graph hop belongs to the realization trace.  It states how much
provider or graph traversal work was performed during this execution.  A
search-result cache may reduce this value.

The previous projection can turn a planned value of four graph hops into a
realized value of one after applying a cache credit.  Therefore that field
cannot simultaneously certify semantic path length.  Lean records this
countermodel as
=legacy_cache_projection_changes_declared_graph_hops=.

* Corrected route type

A route exposes the following typed measure:

#+begin_example
RouteMeasure {
  semanticGraphHops: Nat,
  executedGraphHops: Nat,
  toolRounds: Nat,
  searchTokens: Nat,
  uncachedModelTokens: Nat
}
#+end_example

=semanticGraphHops= is certificate-bound and cache-invariant.
=executedGraphHops=, =toolRounds=, and =searchTokens= are realization costs
that a valid search-cache receipt may reduce.  =uncachedModelTokens= is a
separate realization cost that only a valid model-prefix receipt may reduce.

* Normative clauses

** ASP-RFC-10.05-SPCS-SEMANTIC-INVARIANT

Applying search-cache or model-prefix credits MUST preserve
=semanticGraphHops=.  A cache-adjusted execution receipt MUST NOT be used as a
certificate that a different or shorter semantic evidence path exists.

** ASP-RFC-10.05-SPCS-EXECUTION-CONSERVATION

For every execution-cost dimension, realized cost plus the admitted cache
credit MUST equal planned cost.  Credits MUST be bounded by their corresponding
planned dimensions before subtraction.

** ASP-RFC-10.05-SPCS-CACHE-ORTHOGONAL

Search-result cache credit and model-prefix cache credit MUST remain separate:

- search-result credit may reduce executed traversal, tool rounds, and
  disclosed search tokens;
- model-prefix credit may reduce uncached model tokens;
- neither credit may be projected into the other lane.

** ASP-RFC-10.05-SPCS-LEGACY-COUNTERMODEL

The =graphHops= field in the legacy orthogonal-cache cost projection MUST be
interpreted as executed traversal work.  It MUST NOT be reused as the semantic
path metric without an explicit migration.

** ASP-RFC-10.05-SPCS-OBSERVATION-NONIDENTITY

Equal cache-adjusted execution cost does not identify equal semantic paths.
The route receipt MUST carry the semantic path digest and semantic hop count
independently of the realization-cost receipt.

* Router order

The graph router MUST apply the following order:

1. admit only candidates that cover all mandatory obligations and have valid
   identity, freshness, capability, and projection certificates;
2. compare only completion-equivalent admitted candidates;
3. compute the Pareto frontier over semantic path length and realization-cost
   dimensions;
4. apply an explicit policy order to incomparable frontier members;
5. stop only when the selected completion certificate closes the required
   obligation set.

The router MUST NOT choose a route merely because its cache-adjusted execution
work is smallest.  It also MUST NOT infer completion from the absence of a
cheaper next action.

The recommended agent policy compares the following tuple after admission:

#+begin_example
(
  toolRounds,
  searchTokens,
  semanticGraphHops,
  uncachedModelTokens,
  executedGraphHops
)
#+end_example

This order treats LLM/tool interaction rounds and disclosed context as the hot
path, while retaining semantic path length as a proof property.  A deployment
may select a different explicit order, but it MUST publish the policy identity
in the route receipt.

* Machine-checked consequences

The Lean module proves:

- cache application preserves semantic evidence-path hops;
- valid execution credits conserve every realization-cost dimension;
- search-result and model-prefix credits are orthogonal;
- the legacy cache projection can change its declared =graphHops= field;
- two routes can have equal realized traversal work while retaining different
  semantic path lengths.

The last theorem closes an information-loss bug: a cache-adjusted cost vector is
not sufficient evidence for route identity or shortest-proof-path selection.

* Python Turbo Graph boundary

The future Python Turbo Graph implementation MUST expose semantic path
certificate fields separately from realized execution fields.  It MUST NOT
reuse a cache-adjusted execution counter as the graph-router path rank.

No Python or Rust implementation is authorized by this RFC-only session.  The
contract is intentionally established in RFC, Lean, Typst, and Lean-JSON first.

* Remaining proof boundary

This refinement does not yet prove that a concrete provider enumerates the
complete candidate universe.  Global optimality still depends on the existing
frontier-coverage certificate.  It also does not claim that one fixed
lexicographic policy is optimal for every model or workload; policy identity
must remain explicit and auditable.
