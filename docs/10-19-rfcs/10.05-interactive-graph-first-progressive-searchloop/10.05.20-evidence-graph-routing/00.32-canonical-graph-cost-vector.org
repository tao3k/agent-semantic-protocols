* Problem

RFC 10.05.31 represents an omitted-frontier lower bound as a synthetic
=GraphCandidate=.  This is useful for the first proof, but it is not an
appropriate protocol representation:

- a lower bound is not an executable route;
- it has no real route steps or closure digest;
- it should not carry fake parser or provider evidence;
- rendering it as a candidate risks accidental selection;
- Python needs a compact deterministic frontier receipt.

The protocol therefore needs a first-class =GraphCostVector=.

* Canonical fields

The vector contains exactly:

- =graphHops=;
- =uncachedTokens=;
- =rounds=;
- =transitions=.

Field order is semantic and versioned.  JSON object ordering is not used as
the mathematical order; consumers compare the named fields in the declared
sequence.

=uncachedTokens= retains the existing separation between:

- evidence tokens;
- prompt tokens;
- model prefix-cache savings.

Semantic-search cache validity remains an admission invariant owned by the
route.  The cost vector does not revalidate cache claims.

* Canonical order

=CostVectorNoWorse(left, right)= is lexicographic:

1. fewer graph hops;
2. when hops tie, fewer uncached tokens;
3. when tokens tie, fewer interaction rounds;
4. when rounds tie, no more transitions.

The final dimension uses non-strict comparison so the relation is reflexive.

The order is reflexive and transitive.

* Candidate projection

=ofCandidate(candidate)= projects:

- =candidate.graphHops=;
- =uncachedTokenCost(candidate.route)=;
- =roundCost(candidate.route)=;
- =transitionCount(candidate.route)=.

Lean MUST prove:

=CostVectorNoWorse(ofCandidate(left), ofCandidate(right))=

if and only if:

=graphLexNoWorse(left, right)=.

This equivalence prevents Python Graph Turbo, receipts, and Lean proofs from
silently using different route orders.

* Cost-only frontier certificate

A =CertifiedCostFrontier= contains:

- omitted candidates;
- lower-bound cost vector;
- proof that the vector is no worse than every omitted candidate projection.

The lower bound:

- is never executable;
- is never a route recommendation;
- carries no fake selector or path;
- may be cached and serialized independently;
- remains bound to graph generation and cost-model version through its
  enclosing receipt.

* Global theorem

If:

- the selected candidate is vector-optimal among visible candidates;
- sparse coverage accounts for every full-catalog candidate;
- the selected vector is no worse than every frontier lower bound;
- each lower bound is valid for every frontier member;

then the selected vector is no worse than every full-catalog candidate vector.

By candidate-order equivalence, this implies global optimality under the
existing =graphLexNoWorse= relation.

* Hop-only counterexample

Consider:

- selected/lower vector A: one hop, 100 uncached tokens, one round, one
  transition;
- hidden vector B: one hop, 10 uncached tokens, one round, one transition.

The hop-only bound says A is no worse because hop counts are equal.

The canonical vector correctly rejects the claim because A uses more
uncached tokens.

Therefore Python cannot certify an omitted frontier with:

- hop count alone;
- node depth alone;
- edge count alone;
- a scalar score not proved equivalent to the canonical order.

* Serialization contract

The future shared schema should contain:

- =schemaId=;
- =schemaVersion=;
- =costModelId=;
- =graphHops=;
- =uncachedTokens=;
- =rounds=;
- =transitions=;
- complete Evidence Graph generation;
- sparse projection generation;
- frontier identity;
- lower-bound derivation identity.

All natural numbers use non-negative canonical integer encoding.  Missing
fields fail closed.

* Python Graph Turbo boundary

Python owns efficient computation and storage of the vector.

It MUST:

- use the shared field meanings;
- derive uncached tokens from the shared cache-aware route model;
- retain exact integer values rather than an opaque floating score;
- compare vectors with the canonical order;
- bind cached vectors to the cost-model version;
- reject a frontier when any dimension lacks a valid lower bound.

Python may retain heuristic scores for candidate generation.  Heuristic scores
cannot serve as proof of route optimality.

* Mathematical model

#+name: canonical-graph-cost-vector-model
#+begin_src typst
#let CostVector = $ K(c) = cases(
  h(c),
  u(c),
  r(c),
  t(c),
) $

#let VectorNoWorse = $ K_a <=_"graph" K_b "iff" cases(
  h_a < h_b,
  cases(
    h_a = h_b,
    cases(
      u_a < u_b,
      cases(
        u_a = u_b,
        cases(
          r_a < r_b,
          cases(r_a = r_b, t_a <= t_b),
        ),
      ),
    ),
  ),
) $

#let Reflexive = $ forall K, K <=_"graph" K $

#let Transitive = $ cases(
  K_a <=_"graph" K_b,
  K_b <=_"graph" K_c,
) "implies" K_a <=_"graph" K_c $

#let CandidateEquivalence = $ "VectorNoWorse"(
  "ofCandidate"(a),
  "ofCandidate"(b),
) "iff" "graphLexNoWorse"(a, b) $

#let FrontierBound = $ forall c in f,
  L_f <=_"graph" "ofCandidate"(c) $

#let FrontierClosed = $ "ofCandidate"(c^*) <=_"graph" L_f $

#let FrontierGlobal = $ cases(
  forall c in V,
    "ofCandidate"(c^*) <=_"graph" "ofCandidate"(c),
  forall c in U, cases(
    c in V,
    exists f in F, c in f,
  ),
  forall f in F, cases(
    "FrontierBound"(f, L_f),
    "FrontierClosed"(c^*, L_f),
  ),
) "implies" forall c in U,
  "ofCandidate"(c^*) <=_"graph" "ofCandidate"(c) $

#let HopOnlyCounterexample = $ cases(
  K_A = (1, 100, 1, 1),
  K_B = (1, 10, 1, 1),
  h_A <= h_B,
  "not" K_A <=_"graph" K_B,
) $

#let Main = (
  CostVector,
  VectorNoWorse,
  Reflexive,
  Transitive,
  CandidateEquivalence,
  FrontierBound,
  FrontierClosed,
  FrontierGlobal,
  HopOnlyCounterexample,
)

"ok"

* Non-goals

This RFC does not:

- implement Python Graph Turbo;
- replace admission or executability certificates;
- merge cache identities;
- use heuristic floating scores as proof;
- make lower bounds executable;
- modify Rust provider code;
- use raw LaTeX or standalone Typst.

* Remaining proof boundary

The next layer should bind this vector to a versioned shared JSON schema and
prove deterministic serialization.  It should then formalize incremental
frontier invalidation when any full-graph edge, sparse projection, cache
identity, or cost-model version changes.
