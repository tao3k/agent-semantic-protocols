* Lean-discovered identity error

One =graphGeneration= field cannot serve simultaneously as semantic identity
and as a publication fence.

Lean establishes both counterdirections:

1. equal graph generations do not imply equal semantic coverage identity;
2. different graph generations do not imply different semantic coverage
   identity.

A generation number may stay constant while the route policy or candidate
catalog changes incorrectly.  Conversely, reconciliation may publish a new
generation while preserving the same workspace snapshot, query, policy,
completion key, candidate catalog, frontier, and cost dimensions.

Therefore generation equality is neither necessary nor sufficient for semantic
coverage identity.

* Two-layer identity

** Semantic coverage identity

The certificate semantic identity is:

#+begin_example
SemanticCoverageIdentity {
  workspaceSnapshotDigest,
  queryDigest,
  routePolicyDigest,
  completionKeyDigest,
  globalCatalogDigest,
  frontierDigest,
  costDimensionDigest
}
#+end_example

Every field changes what the global Pareto theorem means.  Exact equality of
this structure is required before a vector-coverage proof can be reused.

** Publication fence

The publication fence contains:

#+begin_example
CoverageHeader {
  semanticIdentity,
  issuedGeneration
}

CoverageContext {
  semanticIdentity,
  graphGeneration,
  transitionAuthorityDigest
}
#+end_example

=issuedGeneration= and =graphGeneration= prevent a stale publication from
being served directly.  They do not replace semantic identity.

* Normative clauses

** ASP-RFC-10.05-VCIF-SEMANTIC-BOUND

Every directly or transition-admitted coverage certificate MUST equal the
current context in all semantic identity fields.  Fieldwise omission is
fail-closed.

** ASP-RFC-10.05-VCIF-GENERATION-NONIDENTITY

The implementation MUST NOT infer semantic equality from generation equality,
and MUST NOT infer semantic inequality solely from generation inequality.

** ASP-RFC-10.05-VCIF-DIRECT-FENCE

Direct service of a coverage certificate requires both:

- exact semantic identity equality;
- =issuedGeneration == graphGeneration=.

Semantic equality without the current direct fence MUST NOT authorize direct
service.

** ASP-RFC-10.05-VCIF-POLICY-IDENTITY

=routePolicyDigest= and =costDimensionDigest= are semantic identity.  Changing
the order, dimensions, cache-lane interpretation, or feasibility policy rejects
the old coverage certificate even when graph generation is unchanged.

** ASP-RFC-10.05-VCIF-TRANSITION-FENCE

A certificate may cross graph generations only with an explicit transition
certificate satisfying:

- the transition semantic identity equals both the old header and current
  context;
- =fromGeneration == issuedGeneration=;
- =toGeneration == graphGeneration=;
- =fromGeneration < toGeneration=;
- the transition authority equals the current authority;
- the transition is explicitly authorized.

** ASP-RFC-10.05-VCIF-GLOBAL-LIFT

Only directly admitted or transition-admitted vector coverage may participate
in the theorem lifting frontier-local Pareto minimality to global Pareto
minimality.

* Two admission paths

** Direct admission

Direct admission is the hot path:

#+begin_example
semanticIdentity(header) == semanticIdentity(context)
and
issuedGeneration(header) == graphGeneration(context)
#+end_example

It requires no transition lookup.

** Transition admission

Transition admission is the reconciliation path.  It proves that a new
publication generation preserves the exact semantic coverage identity.

An unauthorized, backward, wrong-authority, or semantic-changing transition
MUST be rejected.

This transition is different from a registry epoch transition that changes the
registry snapshot.  A semantic-preserving generation transition transports an
unchanged coverage fact; a registry epoch transition establishes a different
authority domain and cannot silently preserve new-decision authorization.

* Receipt contract

The agent-facing receipt requires:

#+begin_example
{
  semanticIdentity: {
    workspaceSnapshotDigest: "...",
    queryDigest: "...",
    routePolicyDigest: "...",
    completionKeyDigest: "...",
    globalCatalogDigest: "...",
    frontierDigest: "...",
    costDimensionDigest: "..."
  },
  issuedGeneration: 8,
  servedGeneration: 9,
  admissionKind: "certified-transition",
  transitionCertificateDigest: "...",
  transitionAuthorityDigest: "...",
  coverageKind: "cost-vector"
}
#+end_example

The receipt MUST distinguish =direct= from =certified-transition=.  A plain
=cacheHit=true= or =generationValid=true= field is insufficient.

* Machine-checked consequences

Lean proves ten obligations:

- direct and transition admission both imply semantic binding;
- either admitted vector-coverage path lifts frontier Pareto minimality to the
  global catalog;
- equal generation does not imply semantic identity;
- changed generation does not imply semantic change;
- semantic equality without a current fence rejects direct service;
- changed policy rejects admission;
- an authorized same-semantic transition admits coverage;
- an unauthorized transition rejects coverage.

Five declarations are axiom-free.  Five depend only on =propext=.  No theorem
contains =sorryAx=.

* SearchLoop consequence

SearchLoop may reuse a global Pareto proof without another graph search when the
semantic identity is unchanged and either the direct fence is current or a
certified semantic-preserving transition is available.

Otherwise it must reopen the frontier.  The next action should identify the
first mismatched semantic field or missing transition evidence instead of
emitting a generic cache miss.

* Implementation boundary

The future Python graph router must preserve the split between semantic identity
and generation fencing.  Generation may remain useful for atomic publication
and stale-reader rejection, but it cannot replace Merkle/catalog/policy
identity.

No Python or Rust implementation is authorized in this RFC-only session.

* Remaining proof boundary

This RFC models one certified generation transition.  The next proof layer must
cover transition-chain composition, prevent forks, and retain the exact
semantic identity across every intermediate generation.
