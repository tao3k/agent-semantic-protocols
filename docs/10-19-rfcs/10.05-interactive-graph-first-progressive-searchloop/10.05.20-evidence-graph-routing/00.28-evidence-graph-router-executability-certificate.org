#+title: RFC 10.05.28 — Evidence Graph Router Executability Certificate

#+property: rfc_layer evidence-graph-routing

* Status

This RFC is a proof-first design amendment for the shared Evidence Graph and
Graph Router.  It does not implement Python Graph Turbo or change Rust
provider code.

* Problem

The existing proof model already ranks validated graph candidates by:

- graph hops;
- uncached token cost, including model prefix-cache savings;
- agent and tool rounds;
- transition count.

It also validates semantic-search cache claims separately from model
prefix-cache claims.  Those cost and cache distinctions remain correct.

The missing invariant is executability.

=SearchRouteDAG.GraphCandidate= contains a route, graph-hop count, and
=pathValidated=.  It does not prove that:

- the provider project resolved in the current workspace;
- the selected structural identity is executable;
- the requested projection is supported;
- the provider response can be decoded under the declared projection contract;
- the route receipt is bound to the current evidence root, provider identity,
  and query identity.

A statically short route can therefore win ranking and still fail before
producing evidence.  Its real cost is then the proposed route cost plus failure
tokens, one or more extra interaction rounds, recovery, and fallback routing.
That cost is absent from the successful-route candidate.

* Observed failure evidence

The proof boundary is motivated by actual parser-owned ASP routing in this
workspace:

- Python =search prime= resolved while a focused =search pipe= failed with
  =provider project-resolution did not resolve=;
- Python owner-query reported that the language harness lacked an owner-query
  interface for the graph-turbo fixture owner;
- an exact selector first required an explicit
  =source|callable-skeleton= projection;
- the corrected =callable-skeleton= request then failed because the native
  exact-selector response did not decode as any declared response variant.

These failures do not prove that the evidence path is semantically wrong.
They prove that semantic path validation alone is insufficient for an
agent-executable Graph Route.

* Evidence graph snapshot

Every executable route decision MUST be evaluated against an
=EvidenceGraphSnapshot= containing at least:

- =rootDigest=;
- =providerDigest=;
- =queryDigest=.

The route receipt MUST additionally carry a =routeDigest=.  A route candidate
is receipt-bound only when its claimed evidence root, provider identity, and
query identity equal the active snapshot.

The route digest is retained even though the first Lean model does not yet
assume a concrete route-digest algorithm.  Python Graph Turbo must eventually
bind it to canonical route serialization.

* Capability state

The shared capability state is:

- =ready= :: the route may participate in selection;
- =recoverable= :: the route may emit one bounded recovery action but may not
  participate in optimality or closure;
- =unavailable= :: the route is rejected for the active snapshot.

=ready= requires all of:

- provider resolution succeeded;
- the selected node is an executable structural identity or another declared
  executable graph node;
- the requested projection is supported and response-compatible;
- the route receipt is bound to the active evidence snapshot.

A source locator hint or display line range is never sufficient.

* Certified feasibility

A candidate is =CertifiedFeasible= only when:

- existing =graphFeasibleB= succeeds;
- its receipt is bound to the active snapshot;
- its capability state is =ready=;
- its selector is executable;
- its projection contract is compatible.

Only certified-feasible candidates enter Graph Router cost comparison.

This preserves the existing ordering over graph hops, uncached tokens, rounds,
and transitions.  The new layer does not redefine cost.  It defines the
admission boundary required before cost is meaningful.

* Recovery is not selection

A recoverable candidate MUST return:

- one failure classification;
- one bounded recovery action;
- the evidence snapshot identity that failed;
- the capability or projection obligation that remains open.

It MUST NOT return:

- a selected route;
- a global-optimality claim;
- closure;
- an empty result interpreted as absence.

Provider bootstrap, source-index rebuild, projection negotiation, and local
runtime materialization are recovery actions.  They are not zero-cost graph
edges.

* Catalog completeness

A =CertifiedSelection= proves:

- the selected candidate belongs to the certified catalog;
- the selected candidate is certified-feasible;
- it is no worse than every other certified-feasible catalog member under the
  existing Graph Router order.

Global optimality additionally requires =CertifiedCatalogComplete=: every
certified-feasible candidate in the committed candidate universe is present in
the comparison catalog.

Completeness over semantic paths alone is insufficient.  The catalog must be
complete over routes that are executable for the active snapshot.

* Cache boundary

Semantic-search cache identity and model prefix-cache identity remain separate.

- semantic-search cache reuse changes evidence acquisition work and must remain
  bound to the evidence root and provider facts;
- model prefix-cache reuse changes uncached prompt-token cost and must remain
  bound to the serialized prompt/proof prefix;
- neither cache hit can turn a =recoverable= or =unavailable= capability into
  =ready=;
- a capability preflight receipt may itself be cached only under the active
  provider, projection, executable, and snapshot identities.

* Python Graph Turbo boundary

The future Python Graph Turbo architecture must project, but not privately
redefine:

- =EvidenceGraphSnapshot=;
- =ExecutableGraphCandidate=;
- capability state;
- receipt binding;
- certified feasibility;
- certified catalog completeness;
- bounded recovery disposition.

Python owns graph storage, sparse ranking, warm indexes, route enumeration,
and performance implementation.  The RFC and Lean model own the
language-neutral correctness boundary.

Until the Python architecture exists, no benchmark or fixture-only route may
claim that Graph Turbo satisfies this RFC.

* Agent-facing route receipt

The compact route receipt SHOULD expose:

- evidence root digest;
- provider digest;
- query digest;
- route digest;
- capability state;
- selected executable node identity;
- projection identity;
- receipt-binding result;
- graph hops;
- uncached token cost;
- interaction rounds;
- transition count;
- semantic-search cache identity;
- model prefix-cache identity;
- bounded =recommendedNext= when capability is not =ready=.

The compact view may omit proof bodies, but the JSON audit/evidence graph must
retain them by identity.

* Mathematical model

#+name: evidence-graph-router-executability-certificate-model
#+begin_src typst
#let Snapshot = (
  root: $rho$,
  provider: $pi$,
  query: $q$,
)

#let ExistingCost = $ K(c) =
  (h(c), u(c), r(c), t(c)) $

#let ReceiptBound = $ "Bound"(S, c) "iff" cases(
  rho(c) = S.rho,
  pi(c) = S.pi,
  q(c) = S.q,
) $

#let RuntimeReady = $ "Ready"(c) "iff" cases(
  "Capability"(c) = "ready",
  "SelectorExecutable"(c),
  "ProjectionCompatible"(c),
) $

#let CertifiedFeasible = $ "CertifiedFeasible"(S, c) "iff" cases(
  "GraphFeasible"(c),
  "Bound"(S, c),
  "Ready"(c),
) $

#let StaticGap = $ exists c, cases(
  "GraphFeasible"(c),
  "Bound"(S, c),
  "not" "Ready"(c),
) $

#let ObservedFailureCost = $ K_"observed"(c) =
  K(c) + K_"failure"(c) + K_"recovery"(c) + K_"fallback"(c) $

#let CertifiedSelection = $ cases(
  c^* in C,
  "CertifiedFeasible"(S, c^*),
  forall c in C,
    "CertifiedFeasible"(S, c)
      "implies" K(c^*) <=_"graph" K(c),
) $

#let CertifiedCatalogComplete = $ forall c in U,
  "CertifiedFeasible"(S, c) "implies" c in C $

#let GlobalExecutableOptimality = $ cases(
  "CertifiedSelection"(S, C, c^*),
  "CertifiedCatalogComplete"(S, U, C),
) "implies" forall c in U,
  "CertifiedFeasible"(S, c)
    "implies" K(c^*) <=_"graph" K(c) $

#let RecoveryBoundary = $ "Capability"(c) = "recoverable"
  "implies" cases(
    "not" "Selectable"(c),
    "not" "Closed"(c),
    exists a, "BoundedRecoveryAction"(a, c),
  ) $

#let Main = (
  Snapshot,
  ExistingCost,
  ReceiptBound,
  RuntimeReady,
  CertifiedFeasible,
  StaticGap,
  ObservedFailureCost,
  CertifiedSelection,
  CertifiedCatalogComplete,
  GlobalExecutableOptimality,
  RecoveryBoundary,
)

"ok"

* Non-goals

This RFC does not:

- implement Python Graph Turbo;
- alter the existing graph cost ordering;
- merge semantic-search cache and model prefix-cache identity;
- claim probabilistic provider availability;
- prove a concrete route-digest construction;
- treat recovery work as a successful search route;
- modify Rust provider code;
- use raw LaTeX or standalone Typst.

* Remaining proof boundary

The next proof layer should model time-varying capability receipts:

- capability expiry after provider/runtime changes;
- warm-index generation identity;
- expected cost when capability preflight is probabilistic;
- recovery-action termination and bounded retry count;
- route-digest binding to canonical executable-node and projection identities;
- consistency between Python sparse-graph facts and the shared committed
  candidate universe.
