#+startup: overview

* Status

Focused formal verification is complete. This RFC refines [[file:../10.05.31-agent-session-host-registry-authenticated-projection/00-overview.org][RFC 10.05.31 — Agent
Session Authenticated Registry Projection]]. It defines executable Merkle path
conformance. The source module and direct audit compile, all 22 audited theorem
declarations are axiom-free, and the module is imported by the proof-package
root. It does not authorize Rust implementation in this session.

The aggregate =lake build ASPProof= gate remains outside this focused claim.
Unrelated proof modules retain the previously recorded =Mathlib= and
=Decidable= failures. This RFC claims focused proof closure, not aggregate
proof-package closure.

* Problem

RFC 10.05.31 binds inclusion and exclusion to a canonical semantic snapshot and
root. It deliberately does not prove that a runtime path verifier implements
that relation.

The executable gap contains five independent failure classes:

- ambiguous leaf serialization can map different key/generation tuples to the
  same preimage before any cryptographic property is considered;
- swapping a left sibling with a right sibling changes branch semantics;
- a path can recompute an attacker-selected root rather than the admitted root;
- an exclusion claim can present plausible neighbors without semantic absence;
- an unbounded path can be correct but destroy token, latency, and memory bounds.

Therefore “hash recomputation succeeded” is not equivalent to authenticated
membership or absence.

* Reused authority

This RFC uses the existing Merkle authority rather than defining another one:

- workspace leaves are sorted by normalized identity;
- leaf, branch, and empty domains are distinct;
- leaf inputs are canonical and length-delimited in the runtime contract;
- path steps preserve ordered left/right sibling direction;
- an odd final node is duplicated as its own right sibling;
- =leafCount=, =rootDepth=, and =rootDigest= come from one provider generation;
- warm verification does not start a provider or rewrite persistent state;
- parser, source-content, snapshot-leaf, and artifact digest domains remain
  distinct.

The Lean layer models the semantic shape with abstract hash functions. It does
not claim that a particular digest algorithm is collision-free.

* Ordered path execution

#+name: registry-merkle-path-fold-law
#+begin_src typst :runtime typst :lint "typst eval --in - 'none'"
#let B(l, r) = $upright("branch")(#l, #r)$
#let Step(a, s) = $upright("step")(#a, #s)$
#let Fold(step, init, path) = $upright("fold")(#step, #init, #path)$

$
  Step(a, ("left", s)) = B(s, a),
  quad Step(a, ("right", s)) = B(a, s).
$

$
  root = Fold(Step, h_r, p).
$
#+end_src

Direction is semantic data. A verifier MUST NOT sort sibling digests or treat
the path as an unordered set.

* Exclusion gap contract

An executable exclusion receipt may carry lower and upper boundary inclusion
paths, but those paths are not sufficient by themselves. Both paths MUST bind
the same root, and the semantic bridge MUST prove =KeyAbsent= for that root.

#+name: registry-merkle-exclusion-law
#+begin_src typst :runtime typst :lint "typst eval --in - 'none'"
#let Gap(k, lo, hi, rho) = $upright("Gap")(#k, #lo, #hi, #rho)$
#let Inc(r, rho) = $upright("Inclusion")(#r, #rho)$
#let Absent(k, rho) = $upright("Absent")(#k, #rho)$
#let Key(r) = $upright("key")(#r)$

$
  Gap(k, l, u, rho) =>
  Inc(l, rho) and Inc(u, rho) and Key(l) < k and k < Key(u)
  and Absent(k, rho).
$

Neighbor labels without root-bound inclusion and semantic absence are a forged
gap claim.
#+end_src

* Proof-size and token bound

#+name: registry-merkle-proof-cost-law
#+begin_src typst :runtime typst :lint "typst eval --in - 'none'"
#let Len(p) = $upright("pathLength")(#p)$
#let Depth(rho) = $upright("rootDepth")(#rho)$
#let Cost(p) = $upright("tokenCost")(#p)$
#let Accepted(p, rho) = $upright("Accepted")(#p, #rho)$

$
  Accepted(p, rho) => Len(p) <= Depth(rho).
$

$
  Cost(p) = Len(p) dot w <= Depth(rho) dot w.
$
#+end_src

This is a protocol admission bound, not merely an implementation optimization.
An otherwise correct oversized proof is rejected before it enters the agent
context.

* Lean contract embedded in Org

#+name: registry-merkle-path-lean-contract
#+begin_src lean
inductive SiblingSide where
  | left
  | right

structure PathStep where
  side : SiblingSide
  sibling : MerkleDigest

def recomputeRoot (branch : BranchHasher) (leaf : MerkleDigest)
    (steps : List PathStep) : MerkleDigest :=
  steps.foldl (applyPathStep branch) leaf

def ExecutablePathAccepted (leafHash : LeafHasher) (branch : BranchHasher)
    (packet : InclusionPacket) : Prop :=
  packet.leafDigest = leafHash (canonicalLeafInput packet.record) ∧
  recomputeRoot branch packet.leafDigest packet.steps = packet.claimedRoot ∧
  packet.steps.length ≤ packet.rootDepth

def RuntimeVerifierConforms (verifier : RuntimePathVerifier)
    (leafHash : LeafHasher) (branch : BranchHasher) : Prop :=
  ∀ packet, verifier packet = true ↔
    ExecutablePathAccepted leafHash branch packet

structure ExclusionPacket where
  lowerPacket : Option InclusionPacket
  upperPacket : Option InclusionPacket

structure ExclusionConformance
    (commitment : ManifestCommitment)
    (leafHash : LeafHasher)
    (branch : BranchHasher)
    (snapshot : ManifestSnapshot)
    (root : ManifestRootDigest)
    (key : KeyId)
    (gap : ExclusionPacket) : Prop where
  lowerAccepted : ∀ packet, gap.lowerPacket = some packet →
    ExecutablePathAccepted leafHash branch packet ∧ packet.claimedRoot = root
  upperAccepted : ∀ packet, gap.upperPacket = some packet →
    ExecutablePathAccepted leafHash branch packet ∧ packet.claimedRoot = root
  semanticExclusion : AuthenticatedExclusion commitment snapshot root key
#+end_src

* Lean-discovered obligations

The formal model distinguishes three claims that prose often collapses:

1. executable path validity: canonical leaf, ordered fold, exact root, and depth
   bound;
2. semantic validity: RFC31 inclusion or exclusion under the same root;
3. verifier conformance: runtime =true= if and only if executable validity holds.

The model constructs counterexamples for ambiguous untagged encoding, an
attacker-selected root, an oversized proof, a forged gap claim, and an
always-accept verifier. A direction-sensitive branch function also proves that
flipping a one-step left/right marker changes the resulting root.

Lean also requires =ExclusionPacket : Type= to own lower/upper transport data,
while =ExclusionConformance : Prop= owns only verification evidence. Putting
packet data inside a proof-valued structure would violate proof irrelevance and
make executable projection impossible.

Cryptographic strength, byte-level canonical serialization, and equality with a
specific runtime implementation remain executable evidence obligations. They
are not silently imported as Lean axioms.
