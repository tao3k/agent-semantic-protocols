#+title: RFC 10.05.38 — Agent Session Host Registry Adjudication Decision Certificate
#+language: en

* Status

Focused formal verification is complete. This RFC refines [[file:../10.05.37-agent-session-host-registry-quarantine-adjudication/00-overview.org][RFC 10.05.37 — Agent Session Host Registry Quarantine Adjudication]]. The Lean source and direct audit compile, all 21 theorem declarations are axiom-free, and the module is imported by the proof-package root.

This RFC verifies provenance binding, decision entailment, certificate sealing, revocation, and appeal generation safety. It does not claim that a concrete evidence collector or decision verifier exists. No Rust implementation is authorized in this session.

* Problem

RFC37 proves that adjudication is authorized, two-sided, append-only, and generation advancing. Authorization does not establish that the evidence roots are genuine or that the selected decision follows from them.

A trustworthy decision certificate must close six additional gaps:

- each terminal capture requires its own acquisition provenance root;
- each acquisition must be independently replayed;
- the two sides may not share one collector or one provenance root;
- the decision must carry a typed entailment witness;
- revocation must block new authorization without rewriting historical evidence;
- appeal must supersede the prior certificate and advance generation again.

Certificate identity is the digest of the complete payload, not a free-standing identifier.

* Lean-discovered ambiguity

RFC37 defines three decisions: uphold accepted, replace with conflicting, or reject both. Lean shows that none of these decisions is entailed when both terminal provenance judgments are valid.

This is not a missing proof tactic. It is a protocol state omitted by the earlier prose. A both-valid dispute must remain quarantined as an ambiguity until additional semantic evidence distinguishes the terminal captures. An authority must not collapse this state into a decision merely to make progress.

:END:

#+name: registry-decision-certificate-entailment-law
#+begin_src typst
#let Entails(d, a, c) = $upright("DecisionEntailed")(#d, #a, #c)$
#let Valid = $upright("valid")$
#let Invalid = $upright("invalid")$
#let Uphold = $upright("upholdAccepted")$
#let Replace = $upright("replaceWithConflicting")$

$
  Entails(Uphold, Valid, Invalid) and
  Entails(Replace, Invalid, Valid) and
  Entails(Reject, Invalid, Invalid),
  quad forall d, not Entails(d, Valid, Valid).
$
#+end_src

A decision label without one of these witnesses is not a certificate.

* Revocation law

:ID: ASP-RFC-10.05-ASDC-REVOCATION
:END:

#+name: registry-decision-certificate-revocation-law
#+begin_src typst
#let Step(c, before, after) = $upright("CertificateLifecycleStep")(#c, #before, #after)$
#let Active = $upright("active")$
#let Revoked(r) = $upright("revoked")(#r)$
#let Admit(s) = $upright("AdmittedForNewDecision")(#s)$

$
  forall c, r,
  Step(c, Active, Revoked(r)) and
  not Admit(Revoked(r)) and
  not Step(c, Revoked(r), Active).
$
#+end_src

Revocation appends a lifecycle fact. It blocks new decisions but does not erase the certificate from historical audit.

Appeal creates a successor certificate. It does not mutate the prior certificate or restore the original quarantined generation.

* Lean contract embedded in Org

#+name: registry-decision-certificate-lean-contract
#+begin_src lean
def ProvenanceBindsTerminal
    (expected : TerminalCapture)
    (provenance : TerminalProvenance) : Prop :=
  provenance.terminal = expected ∧
  provenance.replayed = true ∧
  provenance.replayExecutorDigest ≠ provenance.collectorDigest

inductive DecisionEntailed where
  | upholdAccepted : DecisionEntailed .upholdAccepted .valid .invalid
  | replaceWithConflicting : DecisionEntailed .replaceWithConflicting .invalid .valid
  | rejectBoth : DecisionEntailed .rejectBoth .invalid .invalid

def AppealSupersedes
    (prior : DecisionCertificate)
    (appeal : AppealCertificate) : Prop :=
  appeal.priorCertificateDigest = prior.certificateDigest ∧
  appeal.successor.payload.generation = prior.payload.generation + 1 ∧
  appeal.successor.certificateDigest ≠ prior.certificateDigest
#+end_src

* Lean-discovered obligations

Lean rejects non-replayed provenance, self-replay, a shared collector, a shared provenance root, a wrong certificate seal, revoked-certificate admission, lifecycle unrevocation, and appeal generation rollback.

The typed entailment relation exposes the both-valid ambiguity. Because it has no constructor for =valid/valid=, no decision certificate can be formed for that judgment pair. This closes a real RFC37 design hole by preserving quarantine instead of allowing an authority-selected answer without semantic evidence.

Revocation and historical audit remain distinct. The lifecycle transition prevents new authorization and unrevocation; it does not delete the certificate payload. Appeal binds the prior certificate digest, creates a distinct successor digest, and advances generation again.
