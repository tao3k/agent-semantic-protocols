#+title: Registry-derived Multiple Agent V2 control-plane materialization
#+property: schemaVersion 1

* Status

This document defines the Runtime Server refinement from the durable
AgentSession Registry into ASP's downstream Codex Multiple Agent V2
control-plane projection.

* Execution-plane boundary

Codex remains the execution plane. ASP does not implement Codex spawning,
scheduling, queues, turn execution, interruption, or archival. The Runtime
Server consumes durable host and registry evidence and publishes a queryable
control-plane observation.

* Server-owned refresh

The Runtime Server owns refresh. A client supplies only the project identity
and root session identity. The server queries its local asynchronous
AgentSession Registry owner, computes the source digest and materialization
generation, validates the shared projection, and publishes it through the
existing control-plane admission owner.

The server-local registry query must not use the synchronous client adapter.
That adapter may proxy through the Runtime Server and would recursively enter
the same IPC owner.

* Evidence floor

An AgentSession Registry snapshot is durable evidence for agent identities,
physical generations, parent relations, configured agent types, resident
names, roles, and trusted live message-target bindings.

The root session identifier alone is not root-task evidence. A current
registry-derived projection requires a non-empty, completely scoped snapshot
whose durable child rows attest the requested root identity and topology. The
materializer records that snapshot reference on a separate =CodexRootTask= and
must not invent a root-agent name, role, physical generation, binding, or
lifecycle state. An =AgentSession= row that impersonates the root task is
rejected rather than treated as a managed agent.

Registry status is not a Codex dispatch claim and is not a Codex turn receipt.
Consequently registry-derived lifecycle nodes carry an unobserved dispatch
generation and cannot authorize durable dispatch by themselves.

* No inferred turns or delegations

The AgentSession Registry does not own durable Codex turn identifiers or
delegation delivery receipts. Registry-only materialization therefore emits
an empty turn set and an empty delegation set. A parent session relation may
remain on the agent node, but it must not be upgraded into a delegation edge.

Turn nodes and delegation edges may be added only by a later evidence owner
whose receipt schema names those facts. Delivered or completed delegations
continue to require their indexed delivery receipt.

* Public adapter

The agent-facing adapter exposes two observation-only operations:

- =control-plane refresh= asks the Runtime Server to reconcile the durable
  registry snapshot and returns its typed publication receipt;
- =control-plane show= reads the last published projection for the requested
  root session.

Both operations accept a root session identity and derive the project identity
from the canonical workspace. They do not spawn, resume, send, interrupt,
archive, or delete a Codex task. A client-side sequence that classifies model
guidance, child-message attempts, receipts, and archival as an ASP control-plane
lifecycle is legacy execution-plane duplication and must not be retained.

* Freshness and generation

Records are sorted by session identity before canonical serialization. The
source digest covers the complete scoped registry snapshot. An unchanged
current snapshot is idempotent and reuses its generation. Changed evidence,
stale materialization, or changed Workspace Server observation advances the
generation before publication. Lower generations and same-generation content
conflicts remain rejected by the shared publication owner.

* Performance and failure contract

Digesting and graph construction execute inside the resident Runtime Server,
not in the CLI. Refresh returns a typed publication receipt. Registry owner
absence, scope leakage, invalid physical generation, missing root evidence,
projection validation failure, and publication conflict return typed failures;
none authorizes a client-side fallback or a synthesized graph.
