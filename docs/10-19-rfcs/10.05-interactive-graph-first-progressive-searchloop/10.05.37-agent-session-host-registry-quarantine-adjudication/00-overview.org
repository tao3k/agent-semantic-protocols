#+language: en

* Status

Focused formal verification is complete. This RFC refines [[file:../10.05.36-agent-session-host-registry-crash-safe-materialization-recovery/00-overview.org][RFC 10.05.36 — Agent Session Host Registry Crash-Safe Materialization Recovery]]. The Lean source and direct audit compile, all 19 theorem declarations are axiom-free, and the module is imported by the proof-package root.

This RFC proves adjudication authorization, evidence completeness, history preservation, and generation fencing. It does not prove that an authorized decision is factually correct without external evidence provenance. No Rust implementation is authorized in this session.

* Problem

RFC36 moves different terminal captures into quarantine and prevents further publication. Quarantine is safe but not self-resolving. A clearance protocol that merely carries an authority identifier remains vulnerable to:

- the claimant or challenger adjudicating its own disputed terminal;
- evidence that includes only the preferred terminal;
- mutation or erasure of prior adjudication records;
- two contradictory resolutions for one quarantined slot;
- clearing quarantine without advancing invocation generation;
- resurrection of the old generation after resolution.

Resolution must bind authority, independent adjudicator identity, both competing terminal captures, complete evidence, append-only history, and a successor generation.

* Evidence alignment

The existing authorized quarantine model binds quarantine digest, request/effect identity, ledger revision, evidence digest, and resolver authority while preserving ledger capacity. RFC37 extends that contract for terminal-capture disputes. It adds separation of duties and generation fencing, neither of which follows from capacity conservation.

The decision set is closed: uphold the accepted terminal, replace it with the conflicting terminal, or reject both. Authorization proves that a decision was made under the correct scope; evidence provenance must separately justify which decision is true.

Authority scope and separation of duties are independent predicates. Possessing the correct scope does not permit a disputed worker to judge itself.

* Lean contract embedded in Org

#+name: registry-quarantine-adjudication-lean-contract
#+begin_src lean
def EvidenceBindsCase
    (quarantine : QuarantineCase)
    (evidence : AdjudicationEvidence) : Prop :=
  evidence.complete = true ∧
  evidence.quarantineDigest = quarantine.quarantineDigest ∧
  evidence.accepted = quarantine.accepted ∧
  evidence.conflicting = quarantine.conflicting

def AuthorizedAdjudication
    (expectedAuthority : AdjudicationAuthority)
    (quarantine : QuarantineCase)
    (request : AdjudicationRequest) : Prop :=
  request.authority = expectedAuthority ∧
  request.adjudicatorDigest ≠ quarantine.claimantExecutorDigest ∧
  request.adjudicatorDigest ≠ quarantine.challengerExecutorDigest ∧
  EvidenceBindsCase quarantine request.evidence

inductive AdjudicationHistoryStep where
  | append : AdjudicationHistoryStep before record (before ++ [record])

def advanceGeneration (key : StableInvocationKey) : StableInvocationKey :=
  { key with generation := key.generation + 1 }
#+end_src

* Lean-discovered obligations

Lean rejects incomplete evidence, an accepted-terminal mismatch, a conflicting-terminal mismatch, claimant self-adjudication, challenger self-adjudication, and authority mismatch independently.

The resolution relation has only a quarantined source state. A resolved slot has no second resolution constructor. Its history transition can only append the adjudication record, and its target key is definitionally the successor generation. The previous generation therefore cannot satisfy current-generation authorization.

This model proves authorization and state safety, not empirical truth. An independent authorized adjudicator may still make a bad decision if its evidence provenance is fraudulent. Conflating those properties would turn authority into an oracle and hide the next proof obligation.
