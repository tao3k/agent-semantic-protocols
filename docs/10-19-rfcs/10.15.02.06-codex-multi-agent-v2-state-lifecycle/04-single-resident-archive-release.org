#+TITLE: Single-Resident Archive, Release, and Same-Name Recreation
#+PROPERTY: header-args:typst :results output

* Status

This module is an RFC and proof refinement for the ASP Agent Session lifecycle.
It does not specify a Rust implementation in the current phase.

* Problem

A resident slot exposes one stable registered name and permits at most one live
physical incarnation.  A host archive receipt changes presentation state only.
It does not prove host termination, registry retirement, canonical path release,
or replacement admission.

The unsafe interpretation is:

#+begin_example
archive(old) -> spawn(new)
#+end_example

The required lifecycle is:

#+begin_example
durable close intent -> stable shutdown dispatch -> host termination receipt ->
canonical path release receipt -> fresh-generation same-name recreation
#+end_example

* Stateful Architecture

#+begin_src mermaid
stateDiagram-v2
  [*] --> Live
  Live --> ArchivedVisible: archive receipt
  ArchivedVisible --> Live: presentation only
  Live --> CloseIntentDurable: close CAS
  ArchivedVisible --> CloseIntentDurable: close CAS
  CloseIntentDurable --> ShutdownRequested: durable outbox dispatch
  ShutdownRequested --> BlockedHostCapability: timeout or missing host close
  BlockedHostCapability --> HostTerminated: late indexed termination receipt
  ShutdownRequested --> HostTerminated: indexed termination receipt
  HostTerminated --> PathReleased: canonical path release receipt
  PathReleased --> Live: fresh physical generation, same registered name

  note right of ArchivedVisible
    Replacement is forbidden.
    Archive is not release.
  end note

  note right of PathReleased
    The old incarnation is no longer live.
    Exactly one fresh incarnation may be admitted.
  end note
#+end_src

* Mathematical Contract

Let =I(s)= be the live-incumbent count for close state =s=.  Let =R(s,g)= be
the live-replacement count admitted for candidate generation =g=.  Both counts
are Boolean-valued natural numbers.  The slot live count is:

#+begin_src typst
#let L(s, g) = I(s) + R(s, g)
$ L(s, g) := I(s) + R(s, g) $
$ forall s, g: L(s, g) <= 1 $
#+end_src

Archive without path release cannot authorize replacement:

#+begin_src typst
$ A(s) = 1 and P(s) = 0 => R(s, g) = 0 $
#+end_src

A replacement is admissible only after close intent, host termination, and path
release are all durably witnessed, and its physical generation is fresh:

#+begin_src typst
$ R(s, g) = 1 => C(s) = 1 and T(s) = 1 and P(s) = 1 and G(s) < g $
#+end_src

* Temporary Host Procedure

Until the Rust lifecycle is refactored, the bounded host procedure is:

1. Ask the existing resident to finish its current turn.
2. Archive the exact current Codex child task through the host-native archive
   operation.
3. Observe a distinct canonical path release receipt.  An archive receipt alone
   is insufficient.
4. Recreate the same typed resident name only after release is observed.
5. Reject any attempt to create a suffixed or parallel resident as a workaround.

If the host archives the task but retains the canonical collaboration path, the
procedure stops at =PathReleasePending=.  It must not create a second resident.

* Rust Refinement Boundary

The later Rust refactor must preserve the proof boundary:

- ASP Server health is independent from Agent Session close authority.
- Archive, termination, registry retirement, and path release are distinct
  receipts.
- Stable registered name and physical generation are distinct identities.
- Replacement admission is a CAS transition after release, never an inference
  from agent-tree absence or archive visibility.
- Late termination from an old generation is fenced from the new generation.

Rust implementation begins only after this RFC, its Typst blocks, and the Lean
audit are admitted together.
