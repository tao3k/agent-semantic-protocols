* Three-stage runtime admission and provider-scoped isolation

A lifecycle receipt has three independent admission stages:

- byte identity: the installed artifact digest matches its receipt;
- executable closure: the installed entrypoint can replay in the resident
  runtime environment with every referenced runtime file available;
- semantic acceptance: the replayed response satisfies the current protocol
  identity, state, completeness, and authority checks.

The first stage does not imply the second, and the second does not imply the
third. The runtime observed both counterexamples while repairing the nested
=.data/codex= workspace: a digest-valid release wrapper referenced an absent
=dist/src/cli/main.js=, while the executable develop artifact later returned a
project-resolution response rejected by semantic admission.

#+name: three-stage-runtime-admission
#+begin_src typst
#let accepted(artifact) = (
  artifact.digest and
  artifact.closure and
  artifact.semantic
)
#let digest-only = (
  digest: true,
  closure: false,
  semantic: false,
)
#let semantic-drift = (
  digest: true,
  closure: true,
  semantic: false,
)
#assert(digest-only.digest)
#assert(not accepted(digest-only))
#assert(semantic-drift.closure)
#assert(not accepted(semantic-drift))
"ok"
#+end_src

Workspace generation must therefore be provider-scoped. A failed TypeScript
generation may close the TypeScript route, but it must not erase an independently
admitted Rust generation or block a Rust-only search.

#+name: provider-scoped-generation-isolation

* Lean model

The executable model is
=packages/proofs/ASPProof/AgentSessionLifecycleSpawnObservationGap.lean=.
It proves:

- caller projection does not determine host child ownership;
- a Started activity without durable intent and indexed host accept does not
  admit binding;
- canonical task name does not prove typed role;
- default full-history fork does not admit a configured resident;
- a closed chain contains both durable pre-spawn authority and indexed
  post-spawn evidence.

- digest identity does not prove executable closure;
- executable closure does not prove semantic admission;
- an unrelated provider failure preserves an independently ready route;
- a global provider conjunction can mask that ready route.

* Required refinement

Server health, workspace generation health, and provider generation health are
distinct. Cache migration, artifact installation, executable replay, semantic
admission, and route publication require distinct indexed receipts. Repair may
replace a failed provider generation, but it must preserve every unrelated
admitted route and must never infer executable or semantic readiness from a
digest receipt alone.

The current lower-layer source audit remains blocked at provider admission:
the refreshed state-home Rust artifact reports
=registered-language-runtime-unavailable= because its resolved
project-resolution response omits =scope=. This is evidence of a
provider/runtime ABI drift, not evidence about the durability semantics of
=spawn_agent_with_communication=.

The next source audit must project the lower-layer host spawn receipt. If that
receipt is durable and idempotent, ASP should consume it as the host-accept edge.
If it is not, Codex/ASP integration requires a reservation and durable intent
before host spawn. In either case, activity emission and tool result remain
observations rather than lifecycle authority.
