#+title: Runtime Server Workspace Admission
#+startup: overview

* Status

Required architecture.  This module extends the v1 runtime and search
contracts; it does not introduce a second schema version.

* Problem

The Global Runtime Server may be healthy while its workspace registry is
empty.  Process reconciliation cannot prove that a workspace has an admitted
canonical generation.  Exact query then reports =active-generation-missing=,
while the cache CLI can still escape to a process-local synchronous rebuild.
That split creates two generation authorities and makes provider bootstrap,
MemoryBackend publication, and performance receipts non-deterministic.

* Ownership

- Turso owns durable canonical generation and MVCC history.
- The single Global Runtime Server owns all live workspace entries.
- Each workspace entry owns one async writer lane and a bounded read pool.
- MemoryBackend owns the current query data plane for an admitted workspace.
- A memmap epoch publishes an immutable generation to process consumers.
- Git supplies repository/worktree identity and repository candidates.
- Language providers parse candidate closures and return typed project
  resolution; they do not choose repository identity.

* Workspace admission control

The runtime control plane MUST expose one typed workspace-admission request.
The request carries:

- canonical repository and worktree identity;
- canonical checkout root;
- repository candidate generation and policy-overlay digests;
- the activated provider-registry snapshot;
- the requested root-depth overlay policy.

Admission is idempotent by workspace identity plus candidate generation.
Concurrent sessions requesting the same key join the same in-flight writer
operation.  Different workspaces remain independent.

The typed admission operation MUST carry the complete repository candidate
generation identity and the policy-overlay digest observed by the caller.  A
=Ready= receipt is reusable only when both identities equal the request.  A
newer identity arriving while an older generation is building replaces the
pending intent; the writer finishes at most the currently executing attempt
and then builds the latest pending identity.  It MUST NOT publish an
intermediate attempt after its repository candidate identity has become
stale.

Before committing or restoring a canonical generation, the Runtime Server
MUST rediscover the scoped Git candidate snapshot and compare it with the
requested identity.  A mismatch is a typed failed attempt, never a successful
restore.  A durable materialization that cannot prove its candidate-generation
binding is rebuilt once through the provider-owned source-scope path; it is not
accepted through a compatibility fallback.

Process =status=, =reconcile=, and =restart= remain lifecycle operations.  They
MUST NOT impersonate workspace admission.

* Provider closure fan-out

The daemon groups repository candidates into package-manager closures using
provider descriptors.  It invokes =project-resolution-stdin= once for each
affected closure and keeps the canonical repository/worktree identity in every
request.  A nested package root is an invocation scope, not a replacement
workspace identity.

Independent roots of the same language are separate closures.  Selecting the
first manifest is forbidden.  A manifest delta re-resolves only its affected
closure, then the writer lane assembles one complete workspace generation.

=documentResolution= providers never receive project-resolution requests.

* Atomic publication

The writer lane:

1. reads the durable parent generation from Turso;
2. resolves changed provider closures;
3. builds the next MemoryBackend, selector graph, owner bytes, and root-depth
   live/untracked overlay;
4. validates complete owner/source envelopes and generation evidence;
5. writes the durable generation in one Turso transaction;
6. publishes a new immutable memmap epoch;
7. atomically switches the workspace entry to that epoch.

Readers that acquired the previous epoch continue using it.  No reader may
observe a partially published generation.

* Breaking deletion

The following execution paths MUST be physically removed:

- process-local synchronous source-index rebuild from the cache CLI;
- provider project-resolution without a typed repository-candidate snapshot;
- query-time activation or provider installation;
- exact query compatibility flags =--code= and =--names-only=.

=asp cache source-index rebuild= becomes a Runtime Server admission/rebuild
control client.  It never opens Turso, executes a provider, or creates a Tokio
runtime in the CLI process.

* Hook lifecycle

The synchronous Hook path never submits, joins, enqueues, waits for, or polls a
Runtime Server workspace admission.  Hook execution is a =HookLocalKernel v1=:
it resolves the effective workspace identity, consumes immutable compiled
matcher and agent-registry snapshots, evaluates policy, and emits only bounded
local evidence or a public recovery hint.  It has no Runtime Server, Turso,
workspace IPC, provider activation, source-index generation, or agent-session
admission dependency.

After the Hook returns, an independently owned host lifecycle or Runtime
supervisor may submit a typed workspace admission.  That out-of-band operation
is not part of Hook execution and cannot change the Hook decision already
returned.  Provider parsing, Turso bootstrap, and generation construction
belong to the Runtime single-writer lane; the Hook may not perform or await
them, synchronously or asynchronously.

Exact search/query is read-only against an admitted epoch.  Missing admission
returns a typed control-plane receipt and never falls back to local rebuild.

* Required gates

- cold admission publishes one complete Turso generation, MemoryBackend, and
  memmap epoch;
- warm admission for an unchanged generation performs zero provider processes,
  zero database opens, zero manifest writes, and zero binary reads;
- at least 64 concurrent sessions for one workspace join one writer operation;
- at least 8 workspaces admit concurrently without a global lock;
- old readers remain valid while the next epoch publishes;
- nested independent package roots are resolved as separate closures without
  changing workspace identity;
- =server reconcile= alone leaves workspace admission unchanged;
- the cache CLI cannot call the synchronous rebuild implementation;
- exact query never accepts =--code= or =--names-only=.
