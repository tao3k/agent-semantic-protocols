#+TITLE: RFC 10.05.38 - Tree-sitter Reasoning Search
#+STATUS: accepted

* Problem

=--treesitter-query= currently enters through =asp <language> query= even when
the caller does not know an exact owner or selector.  That is discovery and
reasoning work: the pattern may match several files, several item kinds, or
nothing at all.  Treating it as an exact query obscures the public
=search= / =query= responsibility boundary and makes the next action unclear.

* Decision

Workspace-wide Tree-sitter capture discovery is owned by =search=:

#+begin_src sh
asp rust search --treesitter-query '((type_identifier) @reference.name (#eq? @reference.name "AgentSessionLookupRequest"))' --workspace .
asp search --language rust --treesitter-query '((type_identifier) @reference.name (#eq? @reference.name "AgentSessionLookupRequest"))' --workspace .
#+end_src

The root form may omit =--language= when the active provider set and live
workspace captures identify exactly one language.  If zero or several
languages remain plausible, the CLI fails closed and asks for
=--language <language>=.

=query= remains the deterministic projection surface.  A Tree-sitter query
under =query= is valid only when paired with an exact =--selector=.  A
workspace-wide =query --treesitter-query= invocation returns migration
guidance to =search --treesitter-query= instead of executing discovery.

* Search result contract

The compact result is emitted exactly once.  It identifies the search mode,
language, capture count, truncation state, and parser-owned native fact
references.  A zero-match result explains structural predicate semantics and
provides a search-owned next action.  Source code and capture text remain
omitted unless a later exact selector projection authorizes them.

This change moves CLI ownership; it does not change the versioned search packet
schema.  Provider grammars and source extensions remain provider-owned.

* Root language inference

For =asp search --treesitter-query= without an explicit language:

1. Compile the pattern only against active registered grammars.
2. Evaluate it against the live source-index snapshot using each provider's
   source extensions.
3. Select a language only when exactly one provider produces captures.
4. If no provider produces captures, select a language only when exactly one
   active grammar accepted the pattern.
5. Otherwise require =--language=; never guess from a node-name string.

* Compatibility and validation

- =asp <language> search --treesitter-query= is the canonical explicit form.
- =asp search --language <language> --treesitter-query= is the canonical root
  form for ambiguous workspaces.
- =asp <language> query --treesitter-query= without =--selector= returns an
  actionable migration error.
- Standard help for root and language search surfaces documents
  =--treesitter-query= and the search/query boundary.
- Regression coverage executes predicates over a live temporary workspace,
  verifies single-emission zero-match diagnostics, validates root language
  inference, and rejects ambiguous or selector-free query ownership.
