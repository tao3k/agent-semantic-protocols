#+title: Exact Query Diagnostic Boundary

* Status

Accepted.

* Decision

Exact-query dispatch and exact-query diagnostics are separate protocol
responsibilities.

The direct exact-query owner may:

- resolve the workspace and owner;
- construct and send the provider request;
- receive a typed projection or typed resolution;
- pass a typed resolution context to the diagnostic owner.

The direct exact-query owner must not:

- manufacture an owner-missing receipt;
- classify a resolution state or reason kind;
- validate resolution-envelope identity;
- select JSON versus human diagnostic rendering;
- format or emit diagnostic output.

The diagnostic owner owns the complete resolution lifecycle:

#+begin_example
typed diagnostic input
  -> canonical resolution receipt
  -> envelope validation
  -> JSON or human projection
  -> Tokio output emission or typed failure
#+end_example

This boundary is language-neutral. Language providers return the shared exact
resolution contract; they do not duplicate CLI diagnostic policy.

* Gate

The architecture gate must prove:

1. =provider_direct_exact.rs= contains no owner-missing receipt constructor,
   resolution validator, or resolution renderer.
2. owner-missing and provider-returned resolutions enter the same diagnostic
   implementation.
3. diagnostic contract validation and rendering have focused tests independent
   of provider process execution.
4. JSON output preserves the provider's typed packet, while human output is
   produced only by the diagnostic owner.
