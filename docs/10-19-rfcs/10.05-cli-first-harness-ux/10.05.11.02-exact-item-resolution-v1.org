#+TITLE: 10.05.11.02 Exact Item Resolution V1
#+PROPERTY: header-args :results replace

* Status

Active.

* Intent

Exact query resolves one parser-owned canonical item identity. It does not
search for a symbol and it does not infer an item kind from unrelated workspace
items.

The language harness parser is the sole producer of canonical item identity:

#+begin_example
languageId + kind + symbol + ordered scopes[]
#+end_example

For languages with nested owners, =scopes[]= carries the provider-native owner
identity. Rust examples include implementation owner, trait owner, inline
module owner, and conditional-compilation scope. Other registered providers
must encode their corresponding native owner scopes through the same shared
identity shape.

* Resolution state machine

Within the requested owner, the consumer MUST:

1. collect candidates by =symbol + ordered scopes[]= without using =kind= as
   the lookup key;
2. reject a selector that omits required owner scopes as
   =identity-incomplete / canonical-item-scope-required=;
3. validate the canonical =kind= only after the identity candidate is unique;
4. report a true owner-local mismatch as
   =kind-mismatch / owner-item-kind-mismatch=;
5. return a live hit only for the complete canonical identity.

Relocation is admitted only after the requested owner identity is absent.
Relocation MUST match =kind + symbol + ordered scopes[]= and MAY change only
the owner path. Same-symbol items with another kind or another owner scope are
not mismatch evidence and MUST NOT contribute =actualKinds=.

The legacy =snapshot-item-kind-mismatch= classification is removed. It
conflated workspace symbol search with exact identity validation.

* Provider and consumer contract

Provider transport may return a typed exact-projection failure packet with a
successful transport exit. The ASP consumer MUST interpret non-resolved
=resolutionState= values as query failure. Transport success is not semantic
query success.

Exact query MUST NOT accept legacy projection switches such as =--code= or
=--names-only=. Projection is selected by the typed request contract.

* Registered-language gates

The shared registration gate MUST require every exact-query-capable provider to
declare canonical identity production and typed resolution-state support.
Provider fixtures MUST cover native nested-owner identity where the language
has one.

The Rust provider gate additionally covers:

- function versus struct/reexport with the same symbol;
- repeated methods under different implementation owners;
- trait method versus inherent method;
- conditional-compilation scopes;
- canonical kind aliases at the validation boundary;
- moved items with unrelated same-symbol items elsewhere;
- true owner-local kind mismatch;
- incomplete method identity without implementation or trait owner.

The strong Rust provider gate is =--all-targets --all-features=. A default
feature check is insufficient evidence because the exact-query binary surface
is feature activated.
* Canonical resident runtime freshness

The Global PATH entry MUST be a direct symbolic link from
=/opt/homebrew/bin/asp= to =$ASP_STATE_HOME/runtime/bin/asp=.  The State Home
entry remains the canonical runtime authority and atomically selects an
immutable content-addressed ASP artifact.

Every workspace resident endpoint MUST record the canonical runtime path and
the content digest of the ASP artifact that created it.  Healthcheck compares
that identity with the active artifact receipt:

- a live resident with the current digest is a no-op;
- a missing or unhealthy resident is replaced by the canonical runtime;
- a live resident with a stale digest has its lease revoked and is replaced;
- concurrent healthchecks use one workspace lifecycle claim, so exactly one
  replacement is started;
- readiness has a bounded typed receipt and MUST NOT use an unbounded blocking
  read from a child process.

Resident reconciliation is one Tokio-owned lifecycle, not a sequence of
blocking probes.  The runtime owner tracks asynchronous endpoint reads, health
IPC, stale-owner revocation, canonical child spawn, readiness, cancellation,
and shutdown under one deadline and one workspace election.  Blocking digest
work is admitted only through that runtime owner's tracked blocking lane.

Transport failure is not proof of staleness.  A current endpoint whose runtime
digest matches the active artifact but whose socket is unreachable MUST fail
closed as =current-resident-unreachable= and MUST NOT be killed.  Replacement
authority requires either a successful health receipt with a stale digest or a
validated endpoint whose recorded digest differs from the active receipt.

Installing a new ASP binary MUST copy it into a new immutable artifact inode,
verify the digest after the copy, and only then switch the State Home symlink
and active receipt.  A Cargo target inode, debug binary, or mutable build output
MUST NOT become the canonical runtime artifact.
* Resident transport contract and generation commit

Exact projection consumes one workspace generation through the workspace resident
service.  The endpoint receipt, every request envelope, and every response
envelope MUST carry the same =transportContractDigest=.  A missing or mismatched
digest is a binding failure; it MUST NOT be treated as an unavailable resident,
retried through a direct database open, or repaired by query-time activation.

Source-index rebuild and refresh MUST assemble parser-owned generation evidence
outside the database lane, then submit one typed generation commit to the
workspace resident writer queue.  The cache CLI MUST NOT open a second Turso
write session while the resident owns the workspace.  The resident commits
owners, selectors, membership changes, Merkle evidence, and the generation
receipt in one writer transaction.

An exact selector is resolved only against that committed generation.  If an
owner exists but the canonical item identity is absent, the result is
=item-not-in-live-owner=.  If the same symbol exists under another canonical
kind, the result is =kind-mismatch= with the actual kinds from that same
generation.  Neither state authorizes fuzzy discovery or legacy selector
fallback.

The conformance gate covers request and response digest drift, concurrent
resident reads during a generation commit, moved and removed owners,
conditional modules, enclosing implementation and trait scopes, and a warm
resident no-op path with a millisecond budget.
* Multi-workspace concurrent resolution authority

Exact resolution MUST execute against one resident transaction snapshot identified by
=workspaceIdentity + generationId + rootDigest=.  Requested-owner membership, canonical
identity candidates, owner-local actual kinds, and projection bytes MUST come from that
same snapshot and the same workspace-scoped resident handle.

The state machine is:

- requested owner and canonical identity match: =live-hit=
- one canonical identity match in another owner: =live-relocated=
- multiple canonical identity matches: =ambiguous=
- requested owner exists and its same symbol/scope has another kind: =kind-mismatch=
- requested owner exists without the canonical identity: =item-missing=
- requested owner is absent and the complete generation has no canonical identity match:
  =owner-missing=

Exact query MUST NOT fall back to a single live owner, invoke a provider subprocess, or
materialize a query-time generation after a resident generation miss.  A missing resident
generation fails closed as =active-workspace-generation-required=.

Concurrent readers in one workspace share the resident read pool.  Generation publication
uses that workspace's single-writer lane, so a reader observes either the complete previous
generation or the complete next generation, never mixed owner/selector membership.
Different workspace identities use independent resident entries, DB handles, read pools,
writer lanes, and generation receipts; no global lock or cross-workspace candidate set is
permitted.

Required gates include same-workspace multi-session reads, concurrent read/write generation
switches, multi-workspace isolation, disconnected-session survival, exact state coverage,
zero query-time DB opens/provider processes/source writes, and the warm resident latency
budget.
