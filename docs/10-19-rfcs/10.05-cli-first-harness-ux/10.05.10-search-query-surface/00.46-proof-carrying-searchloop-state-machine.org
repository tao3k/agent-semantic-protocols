#+title: RFC 10.05.10.00.46 — Proof-Carrying SearchLoop State Machine
#+startup: overview

* Status

Draft research specification.

This RFC synthesizes the obligation, feasibility, ledger, cost, inspect, and
completion proofs into one SearchLoop transition system. It does not add CLI
commands or authorize implementation.

* Problem

The preceding RFCs establish local invariants:

- proof plans realize typed AND/OR obligations;
- route feasibility precedes optimization;
- shared resources require atomic reservation;
- cost and lower-bound certificates bind cache and graph generations;
- inspect refinement strictly reduces certified ambiguity; and
- exact, bounded, and incomplete completion have different claims.

Local certificates do not by themselves define legal phase order. A runtime
could possess several valid but unrelated receipts and still:

- execute directly from exploration;
- execute while decision ambiguity is nonzero;
- combine certificates from different generations;
- skip ledger reservation;
- use an old lower bound with a new route; or
- report exact completion after executing an incomplete incumbent.

* Decision

SearchLoop uses five typed phases:

1. =exploring=;
2. =decision-ready=;
3. =admitted=;
4. =executing=; and
5. =completed=.

The legal phase edges are:

#+begin_quote
=exploring -> exploring=

=exploring -> decision-ready=

=decision-ready -> admitted=

=admitted -> executing=

=executing -> completed=.
#+end_quote

A bounded failure may transition from =decision-ready= to =completed= through a
separately typed failure edge. No other phase jump is legal.

* Search context

Every state binds one context identity containing:

- decision-scope digest;
- evidence-root and source-index generation;
- provider-set digest;
- route-budget and ledger revision;
- semantic-cache context;
- model prefix-cost context;
- objective identity; and
- schema version.

Context equality is required along ordinary transitions. A context change uses
an explicit reset or transport transition with its own proof.

* Exploring

An exploring state contains:

- current root obligation;
- certified ambiguity;
- open proof frontier;
- incumbent, if any;
- remaining round and transition budgets; and
- current context identity.

An =exploring -> exploring= edge must carry the monotone refinement proof from
RFC 00.41 and the conflict-certificate proof from RFC 00.42.

An =exploring -> decision-ready= edge requires certified ambiguity zero. This
means the next action is determined, not necessarily that the route is exact.

* Decision-ready

A decision-ready state contains a decoded action:

- admit and execute an incumbent;
- return bounded failure;
- perform an explicitly scoped reset; or
- finish without execution.

The decoder and projection are bound to the same decision scope.

An execute action cannot jump directly to =executing=. It first constructs an
admission bundle.

* Admission bundle

An admitted state carries verified references for:

- obligation realization;
- route feasibility;
- atomic ledger reservation;
- current cost/bound certificate; and
- the selected completion mode.

Every reference binds the admitted state's context identity. A reference whose
claim is true in another generation is still stale for this state.

The Lean model represents a verified reference as a certificate-kind-indexed
proposition plus its proof, not as a mutable =valid=true= flag. Obligation,
feasibility, ledger, and cost-bound references have different phantom types and
cannot be substituted for one another.

* Executing

=admitted -> executing= requires =ExecutionReady=:

- decoded action is =execute=;
- every required certificate is present and verified;
- every reference is bound to the current context; and
- executing state preserves context and completion mode.

The state machine has no constructor for:

- =exploring -> executing=;
- =decision-ready -> executing=; or
- stale =admitted -> executing=.

Lean proves these transitions uninhabited.

* Completion

=executing -> completed= binds:

- execution request identity;
- observed evidence and token receipts;
- outcome;
- original admission bundle identity; and
- completion mode.

Post-hoc observations can update accounting and future search problems. They
cannot retroactively change the premises that admitted the request.

An exact completed result preserves an exact admission mode. A bounded or
incomplete execution cannot be relabeled exact after success.

* Bounded failure

A decision-ready state may complete without execution when it carries a
verified bounded-failure receipt:

- no admitted action exists under current budget/context; or
- the policy stops with an explicitly open frontier.

Failure completion is not routed through an empty admission bundle.

* Context reset and transport

When evidence, provider, cache, objective, or ledger context changes:

- the current state does not mutate in place;
- a reset/transport receipt identifies old and new contexts;
- reusable certificates carry explicit transport proofs;
- non-transportable frontier families reopen; and
- the new state starts in =exploring= or =decision-ready= according to its
  certified ambiguity.

This prevents generation drift from bypassing phase invariants.

* SearchLoop surface

The compact agent packet exposes:

    "obligation": "...",

The agent follows the next action rather than assembling complex CLI state.

* Python Turbo Graph consequence

The future Python implementation SHOULD:

- represent phase transitions as closed variants;
- make certificate bundles immutable;
- verify context equality at transition construction;
- keep reset/transport separate from ordinary transitions;
- preserve admission receipts through execution and completion; and
- reject phase jumps before any provider side effect.

The graph engine proposes transitions. The SearchLoop state machine authorizes
them.

* Required Lean obligations

The companion Lean model MUST prove:

- direct =exploring -> executing= is impossible;
- direct =decision-ready -> executing= is impossible;
- any legal execution transition yields =ExecutionReady=;
- execution preserves context identity;
- a fresh example admission bundle is execution-ready;
- a stale ledger reference makes the bundle not execution-ready; and
- the phase transition relation preserves completion mode through execution.

The modular audit emits these theorem families as Lean-generated JSON.

* Design finding

The prior RFCs could each be satisfied while their receipts referred to
different worlds. Lean's indexed transition constructors expose this missing
composition boundary. Legal execution is not a Boolean conjunction assembled
at runtime; it is the only constructor from a context-bound admitted state to
an executing state.

The first state-machine draft also used one unbranded verified-reference type
for every admission slot. That allowed an arbitrary proven proposition to
occupy the feasibility or ledger position. Certificate-kind indexing removes
this type-confusion path.
