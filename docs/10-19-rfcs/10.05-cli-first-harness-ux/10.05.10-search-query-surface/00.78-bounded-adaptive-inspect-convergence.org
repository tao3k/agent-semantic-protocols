#+title: 00.78 Bounded Adaptive Inspect Convergence
#+startup: overview

* Status

This module defines a proof-carrying interactive inspect state machine.  It
does not implement a Rust or Python runtime.

* Problem

Selective disclosure lowers token cost only if the agent can acquire missing
required edges without entering an unbounded loop.  Each inspect action must
make measurable progress, preserve the request identity, and account for both
tokens and LLM rounds.

Batching creates a second optimization axis:

#+begin_example
larger batch  -> fewer inspect and LLM rounds
same coverage -> same final disclosed token units
#+end_example

The router must not claim token savings merely because several edges were
disclosed in one round.

* Contract

** ASP-RFC-10.05-BAIC-STATE

An inspect state MUST bind one disclosure request, the already disclosed edge
prefix, the remaining required edge suffix, disclosed token units, and LLM
round count.

** ASP-RFC-10.05-BAIC-PARTITION

For a valid state, ~disclosed ++ remaining~ MUST equal the request's canonical
required-edge list.

** ASP-RFC-10.05-BAIC-STEP

An inspect step MUST preserve request identity, move a non-empty prefix from
remaining edges to disclosed edges, add exactly that prefix length to token
units, and add exactly one LLM round.

** ASP-RFC-10.05-BAIC-PROGRESS

Every inspect step MUST strictly decrease missing-edge potential.  A no-op or
repeated step is invalid.

** ASP-RFC-10.05-BAIC-TOKEN

For every step and run, disclosed token units plus remaining-edge count MUST be
conserved.  Batching changes rounds, not final coverage units.

** ASP-RFC-10.05-BAIC-BATCH

A batch containing at least two edges MUST reduce missing-edge potential by at
least two.

** ASP-RFC-10.05-BAIC-BOUND

The number of steps in any valid run MUST be no greater than the initial
missing-edge count.

** ASP-RFC-10.05-BAIC-ROUND

The final LLM-round counter MUST equal the initial counter plus the exact run
step count.

** ASP-RFC-10.05-BAIC-READY

Decision readiness MUST require a verified chain, a valid partition, and no
remaining edges.  At readiness, disclosed edges MUST equal required edges.

** ASP-RFC-10.05-BAIC-ROUTER

The router SHOULD choose batches that reduce rounds when latency or loop cost
dominates, while preserving the token conservation law.  It MUST stop when the
state is ready and MUST reject no-progress inspect results.

* Org-Babel Typst model

#+name: bounded-adaptive-inspect-convergence-math
#+begin_src typst
#let required = (1, 3, 4)
#let batches = ((1, 3), (4,))

#let initial = (
  disclosed: (),
  remaining: required,
  token-units: 0,
  llm-rounds: 0,
)

#let final = (
  disclosed: required,
  remaining: (),
  token-units: required.len(),
  llm-rounds: batches.len(),
)

(
  initial-missing: initial.remaining.len(),
  final-missing: final.remaining.len(),
  run-steps: batches.len(),
  rounds-bounded:
    batches.len() <= initial.remaining.len(),
  token-plus-missing-initial:
    initial.token-units + initial.remaining.len(),
  token-plus-missing-final:
    final.token-units + final.remaining.len(),
  token-conserved:
    initial.token-units + initial.remaining.len()
    == final.token-units + final.remaining.len(),
  batch-reduces-rounds:
    batches.len() < required.len(),
  ready:
    final.remaining.len() == 0
    and final.disclosed == required,
)
#+end_src

The expected record has three required edges, two inspect rounds, three final
token units, equal token-plus-missing totals, and a ready final state.

* SearchLoop consequence

The provider returns the next missing-edge batch rather than exposing a complex
search command grammar.  The agent repeats one inspect action, while the
receipt proves strict progress and a finite round bound.  Router policy may
trade batch size against latency, but it cannot hide token cost or accept a
repeated result as progress.
