#+title: RFC 10.05.80 — SearchRoute Cache Rejoin Sink Acceptance
#+startup: overview

* Status

Draft proof-bearing extension of RFC 10.05.79.

* Abstract

RFC 10.05.79 makes graph publication recoverable through a durable outbox, but
its local =published= phase is not evidence that the graph sink accepted the
edge.  A transport can fail, a receipt can refer to another sink or edge, or a
forged response can be mistaken for acceptance.

This RFC introduces a stable delivery identity and a sink acceptance receipt.
The identity binds the sink, protocol version, winning edge, terminal digest,
and committed revision.  An outbox obligation may be acknowledged only when
the receipt matches the expected identity and an explicit sink verifier accepts
its evidence.

* Scope

The Lean model treats verifier acceptance as an explicit policy predicate.  It
does not prove the security of a signature scheme, trust store, hardware key,
or remote sink.  A runtime claiming authenticated acceptance must supply and
audit the concrete verifier.

* Normative clauses

** ASP-RFC-10.05-CRSA-IDENTITY — Delivery identity is stable across retries

The publication idempotency identity MUST contain:

- sink identity;
- protocol version;
- winning graph edge;
- terminal receipt digest;
- committed admission revision.

Publication retry MUST preserve this identity exactly.

The selected sink and protocol version MUST be persisted with the publication
obligation.  They MUST NOT be supplied as free acknowledgement-time choices.

** ASP-RFC-10.05-CRSA-SINK — Acceptance is sink-scoped

The receipt sink identity MUST equal the sink selected by the publication
obligation.  A receipt from another sink MUST fail closed even when the same
edge is present there.

** ASP-RFC-10.05-CRSA-VERSION — Acceptance is protocol-version scoped

The receipt protocol version MUST equal the version used to derive the delivery
identity.  Compatibility inference or silent version coercion MUST NOT be used
as verification evidence.

** ASP-RFC-10.05-CRSA-EDGE — Acceptance names the exact winning edge

The receipt edge MUST equal the outbox edge, including the winning claim and
committed revision.  A receipt for an older, newer, losing, or conflicting edge
MUST fail closed.

** ASP-RFC-10.05-CRSA-VERIFY — Receipt evidence passes the selected verifier

Receipt evidence MUST pass the verifier selected for its sink and protocol
version.  Merely possessing correctly shaped receipt fields MUST NOT establish
acceptance.

The verifier implementation, trust roots, algorithms, and configuration digest
MUST be contract-visible audit inputs.

** ASP-RFC-10.05-CRSA-ACK — Verified acceptance admits acknowledgement

Acknowledgement MUST require both RFC 10.05.79 local acknowledgement admission
and a sink acceptance receipt satisfying CRSA-SINK, CRSA-VERSION, CRSA-EDGE,
and CRSA-VERIFY.

The closed obligation MUST retain the receipt used for acknowledgement.

** ASP-RFC-10.05-CRSA-STALE — Stale edge receipts cannot close current obligations

If the obligation edge revision is older than the accompanying admission
revision, no receipt for that edge MAY acknowledge the obligation.

** ASP-RFC-10.05-CRSA-NONIMPLICATION — Verifier shape is not verifier soundness

The existence of a verifier predicate and an axiom-free Lean proof does not
imply that a concrete cryptographic verifier is correctly implemented or that
its trust root remains valid.

* Mathematical model

The executable model uses an idealized deterministic signature to exercise
binding failures.  Production systems must replace it with a concrete verifier
policy rather than copy this construction.

#+begin_src typst
#let claim(replica, epoch, terminal) = (
  replica: replica,
  epoch: epoch,
  terminal: terminal,
)
#let edge(candidate, revision) = (
  claim: candidate,
  revision: revision,
)
#let identity(sink, version, published-edge) = (
  sink: sink,
  version: version,
  edge: published-edge,
)
#let sign(value) = (
  signer: value.sink,
  version: value.version,
  edge: value.edge,
)
#let receipt(delivery, evidence) = (
  identity: delivery,
  evidence: evidence,
)
#let verifies(value) = value.evidence == sign(value.identity)
#let bundle(active, revision, published-edge, phase, sink, version) = (
  active: active,
  revision: revision,
  edge: published-edge,
  phase: phase,
  sink: sink,
  version: version,
)
#let edge-authorized(value) = (
  value.revision == value.edge.revision
  and value.active == value.edge.claim
)
#let can-acknowledge-with(
  value,
  acceptance,
) = (
  value.phase == "published"
  and edge-authorized(value)
  and acceptance.identity.sink == value.sink
  and acceptance.identity.version == value.version
  and acceptance.identity.edge == value.edge
  and verifies(acceptance)
)
#let acknowledge(value, acceptance) = {
  assert(can-acknowledge-with(
    value,
    acceptance,
  ))
  (
    active: value.active,
    revision: value.revision,
    edge: value.edge,
    phase: "acknowledged",
    sink: value.sink,
    version: value.version,
    receipt: acceptance,
  )
}
#let accepted = claim(3, 7, 104)
#let winner-edge = edge(accepted, 8)
#let delivery = identity(20, 1, winner-edge)
#let valid = receipt(delivery, sign(delivery))
#let published = bundle(accepted, 8, winner-edge, "published", 20, 1)
#assert(can-acknowledge-with(published, valid))
#let closed = acknowledge(published, valid)
#assert(closed.phase == "acknowledged")
#assert(closed.receipt == valid)
#let cross-sink-delivery = identity(21, 1, winner-edge)
#let cross-sink = receipt(cross-sink-delivery, sign(cross-sink-delivery))
#assert(not can-acknowledge-with(published, cross-sink))
#let wrong-version-delivery = identity(20, 2, winner-edge)
#let wrong-version = receipt(
  wrong-version-delivery,
  sign(wrong-version-delivery),
)
#assert(not can-acknowledge-with(published, wrong-version))
#let other-edge = edge(claim(3, 7, 999), 8)
#let wrong-edge-delivery = identity(20, 1, other-edge)
#let wrong-edge = receipt(wrong-edge-delivery, sign(wrong-edge-delivery))
#assert(not can-acknowledge-with(published, wrong-edge))
#let forged = receipt(delivery, ("forged",))
#assert(not can-acknowledge-with(published, forged))
#let stale = bundle(none, 9, winner-edge, "published", 20, 1)
#assert(not can-acknowledge-with(stale, valid))
"ok"

* Lean correspondence

The Lean model is
=ASPProof.SearchRouteAdmissionRetryCacheRejoinSinkAcceptance=.

| RFC clause | Lean witness |
|-
| CRSA-IDENTITY | =publication_retry_preserves_delivery_identity= |
| CRSA-SINK, CRSA-VERSION, CRSA-EDGE | =admitted_receipt_matches_expected_delivery= |
| CRSA-ACK | =verified_receipt_closes_publication_obligation= |
| CRSA-SINK | =cross_sink_receipt_cannot_acknowledge= |
| CRSA-VERSION | =wrong_protocol_version_receipt_cannot_acknowledge= |
| CRSA-EDGE | =wrong_edge_receipt_cannot_acknowledge= |
| CRSA-VERIFY | =unverifiable_receipt_cannot_acknowledge= |
| CRSA-STALE | =stale_edge_receipt_cannot_acknowledge= |
| CRSA-ACK | =receipt_closed_bundle_cannot_acknowledge_again= |

CRSA-NONIMPLICATION is the model boundary: =SinkVerifier.verifies= is supplied
by the implementation.  No theorem derives cryptographic soundness from its
type.

The JSON audit is isolated in
=ASPProof.Audit.SearchRouteAdmissionRetryCacheRejoinSinkAcceptance=.

* SearchLoop and graph-router consequence

The router may expose a closed publication edge with a compact acceptance
reference:

#+begin_example
edge(replica, attempt, terminalDigest, committedRevision)
accepted-by(sink, protocolVersion, receiptReference)
#+end_example

The agent can inspect the receipt only when auditing delivery.  Routine search
uses the verified acceptance edge without replaying transport history.

* Remaining proof boundary

Verifier acceptance is scoped by sink and protocol version but not by trust-key
epoch or revocation state.  A receipt valid under an old key could remain
accepted after compromise or rotation.

A follow-up RFC must model verifier lifecycle:

- authority-issued trust epochs;
- key rotation and overlap windows;
- revocation effective revision;
- distinction between acceptance time and verification time;
- rejection of receipts issued after revocation;
- preservation rules for historically accepted edges.
