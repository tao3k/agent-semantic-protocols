#+title: Exact Selector And Memory Read Model V1

* Status

This document defines the v1 search/query boundary used by every registered
language harness.  It replaces direct-source-read and ASP-owned language
fallback behavior.

* Discovery and projection

- =search= owns unknown-identity discovery and reasoning.
- Owner and lexical discovery may return only parser-owned owners, facts, and
  canonical structural selectors.
- =query= owns deterministic projection of one exact structural selector.
- An exact selector is a complete query key.  It never requires a lexical
  =--term=.
- A missing selector is a typed routing failure.  It must return to =search=;
  it must not be converted into a path/range read.

Provider manifests bind code projection to =query/exact-selector=.  A provider
may advertise =ownerItems=true= only when its language harness implements the
owner-items packet.  ASP invokes that packet directly and fails closed when the
capability is unavailable.  ASP must not synthesize language items from source
text.

* Canonical identity

Canonical item identity is language-harness data, not Rust command logic.  Each
registered language maps its parser facts into the shared v1 identity envelope:

- language id
- owner path
- item kind and symbol
- implementation, trait, namespace, conditional-compilation, or equivalent
  language-owned scopes
- parser identity digest
- query-pack digest
- source-blob digest and owner-subtree digest

The harness must preserve every enclosing scope needed to distinguish two
otherwise equal items.  Routers and renderers consume this envelope without
reconstructing identity from strings.

* Live memory read model

The live source snapshot is authoritative.  One source capture produces both
the Merkle evidence and the in-memory source-index facts.

When project root, schema, snapshot root, artifact digest, and generation all
match, lookup ranks the live facts synchronously and returns before entering an
async runtime.  The accepted warm receipt is:

#+begin_example
source=live-memory
subprocesses=0
dbOpens=0
lockAttempts=0
manifestWrites=0
sourceByteReads=0
#+end_example

Turso is the persisted read model for a live-memory miss or identity mismatch.
Read-only lookup must not create directories, write manifests, bootstrap a
schema, or acquire a write connection.

* Activation and regression gates

Activation records the exact provider manifest and binary digest.  Installed
artifacts are valid only when every activated provider is included in that
content closure.

The v1 gates require:

- no =query/direct-source-read= route or executable direct-read module
- no ASP-owned language owner-items fallback
- selector-only query succeeds without =--term=
- unscoped ambiguous identity returns scoped candidates
- live-memory hit records zero DB, lock, subprocess, manifest, and source-read
  operations
- installed cold then warm runs preserve the same snapshot and provider
  identities
