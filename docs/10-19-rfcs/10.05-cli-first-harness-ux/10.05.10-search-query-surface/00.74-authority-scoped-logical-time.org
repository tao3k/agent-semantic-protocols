#+title: 00.74 Authority-Scoped Logical Time
#+startup: overview

* Status

This module is a proof-driven refinement of temporal certificate validity.  It
does not define a Rust or Python runtime implementation.

* Problem

Temporal certificate rules are unsound if they compare bare numeric timestamps.
Two providers, two registry authorities, or two process epochs can each emit
the same numeric range while referring to unrelated histories.  Therefore
~sequence(left) < sequence(right)~ is not evidence that one event happened
before the other.

SearchLoop must bind every ordering claim to a clock domain:

#+begin_example
clock-domain = (registry-authority-digest, logical-epoch)
logical-instant = (clock-domain, monotone-sequence)
#+end_example

Wall-clock time may remain diagnostic metadata.  It MUST NOT authorize route
issuance, revocation, historical audit, or Pareto comparison unless a separate
clock-synchronization contract proves comparability.

* Contract

** ASP-RFC-10.05-ASLT-DOMAIN

Every certificate lifecycle instant MUST carry the registry authority digest
and logical epoch that own its monotone sequence.

** ASP-RFC-10.05-ASLT-ORDER

~BeforeOrAt~ and ~StrictBefore~ MUST require equal clock domains in addition to
the corresponding sequence inequality.

** ASP-RFC-10.05-ASLT-RAW

A bare sequence inequality MUST NOT establish comparability.  In particular,
equal epochs under different authority digests remain incomparable.

** ASP-RFC-10.05-ASLT-EPOCH

An epoch rollover MUST make old-epoch and new-epoch instants incomparable even
when their authority digest is unchanged and their raw sequences are ordered.

** ASP-RFC-10.05-ASLT-EXECUTION

A valid execution MUST bind issuance, execution, and revocation to one clock
domain.

** ASP-RFC-10.05-ASLT-AUDIT

A historical audit decision MUST additionally bind its observation instant to
the execution clock domain.

** ASP-RFC-10.05-ASLT-REVOCATION

If revocation strictly precedes observation within one clock domain, the
observation instant MUST NOT be accepted as a new execution before that
revocation.

** ASP-RFC-10.05-ASLT-CONSTRUCTION

Within one clock domain, issuance at or before execution and execution strictly
before revocation MUST be sufficient to construct execution validity.

** ASP-RFC-10.05-ASLT-AUTHORITY-MISMATCH

An issuance/execution authority or epoch mismatch MUST reject execution
validity, regardless of raw sequence values.

** ASP-RFC-10.05-ASLT-OBSERVATION-MISMATCH

An execution/observation authority or epoch mismatch MUST reject historical
audit validity.  This rejection does not rewrite the validity of an already
recorded execution under its original domain.

* Org-Babel Typst model

#+name: authority-scoped-logical-time-math
#+begin_src typst
#let same-clock(left, right) = (
  left.authority == right.authority
  and left.epoch == right.epoch
)

#let strict-before(left, right) = (
  same-clock(left, right)
  and left.sequence < right.sequence
)

#let issued = (authority: 17, epoch: 3, sequence: 5)
#let executed = (authority: 17, epoch: 3, sequence: 7)
#let revoked = (authority: 17, epoch: 3, sequence: 10)
#let other-authority = (authority: 23, epoch: 3, sequence: 10)
#let next-epoch = (authority: 17, epoch: 4, sequence: 10)

(
  valid-execution:
    issued.sequence <= executed.sequence
    and strict-before(executed, revoked),
  raw-order-across-authority:
    executed.sequence < other-authority.sequence,
  comparable-across-authority:
    strict-before(executed, other-authority),
  raw-order-across-epoch:
    executed.sequence < next-epoch.sequence,
  comparable-across-epoch:
    strict-before(executed, next-epoch),
)
#+end_src

The expected value is a record in which ~valid-execution~ and both raw-order
fields are true, while both cross-domain comparability fields are false.  This
is the executable counterexample to treating a raw integer as a trustworthy
distributed timestamp.

* Design consequence for SearchLoop

The agent-facing loop does not need another complex CLI flag.  The provider
must return the clock-domain binding in the certificate receipt, and the router
must fail closed when two receipts are incomparable.  Interactive inspection
may then request the missing authority/epoch evidence as a focused next step.
This keeps the command surface small while preventing a shorter but logically
invalid graph path from winning solely because its unscoped sequence number is
smaller.
