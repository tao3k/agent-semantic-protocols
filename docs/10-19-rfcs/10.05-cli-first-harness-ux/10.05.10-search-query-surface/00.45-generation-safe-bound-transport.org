#+title: RFC 10.05.10.00.45 — Generation-Safe Bound Transport
#+startup: overview

* Status

Draft research specification.

This RFC defines when a frontier lower bound may be reused after graph, provider,
feasibility, or cost-context generation changes. It does not add CLI commands
or authorize implementation.

* Problem

A lower-bound certificate is valid for one search problem. Reusing it after a
generation change can be unsound.

Suppose the old OR frontier contains one feasible candidate with cost 10. The
global lower bound 10 is exact. A new graph generation adds another feasible
candidate with cost 4. The old statement:

#+begin_quote
=10 <= every feasible candidate=
#+end_quote

is false in the new problem.

The evidence cache can still contain the old certificate, and every old witness
can still be valid. Neither fact covers the new alternative.

The same failure occurs when a cost-model change makes an existing candidate
cheaper.

* Decision

A lower bound is never reused across problem identity changes without a
=BoundTransport= certificate.

A transport from old problem to new problem proves, for every new feasible
candidate:

1. a corresponding old feasible abstraction exists; and
2. the new candidate cost is no lower than the old abstraction cost.

If the old lower bound applies to every old feasible abstraction, transitivity
makes it a lower bound for every new feasible candidate.

New candidates that cannot be mapped require independent lower-bound evidence.

* Executable mathematical surface

#+name: generation-safe-bound-transport-math
#+begin_src typst
#let global-lower-bound(candidates, lower) = {
  candidates
    .filter(candidate => candidate.feasible)
    .all(candidate => lower <= candidate.cost)
}

#let old-candidates = (
  (name: "existing", feasible: true, cost: 10),
)

#let new-candidates-with-cheaper-alternative = (
  (name: "existing", feasible: true, cost: 10),
  (name: "new-cheap", feasible: true, cost: 4),
)

#let new-candidates-with-monotone-cost = (
  (name: "existing", feasible: true, cost: 12),
)

(
  old-bound:
    global-lower-bound(old-candidates, 10),
  drifted-bound:
    global-lower-bound(
      new-candidates-with-cheaper-alternative,
      10,
    ),
  monotone-cost-bound:
    global-lower-bound(
      new-candidates-with-monotone-cost,
      10,
    ),
)
#+end_src

* Problem identity

A search-problem identity binds:

- evidence-root digest;
- source-index generation;
- provider-set digest;
- feasibility-context digest;
- objective identity and version;
- semantic-cache context;
- model prefix-cost context where relevant; and
- candidate-family schema version.

Equality permits direct certificate reuse. Inequality requires transport or
recomputation.

* Transport theorem

Let =L= be a global lower bound for the old problem. For every new feasible
candidate =n=, transport provides an old candidate =map(n)= such that:

#+begin_quote
=map(n)= is old-feasible

and

=oldCost(map(n)) <= newCost(n)=.
#+end_quote

Then:

#+begin_quote
=L <= oldCost(map(n)) <= newCost(n)=,
#+end_quote

so =L= is a global lower bound for the new problem.

The mapping can target an abstract old candidate family rather than a concrete
route, but its coverage and cost monotonicity remain proof obligations.

* Unsafe generation changes

Transport is rejected when:

- a new OR alternative has no covered old abstraction;
- a provider update introduces a cheaper route;
- a cache or tokenizer change lowers effective prompt cost;
- feasibility changes make a previously excluded cheap candidate admissible;
- identity sharing reduces proof-DAG acquisition cost;
- objective weights or version change; or
- sparse projection changes without full-frontier coverage.

These changes do not necessarily invalidate semantic evidence. They invalidate
the old optimization bound.

* Safe examples

An old lower bound can transport when:

- every new candidate cost is proven greater than or equal to its old
  abstraction;
- candidates are removed and every remaining candidate is covered;
- new candidates are introduced with separately proven cost at least the old
  lower bound; or
- provider/cost changes are accompanied by a monotonicity theorem.

"The new version is expected to be slower" is not a theorem.

* Counterexample

Old generation:

- one feasible candidate;
- cost 10;
- lower bound 10.

New generation:

- original candidate cost 10;
- new feasible alternative cost 4.

The old lower bound 10 is false because =10 <= 4= does not hold.

This counterexample proves that append-only graph growth is not enough to
preserve a lower bound. Adding alternatives can only decrease an OR optimum.

* Cache consequence

A cached lower-bound receipt stores its problem identity. Cache lookup has three
outcomes:

- identity equal: reuse;
- identity changed with valid transport: reuse the transported certificate;
- otherwise: cache hit for historical data, but bound miss for optimization.

The receipt MUST distinguish semantic-cache availability from bound validity.

Model prefix-cache drift follows RFC 00.33 and RFC 00.34. A cheaper verified
prompt cost can invalidate an old token lower bound for omitted candidates.

* SearchLoop consequence

When transport fails, SearchLoop does not discard all graph evidence. It opens
only the affected frontier families and returns a focused action such as:

- inspect new provider alternatives;
- recompute token bounds under the new prefix context;
- revalidate feasibility exclusions; or
- refresh identity-sharing decomposition.

This is cheaper than rebuilding the complete graph while remaining fail-closed.

* Python Turbo Graph consequence

The future Python graph engine SHOULD persist:

- problem identity;
- lower-bound certificate;
- candidate-family coverage map;
- transport proof or failure reason; and
- affected frontier families.

Incremental graph updates can reuse unaffected evidence and recompute only
optimization certificates whose transport obligations fail.

* Required Lean obligations

The companion Lean model MUST prove:

- a transport mapping with feasibility coverage and cost monotonicity preserves
  a global lower bound;
- the old example has lower bound 10;
- adding the cost-4 candidate invalidates lower bound 10;
- a monotone cost increase from 10 to 12 transports lower bound 10; and
- old-bound validity does not imply new-bound validity without transport.

The modular audit emits these theorem families as Lean-generated JSON.

* Design finding

Earlier cache-bound RFCs invalidated certificates on identity drift but did not
state when selective reuse is mathematically safe. Lean exposes the exact
transport premises. The cheaper-new-alternative counterexample prevents graph
growth or cache presence from being mistaken for lower-bound preservation.
