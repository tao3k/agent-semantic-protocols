#+title: RFC 10.05.69 — SearchRoute Retry Winner Noninterference
#+author: ASP Search Protocol Working Notes
#+startup: overview

* Status

This RFC is a proof-oriented refinement of RFC 10.05.68.  It defines
protocol-observable noninterference for unauthorized winner recovery.  It does
not claim machine-level constant-time execution or implement Rust/Python code.

* Abstract

RFC 10.05.67 requires authorization before winner lookup, and RFC 10.05.68
binds release to a current authorization snapshot.  An unauthorized caller may
still distinguish occupied and empty winner cells through secondary effects:

- =denied= versus =missing= outcome classes;
- payload or metadata attached to denial;
- cache insertion, warming, or invalidation;
- a protocol-visible fast/slow timing class.

This RFC models the complete protocol observation as:

#+begin_example
(outcome class, optional payload, cache mutation, timing class)
#+end_example

For unauthorized requests, the observation function MUST be independent of the
winner cell.  Occupied and empty cells produce exactly the same modeled
observation.

* Proof boundary

The Lean theorem proves equality of explicit protocol-visible observation
classes.  It does not prove:

- CPU-instruction constant time;
- identical network latency;
- freedom from microarchitectural side channels;
- equivalent storage-device behavior.

Those require implementation-specific measurement and stronger verification.
The RFC nevertheless prevents the protocol from deliberately exposing
occupancy through outcome, payload, cache receipts, or timing categories.

* Normative requirements

** ASP-RFC-10.05-RWNI-OUTCOME

Every unauthorized recovery MUST return the same =denied= outcome class.
=missing= and =released= are authorized outcomes and MUST NOT be returned to an
unauthorized requester.

** ASP-RFC-10.05-RWNI-PAYLOAD

Unauthorized responses MUST contain no winner payload, winner-derived metadata,
receipt identity, digest, size, generation, or existence-dependent diagnostic.

Logging and tracing MUST obey the same boundary when those channels are visible
outside the trusted authorization domain.

** ASP-RFC-10.05-RWNI-CACHE

Unauthorized recovery MUST NOT create, warm, evict, refresh, or otherwise
mutate a cache based on winner occupancy.

An authorization-denial cache MAY be used only when its key and mutation are
independent of winner existence.

** ASP-RFC-10.05-RWNI-TIMING-CLASS

The protocol-visible timing class for unauthorized recovery MUST be independent
of winner occupancy.  The runtime MUST NOT expose separate immediate-miss and
storage-hit paths through status transitions, progress events, retry hints, or
declared latency classes.

This clause does not claim physical constant time.

** ASP-RFC-10.05-RWNI-EQUALITY

For every two winner-cell states =left= and =right=, the unauthorized
observation MUST satisfy:

#+begin_example
observeUnauthorized(left) = observeUnauthorized(right)
#+end_example

Equality includes outcome, payload, cache mutation, and modeled timing class.

** ASP-RFC-10.05-RWNI-NONIMPLICATION

The protocol MUST preserve these explicit non-implications:

- identical error text does not imply identical observation;
- identical outcome class does not imply payload noninterference;
- no payload does not imply cache noninterference;
- equal modeled timing class does not prove physical constant time;
- authorization denial does not automatically erase prior cache state;
- winner noninterference does not prove graph-route optimality.

The mathematical source remains embedded in Org and is evaluated through
=typst eval= on stdin.

#let outcome(observation) = $upright("Outcome")(#observation)$
#let payload(observation) = $upright("Payload")(#observation)$
#let cache(observation) = $upright("CacheMutation")(#observation)$

#[
  A protocol observation is
  $
    O = (C, P, M, T),
  $
  containing outcome class, optional payload, cache mutation, and modeled
  timing class.

  Unauthorized noninterference requires
  $
    forall L, R,
    #observe($L$) = #observe($R$).
  $

  The canonical unauthorized observation is constant:
  $
    #observe($X$) = (#denied, #noPayload, #noMutation, 0).
  $

  Consequently an empty cell $E$ and occupied cell $F$ satisfy
  $
    #observe($E$) = #observe($F$).
  $

  The four countermodels each violate exactly one projection:
  $
    #outcome(observe($E$)) != #outcome(observe($F$)),
  $
  or
  $
    #payload(observe($E$)) != #payload(observe($F$)),
  $
  or
  $
    #cache(observe($E$)) != #cache(observe($F$)),
  $
  or
  $
    #timing(observe($E$)) != #timing(observe($F$)).
  $
]
#+end_src

* SearchLoop cost relevance

Winner-existence leakage can reveal whether another scope already explored,
published, or cached a route.  That changes agent branching and may disclose
cross-tenant graph activity.  Conversely, a uniform authorized reuse path
avoids repeated discovery and preserves token and model-prefix cache savings.

This RFC protects unauthorized observation.  It does not prove minimum graph
distance, token optimality, minimum interaction rounds, or a model-cache hit.

* Non-goals and next proof boundary

This RFC does not yet prove:

- physical constant-time execution;
- erasure of winner-derived cache state created before revocation;
- noninterference of logs, metrics, storage I/O, or microarchitecture;
- authorization issuer authenticity;
- graph-route optimality.

The next proof layer should model revocation-triggered cache invalidation.  It
must distinguish “unauthorized lookup causes no new cache mutation” from the
stronger requirement that entries created under a formerly active grant become
unusable after authorization-generation advance.
