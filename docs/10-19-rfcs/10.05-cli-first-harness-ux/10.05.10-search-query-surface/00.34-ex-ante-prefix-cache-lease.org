#+title: RFC 10.05.10.00.34 — Ex-Ante Prefix-Cache Lease
#+startup: overview

* Status

Draft research specification.

This RFC closes a causal gap in RFC 00.33. It does not add CLI commands and
does not authorize Rust or Python implementation.

* Problem

RFC 00.33 binds graph cost to a model prefix-cache state. Binding identity is
necessary but insufficient: a router must also know when the cache observation
became authoritative.

Many model runtimes report cached prompt tokens only after a request finishes.
That observation is valid for accounting, telemetry, and later calibration. It
cannot justify an earlier route selection, budget admission, or omitted-frontier
closure. Using a post-hoc hit as an ex-ante premise reverses causality.

For example, route A costs 10 tokens after a verified hit and 100 tokens after a
miss. A response-time report that A hit the cache does not prove that the router
was entitled to assume cost 10 before issuing the request.

* Three cost authorities

The Graph Router recognizes three disjoint prefix-cost authorities:

1. =conservative=: plan using the miss-side token cost;
2. =leased-hit=: plan using hit-side cost only under an authoritative,
   context-bound, unexpired lease; and
3. =post-hoc-hit=: account for a completed request using an observed hit.

A post-hoc observation MUST NOT be accepted by a planning proof. A leased hit
MUST bind the model prefix key, runtime generation, request digest, and expiry
time. Request binding prevents one cache promise from being reused by multiple
SearchLoop or DAG branches.

* Planning admissibility

A conservative authority is always admissible for planning. It makes no cache
hit promise and charges the miss-side cost.

A leased-hit authority is admissible only if:

- the active prefix state is =verified-hit=;
- the lease prefix key equals the active prefix key;
- the lease runtime generation equals the active runtime generation; and
- the lease request digest equals the planned request digest; and
- the active clock has not passed the lease expiry.

Failure of any condition rejects the low-cost planning premise. The search MAY
continue using conservative cost; it does not need to discard valid semantic
evidence.

A post-hoc-hit authority is never planning-admissible.

* Accounting admissibility

A post-hoc hit is accounting-admissible only for the completed request and
prefix key to which it is bound. It can update observed cost distributions and
model-cache telemetry. It cannot retroactively alter the proof that admitted
the request.

Planning cost and accounting cost therefore answer different questions:

- planning cost: what cost was the router entitled to assume?
- accounting cost: what cost did the completed action incur?

Receipts MUST retain both when they differ.

* Relationship to temporal capability leases

RFC 00.29 establishes the general rule that runtime capability evidence is
generation-bound and expires. A prefix-cache lease is a specialized capability
lease. Its payload additionally binds a model prefix key and one request
digest, and authorizes one specific cost interpretation.

The request digest makes the authority affine at the protocol boundary. A
router cannot present the same lease as evidence for two distinct model calls.
If a DAG fan-out will issue two requests, it needs two authorities even when
both requests share the same prompt prefix.

A lease is not a cache prediction. The authority issuing it must guarantee the
meaning of =verified-hit= for the lease lifetime. If the runtime cannot make
that guarantee before execution, the router MUST plan conservatively and treat
the eventual hit as post-hoc accounting evidence.

* Consequences for SearchLoop

SearchLoop does not expose lease mechanics as a complex user-facing command.
The interactive loop receives compact state:

- =cost-authority: conservative=;
- =cost-authority: leased-hit= with expiry metadata; or
- an execution receipt carrying =post-hoc-hit=.

The router can then decide whether to:

- close a frontier using a valid leased cost;
- continue with conservative cost;
- refresh an expired lease; or
- record an observation without changing the prior route proof.

Lease refresh is a graph transition and consumes a round, transition, latency,
and token budget. It is not a free retry.

* Consequences for Python Turbo Graph

The future Python graph runtime SHOULD keep:

- semantic evidence receipts in the Evidence Graph layer;
- planning cost authorities in the Graph Router layer; and
- post-hoc token observations in an accounting/telemetry layer.

The layers can share immutable identities but MUST NOT share a mutable
=cache_hit= Boolean. Frontier memoization keys include the planning authority
class. A frontier closed under a leased hit becomes open when the lease expires
or its runtime generation changes.

* Required Lean obligations

The companion Lean model MUST prove:

- conservative authority is always planning-admissible;
- post-hoc authority is never planning-admissible;
- prefix-key drift rejects a leased hit;
- runtime-generation drift rejects a leased hit;
- request drift rejects a leased hit;
- lease expiry rejects a leased hit;
- prefix-state drift rejects a leased hit;
- an example bound lease is planning-admissible;
- post-hoc planning cost remains conservative; and
- the same post-hoc observation can report a lower accounting cost without
  changing the earlier planning premise.

The audit output is a modular Lean-generated JSON manifest.

* Design finding

RFC 00.33 originally permitted a =verified-hit= state without stating whether
it was known before or after execution. Lean modeling makes that omission
visible because the same Boolean could inhabit both planning and accounting
proofs. The authority sum type removes that ambiguity: a value cannot be both a
planning lease and a post-hoc observation.

The first lease draft also omitted request identity. In that form, the same
lease inhabited the planning proof for arbitrarily many DAG branches. Binding
the authority to a request digest removes that duplication path.
