#+title: RFC 10.05.88 — Unified Hook–Session Lifecycle Authority
#+subtitle: Materialization, resident binding, generation-safe dispatch, and receipt-chain authority
#+language: en
#+options: toc:3 num:t

* Status

Draft replacement contract for Lean-backed architectural audit.

This RFC supersedes conflicting bootstrap, resume, and materialization semantics
across the hook and resident-session control planes. It does not remove
provider, workspace, or language-generation RFCs; it makes them consumers of
one lifecycle authority.

* Live failure that motivated replacement

The configured agent registry contained the =asp_explorer= role, while the
current root session's resident registry contained no child sessions. The hook
returned “resume =asp-explore=” as its only recovery action.

After an explicitly authorized native subagent start:

- a child session was created;
- =messageTargetId= was bound;
- =parentSessionId= and =rootSessionId= were recorded;
- =physicalGeneration= became 1;
- status became =active=; and
- parser-owned ASP discovery became directly executable by the child.

The configured role was never missing. The missing transition was role
materialization into the current root-session authority.

* Implementation calibration

Live Rust/runtime evidence is the implementation baseline. Documentation alone
does not establish implementation conformance.

| Surface | Current evidence | Calibration status |

| Resident materialization | native subagent start created an active generation-1 child | Observed |

A Rust behavior becomes =Verified Implemented= only after an exact

then, this RFC records =Observed=, =Contradicted=, or =Unverified= rather than
inferring implementation from the specification.

=configured= is an intent-level fact. =materialized= is a generation-bound
resident fact. =active= additionally requires a live message route.

There is no child-facing =bootstrap= action. Bootstrap is a root lifecycle-loop

* Materialization transaction

Native child start MUST logically publish:

1. child-session observation;
2. durable registry membership;
3. root/parent binding;
4. message-target binding;
5. physical-generation binding;
6. model/profile evidence;
7. fresh heartbeat; and
8. authority receipt.

#+name: hook-session-materialization
#+begin_src typst
$ "Materialize"(S, i_c, i_m) = S' $

$ "Active"(S') $

$ "next-action"(S') = "dispatch" $

$ g_p' = g_a
quad
r_a' = r_a $

"ok"
#+end_src

Implementations MAY persist these facts through a recoverable journal rather
than one physical database transaction. Until every required fact is durable,
the hook MUST return a reconciliation action and MUST NOT dispatch.

* Replacement and receipt chain

Replacement creates a new physical generation and authority revision:

#+name: hook-session-replacement
#+begin_src typst
$ g_p' = g_a' = g_a + 1 $

$ r_a' = r_a + 1 $

$ rho = (i_r, i_c, i_m, g_p, r_a, h_"prev") $

$ "CanDispatch"(S', rho)
arrow.r.double
(g_p = g_p' and r_a = r_a') $

"ok"
#+end_src

Therefore a receipt from the previous child generation cannot authorize
dispatch to its replacement.

* Normative requirements

** ASP-RFC-10.05-HSLA-CONFIGURED

A configured role MUST be treated as materialization intent only. It MUST NOT
be treated as evidence that a child session or message target exists.

** ASP-RFC-10.05-HSLA-MATERIALIZE

When a role is configured and no current-generation child is observed, the
unique recovery action MUST be =materialize-resident=.

** ASP-RFC-10.05-HSLA-RECONCILE

Partial native-start states MUST route to explicit registry or message-target
reconciliation. They MUST NOT route to dispatch.

** ASP-RFC-10.05-HSLA-BOOTSTRAP

Lifecycle bootstrap is root-only. A resident child MUST execute parser-owned
query/search directly and MUST NOT re-enter bootstrap.

** ASP-RFC-10.05-HSLA-RESUME

=resume= is removed as an unbound hook action. Continuing work is represented
as dispatch to a bound, active, generation-matching message target.

** ASP-RFC-10.05-HSLA-GENERATION

Every resident dispatch MUST bind the current physical generation and authority
revision. Stale generations MUST route to replacement.

** ASP-RFC-10.05-HSLA-TARGET

Dispatch MUST bind =rootSessionId=, =childSessionId=, and =messageTargetId=.
Display name or configured role is insufficient routing authority.

** ASP-RFC-10.05-HSLA-RECEIPT

Lifecycle receipts MUST bind root session, child session, message target,
physical generation, authority revision, and previous receipt digest.

** ASP-RFC-10.05-HSLA-ACTION

The hook decision MUST be total and deterministic. =dispatch= is legal only
when =ActiveResident= holds and a matching receipt is available.

** ASP-RFC-10.05-HSLA-REPLACEMENT

Replacing a dead or stale resident MUST increment physical generation and
authority revision and MUST invalidate every previous dispatch receipt.

** ASP-RFC-10.05-HSLA-ECOSYSTEM

Resident readiness and provider activation status MUST NOT be promoted to
end-to-end executability. Dispatch requires active resident binding, hook
routing, valid provider activation schema, reachable workspace owner, active
provider generation, executable parser route, and a matching lifecycle
receipt.

** ASP-RFC-10.05-HSLA-CALIBRATION

RFC conformance MUST be calibrated against exact parser-owned Rust selectors,
focused tests, and live runtime receipts. When those routes are blocked,
implementation status MUST remain =Unverified= or =Contradicted=.

* Lean audit

The executable model is:

- =packages/proofs/ASPProof/HookSessionLifecycle.lean=

It proves:

- registered absence routes to materialization;
- legacy resume is not executable without a child and target;
- partial spawn routes to registry reconciliation;
- an unbound resident routes to message-target binding;
- generation drift routes to replacement;
- materialization constructs an active resident;
- only an active resident selects dispatch;
- dispatch selection implies active residency;
- a matching receipt authorizes dispatch;
- replacement increments generation and authority revision;
- an old receipt cannot dispatch to the replacement; and
- materialization eliminates the registered-absence deadlock.

The ecosystem extension additionally proves:

- manifest activation does not imply provider execution;
- active residency does not imply end-to-end execution;
- the observed ecosystem repairs hook routing before provider activation;
- schema, workspace-owner, and provider-generation failures are ordered;
- ecosystem dispatch implies every end-to-end predicate; and
- a fully executable ecosystem dispatches.

* Logic bugs replaced

** Registration was conflated with instantiation

The configured agent registry describes roles that may be instantiated. The
resident registry describes concrete children of one root session. No proof
connects them until materialization occurs.

** Resume was prescribed without a message target

A resume instruction naming =asp-explore= is not executable when no
=messageTargetId= exists. The replacement action is materialization.

** Bootstrap crossed the root/child boundary

Bootstrap owns entry into the root lifecycle loop. A child already created by
native spawn must perform its assigned parser-owned search rather than
bootstrapping another lifecycle.

** Hook and session authority used different evidence moments

The hook observed configured intent while the session registry observed
physical instances. The unified receipt binds both to one authority revision.

** Provider activation status was also local

The Rust provider reports =activated= while its activation schema is rejected,
workspace owner is unreachable, active generation is missing, and no parser
route executes. Provider activation must become a derived capability aggregate
just like resident readiness.

* Remaining proof boundary

The next refinement must prove:

- exactly-once materialization under competing hooks;
- crash recovery between native spawn and durable registry binding;
- child termination concurrent with dispatch;
- heartbeat lease expiry during a query;
- message-target rebinding without generation confusion;
- generic lifecycle management for roles other than =asp-explore=; and
- recovery graph/token bounds for materialize, reconcile, replace, and dispatch.

Exact Rust implementation calibration remains blocked until the invalid
=workspaceScope= activation field and workspace-owner endpoint failure are
resolved. This is an implementation-evidence blocker, not permission to treat
the proposed Lean model as already landed.
