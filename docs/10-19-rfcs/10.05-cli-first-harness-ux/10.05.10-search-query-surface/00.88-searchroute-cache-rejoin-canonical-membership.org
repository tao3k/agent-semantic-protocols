#+title: RFC 10.05.88 — SearchRoute Cache Rejoin Canonical Membership
#+startup: overview

* Status

Draft proof-bearing extension of RFC 10.05.87.

* Abstract

RFC 10.05.87 binds votes to membership digests but leaves digest content
abstract.  Equivalent member sets can serialize in different orders, while
quorum weight or failure-domain requirements can be omitted accidentally.

This RFC defines a scheme-owned canonical membership representation.  Member
ordering does not affect its digest, while voting weights, node identities,
failure domains, quorum weight, and minimum failure-domain requirement are
committed policy inputs.

* Normative clauses

** ASP-RFC-10.05-CRCM-CANONICAL — Member ordering is canonical

Equivalent permutations of the same membership entries and policy parameters
MUST produce equal canonical representations and equal digests.

** ASP-RFC-10.05-CRCM-CONTENT — Membership entries contain security semantics

Each committed entry MUST include node identity, voting weight, and failure
domain identity.

** ASP-RFC-10.05-CRCM-POLICY — Quorum policy is committed

Quorum weight and minimum failure-domain requirement MUST affect the membership
digest.  Changing either value MUST change the digest.

** ASP-RFC-10.05-CRCM-UNIQUE — Node identities are unique

A membership policy containing duplicate node identities MUST fail closed.

** ASP-RFC-10.05-CRCM-WEIGHT — Voting weights are positive

Every member voting weight MUST be strictly positive.  Zero-weight placeholder
members are not valid voting membership entries.

** ASP-RFC-10.05-CRCM-DIGEST — Commitment assumptions are explicit

The proof model requires an injective commitment over canonical policy.
Runtime implementations MUST declare canonical encoding, digest algorithm,
version, and collision policy.

* Mathematical model

#+name: searchroute-cache-rejoin-canonical-membership-model
#+begin_src typst
#let member(id, weight, domain) = (
  id: id,
  weight: weight,
  domain: domain,
)
#let policy(members, quorum-weight, minimum-domains) = (
  members: members,
  quorum-weight: quorum-weight,
  minimum-domains: minimum-domains,
)
#let canonical(value) = (
  members: value.members.sorted(key: entry => entry.id),
  quorum-weight: value.quorum-weight,
  minimum-domains: value.minimum-domains,
)
#let left = policy(
  (member(2, 1, 20), member(1, 2, 10)),
  2,
  2,
)
#let reordered = policy(
  (member(1, 2, 10), member(2, 1, 20)),
  2,
  2,
)
#let changed-quorum = policy(reordered.members, 3, 2)
#let changed-domains = policy(reordered.members, 2, 1)
#assert(canonical(left) == canonical(reordered))
#assert(canonical(left) != canonical(changed-quorum))
#assert(canonical(left) != canonical(changed-domains))
"ok"
#+end_src

#+name: searchroute-cache-rejoin-canonical-membership-proposition
#+begin_src typst
#let order-invariance = $upright("Perm")(M_1, M_2)
  and Q_1 = Q_2 and F_1 = F_2
  arrow.r.double D(M_1, Q_1, F_1) = D(M_2, Q_2, F_2)$
#assert(type(order-invariance) == content)
"ok"
#+end_src

* Remaining proof boundary

Positive weights and committed thresholds do not prove that a selected quorum
actually meets total voting weight and failure-domain diversity.  A follow-up
RFC must model weighted quorum realization and domain coverage.
