#+title: Canonical Selector Action Rendering

* Decision

The search action frontier MUST carry an exact query target as
=CanonicalItemSelector=.  A raw string, a source locator hint, or an owner path
is not a query target.

The canonical selector parser is language neutral.  It decodes the shared
=item/<kind>/<symbol>/scope/...= identity path and validates the language,
owner, kind, symbol, scopes, and canonical encoding.  Provider harnesses own the
language-specific item vocabulary; Protocol MUST NOT maintain a Rust item-kind
allowlist.

* Construction boundary

A =QueryCode= action may be constructed only after the structural selector has
been decoded into =CanonicalItemSelector=.  Invalid, empty, range-based, or
owner-only values are not downgraded or repaired into a query action.  They
remain discovery evidence and require an owner or lexical search action.

The action renderer accepts the typed selector and materializes the query
command from =CanonicalItemSelector.structuralSelector=.  Consequently the
renderer cannot emit =asp <language> query= without a canonical exact selector.
The command language is taken from the typed selector identity rather than from
an unrelated outer request string.

* Required gates

- Parse canonical selectors for every registered code-provider language without
  a Protocol-side kind table.
- Reject path ranges, source locator hints, missing owners, incomplete scopes,
  and non-canonical identity encoding.
- Prove that =QueryCode= stores the typed selector, not =String=.
- Prove that rendered query commands always contain the typed exact selector and
  never add =--term=.

* Registered-language consumer boundary

The provider-owned structural query dispatcher MUST validate the selector with
=CanonicalItemSelector= and derive the owner from that validated selector.
It MUST NOT enumerate language IDs when extracting the owner.  The registered
provider manifest and the shared v1 registry method set are the language
inventory.

Document providers use the same =query/exact-selector= method as code providers.
Legacy =query/document= and =query/direct-source-read= method IDs are removed
from the shared v1 registry rather than retained as aliases.  Document metadata
or content projection remains provider-owned after the common canonical owner
boundary.
