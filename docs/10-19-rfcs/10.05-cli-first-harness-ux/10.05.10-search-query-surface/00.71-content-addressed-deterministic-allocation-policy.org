#+title: 10.05.10.00.71 Content-Addressed Deterministic Allocation Policy
#+startup: overview

* Status

Draft proof refinement for deterministic replay of shared-cost allocations.
This document changes no Rust or Python implementation.

* Problem

Equality of a numeric =allocationPolicyId= does not prove equality of policy
semantics.  Two registries can reuse the same identifier for different
algorithms, or a policy implementation can drift without changing its label.
The same batch facts can then produce different route allocations while every
surface identifier still appears equal.

This invalidates route-level Pareto replay:

#+begin_quote
Policy-label equality is not policy-semantic equality.
#+end_quote

* Resolved policy semantics

An allocation receipt binds a resolved policy semantics value, not only an
uninterpreted label.  The policy digest is content-addressed over:

- allocation algorithm and version;
- rounding and remainder rules;
- route ordering and tie-breaking;
- token-accounting units;
- required input-fact schema;
- provider and registry extension semantics.

The digest-resolution receipt MUST identify the registry snapshot that resolved
the policy semantics.

* Deterministic evaluator

The allocation evaluator is a pure function of:

- resolved policy semantics;
- graph generation;
- batch identity and facts;
- provider-call and synthesis tokens;
- search-cache context;
- model-prefix-cache context.

Two certified allocations with the same resolved policy digest and structurally
equal facts MUST replay to the same allocation.

* Complete batch facts

Policy equality alone is insufficient.  A cache-sensitive policy may produce a
different allocation after the search-cache or model-prefix-cache context
changes.  The batch-facts identity therefore belongs to the replay key.

The facts digest MUST resolve to the complete structured facts.  Comparing only
the digest without its content-identity resolution certificate repeats the same
logical error as an unverified policy ID.

* Digest injectivity boundary

Lean proves determinism for an injective finite policy digest model.  It does
not claim to prove cryptographic collision resistance for SHA-256, BLAKE3, or
another production digest.

Production collision resistance and digest-to-content resolution belong to the
content-identity owner.  The Lean theorem begins after the receipt has resolved
one digest to one policy semantics value.

This boundary is intentional:

- Lean proves the protocol logic under unique resolution;
- content identity proves the bytes and digest binding;
- AXLE verifies that the required Lean theorem families are present.

* Collision counterexample

An unsafe digest mapping every policy to the same value is not injective.
=shared-only= and =alpha-all= then have equal digests but produce different
allocations for the same batch facts.

Any protocol accepting that equality as replay proof can reverse route costs
without changing its reported policy identity.

* Cache-sensitive counterexample

A =cache-directed= policy allocates all tokens to =alpha= under search-cache
context 11 and leaves them shared under context 99.  Its policy digest is
unchanged, but the facts and allocations differ.

Therefore same policy digest without same facts is not replay comparability.

* Normative clauses

- =ASP-RFC-10.05-DAP-INJECTIVE=: the resolved policy digest uniquely identifies
  policy semantics.
- =ASP-RFC-10.05-DAP-CONSERVES=: every resolved policy evaluation conserves
  complete batch token cost.
- =ASP-RFC-10.05-DAP-CERTIFIED=: every certified allocation inherits policy
  conservation.
- =ASP-RFC-10.05-DAP-REPLAY=: same resolved policy digest and identical batch
  facts replay to the same allocation.
- =ASP-RFC-10.05-DAP-REFLEXIVE=: replay comparability is reflexive.
- =ASP-RFC-10.05-DAP-NONINJECTIVE=: a constant raw digest is not a valid policy
  content identity.
- =ASP-RFC-10.05-DAP-COLLISION=: a digest collision can produce different
  allocations for identical facts.
- =ASP-RFC-10.05-DAP-FACTS=: same policy digest without equal batch facts is
  insufficient.
- =ASP-RFC-10.05-DAP-CACHE=: a cache-context change rejects replay comparison.
- =ASP-RFC-10.05-DAP-PARETO=: deterministic replay preserves the route cost used
  by Pareto comparison.

* SearchLoop receipt

The compact allocation receipt SHOULD contain:

- policy digest and registry-snapshot digest;
- batch-facts digest and resolved fact schema;
- graph generation;
- both cache contexts;
- policy output allocation;
- conservation proof status;
- content-identity resolution receipts.

SearchLoop compares route costs only after policy and fact resolution succeed.
It does not expose a CLI switch that lets the agent select an arbitrary
allocation implementation.

* Consequences for Python Turbo Graph

The future Python layer should treat allocation policies as immutable,
content-addressed projections.  Changing policy code produces a new digest and
a new graph projection; historical allocations remain attached to their
original policy and facts.

The registry lookup must fail closed when the same claimed digest resolves to
different semantics.

#+name: content-addressed-deterministic-allocation-policy-math
#+begin_src typst
#let facts = (
  callTokens: 20,
  synthesisTokens: 5,
  searchCache: 11,
  modelPrefixCache: 13,
)

#let shared-only = (
  alpha: 0,
  beta: 0,
  shared: facts.callTokens + facts.synthesisTokens,
)

#let alpha-all = (
  alpha: facts.callTokens + facts.synthesisTokens,
  beta: 0,
  shared: 0,
)

#let safe-digests = (
  sharedOnly: "policy-shared-v1",
  alphaAll: "policy-alpha-v1",
)

#let unsafe-digests = (
  sharedOnly: "policy-constant",
  alphaAll: "policy-constant",
)

(
  safe-digests-distinguish-semantics:
    safe-digests.sharedOnly != safe-digests.alphaAll,
  unsafe-digests-collide:
    unsafe-digests.sharedOnly == unsafe-digests.alphaAll,
  colliding-policies-produce-same-allocation:
    shared-only == alpha-all,
  shared-policy-conserves:
    shared-only.alpha + shared-only.beta + shared-only.shared
    == facts.callTokens + facts.synthesisTokens,
  alpha-policy-conserves:
    alpha-all.alpha + alpha-all.beta + alpha-all.shared
    == facts.callTokens + facts.synthesisTokens,
)
#+end_src
