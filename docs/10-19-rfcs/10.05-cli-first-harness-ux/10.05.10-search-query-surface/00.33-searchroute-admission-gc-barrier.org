#+title: RFC 10.05.33 — SearchRoute Concurrent Admission GC Barrier
#+author: ASP contributors
#+language: en

* Status

Draft.

RFC 10.05.32 proves safe garbage collection against a fixed admission-ledger
snapshot.  This RFC defines the write barrier required when a new admission
record becomes visible after GC mark and before sweep completes.

* Problem

Snapshot-at-the-beginning GC marks receipt payloads referenced when the mark
snapshot is taken.  A concurrent admission can then publish a new record that
references an older, unmarked payload.  A sweep that protects only snapshot
references can delete that payload even though the new run is committed and
inside its retention horizon.

Therefore:

#+begin_example
safe against the mark snapshot
does not imply
safe against records published during sweep
#+end_example

* Normative clauses

** ASP-RFC-10.05-AGC-EPOCH

Every GC cycle MUST bind a mark epoch and a sweep-completion epoch, with the
mark epoch no later than the sweep epoch.

A commit whose publication epoch is after mark and no later than sweep is a
concurrent commit for that GC cycle.

** ASP-RFC-10.05-AGC-BARRIER

Before a concurrent admission record becomes visible, the GC write barrier
MUST place both its baseline and extension receipt identities into the cycle's
remembered set.

Record visibility MUST NOT precede successful installation of both entries.

** ASP-RFC-10.05-AGC-SAFE-SWEEP

Sweep MUST preserve every receipt payload that was either:

- referenced by the mark snapshot; or
- added to the remembered set by a concurrent-commit barrier.

Under this rule, payloads referenced by a barrier-covered concurrent commit
remain byte-for-byte identical after sweep.

** ASP-RFC-10.05-AGC-MONOTONE

The remembered set MUST grow monotonically during a GC cycle.  Once a receipt
identity has been installed by a write barrier, it MUST remain protected until
that cycle completes.

** ASP-RFC-10.05-AGC-NONIMPLICATION

None of the following proves concurrent GC safety:

- snapshot-only reachability;
- a well-formed mark/sweep epoch interval;
- publication of a new admission record without both barrier entries;
- retaining only one receipt identity from the record; or
- installing the barrier after record visibility.

* Mathematical model

The following Org-Babel Typst block is evaluated through stdin.

#+name: searchroute-admission-gc-barrier-model
#+begin_src typst
#let WellFormedCycle = $ "WellFormedCycle"(G) "iff"
  e_"mark"(G) <= e_"sweep"(G) $

#let ConcurrentDuringSweep = $ "ConcurrentDuringSweep"(G, e_c) "iff"
  cases(
    e_"mark"(G) < e_c,
    e_c <= e_"sweep"(G),
  ) $

#let Protected = $ "Protected"(G, i) "iff" cases(
  G_"snapshot"(i),
  G_"remembered"(i),
) $

#let BarrierCovers = $ "BarrierCovers"(G, A) "iff" cases(
  G_"remembered"(A_"baseline"),
  G_"remembered"(A_"extension"),
) $

#let SafeSweep = $ "SafeSweep"(G, S_0, S_1) "iff"
  forall i,
  "Protected"(G, i) "implies" S_1(i) = S_0(i) $

#let ConcurrentCommitCertificate = $ cases(
  "ConcurrentDuringSweep"(G, e_c),
  "BarrierCovers"(G, A),
) $

#let BarrierPreservationLaw = $ cases(
  ConcurrentCommitCertificate,
  "SafeSweep"(G, S_0, S_1),
) "implies" cases(
  S_1(A_"baseline") = S_0(A_"baseline"),
  S_1(A_"extension") = S_0(A_"extension"),
) $

#let RememberedMonotone = $ "RememberedMonotone"(G_0, G_1) "iff"
  forall i,
  G_0_"remembered"(i) "implies" G_1_"remembered"(i) $

#let MonotoneBarrierLaw = $ cases(
  "RememberedMonotone"(G_0, G_1),
  "BarrierCovers"(G_0, A),
) "implies" "BarrierCovers"(G_1, A) $

#let SnapshotOnlyCounterexample = $ cases(
  "WellFormedCycle"(G),
  "ConcurrentDuringSweep"(G, e_c),
  "SnapshotOnlySafe"(G, S_0, S_1),
  S_0(A_"baseline") != "none",
  S_1(A_"baseline") = "none",
  "not" "BarrierCovers"(G, A),
) "implies" "not" "ConcurrentGcSafe" $

#let Main = (
  WellFormedCycle,
  ConcurrentDuringSweep,
  Protected,
  BarrierCovers,
  SafeSweep,
  ConcurrentCommitCertificate,
  BarrierPreservationLaw,
  RememberedMonotone,
  MonotoneBarrierLaw,
  SnapshotOnlyCounterexample,
)
#+end_src

* Lean correspondence

The executable model is:

#+begin_example
packages/proofs/ASPProof/SearchRouteAdmissionGcBarrier.lean
#+end_example

The Lean module proves:

- barrier-safe sweep preserves both concurrent-commit receipt payloads;
- snapshot-only GC can delete a concurrently referenced receipt;
- publication during sweep requires both remembered-set entries; and
- remembered-set monotonicity preserves an installed barrier.

* SearchLoop consequence

Concurrent admission and GC must not force SearchLoop to rerun search merely
because a just-committed receipt was swept.  Installing the barrier before
record visibility preserves the constant-size acknowledgement lookup path and
avoids renewed graph traversal, model inference, and cache population.
