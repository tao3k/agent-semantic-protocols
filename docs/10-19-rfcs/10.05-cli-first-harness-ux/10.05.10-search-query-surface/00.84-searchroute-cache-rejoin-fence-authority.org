#+title: RFC 10.05.84 — SearchRoute Cache Rejoin Fence Authority
#+startup: overview

* Status

Draft proof-bearing extension of RFC 10.05.83.

* Abstract

RFC 10.05.83 defines a composite fence but leaves its authority abstract.  This
RFC scopes commands by consensus term and leader identity, and records every
successful fence transition in an append-only durable receipt ledger.

Old terms and nonleaders fail closed.  Leader election increments the term and
fences commands from the former leader.  If a commit response is lost, the
client can query the ledger for the receipt binding observed and committed
fences.  Later commits preserve earlier receipts.

* Normative clauses

** ASP-RFC-10.05-CRFA-TERM — Commands are consensus-term scoped

Every fence command MUST carry the current consensus term.  A command from an
older term MUST fail.

** ASP-RFC-10.05-CRFA-LEADER — Only the current leader may commit

Command leader identity MUST match the authority state.  Leader election MUST
increment term, thereby fencing all commands prepared by the former leader.

** ASP-RFC-10.05-CRFA-GATE — Authority admission includes joint-fence admission

Matching term and leader are necessary but not sufficient.  The complete RFC
10.05.83 joint acknowledgement predicate MUST also hold.

** ASP-RFC-10.05-CRFA-RECEIPT — Commit produces a fence-bound durable receipt

The receipt MUST bind term, leader, observed fence, and committed successor
fence.  It MUST be appended atomically with the authority successor.

** ASP-RFC-10.05-CRFA-RECOVERY — Lost responses recover through receipt query

Receipt query MUST distinguish a committed command from an uncommitted retry
without repeating the mutation.

** ASP-RFC-10.05-CRFA-LEDGER — Receipt history is append-only

Later commits MUST preserve earlier receipts.  A single overwriteable
=lastReceipt= slot is insufficient.

** ASP-RFC-10.05-CRFA-NONIMPLICATION — Term arithmetic is not consensus safety

The Lean state machine does not prove quorum intersection, log replication, or
durable majority commit for a concrete consensus implementation.

The Lean model is

| RFC clause | Lean witness |
|-
| CRFA-RECEIPT | =authority_commit_records_bound_durable_receipt= |
| CRFA-TERM | =stale_term_command_cannot_commit= |
| CRFA-LEADER | =nonleader_command_cannot_commit= |
| CRFA-LEADER | =leader_change_fences_old_term= |
| CRFA-RECOVERY | =committed_receipt_is_queryable_after_lost_response= |
| CRFA-LEDGER | =later_commit_preserves_existing_receipt= |

CRFA-GATE is represented by =CanCommitAuthorityCommand=.  CRFA-NONIMPLICATION
is the remaining consensus-implementation boundary.

* Remaining proof boundary

The model still assumes a leader may append a durable receipt when admitted.
A follow-up RFC must model quorum certificates, log-index/term matching,
majority durability, and recovery after an uncommitted suffix from an old
leader.
