* Problem statement

RFC 10.05.23 proves that one closed inspect trace can be projected to a
=GraphCandidate= without changing its graph-hop, uncached-token, round, or
transition cost.  That result is necessary, but it does not prove that the
driver selected the globally best trace.

Three logical gaps remained.

1. The graph candidate selector had concrete examples but no generic theorem
   that its fold returns a feasible member which is no worse than every other
   feasible member.
2. =GraphCandidate.pathValidated = true= is only a Boolean admission fact.  It
   is not a proof that the candidate realizes a walk between the requested
   source and target in the ranked DAG.
3. A locally optimal result is globally optimal only when the generated
   catalog is complete for every feasible realized candidate.  An interactive
   loop may stop with a valid result while still omitting a cheaper route.

The driver therefore cannot optimize a bare list of projected candidates.  It
must optimize a finite catalog whose entries retain both operational trace
provenance and semantic graph realization.

* Cost order
:PROPERTIES:
:CUSTOM_ID: ASP-RFC-10.05-STC-SELECTOR
:END:

For a graph candidate, the driver cost vector is defined exactly once as
=Cost= in the embedded Org-Babel Typst model.

where:

- =h(c)= is the validated graph-hop count;
- =u(c)= is the uncached token cost;
- =r(c)= is the model/tool interaction round cost;
- =t(c)= is the transition count.

The order is lexicographic in exactly that sequence.  A shorter realized graph
path dominates all later axes.  For equal graph hops, fewer uncached tokens
dominate fewer rounds; for equal graph hops and uncached tokens, fewer rounds
dominate fewer transitions.

This ordering expresses the SearchLoop objective:

- reach the semantic target through the shortest validated graph route;
- minimize prompt/evidence material which is not covered by a model prefix
  cache;
- minimize agent/LLM interaction rounds;
- minimize remaining state-machine transitions.

The generic selector MUST satisfy all of the following for every finite input:

- binary preference returns either its left or right argument;
- binary preference is no worse than both arguments;
- a successful fold result is a member of the input;
- a successful fold result is feasible;
- a successful fold result is no worse than every feasible input member;
- a failed fold means every input member is infeasible.

These are selector laws, not test examples.  Provider implementations may use a
different fold or priority queue only when they preserve the same laws and cost
order.

* Realized trace catalog
:PROPERTIES:
:CUSTOM_ID: ASP-RFC-10.05-STC-REALIZATION
:END:

A realized trace catalog entry MUST contain:

1. a =TraceRouteContext=;
2. a =CostedClosedTraceReceipt=;
3. the projected =GraphCandidate=;
4. a proof or provider-owned witness that the projected candidate realizes a
   walk from the requested source to the requested target in the ranked DAG.

The deterministic projection and the DAG walk obligation are represented by
=Projection= and =RealizedTraceCatalogEntry= in the embedded Org-Babel Typst
model.

The catalog retains more information than the optimizer consumes.  The
optimizer compares the four cost axes, while the selected entry preserves:

- every costed inspect step;
- the loop closure proof;
- route domain and closure digest;
- semantic-search cache identity and validation evidence;
- model prefix cache accounting in the projected route;
- the actual DAG walk witness.

The Boolean =pathValidated= remains part of feasibility admission, but MUST NOT
be treated as a replacement for the walk witness.  This distinction prevents a
provider from manufacturing a globally optimal-looking candidate by setting a
Boolean without proving source-to-target reachability.

If two entries project to an equal candidate, selection proves that at least
one matching entry exists.  It does not prove unique trace provenance.
Uniqueness requires a separate trace identity or catalog deduplication
contract; this RFC intentionally does not assume one.

* Catalog completeness
:PROPERTIES:
:CUSTOM_ID: ASP-RFC-10.05-STC-COMPLETE
:END:

For a graph, source, target, requirement, budget, and finite catalog, the exact
quantified completeness condition is =Complete= in the embedded Org-Babel
Typst model.

Completeness ranges over feasible realized candidates, not over arbitrary
Boolean-validated records.

A complete catalog may be produced by:

- constructive finite DAG route enumeration;
- a branch-and-bound frontier with a closure certificate;
- an inspect scheduler whose closed frontier proves no unrealized cheaper
  candidate remains;
- another provider-owned algorithm carrying an equivalent completeness
  receipt.

The generation algorithm is not fixed by this RFC.  The semantic obligation is
fixed: every feasible realized candidate relevant to the request and budget
must occur in the projected catalog.

Completeness is bound to the graph snapshot, source, target, requirement, and
budget.  A receipt for another snapshot or another budget cannot be reused.

* Global driver theorem
:PROPERTIES:
:CUSTOM_ID: ASP-RFC-10.05-STC-GLOBAL
:END:

Let =select(q,b,map(π,E)) = some c*=.  If:

- every catalog entry carries a realization witness;
- the selector laws hold;
- =E= is complete for =G,s,t,q,b=;

then a matching catalog entry exists, the selected candidate realizes the
requested DAG route, and it is no worse than every feasible realized
candidate.  The exact theorem is =GlobalDriver= in the embedded Org-Babel
Typst model.

This theorem joins four previously separate proof layers:

1. the inspect loop produces a closed trace;
2. the trace projection preserves driver cost exactly;
3. the catalog entry proves DAG realization;
4. complete generation lifts local selector optimality to global optimality.

The theorem is conditional on catalog completeness.  It does not claim that an
arbitrary partial interactive history is globally optimal.

* Cache semantics at the global boundary

Global selection compares =uncachedTokenCost=, not raw prompt size.

Two independent cache layers remain visible in the selected provenance:

- the semantic-search cache avoids recomputing or retransmitting parser-owned
  evidence and is valid only under its semantic identity and validation proof;
- the model prefix cache avoids billing/reprocessing an identical model input
  prefix and is valid only under the model/runtime cache identity.

Neither cache hit implies the other.  Equal total cost does not prove equal
cache provenance.  The cache identities therefore remain receipt fields even
though cache kind is not an additional lexicographic ranking axis.

A provider MUST NOT collapse the two cache layers into one undifferentiated
=cacheHit= Boolean.  Doing so would make replay, billing, and invalidation
claims unverifiable after global selection.

* Incomplete catalog counterexample
:PROPERTIES:
:CUSTOM_ID: ASP-RFC-10.05-STC-INCOMPLETE
:END:

Consider:

- candidate =a=: five graph hops and a short interaction route;
- candidate =b=: two graph hops and a longer interaction route;
- a catalog containing only =a=.

The selector correctly returns =a=, because =a= is the only feasible catalog
member.  Candidate =b= is nevertheless feasible.

Candidate =b= is strictly better than candidate =a= in the lexicographic cost
order because its graph-hop axis is smaller.

because =2 < 5= on the first axis.

The exact non-implication is =IncompleteCounterexample= in the embedded
Org-Babel Typst model: local selection over the singleton catalog does not
establish global optimality.

This is not a selector bug.  It is a missing generation-completeness receipt.
The counterexample forbids an agent from presenting “best result seen so far”
as globally optimal merely because the local fold is correct.

* SearchLoop and inspect consequences

The agent-facing interaction remains progressive:

1. inspect emits a compact current candidate plus frontier/closure evidence;
2. the agent may request another bounded expansion when completeness is not yet
   established;
3. the driver closes only when it has a complete-catalog receipt or explicitly
   returns a partial/non-global status;
4. global selection returns the chosen candidate together with a matching
   realized trace entry.

This design reduces public CLI complexity.  The agent does not need separate
commands for every graph operation, cache check, or cost comparison.  It needs
a small loop over the typed states =inspect=, =expand=, =close=, and =select=.

Each response reveals only the next useful evidence.  The provider remains
responsible for parser-owned graph facts, finite frontier accounting, and
machine-checkable receipts.

The protocol SHOULD measure:

- graph hops to the selected semantic target;
- uncached evidence and prompt tokens;
- model/tool interaction rounds;
- SearchLoop transitions;
- semantic-search cache hits with validation identity;
- model prefix cache hits with runtime identity;
- catalog size and frontier expansions;
- whether global completeness was proved or only partial progress was returned.

* Mathematical model

The complete mathematical projection is embedded here so Org remains the
source document.  The block is evaluated through stdin with =typst eval=; it is
not compiled to or maintained as a standalone =.typ= source.

#+name: searchroute-realized-trace-catalog-global-driver-model
#+begin_src typst
#let Candidate = (
  graph_hops: "Nat",
  uncached_tokens: "Nat",
  rounds: "Nat",
  transitions: "Nat",
  path_validated: "Bool",
)

#let Cost = $ K(c) =
  (h(c), u(c), r(c), t(c)) $

#let LexNoWorse = $ c_1 <=_"lex" c_2 "iff"
  K(c_1) <=_"lex" K(c_2) $

#let CostedClosedTraceReceipt = (
  steps: "List[CostedInspectStep]",
  final_state: "InspectLoopState",
  closed: "LoopClosed(final_state)",
)

#let RealizedTraceCatalogEntry = (
  trace_context: "TraceRouteContext",
  receipt: CostedClosedTraceReceipt,
  candidate: "toGraphCandidate(receipt, context)",
  realization: "Walk(graph, source, target, candidate.graph_hops)",
)

#let Projection = $ pi(e) =
  "toGraphCandidate"(e."receipt", e."trace_context") $

#let Complete = $ "Complete"(E, G, s, t, q, b) "iff"
  forall c,
    ("Realizes"(G, s, t, c) "and" "Feasible"(q, b, c))
      "implies" c in "map"(pi, E) $

#let SelectorLaws = (
  $ "select"(q, b, C) = "some"(c^*) "implies" c^* in C $,
  $ "select"(q, b, C) = "some"(c^*) "implies" "Feasible"(q, b, c^*) $,
  $ "select"(q, b, C) = "some"(c^*) "implies"
      forall c in C, "Feasible"(q, b, c) "implies" c^* <=_"lex" c $,
  $ "select"(q, b, C) = "none" "implies"
      forall c in C, "not" "Feasible"(q, b, c) $,
)

#let GlobalDriver = $ cases(
  "Complete"(E, G, s, t, q, b),
  "select"(q, b, "map"(pi, E)) = "some"(c^*),
) "implies" cases(
  exists e in E, pi(e) = c^*,
  "Realizes"(G, s, t, c^*),
  forall c,
    ("Realizes"(G, s, t, c) "and" "Feasible"(q, b, c))
      "implies" c^* <=_"lex" c,
) $

#let IncompleteCounterexample = $ cases(
  E = {a},
  h(a) = 5,
  h(b) = 2,
  "Feasible"(q, b_0, a),
  "Feasible"(q, b_0, b),
  "select"(q, b_0, "map"(pi, E)) = "some"(a),
) "implies" "not" (a <=_"lex" b) $

#let CacheSeparation = $ cases(
  "semantic_search_cache_identity" != "model_prefix_cache_identity",
  "semantic_search_cache_hit" "does not imply" "model_prefix_cache_hit",
  "model_prefix_cache_hit" "does not imply" "semantic_search_cache_hit",
) $

#let Main = (
  Candidate,
  Cost,
  LexNoWorse,
  RealizedTraceCatalogEntry,
  Projection,
  Complete,
  SelectorLaws,
  GlobalDriver,
  IncompleteCounterexample,
  CacheSeparation,
)

"ok"
#+end_src

* Non-goals

This RFC does not:

- prescribe a Rust implementation;
- add a complex agent-facing search subcommand tree;
- equate semantic-search cache hits with model prefix cache hits;
- claim unique provenance for duplicate catalog projections;
- claim global optimality for an incomplete catalog;
- replace a DAG walk witness with =pathValidated=true=;
- require a standalone Typst source file or PDF artifact.

* Open proof boundary

The next proof layer should connect the inspect scheduler's frontier closure
certificate directly to =RealizedTraceCatalogComplete=.  That theorem would
remove the remaining assumption between bounded interactive expansion and the
global driver theorem.

It must also decide how catalog identity treats two distinct closed traces that
project to the same =GraphCandidate=.  Until then, the protocol guarantees
existential provenance, not a unique selected trace.
