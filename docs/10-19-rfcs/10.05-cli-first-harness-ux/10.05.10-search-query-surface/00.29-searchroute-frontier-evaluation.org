#+title: RFC 10.05.29 — SearchRoute Frontier Completeness and Evaluation Independence
#+author: ASP contributors
#+language: en

* Status

Draft.

This RFC is a modular continuation of RFC 10.05.28.  RFC 10.05.28 defines
when a graph-router change has admissible value.  This RFC defines when the
search experiment used to claim that value has considered a sufficiently
complete candidate frontier and has not trained on its own evaluation set.

* Problem

A router can be locally optimal inside the routes it happened to inspect while
being globally dominated by an omitted route.  The same router can appear to
improve token cost or interaction rounds when its learned state, semantic-search
cache, or model-prefix cache has already observed the evaluation workload.

Therefore none of the following implications are valid:

#+begin_example
locally optimal on the observed frontier => globally optimal
lower cost on training workloads         => generalization
warm-cache improvement                   => cold or independent improvement
an uncommitted candidate set             => reproducible optimality
#+end_example

* Design decision

SearchRoute evaluation MUST commit the candidate universe, candidate frontier,
workload split, baseline/extension router-policy pair, graph snapshot,
semantic-search cache identity, model-prefix cache identity, and evaluation
protocol before an improvement claim is admitted.

Identity equality is not a semantic commitment by itself.  An authorized
verifier MUST bind the candidate-universe identity to the actual candidate
predicate and the workload-split identity to the actual training/evaluation
predicates.

The interactive SearchLoop remains progressive.  It does not need to enumerate
the whole graph eagerly.  It does need a frontier-completeness certificate that
accounts for every feasible candidate in the committed universe, either by
including that candidate in the frontier or by naming a feasible frontier
representative that is no worse.

* Normative clauses

** ASP-RFC-10.05-EGF-COMMIT

Every evaluation receipt MUST bind:

- graph snapshot identity;
- candidate-universe identity;
- baseline router-policy identity;
- extension router-policy identity;
- workload-split identity;
- semantic-search cache identity;
- model-prefix cache identity; and
- evaluation-protocol identity.

Baseline and extension results are comparable only when their shared evaluation
context identities are equal and their two router-policy identities are
distinct.  Requiring the policy identities themselves to be equal would reduce
the experiment to comparing one policy with itself.

Both baseline and extension receipts MUST pass the same authorized
candidate-universe verifier and workload-split verifier.  A caller-provided
label, digest-shaped string, or equal opaque identity without successful
verification does not bind the underlying sets.

** ASP-RFC-10.05-EGF-NON-EQUIVOCATION

An authorized commitment verifier MUST be non-equivocating: if it verifies the
same identity against two values, those values MUST be semantically equal.
This obligation applies independently to candidate universes and workload
splits and MUST hold across receipts, sessions, and cache lifetimes.

Authorization alone is insufficient.  A permissive verifier that accepts every
identity/value pair is not admissible even when an authorization predicate has
incorrectly approved it.

A content-addressed verifier satisfies this clause when its commitment function
is injective over the admitted value domain.  In operational implementations,
this means collision handling and canonical serialization are part of the
proof obligation rather than undocumented hash assumptions.

** ASP-RFC-10.05-EGF-GENERATION

Every evaluation receipt MUST bind a generation vector containing at least the
graph snapshot, candidate universe, workload split, and router learning state.
Baseline and extension receipts in one comparison MUST use the same generation
and that generation MUST equal the evaluator's current generation.

Across accepted sessions, generation advancement MUST be componentwise
monotone.  Equality of evaluation-run identities does not imply generation
equality.

** ASP-RFC-10.05-EGF-FRESHNESS

Every evaluation receipt MUST have an issuance time and an expiry time.  A
receipt is fresh at time =t= only when:

#+begin_example
issuedAt <= t <= expiresAt
#+end_example

Semantic commitment validity and verifier non-equivocation do not imply
freshness.

** ASP-RFC-10.05-EGF-ANTI-REPLAY

Baseline and extension receipts MUST have distinct receipt identities, MUST
belong to the same evaluation run, and MUST both be unconsumed when admitted.
Freshness does not imply that a receipt has not already been consumed.

Receipt consumption MUST be treated as state that survives retries and session
boundaries.  Replaying an otherwise fresh and semantically valid receipt MUST
fail closed.

Admission MUST perform an atomic check-and-consume transition for both receipt
identities.  A read-only check that observes both identities as unconsumed does
not satisfy this clause because concurrent admissions can observe the same
pre-state.

** ASP-RFC-10.05-EGF-COMPLETE

For every feasible route in the committed candidate universe, the evaluation
frontier MUST contain either that route or a feasible representative whose cost
vector is componentwise no worse.  Both the candidate and representative MUST
also satisfy the committed evidence-sufficiency predicate.  A cheaper route
with incomplete evidence is not an eligible dominator.

This is a dominance-coverage obligation, not an eager graph-enumeration
requirement.

** ASP-RFC-10.05-EGF-OPTIMALITY

A local optimum MAY be promoted to a global optimum only when
ASP-RFC-10.05-EGF-COMPLETE holds and every frontier route belongs to the
committed candidate universe.

** ASP-RFC-10.05-EGF-SPLIT

The evaluation workload MUST be disjoint from the workloads used to train,
tune, select, or self-improve the router policy being evaluated.

An admitted workload MUST be covered by the evaluation side of the committed
split.  Success on a workload present on both sides is training evidence, not a
generalization certificate.

** ASP-RFC-10.05-EGF-CACHE

Semantic-search cache state and model-prefix cache state are separate
measurement axes.  A receipt MUST NOT use either cache as an implicit channel
from the training side into the evaluation side.

Warm-path measurements remain useful, but they MUST be reported under their
actual cache identities and MUST NOT be compared with a baseline measured under
different identities.

** ASP-RFC-10.05-EGF-NONIMPLICATION

The following facts do not independently certify a router improvement:

- fewer graph hops;
- local optimality inside an incomplete frontier;
- dominance by a cheaper route that lacks required evidence;
- success on the training workload;
- success on an evaluation workload previously observed by learned state;
- a lower cost measured against a different candidate universe;
- a lower cost measured under different semantic-search or prefix-cache state;
- equality of opaque candidate-universe identities without an authorized
  semantic binding to the actual candidate predicates; or
- authorization of a verifier without a non-equivocation proof;
- verifier non-equivocation without receipt freshness;
- receipt freshness without an unconsumed receipt identity; or
- equality of evaluation-run identities without generation equality.

#+name: searchroute-frontier-evaluation-model
#+begin_src typst
#let RouteCost = $ K(r) = (h(r), t(r), q(r)) $

#let NoWorse = $ "NoWorse"(r_1, r_0) "iff" cases(
  h(r_1) <= h(r_0),
  t(r_1) <= t(r_0),
  q(r_1) <= q(r_0),
) $

#let LocalOptimal = $ "LocalOptimal"(r^*, F) "iff" cases(
  r^* in F,
  "Feasible"(r^*),
  "EvidenceSufficient"(r^*),
  forall r in F,
    cases("Feasible"(r), "EvidenceSufficient"(r))
    "implies" "not" "StrictlyBetter"(r, r^*),
) $

#let GlobalOptimal = $ "GlobalOptimal"(r^*, U) "iff" cases(
  r^* in U,
  "Feasible"(r^*),
  "EvidenceSufficient"(r^*),
  forall r in U,
    cases("Feasible"(r), "EvidenceSufficient"(r))
    "implies" "not" "StrictlyBetter"(r, r^*),
) $

#let FrontierComplete = $ "FrontierComplete"(F, U) "iff" cases(
  F subset.eq U,
  forall r in U,
    cases("Feasible"(r), "EvidenceSufficient"(r))
    "implies" exists r_f in F, cases(
      "Feasible"(r_f),
      "EvidenceSufficient"(r_f),
      "NoWorse"(r_f, r),
    ),
) $

#let Promotion = $ cases(
  "FrontierComplete"(F, U),
  "LocalOptimal"(r^*, F),
) "implies" "GlobalOptimal"(r^*, U) $

#let EvaluationContext = $ E = (
  d_"graph-snapshot",
  d_"candidate-universe",
  d_"workload-split",
  i_"semantic-search-cache",
  i_"model-prefix-cache",
  i_"evaluation-protocol",
) $

#let PolicyComparison = $ P = (
  d_"baseline-policy",
  d_"extension-policy",
) quad d_"baseline-policy" != d_"extension-policy" $

#let SemanticCommitment = $ cases(
  "AuthorizedVerifier"("VerifyUniverse"),
  "AuthorizedVerifier"("VerifySplit"),
  "NonEquivocating"("VerifyUniverse"),
  "NonEquivocating"("VerifySplit"),
  "VerifyUniverse"(d_"candidate-baseline", U),
  "VerifyUniverse"(d_"candidate-extension", U),
  "VerifySplit"(d_"split-baseline", S),
  "VerifySplit"(d_"split-extension", S),
) $

#let NonEquivocating = $ "NonEquivocating"(V) "iff"
  forall d, x, y, cases(
    V(d, x),
    V(d, y),
  ) "implies" x = y $

#let ContentAddressed = $ "ContentAddressed"(c, V) "iff"
  forall d, x, V(d, x) "iff" d = c(x) $

#let CollisionFree = $ "CollisionFree"(c) "iff"
  forall x, y, c(x) = c(y) "implies" x = y $

#let ContentAddressingLaw = $ cases(
  "ContentAddressed"(c, V),
  "CollisionFree"(c),
) "implies" "NonEquivocating"(V) $

#let Generation = $ G(r) = (
  g_"graph"(r),
  g_"candidate-universe"(r),
  g_"workload-split"(r),
  g_"router-learning-state"(r),
) $

#let GenerationNoOlder = $ "NoOlder"(G_1, G_0) "iff"
  G_0 <=_"componentwise" G_1 $

#let Fresh = $ "Fresh"(t, r) "iff" cases(
  t_"issued"(r) <= t,
  t <= t_"expires"(r),
) $

#let Current = $ "Current"(G_"current", r) "iff"
  G(r) = G_"current" $

#let Unconsumed = $ "Unconsumed"(C, r) "iff"

#let TemporalCertificate = $ cases(
  i_"run"(r_0) = i_"run"(r_1),
  i_"receipt"(r_0) != i_"receipt"(r_1),
  E(r_0) = E(r_1),
  G(r_0) = G(r_1),
  "Fresh"(t, r_0),
  "Fresh"(t, r_1),
  "Current"(G_"current", r_0),
  "Current"(G_"current", r_1),
  "Unconsumed"(C, r_0),
  "Unconsumed"(C, r_1),
) $

#let ConsumesPair = $ "ConsumesPair"(C_0, C_1, r_0, r_1) "iff"
  forall i, C_1(i) "iff" cases(
    C_0(i),
    i = i_"receipt"(r_0),
    i = i_"receipt"(r_1),
  ) $

#let AtomicAdmission = $ cases(
  "Unconsumed"(C_0, r_0),
  "Unconsumed"(C_0, r_1),
  "ConsumesPair"(C_0, C_1, r_0, r_1),
) $

#let NoLeakage = $ forall w,
  "Evaluation"(w) "implies" "not" "Training"(w) $

#let EvaluationCoverage = $ forall w,
  "AdmittedWorkload"(w) "implies" "Evaluation"(w) $

#let GeneralizationCertificate = $ cases(

  "StrictlyBetter"(r_1, r_0),

* Lean correspondence

The executable model is:

packages/proofs/ASPProof/SearchRouteFrontierEvaluation.lean

The Lean module proves:

- componentwise no-worse transitivity and antisymmetry;
- dominance preservation of strict improvement;
- complete-frontier local optimality implies global optimality;
- an incomplete frontier can hide a globally better route;
- a cheaper evidence-incomplete route is not an eligible dominator;
- a generalization certificate binds candidate-universe identity;
- a generalization certificate compares distinct router-policy identities;
- a bound generalization certificate uses authorized candidate-universe and
  workload-split verifiers;
- equal opaque identities do not imply equal candidate-set semantics;
- injective content addressing implies verifier non-equivocation;
- non-equivocating verification provides cross-receipt consistency;
- a permissive verifier accepts conflicting bindings and is therefore
  inadmissible;
- generation advancement is componentwise transitive;
- temporal certificates bind both receipts to the current generation;
- temporal certificates reject consumed receipt identities;
- atomic admission marks both receipt identities as consumed;
- read-only unconsumed checks do not constitute a consumption transition;
- verifier non-equivocation does not imply receipt freshness;
- receipt freshness does not imply anti-replay; and
- equal evaluation-run identities do not imply equal generations;
- a generalization certificate requires evaluation independence; and
- training success on the evaluation workload is not generalization.

* Consequence for SearchLoop

SearchLoop should expose a compact frontier commitment and allow the agent to
request the next unresolved dominance obligation interactively.  The protocol
does not require a large human-oriented search command surface.  The shortest
valid loop is the one that closes the remaining frontier and evidence
obligations with the fewest graph hops, tokens, and model/tool rounds while
preserving the committed evaluation context.
