#+title: RFC 10.05.10.00.48 — End-to-End SearchLoop Trace Safety
#+startup: overview

* Status

Draft research specification.

This RFC lifts the local transition rules from RFC 00.46 into an end-to-end run
certificate. It does not add CLI commands or authorize implementation.

* Problem

Proving each state-machine edge independently does not prove that a persisted or
assembled run used one coherent chain.

A runtime could splice:

- exploration from context A;
- decision resolution from context B;
- admission certificates from context C; and
- execution outcome from context D.

Every local receipt may be valid in its own context. The combined story is not a
legal SearchLoop run.

Log order is also insufficient. A sequence of timestamps does not prove that
the output state of one transition equals the input state of the next.

* Decision

An executable SearchLoop trace is a typed proof object containing:

1. zero or more legal =exploring -> exploring= refinements;
2. one legal =exploring -> decision-ready= edge;
3. one legal =decision-ready -> admitted= edge; and
4. one legal =admitted -> executing= edge.

A completed trace extends an executable trace with one legal
=executing -> completed= edge.

The output state of each edge is definitionally the input state of the next
edge. Context and completion-mode equality are preserved by the edge proofs.

* Exploration subtrace

The exploration portion is an inductive refinement run:

- =done= contains no refinement;
- =step= contains one legal refinement followed by another exploration run.

Every refinement preserves context and strictly decreases certified ambiguity,
round budget, and transition budget. The subtrace therefore preserves its
initial context and inherits the bounded-run theorem from RFC 00.41.

* Decision boundary

The decision edge proves:

- resolved ambiguity is zero;
- decision projection and decoder belong to the same scope;
- decoded action is fixed; and
- context is preserved.

The trace cannot skip from an unresolved exploration state to admission.

* Admission boundary

The admission edge proves:

- decoded action is =execute=;
- completion mode is preserved;
- obligation, feasibility, ledger, and cost-bound references are verified;
- all certificate kinds occupy their correct slots; and
- every reference binds the current context.

The trace carries the actual =AdmittedState=. It does not reconstruct admission
from a list of unrelated receipt digests.

* Execution boundary

The execution edge proves:

- =ExecutionReady= for the admitted state;
- executing context equals admitted context; and
- executing completion mode equals admitted completion mode.

The end-to-end theorem combines the edge proofs:

#+begin_quote
Every executable trace has zero ambiguity at its decision boundary, a current
execution-ready admission bundle, and one context from initial exploration
through execution.
#+end_quote

* Completion boundary

A completed trace preserves:

- executing context;
- execution request digest;
- completion mode; and
- the complete executable subtrace.

Post-hoc outcome receipts attach through RFC 00.47. They cannot replace any
earlier edge.

* Anti-splicing theorem

If initial and executing contexts differ, no end-to-end execution trace exists.

This rejects:

- cross-generation admission reuse;
- ledger receipts from another SearchLoop session;
- decision projections from another objective;
- cache-bound costs from another model context; and
- completion-mode substitution.

Explicit reset/transport begins a new trace segment. It is not represented as
ordinary context preservation.

* Trace identity

A durable trace receipt SHOULD bind:

- trace digest;
- parent trace digest for a reset/continuation;
- ordered transition receipt digests;
- initial and final state digests;
- context identity;
- admission digest;
- request digest when executed; and
- completion mode.

Digest linkage provides persistence integrity. Lean state equality provides
semantic continuity.

* SearchLoop surface

The normal agent packet exposes only a compact trace summary:

#+begin_src json
{
  "traceDigest": "...",
  "phase": "executing",
  "contextDigest": "...",
  "decisionResolved": true,
  "admissionDigest": "...",
  "executionReady": true,
  "completionMode": "bounded"
}
#+end_src

Full edge receipts remain available through audit/inspect.

* Python Turbo Graph consequence

The future Python runtime SHOULD:

- construct traces from typed transition results;
- persist state digests at every boundary;
- reject receipt splicing before provider side effects;
- retain the executable subtrace inside completion records; and
- represent reset/transport as a new linked trace segment.

An event log can render the trace. It is not the proof object by itself.

* Required Lean obligations

The companion Lean model MUST prove:

- exploration refinement runs preserve context;
- an execution trace exposes a zero-ambiguity decision boundary;
- an execution trace exposes =ExecutionReady=;
- initial exploration and final execution contexts are equal;
- completion preserves context, request, and completion mode; and
- context drift makes an alleged execution trace impossible.

The modular audit emits these theorem families as Lean-generated JSON.

* Design finding

The local state machine prevents illegal single edges, but it does not by itself
prevent storage or orchestration from assembling edges belonging to different
runs. The typed end-to-end trace makes intermediate state equality explicit and
turns context splicing into an uninhabited proposition.
