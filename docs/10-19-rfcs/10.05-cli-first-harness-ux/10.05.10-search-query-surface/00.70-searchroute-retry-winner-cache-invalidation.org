#+title: RFC 10.05.70 — SearchRoute Retry Winner Cache Invalidation
#+author: ASP Search Protocol Working Notes
#+startup: overview

* Status

This RFC is a proof-oriented refinement of RFC 10.05.69.  It specifies
authorization-bound cache usability and invalidation.  It does not implement a
cache runtime in Rust or Python.

* Abstract

RFC 10.05.69 prevents an unauthorized lookup from creating a new
occupancy-dependent cache effect.  It does not invalidate winner entries
created while a grant was formerly active.

Every authorized cache entry therefore binds:

- authorization generation;
- grant identity;
- cached winner payload.

A lookup may return the payload only when the entry generation equals the
current authorization generation and the grant remains active.  Same-generation
revocation and generation advance both turn the entry into a miss.  A grant
that becomes active again in a later generation does not revive the old entry.

* Normative requirements

** ASP-RFC-10.05-RWCI-ENTRY

Every winner-cache entry MUST bind the authorization generation and grant
identity under which it was created.  Payload-only entries are forbidden.

** ASP-RFC-10.05-RWCI-LOOKUP

Cache lookup MUST recheck:

#+begin_example
entry.authorizationGeneration = current.generation
and current.grantActive(entry.grantIdentity)
#+end_example

Failure of either condition MUST return a cache miss without releasing the
payload.

** ASP-RFC-10.05-RWCI-REVOCATION

Same-generation grant revocation MUST make every entry bound to that grant
unusable.

** ASP-RFC-10.05-RWCI-GENERATION

Authorization generation advance MUST make earlier-generation entries
unusable, even when the same grant identity becomes active again.

** ASP-RFC-10.05-RWCI-PURGE

Unusable entries SHOULD be removed or cryptographically fenced from future
reads.  Correctness MUST NOT depend on asynchronous physical deletion:
lookup-time authorization checks remain mandatory.

** ASP-RFC-10.05-RWCI-NONIMPLICATION

The protocol MUST preserve these explicit non-implications:

- unauthorized non-mutation does not imply historical cache invalidation;
- active grant identity does not make an old-generation entry current;
- physical cache presence does not imply payload usability;
- asynchronous purge completion does not authorize lookup;
- cache safety does not prove graph-route optimality or a model-cache hit.

* Mathematical model

#+name: searchroute-retry-winner-cache-invalidation-model
#+begin_src typst
#let usable(snapshot, entry) = $upright("Usable")(#snapshot, #entry)$
#let generation(value) = $upright("Generation")(#value)$
#let active(snapshot, grant) = $upright("Active")(#snapshot, #grant)$
#let lookup(snapshot, entry) = $upright("Lookup")(#snapshot, #entry)$
#let purge(snapshot, entry) = $upright("Purge")(#snapshot, #entry)$
#let miss = $upright("Miss")$

#[
  Cache usability is
  $
    #usable($S$, $E$)
    equiv
    #generation($E$) = #generation($S$)
    and #active($S$, $G_E$).
  $

  Failed usability produces a miss:
  $
    not #usable($S$, $E$)
    arrow.r.double
    #lookup($S$, $E$) = #miss.
  $

  Same-generation revocation makes the entry unusable.  Generation advance
  also makes it unusable even when $#active($S'$, $G_E$)$ is true.

  Purging an unusable entry satisfies
  $
    not #usable($S$, $E$)
    arrow.r.double
    #purge($S$, $E$) = #miss.
  $

  A generation-free lookup can still return the stale payload and therefore
  does not implement this RFC.
]
#+end_src

* SearchLoop cost relevance

Correctly reusable winner entries reduce repeated graph search, packet size,
tool rounds, and model-prefix disruption.  Stale authorized entries instead
reuse evidence across a revoked policy boundary.  This RFC preserves cache
efficiency only while authorization identity remains current.

* Non-goals and next proof boundary

This RFC does not prove physical cache erasure, distributed invalidation
delivery, constant-time lookup, or graph-route optimality.

The next proof layer should model distributed invalidation acknowledgments and
show that “invalidation event emitted” does not imply every cache replica has
crossed the revocation barrier.
