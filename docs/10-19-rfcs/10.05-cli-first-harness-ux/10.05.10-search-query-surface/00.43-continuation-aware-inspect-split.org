#+title: RFC 10.05.10.00.43 — Continuation-Aware Inspect Split
#+startup: overview

* Status

Draft research specification.

This RFC defines how SearchLoop compares candidate inspect refinements without
mistaking immediate information gain for minimum total search cost. It does not
add CLI commands or authorize implementation.

* Problem

RFC 00.41 requires every refinement to reduce certified action ambiguity.
RFC 00.42 makes that reduction auditable. A natural optimizer chooses the query
with the largest immediate ambiguity reduction per token.

That greedy rule can be globally worse.

A query may remove most conflicts cheaply while leaving one conflict that is
expensive to resolve. Another query may remove fewer conflicts immediately but
leave a frontier that can be closed cheaply within the remaining budget.

The local score ignores continuation cost.

* Decision

Candidate refinement admission uses:

- query token cost;
- certified ambiguity after the split;
- a lower bound on the cost of closing the residual frontier;
- remaining SearchLoop token, round, and transition budgets; and
- the completion policy.

The minimum planning charge for a split is:

#+begin_quote
=query cost + residual closure lower bound=.
#+end_quote

A split whose minimum planning charge exceeds the remaining budget is rejected,
even if it has the best immediate ambiguity-reduction ratio.

Immediate information gain remains a candidate-priority heuristic. It is not a
feasibility or global-efficiency certificate.

* Executable mathematical surface

#+name: continuation-aware-inspect-split-math
#+begin_src typst
#let reduction(initial, option) = (
  initial - option.ambiguity-after
)

#let immediate-no-worse(initial, left, right) = (
  reduction(initial, left) * right.query-tokens
  >= reduction(initial, right) * left.query-tokens
)

#let minimum-total-cost(option) = (
  option.query-tokens + option.residual-lower-bound
)

#let admissible(budget, option) = (
  minimum-total-cost(option) <= budget
)

#let greedy = (
  ambiguity-after: 1,
  query-tokens: 1,
  residual-lower-bound: 2,
)

#let strategic = (
  ambiguity-after: 2,
  query-tokens: 1,
  residual-lower-bound: 1,
)

(
  initial-ambiguity: 4,
  budget: 2,
  greedy-immediate-no-worse:
    immediate-no-worse(4, greedy, strategic),
  greedy-minimum-total: minimum-total-cost(greedy),
  strategic-minimum-total: minimum-total-cost(strategic),
  greedy-admissible: admissible(2, greedy),
  strategic-admissible: admissible(2, strategic),
)
#+end_src

=orgize eval plan --json continuation-aware-inspect-split-math ...= and
evaluated with =typst eval --in -=. It is not written to another Typst source.

* Counterexample

Start with ambiguity 4 and a two-token refinement budget.

The greedy split:

- costs 1 token;
- reduces ambiguity from 4 to 1;
- leaves a certified residual closure lower bound of 2;
- has minimum total cost 3; and
- is infeasible under the two-token budget.

The strategic split:

- costs 1 token;
- reduces ambiguity from 4 to 2;
- leaves residual closure lower bound 1;
- has minimum total cost 2; and
- is feasible.

The greedy split has better immediate reduction per token but cannot complete
within budget. The strategic split can.

* Residual lower bound

The residual closure lower bound is proof-carrying. It may be derived from:

- unresolved AND obligations;
- minimum provider or selector action cost;
- remaining conflict partition depth;
- mandatory model/tool calls;
- capability or lease refresh cost; or
- a certified omitted-frontier bound.

A heuristic estimate MAY prioritize exploration. Only a certified lower bound
can reject a split as necessarily over budget or support bounded optimality.

The bound is tied to decision scope, evidence generation, cost context, and
objective identity.

* Admission and ranking

Split selection follows:

1. reject refinements that do not strictly reduce certified ambiguity;
2. reject refinements whose query cost cannot be reserved;
3. reject refinements whose minimum total cost exceeds the remaining plan
   budget;
4. rank the admitted splits by the declared objective;
5. use immediate information gain as a tie-breaker or exploration heuristic.

This is the same feasibility-first pattern established for graph routes in RFC
00.35.

* Expected versus worst-case cost

Expected cost requires a probability model over possible worlds. Worst-case
cost does not. A receipt MUST state which objective it uses.

An uncalibrated model confidence is not a probability certificate. When no
probability witness is available, SearchLoop uses worst-case or lower-bound
planning.

Changing from worst-case to expected cost changes the objective identity and
invalidates existing bounded-completion receipts.

* SearchLoop consequence

The agent-facing next action includes compact planning evidence:

#+begin_src json
{
  "nextAction": "inspect selector compatibility",
  "queryTokens": 1,
  "ambiguity": {
    "before": 4,
    "after": 2
  },
  "residualClosureLowerBound": 1,
  "minimumTotalTokens": 2,
  "admitted": true
}
#+end_src

The agent does not need to manually combine a complex family of CLI flags. It
follows the chosen split or requests the alternative frontier.

* Graph Router consequence

The Graph Router treats an inspect query as an edge whose continuation includes
the residual obligation frontier. Edge-local cost is insufficient for route
selection.

For AND/OR proof search:

- immediate query cost belongs to the selected edge;
- residual lower bound belongs to the child proof frontier;
- total feasibility is evaluated over both.

This prevents a locally cheap edge from hiding an expensive required subtree.

* Python Turbo Graph consequence

The future Python engine SHOULD maintain for each candidate split:

- certified conflict reduction;
- query cost;
- residual proof-frontier lower bound;
- budget admissibility;
- objective identity; and
- heuristic priority.

Sparse matrix split scores can accelerate candidate ranking. The admissibility
gate uses certified continuation bounds.

* Required Lean obligations

The companion Lean model MUST prove:

- both example splits strictly reduce ambiguity;
- the greedy split is immediately no worse by reduction per token;
- the greedy minimum total cost is three;
- the strategic minimum total cost is two;
- the greedy split is infeasible under budget two;
- the strategic split is feasible; and
- immediate preference does not imply continuation feasibility.

The modular audit emits these theorem families as Lean-generated JSON.

* Design finding

The previous RFC suggested maximizing useful ambiguity reduction per token.
Lean supplies a counterexample once residual closure cost is modeled. The ratio
is safe as a heuristic but cannot determine admission. The protocol therefore
extends graph feasibility-first semantics to interactive inspect splits.
