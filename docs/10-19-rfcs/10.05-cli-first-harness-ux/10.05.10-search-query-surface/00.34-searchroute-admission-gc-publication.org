#+title: RFC 10.05.34 — SearchRoute GC Publication Linearization
#+author: ASP contributors
#+language: en

* Status

Draft.

RFC 10.05.33 proves that a barrier-covered concurrent commit survives sweep,
but takes correct barrier installation as a certificate premise.  This RFC
defines cycle-bound barrier tokens and the publication ordering required to
construct that certificate.

* Problem

A remembered-set entry is insufficient when:

- it belongs to a previous GC cycle;
- it names the wrong receipt;
- it is installed after record visibility; or
- its publication occurs outside the cycle's mark/sweep window.

The admission record and both barrier tokens must share one GC cycle identity,
and both barrier installations must precede the record's visibility
linearization point.

* Normative clauses

** ASP-RFC-10.05-AGP-CYCLE

Every barrier token and record publication MUST bind a GC cycle identity.
Tokens from another cycle MUST NOT satisfy the current cycle's barrier.

The cycle window MUST bind mark and sweep epochs, and every valid barrier token
MUST imply a well-formed window.

** ASP-RFC-10.05-AGP-TOKEN

A barrier token MUST bind:

- GC cycle identity;
- receipt identity; and
- installation epoch.

The baseline token MUST name the baseline receipt and the extension token MUST
name the extension receipt.

** ASP-RFC-10.05-AGP-ORDER

For both tokens:

#+begin_example
mark < barrier installation <= record publication <= sweep
#+end_example

Installing a token after record visibility does not retroactively protect the
publication.

** ASP-RFC-10.05-AGP-BRIDGE

A publication certificate containing two valid tokens and two installed
remembered-set entries MUST construct the concurrent-commit certificate defined
by RFC 10.05.33.

This bridge is required before the safe-sweep preservation theorem may be
applied.

** ASP-RFC-10.05-AGP-NONIMPLICATION

None of the following independently establishes publication safety:

- a token for the correct receipt but a different cycle;
- a correct-cycle token installed after visibility;
- only one valid receipt token;
- matching epochs without matching cycle identities; or
- remembered-set membership without an ordering receipt.

* Mathematical model

The following Org-Babel Typst block is evaluated through stdin.

#+name: searchroute-admission-gc-publication-model
#+begin_src typst
#let CycleWindow = $ W = (
  i_"cycle",
  e_"mark",
  e_"sweep",
) $

#let BarrierToken = $ B = (
  i_"cycle",
  i_"receipt",
  e_"installed",
) $

#let Publication = $ P = (
  i_"cycle",
  A_"record",
  e_"published",
) $

#let ValidBarrier = $ "ValidBarrier"(W, P, B, i_r) "iff" cases(
  B_"cycle" = W_"cycle",
  P_"cycle" = W_"cycle",
  B_"receipt" = i_r,
  W_"mark" < B_"installed",
  B_"installed" <= P_"published",
  P_"published" <= W_"sweep",
) $

#let PublicationCertificate = $ cases(
  "ValidBarrier"(W, P, B_b, A_"baseline"),
  "ValidBarrier"(W, P, B_e, A_"extension"),
  G_"remembered"(A_"baseline"),
  G_"remembered"(A_"extension"),
) $

#let OrderingLaw = $ PublicationCertificate "implies" cases(
  B_b_"installed" <= P_"published",
  B_e_"installed" <= P_"published",
  B_b_"cycle" = P_"cycle",
  B_e_"cycle" = P_"cycle",
) $

#let BridgeLaw = $ PublicationCertificate "implies"
  "ConcurrentCommitCertificate"(G, P_"published", A) $

#let CrossCycleCounterexample = $ cases(
  B_"receipt" = A_"baseline",
  B_"cycle" != W_"cycle",
) "implies" "not" "ValidBarrier"(W, P, B, A_"baseline") $

#let LateBarrierCounterexample = $ cases(
  P_"published" < B_"installed",
) "implies" "not" "ValidBarrier"(W, P, B, A_"baseline") $

#let Main = (
  CycleWindow,
  BarrierToken,
  Publication,
  ValidBarrier,
  PublicationCertificate,
  OrderingLaw,
  BridgeLaw,
  CrossCycleCounterexample,
  LateBarrierCounterexample,
)
#+end_src

* Lean correspondence

The executable model is:

#+begin_example
packages/proofs/ASPProof/SearchRouteAdmissionGcPublication.lean
#+end_example

The Lean module proves:

- a valid token implies a well-formed cycle window;
- both barrier installations precede record visibility;
- a publication certificate constructs the RFC 10.05.33 certificate;
- a token from another cycle is invalid; and
- a token installed after publication is invalid.

* SearchLoop consequence

GC safety is now derivable from durable publication evidence instead of being
an unverified runtime assumption.  A successful acknowledgement lookup remains
constant-size even when admission and GC overlap, avoiding repeated semantic
search and model/tool interaction after a barrier-ordering failure.
