** Status and authority

This module refines the semantic-cache hierarchy with a Lean-checked boundary
between sound reuse, mandatory invalidation, and unnecessary invalidation.

The normative proof source is
[[file:../../../../packages/proofs/ASPProof/SearchLoopCacheIdentity.lean][ASPProof.SearchLoopCacheIdentity]].
The complete mathematical projection is the named Org Babel Typst block in
this document.  There is no detached =.typ= authority source; lint and compile
consume the parser-owned block through stdin.

An independently evolving =ASPProof.SearchLoopCache= module already exists in
the workspace and models more detailed typed invalidation reasons.  This RFC
does not overwrite or silently merge with it.  The present refinement owns the
minimal-identity, cache-tier, false-reuse, and false-invalidation obligations.

** Exact semantic identity
:PROPERTIES:
:ID:       ASP-RFC-10.05-SCI-EXACT-IDENTITY
:END:

A semantic cache entry MUST be reused only when its complete semantic key
equals the current key.  The key includes:

- obligation identity;
- canonical workspace identity;
- minimal witness-set digest;
- source snapshot, provider identity, and provider artifact digest;
- schema and RFC contract identity, plus policy identity;
- selector identity;
- projection version; and
- relevant budget class.

Text equality, endpoint overlap, equal rendered stdout, or equal clause labels
are not semantic-key equality.

The Lean model proves both directions: exact key equality is sufficient for
reuse, and a reuse decision implies exact key equality.

** Dependency invalidation
:PROPERTIES:
:ID:       ASP-RFC-10.05-SCI-DEPENDENCY-INVALIDATION
:END:

Drift in any semantic-key component MUST make the entry stale before it can
contribute evidence or closure.  Reconciliation is a state transition:

- exact key produces =valid=;
- key drift produces =stale=; and
- a reconciled =valid= state implies exact key equality.

Invalidation failure MUST NOT be hidden behind a successful compact rendering
or converted to an empty result.

Lean constructs four false-reuse countermodels:

1. removing provider identity makes a provider-drift key collide with the
   original key;
2. removing policy identity makes a policy-drift key collide with the original
   key.
3. removing provider artifact digest makes artifact drift collide with the
   original key.
4. removing RFC contract digest makes RFC drift collide with the original key.

Both projected keys appear reusable, while the complete semantic keys correctly
invalidate.

** Minimal witness boundary
:PROPERTIES:
:ID:       ASP-RFC-10.05-SCI-MINIMAL-WITNESS
:END:

Whole-workspace generation is not automatically the semantic identity of a
branch or closure receipt.  Entries SHOULD name the minimal witness set whose
change affects their validity.

Lean constructs the dual countermodel: workspace generation changes while the
complete semantic key and witness digest remain equal.  A generation-only
policy invalidates the entry, but semantic validation correctly reuses it.

Therefore cache correctness has two independent failure modes:

- an under-specified key causes false reuse;
- an over-scoped invalidator causes false invalidation.

Protocol review MUST examine both directions.

** Cache tier scope
:PROPERTIES:
:ID:       ASP-RFC-10.05-SCI-TIER-SCOPE
:END:

Model and prompt identities belong to L4 model-judgment cache keys.  They MUST
NOT be inserted into semantic receipt keys that contain no model-dependent
judgment.

Lean proves:

- changing model and prompt invalidates the L4 key; and
- the same change preserves reuse of the underlying semantic key.

This prevents a model upgrade from flushing parser-owned evidence, while still
preventing reuse of model-dependent judgments across incompatible model or
prompt identities.

** Lean-discovered RFC repairs

The proof pass repaired six weaknesses in the prior cache prose:

1. “compatible” is replaced by exact equality over a named semantic key.
2. Provider and policy omissions have executable false-reuse counterexamples.
3. Whole-workspace generation is shown to be too broad for minimal-witness
   receipts.
4. False reuse and false invalidation are made separate proof obligations.
5. Model/prompt identity is limited to L4 rather than leaking into semantic
   cache tiers.
6. Reconciliation cannot report =valid= after key drift.

This module still does not prove storage-engine atomicity, Turso transaction
behavior, selector-relocation soundness, or freshness of provider-produced
witness hashes.

== Exact semantic reuse

$ decideSemantic(K_c, K_n) = reuse <=> K_c = K_n. $

$ K_c != K_n => decideSemantic(K_c, K_n) = invalidate. $

$ decideSemantic(K, K) = reuse. $

These are `semantic_reuse_iff_exact_key`,
`semantic_key_drift_invalidates`, and `stable_semantic_key_reuses`.

== False-reuse countermodels

Let $K_P$ differ from $K$ only in provider identity:

$ omitProvider(K) = omitProvider(K_P), $

$ decideSemantic(K, K_P) = invalidate. $

Let $K_Pi$ differ from $K$ only in policy identity:

$ omitPolicy(K) = omitPolicy(K_Pi), $

$ decideSemantic(K, K_Pi) = invalidate. $

Let $K_a$ differ from $K$ only in provider artifact digest:

$ omitProviderArtifact(K) = omitProviderArtifact(K_a), $

$ decideSemantic(K, K_a) = invalidate. $

Let $K_r$ differ from $K$ only in RFC contract digest:

$ omitRfc(K) = omitRfc(K_r), $

$ decideSemantic(K, K_r) = invalidate. $

Thus equality of an under-specified projection does not authorize reuse.

== False-invalidation countermodel

Let cache states $C_0$ and $C_1$ have equal semantic keys and minimal witnesses,
but unrelated workspace generations:

$ C_0.K_s = C_1.K_s, $

$ not generationCompatible(C_0, C_1), $

$ decideSemantic(C_0.K_s, C_1.K_s) = reuse. $

Whole-generation invalidation is therefore stronger than semantic invalidation
and can discard a sound minimal-witness receipt.

== Tier-scoped model identity

For two L4 keys with equal semantic key and different model/prompt identity:

$ K_4^a.K_s = K_4^b.K_s, $

$ decideModel(K_4^a, K_4^b) = invalidate, $

$ decideSemantic(K_4^a.K_s, K_4^b.K_s) = reuse. $

Model drift invalidates model judgment without invalidating parser-owned
semantic evidence.

== Reconciliation safety

$ E_"key" != K_n =>
  reconcile(K_n, E)_"state" = op("stale"). $

$ reconcile(K_n, E)_"state" = op("valid") =>
  E_"key" = K_n. $

No drifted entry can remain valid after reconciliation.
