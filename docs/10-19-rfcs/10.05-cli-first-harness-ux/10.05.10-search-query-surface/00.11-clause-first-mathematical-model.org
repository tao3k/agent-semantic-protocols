This module is the human-facing mathematical projection of the executable Lean
model in =packages/proofs/ASPProof/SearchLoopClauseFirst.lean=.  The Org file is
the documentation source of truth.  The Typst program is intentionally embedded
as an Org Babel block so Orgize can query its parser-owned block identity and
Typst can lint or compile the extracted body.

Lean remains authoritative for checked derivations.  This document explains
definitions, counterexamples, theorem meaning, and the repairs fed back into the
RFC.  A successful Typst compilation proves only that the mathematical
projection is syntactically valid; it does not prove the RFC.

* Orgize query and Typst lint contract
:PROPERTIES:
:ID: ASP-RFC-10.05-CFR-MATH-EXECUTION
:END:

The execution boundary is:

1. Orgize parses this Org document and selects a =block= with
   =kind=source= and =lang=typst=.
2. The block selector, owning Org path, block body digest, and source snapshot
   identify the extracted mathematical projection.
3. Typst consumes only that extracted body and returns diagnostics or a compiled
   artifact.
4. The block body is streamed to Typst stdin; lint writes no source or rendered
   artifact.
5. A receipt binds the Org identity to the Typst tool version, exit status, and
   normalized diagnostics.

Orgize does not parse Typst semantics, and Typst does not discover or rewrite
the owning Org document.

For a =typst= source block, all three execution headers are implicit:

| Effective header | Inferred value  |
|------------------+-----------------|
| =:runtime=       | =typst=         |
| =:lint=          | =command-stdin= |
| =:format=        | =command-stdin= |

The inference is language-registry data, not stringly shell construction.
Explicit headers MAY override the registry or disable a capability, for example
=:lint no= or =:format no=.  Unknown values fail closed.

The logical =typst= runtime owns two separate fixed-argv capabilities:

- lint sends the block body to =typst compile --diagnostic-format short
  --format pdf - /dev/null=;
- format sends the block body to a registered Typst formatter on stdin and
  consumes formatted source from stdout.

Typst 0.15.1 does not itself provide a format subcommand.  A conforming runtime
therefore maps the format capability to an explicit formatter such as
=typstyle= and reports =formatter-unavailable= when that executable is absent.
It MUST NOT invent =typst format= or silently skip the format gate.

Plain =orgize lint= compares formatter stdout with the parsed block body and
reports drift without changing the Org document.  Only =orgize lint --fix= may
replace the block body, and that replacement MUST be expressed as an Org
parser-owned AST patch that preserves the block name, language, headers, and
surrounding document.

#+begin_src sh
orgize lint 00.11-clause-first-mathematical-model.org
orgize lint --fix 00.11-clause-first-mathematical-model.org
#+end_src

** Effective header resolution

The three headers are optional syntax projections of one language-registry
entry.  For every source block, Orgize computes an effective policy in this
order:

1. read the block language;
2. load that language's registered defaults;
3. apply explicit block-header overrides;
4. validate the resulting runtime and capabilities;
5. only then schedule lint or format execution.

For =typst=, the registry entry is equivalent to:

| Field     | Implicit value  | Meaning                                         |
|-----------+-----------------+-------------------------------------------------|
| =runtime= | =typst=         | select the registered Typst toolchain           |
| =lint=    | =command-stdin= | send the block body to the registered lint argv |
| =format=  | =command-stdin= | send the body to the registered formatter argv  |

Therefore the following block is complete:

#+begin_src org
#+begin_src typst
= A checked heading
#+end_src
#+end_src

It MUST behave as if the three effective headers were present.  Authors add a
header only to override or disable a default:

#+begin_src org
#+begin_src typst :lint no :format no
= Intentionally unchecked generated input
#+end_src
#+end_src

An explicit value such as =:format typstyle= names a registered formatter
binding; it is not a shell fragment.  Implementations MUST NOT evaluate header
values through a shell, split an arbitrary command string, interpolate
environment variables, or accept an executable outside the configured runtime
registry.

** Lint and fix state transitions

For each selected block, linting has these ordered outcomes:

| Condition                     | =orgize lint=                     | =orgize lint --fix=          |
|-------------------------------+-----------------------------------+------------------------------|
| lint process exits nonzero    | diagnostic, fail                  | diagnostic, fail             |
| formatter unavailable         | =formatter-unavailable=, fail     | same, no rewrite             |
| formatter output equals body  | pass                              | pass, no rewrite             |
| formatter output differs      | =format-drift=, fail, no mutation | AST body patch, then re-lint |
| output/timeout limit exceeded | typed failure                     | typed failure, no rewrite    |

The =--fix= transition is transactional at block granularity.  Orgize first
validates the complete formatter output, then constructs an AST patch against
the recorded Org snapshot and block-body digest.  Snapshot or digest drift
invalidates the patch.  A successful patch preserves the block's name,
language, explicit headers, indentation convention, and surrounding document.
It never writes an extracted =.typ= file.

The lint and format capabilities are independent even though both use stdin.
Lint diagnostics are authoritative for syntax validity.  Formatter output is
only a proposed source replacement and MUST pass lint after normalization
before =--fix= succeeds.

= Scope and artifact identity

This note is the mathematical explanation corresponding to
`packages/proofs/ASPProof/SearchLoopClauseFirst.lean`.

It explains the executable model for:

- `ASP-RFC-10.05-CFR-GOD-DECISION`,
- `ASP-RFC-10.05-BECA-STATES`,
- `ASP-RFC-10.05-CFR-GOD-GLOBAL-BUDGET`,
- `ASP-RFC-10.05-RPGE-CLOSED-WORLD`,
- `ASP-RFC-10.05-CFR-GOD-GRAPH-AUTHORITY`.

The Lean source is authoritative for checked derivations. This Typst projection
is explanatory and cannot establish implementation readiness by itself.

= Validation domain

Every reusable search fact is interpreted inside a validation domain

$ D = (s, p, sigma, pi), $

where $s$ is the source snapshot, $p$ the provider identity, $sigma$ the schema
identity, and $pi$ the policy identity.

Two bindings or cache entries are compatible only when all required domain
components agree. Provider drift and snapshot drift therefore change identity,
even when human-readable text is unchanged.

= Atomic evidence clauses

An evidence obligation is decomposed into atomic clauses

$ c = (o, q, b, D, kappa), $

where $o$ is the obligation, $q$ the predicate, $b$ the current binding, $D$ the
validation domain, and $kappa$ the closure requirement.

Endpoint overlap is not fact identity:

$ op("same_endpoint")(c_1, c_2) != op("same_fact")(c_1, c_2). $

The online path may use compact postings to bind a clause. Graph expansion is a
separate escalation step and is not required for every lexical or structural
lookup.

= Ordered clause classification

Naive state predicates may overlap. The model therefore classifies each clause
with explicit precedence:

1. sufficient;
2. posting action available;
3. discovery action available;
4. typed terminal failure.

The intended sufficient condition is

$ op("sufficient")(c) =
  op("valid")(c) ∧ op("covers")(c) ∧ op("admissible")(c). $

Classification precedence prevents the same clause from being simultaneously
reported as sufficient, actionable, fuzzy, and stalled.

= Admissibility, budget, and progress

Only actions whose preconditions and identity domain are valid are admitted.
The local progress property is

$ op("admitted")(c) != ∅ ⇒ op("next")(c) != "stalled". $

Zero budget cannot satisfy a mandatory action. It must produce a typed terminal
state rather than a false liveness claim:

$ B = 0 ∧ op("mandatory")(c) ⇒ op("terminal")(c) = "needs-budget". $

A positive fairness floor is meaningful only after the required budget is known
to be sufficient.

= Closed-world absence

A no-hit result is not evidence of absence by itself. Absence is derivable only
inside a complete and fresh scope:

$ op("no_hit")(c) ∧ op("complete")(op("scope")(c)) ∧ op("fresh")(D)
  ⇒ op("absent")(c). $

Without scope completeness or freshness, the only sound result is unknown or a
new search action.

= Closure evidence and rank

Ranking selects useful candidates; it does not discharge an evidence
obligation:

$ op("rank")(a) ∉ op("closure_evidence")(a). $

Thus a high-scoring item cannot replace source identity, selector validity,
scope coverage, provenance, or policy evidence.

= Graph escalation

Graph construction is on demand. It becomes mandatory when the clause requires:

- enumeration completeness,
- absence reasoning,
- a cross-namespace join,
- or another relation whose closure cannot be established from postings.

The escalation rule is independent of ranking:

$ op("mandatory_graph")(c) ⇒ op("escalate_graph")(c). $

No ranking function may disable a mandatory graph escalation.

= Cache identity

Reusable search state is keyed by content and validation authority:

$ K = H(x, s, p, sigma, pi). $

Omitting the provider, snapshot, schema, or policy component permits stale or
cross-authority cache reuse and is therefore unsound.

= Lean-discovered RFC repairs

The first executable proof bundle forced nine repairs:

1. endpoint overlap is not fact identity;
2. clause-state predicates require ordered classification;
3. zero budget requires a typed `needs-budget` result;
4. action identity includes the source snapshot;
5. no-hit requires complete scope and freshness before proving absence;
6. rank is not closure evidence;
7. selector drift blocks materialization;
8. mandatory graph escalation is independent of rank;
9. cache identity includes the provider.

= Trace semantics and bounded progress
The trace extension models a SearchLoop state as
$ S = (D, m, u, b, e, z), $
with validation domain $D$, remaining mandatory work $m$, unresolved work $u$,
budget $b$, closure evidence $e$, and status $z$.

The work measure is
$ W(S) = m + u. $

A productive step consumes exactly one work item:
$ W(S') + 1 = W(S). $

For a productive trace of length $n$:
$ n + W(S_n) = W(S_0), $
so
$ n <= W(S_0). $

The general progress proposition must include typed termination:
$ op("Step")(S, S') =>
  W(S') < W(S) or op("TypedTerminal")(S'). $

Lean rejects three weaker formulations:
- $m = 0$ does not imply safe closure without valid closure evidence;
- $m <= b$ does not prove sufficient budget when unresolved work $u > 0$;
- a `needs-budget` transition can preserve $W$ while still making semantic
  progress by exposing a typed terminal condition.

Complete-trace closure safety also requires an admitted initial-state invariant.
It cannot be derived for an arbitrary state that merely claims to be closed.

Lean emits `asp.lean-proof-audit.v1` with theorem names, elaborated types, RFC

AXLE consumes the JSON document under an explicit admission policy. It rejects

= Admitted-result merge algebra

A transport result is $(c, d, o)$: clause identity, validation domain, and
outcome. It is admitted before merge. A domain mismatch is typed protocol
control data, not an outcome:

$ d' != d => op("admit")(c, d', o) =
  op("conflict")("validation-domain"). $

For a fixed admitted domain $d$, the normalized ledger is

$ L_d : C arrow.r O. $

with outcome information order

$ op("pending") <= op("discharged") <= op("contradiction"). $

The per-clause reducer is a commutative, associative, and idempotent join.
Therefore admitted updates commute, replay is idempotent, and every finite
permutation has the same reduction:

$ op("Perm")(x_s, y_s) =>
  op("mergeMany")(L_d, x_s) = op("mergeMany")(L_d, y_s). $

Lean also constructs the last-write-wins counterexample:

$ op("LWW")(op("pending"), op("contradiction")) !=
  op("LWW")(op("contradiction"), op("pending")). $

Thus arrival order may remain diagnostic metadata, but it cannot determine the
normalized semantic ledger.
= Proof status

The Clause-first base bundle contains twenty named theorems. The trace extension
adds twelve audited theorems covering trace safety, bounded progress, typed
progress, and counterexamples. The merge extension adds thirteen audited
theorems covering merge algebra, finite permutation confluence, typed
conflicts, ledger independence, and the last-write-wins counterexample. The
generated JSON records the exact split between axiom-free and axiom-dependent

This is not full protocol closure. Open theorem families include trace-level
safety and liveness, side-effect confluence, cache invalidation,

* Receipt requirements
:PROPERTIES:
:ID: ASP-RFC-10.05-CFR-MATH-RECEIPT
:END:

A conforming Org-Babel Typst receipt MUST record:

- owning Org path and block selector;
- Org source snapshot and block body digest;
- Typst version and command identity;
- exit status and normalized diagnostics;
- inferred or explicit runtime, lint, and format policies;
- formatter identity and whether format drift was detected;
- AST patch identity when =orgize lint --fix= rewrites the block;
- the matching Lean source digest and proof receipt identity.

The receipt MUST fail closed if the selected block is missing, ambiguous, stale,
or no longer owned by the recorded Org snapshot.
