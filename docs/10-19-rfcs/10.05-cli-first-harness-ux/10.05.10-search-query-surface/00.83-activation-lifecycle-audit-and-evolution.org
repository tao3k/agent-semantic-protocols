#+title: RFC 10.05.83 — Activation Lifecycle Audit and Evolution
#+startup: overview

* Status

Draft foundational redesign.  This RFC pauses incremental cache-rejoin work and
audits the activation control plane itself.

* Executive conclusion

The current architecture treats activation too much like a cached status and
repair too much like an exceptional command path.  That design permits a
declared =Ready= state to diverge from the live host, transport, installed
binary, dispatch ledger, and current authority revision.

The replacement design makes =Ready= a derived, expiring proof over five
independent evidence domains:

1. durable activation intent;
2. live host and transport observation;
3. runtime identity and schema compatibility;
4. dispatch-ledger recoverability;
5. observation freshness.

Repair and evolution become first-class, proof-gated lifecycle transitions.
They are not hidden side effects of bootstrap or sync.

* Evidence motivating the redesign

The lifecycle audit recovered the following failure classes:

- an activation file can be missing while the hook requires that file before
  allowing the normal recovery path;
- registry status can remain =ready= or =routable= after the native child is
  absent;
- a hidden or idle canonical child can be reachable while replacement logic
  sees only an absent registry entry;
- same-child Resume can succeed without a new =SubagentStart= event, leaving
  event-only transport binding stale;
- a missing terminal dispatch receipt makes resend versus accept-complete
  ambiguous;
- installed ASP identity can drift across login shell, repository environment,
  and the path recorded by activation;
- a one-time Ready receipt can remain cached after the host or authority
  revision changes.

The current live artifact check found:

#+begin_example
login-shell ASP: /opt/homebrew/bin/asp
previous activation entry: ~/.local/bin/asp
current ~/.local/bin/asp: missing or not executable
repository direnv ASP: not present
#+end_example

Parser-owned repository discovery was also resident-routed and could not run
without the activation lifecycle it was intended to audit.  This is a
control-plane dependency cycle, not authorization to use raw source fallback.

* Architectural bugs

** Bug A — Ready is stored rather than derived

A phase label or cached registry record can say =Ready= while the host target is
absent, transport is unbound, runtime identity has drifted, or a dispatch
receipt is missing.

** Bug B — Recovery depends on the failed artifact

If reading activation is a prerequisite for every repair command, loss or
corruption of activation removes the route needed to repair activation.

** Bug C — Absence is inferred from one observer

Registry absence, host-tree absence, transport failure, and canonical-target
unreachability are different observations.  None alone authorizes replacement.

** Bug D — Rebind authority is event-specific

Using only =SubagentStart= as binding authority makes idle Resume unrecoverable,
because same-child acknowledgement can occur without another start event.

** Bug E — Dispatch recovery is not part of readiness

Missing claimed or terminal receipt evidence creates an exactly-once ambiguity.
The state must be quarantined rather than presented as Ready.

** Bug F — Evolution lacks a trusted transaction

Binary, schema, config, provider, and activation generations can drift
independently.  An update without an expected generation, compatibility
witness, canonical-identity preservation, and rollback checkpoint is not a
safe evolution.

** Bug G — Live evidence has no freshness boundary

Even a genuinely live and bound observation becomes stale after the authority
revision changes.  Operational readiness at revision =r= does not imply trusted
readiness at revision =r + 1=.

* Redesigned lifecycle object

Activation MUST be represented as a proof-carrying aggregate, not one mutable
status file:

| Component | Authority | Required evidence |
|-
| Intent | activation store | canonical identity, desired generation, schema, binary/config digests |
| Host observation | native host | canonical target reachability and physical generation |
| Transport binding | native dispatch | acknowledged routable target |
| Dispatch ledger | durable ledger | claimed or terminal receipt state |
| Repair capability | independent recovery authority | executable identity, scope, expiry, recovery generation |
| Evolution plan | evolution authority | expected generation, target identity, compatibility, rollback |
| Freshness | control-plane revision | observation revision equals current authority revision |

=Ready= MUST be a query result derived from these components.  Persisted phase
is diagnostic intent, not readiness authority.

* Normative clauses

** ASP-RFC-10.05-ALAE-READY — Ready is a fresh derived proof

Trusted Ready MUST require readable activation, durable registry binding, live
host reachability, acknowledged transport binding, matching runtime identity,
recoverable dispatch evidence, and a current observation revision.

** ASP-RFC-10.05-ALAE-REPAIR — Repair has an independent capability path

Repair tooling and authorization MUST remain available when activation is
missing or unreadable.  The capability MUST be narrowly scoped, expiring,
generation-bound, and independent of the failed activation artifact.

** ASP-RFC-10.05-ALAE-REPLACEMENT — Replacement requires composite absence

Replacement MUST require a completed host audit plus evidence that the
canonical child is unreachable and transport-unbound.  Registry absence alone
MUST NOT authorize replacement.

** ASP-RFC-10.05-ALAE-REBIND — Same-child acknowledgement can rebind transport

A canonical live child with an authenticated dispatch/follow-up
acknowledgement MAY restore transport binding without a new =SubagentStart=.
The acknowledgement MUST bind canonical identity and physical generation.

** ASP-RFC-10.05-ALAE-DISPATCH — Receipt ambiguity quarantines activation

A dispatch that was attempted but lacks durable claimed or terminal evidence
MUST move activation to =degraded= or =repairing=.  It MUST NOT be blindly
resent or accepted complete.

** ASP-RFC-10.05-ALAE-IDENTITY — Runtime identity is multi-dimensional

Readiness MUST compare generation, schema version, binary digest, configuration
digest, and provider-set digest.  PATH resolution alone is not identity.

** ASP-RFC-10.05-ALAE-EVOLUTION — Evolution is proof-gated and monotone

Evolution MUST require the observed source generation, a strictly newer target
generation, compatibility evidence, canonical-identity preservation, and a
rollback checkpoint.

** ASP-RFC-10.05-ALAE-FRESHNESS — Observations expire by authority revision

Live observations MUST be tagged with the authority revision at which they were
obtained.  A revision change invalidates Ready until the required observations
are refreshed.

* Lifecycle state machine

#+begin_example
inactive -> activating -> ready
                    \-> degraded -> repairing -> activating
ready|degraded -> evolving -> activating
inactive|degraded|ready -> retired
#+end_example

No transition enters =ready= directly.  =ready= is emitted only after the
derived TrustedReady predicate succeeds.

* Executable mathematical model

#+name: activation-lifecycle-audit-model
#+begin_src typst
#let runtime-matches(value) = (
  value.declared-generation == value.observed-generation
  and value.declared-schema == value.runtime-schema
  and value.declared-binary == value.observed-binary
)
#let dispatch-recoverable(value) = value.dispatch != "missing-after-dispatch"
#let operational-ready(value) = (
  value.phase == "ready"
  and value.activation-readable
  and value.registry-bound
  and value.host-reachable
  and value.transport-bound
  and runtime-matches(value)
  and dispatch-recoverable(value)
)
#let trusted-ready(value, observed-revision, authority-revision) = (
  operational-ready(value)
  and observed-revision == authority-revision
)
#let can-repair(value) = (
  value.repair-tool
  and (value.activation-readable or value.emergency-capability)
)
#let safe-replacement(value) = (
  value.host-audit-complete
  and not value.host-reachable
  and not value.transport-bound
)
#let can-evolve(value, plan) = (
  plan.expected-generation == value.observed-generation
  and value.observed-generation < plan.target-generation
  and plan.compatibility
  and plan.rollback
  and plan.preserves-identity
)
#let base = (
  phase: "ready",
  activation-readable: true,
  registry-bound: true,
  host-reachable: true,
  transport-bound: true,
  repair-tool: true,
  emergency-capability: false,
  host-audit-complete: true,
  dispatch: "terminal",
  declared-generation: 4,
  observed-generation: 4,
  declared-schema: 1,
  runtime-schema: 1,
  declared-binary: 10,
  observed-binary: 10,
)
#assert(operational-ready(base))
#assert(not trusted-ready(base, 4, 5))
#assert(not operational-ready(base + (host-reachable: false)))
#assert(not operational-ready(base + (dispatch: "missing-after-dispatch")))
#assert(not operational-ready(base + (observed-binary: 11)))
#let broken-activation = base + (
  phase: "degraded",
  activation-readable: false,
  emergency-capability: false,
)
#assert(not can-repair(broken-activation))
#assert(not safe-replacement(base + (
  phase: "degraded",
  host-audit-complete: false,
)))
#let safe-plan = (
  expected-generation: 4,
  target-generation: 5,
  compatibility: true,
  rollback: true,
  preserves-identity: true,
)
#assert(can-evolve(base, safe-plan))
#assert(not can-evolve(base, safe-plan + (target-generation: 3)))
#assert(not can-evolve(base, safe-plan + (rollback: false)))
"ok"
#+end_src

#+name: activation-lifecycle-audit-proposition
#+begin_src typst
#let ready = $upright("TrustedReady")(a, r) arrow.r.double
  upright("LiveHost")(a)
  and upright("BoundTransport")(a)
  and upright("RuntimeMatches")(a)
  and upright("DispatchRecoverable")(a)
  and upright("ObservedAt")(a) = r$
#let evolution = $upright("CanEvolve")(a, p) arrow.r.double
  upright("generation")(a) < upright("target")(p)
  and upright("Compatible")(p)
  and upright("Rollback")(p)$
#assert(type(ready) == content)
#assert(type(evolution) == content)
"ok"

* Repair and evolution protocol

Repair MUST produce a new generation rather than editing the current activation
in place:

1. capture the failed generation and authority revision;
2. quarantine ambiguous dispatches;
3. audit host and canonical target;
4. obtain an independent repair capability;
5. write a candidate generation;
6. validate compatibility and rollback;
7. atomically publish the candidate as desired intent;
8. reacquire live observations;
9. derive TrustedReady;
10. retire the previous generation after the rollback window.

Evolution uses the same transaction with an additional compatibility witness.
Repair is therefore a constrained evolution from degraded state, not an
unstructured mutation.

* Remaining proof boundaries

This RFC provides the foundational safety model, but the following require
separate proofs:

- liveness: a repairable degraded activation eventually leaves repair;
- capability revocation and expiry;
- atomic publication of candidate generations;
- multi-writer repair one-winner behavior;
- rollback after partial external side effects;
- bounded retention and garbage collection of retired generations;
- policy for dispatches whose terminal receipt can never be recovered.
