#+title: RFC 10.05.90 — Multi-Role Lifecycle Authority
#+subtitle: Generic role isolation, quotas, termination linearization, and shortest safe recovery
#+language: en
#+options: toc:3 num:t

* Status

Draft Lean-backed generalization of RFC 10.05.89.

The lifecycle protocol is role-generic. =asp-explore= is a configured default
lane, not a lifecycle constant.

* Role-local authority

#+name: multi-role-lifecycle-authority
#+begin_src typst
$ K = (i_r, i_"role", g_p) $

$ A = (
  i_r,
  i_"role",
  r_a,
  g_p,
  n_"role",
  n_"total",
  q_"role",
  q_"total",
) $

$ "CanClaimRole"(A, P)
:=
"identity-bound"
and r_P = r_a
and g_P = g_p
and n_"role" < q_"role"
and n_"total" < q_"total"
and k_P != 0 $

"ok"
#+end_src

Instance identity includes root session, role, and physical generation.
Different roles therefore cannot share an instance key even when their
generation numbers are equal.

* Quota safety

Both quota dimensions are required:

- =maxPerRole= prevents one role from monopolizing a root session;
- =maxTotal= bounds the complete resident tree.

#+name: multi-role-lifecycle-quota
#+begin_src typst
$ n_"role" >= q_"role"
arrow.r.double
not "CanClaimRole"(A, P) $

$ n_"total" >= q_"total"
arrow.r.double
not "CanClaimRole"(A, P) $

"ok"
#+end_src

A legacy claim predicate that checks only identity, generation, and revision
admits new children after quota exhaustion. Agent automation makes this an
architectural resource leak rather than a rare operator mistake.

* Termination versus dispatch

Dispatch and termination can both be admissible on the same immutable
snapshot. The authority revision selects the winner:

#+name: multi-role-termination-race
#+begin_src typst
$ "CanDispatch"(A_r, I, rho)
and "CanTerminate"(A_r, I, tau) $

$ "begin-termination"(A_r, I, tau) = (A_(r + 1), I_"terminating") $

$ not "CanDispatch"(A_(r + 1), I_"terminating", rho_r) $

"ok"
#+end_src

Quota is released only after durable termination completion. Beginning
termination does not immediately free capacity.

* Replacement target isolation

A replacement generation MUST receive a new message target. Reusing the old
target allows delayed messages to cross the generation boundary.

#+name: multi-role-target-replacement
#+begin_src typst
$ "CanReplaceTarget"(I_"terminated", i_m')
:=
i_m' != 0 and i_m' != i_m $

$ i_m' = i_m
arrow.r.double
not "CanReplaceTarget"(I_"terminated", i_m') $

"ok"
#+end_src

* Shortest safe recovery

The durable materialization phase determines the unresolved obligation
frontier:

#+begin_src typst
#table(

  [configured-absent], [5],
  [claimed], [4],
  [spawned], [3],
  [bound], [2],
  [active], [1],
)

$ "SafePath"(p, C)
:=
h(C) >= h_"required"(p) $

$ "SafePath"("spawned", C)
arrow.r.double
3 <= h(C) $

#table(
  columns: 3,
  [Metric], [Spawned frontier], [Restart loop],
  [Graph hops], [3], [7],
  [Agent/LLM rounds], [1], [4],
  [Exposed tokens], [240], [1100],

"ok"
#+end_src

The lower bound is semantic: each hop discharges one unresolved obligation.
Skipping binding, heartbeat, or dispatch evidence is not an optimization.

* Normative requirements

** ASP-RFC-10.05-MRLA-GENERIC

Lifecycle state and actions MUST be parameterized by configured role identity.
No default role name MAY be encoded as a protocol constant.

** ASP-RFC-10.05-MRLA-KEY

Resident instance keys MUST bind root session, role, and physical generation.

** ASP-RFC-10.05-MRLA-ROLE-QUOTA

Materialization admission MUST enforce a per-root, per-role active-instance
quota.

** ASP-RFC-10.05-MRLA-TOTAL-QUOTA

Materialization admission MUST enforce a total active-resident quota for the
root session.

** ASP-RFC-10.05-MRLA-CLAIM

Claim commit MUST increment authority revision, role generation, role count,
and total count in one linearized transition.

** ASP-RFC-10.05-MRLA-TERMINATION

Termination start MUST increment authority revision and invalidate dispatch
receipts from the previous snapshot.

** ASP-RFC-10.05-MRLA-RELEASE

Quota MUST be released only after durable termination completion.

** ASP-RFC-10.05-MRLA-TARGET

A replacement generation MUST NOT reuse the terminated generation's message
target.

** ASP-RFC-10.05-MRLA-FRONTIER

Recovery MUST resume from the latest durable phase and MUST NOT restart already
completed obligations.

** ASP-RFC-10.05-MRLA-COST

Recovery receipts MUST report graph hops, agent/LLM interaction rounds, and
exposed tokens. A shortest-path claim MUST include a semantic lower bound.

** ASP-RFC-10.05-MRLA-CALIBRATION

Rust implementation conformance remains unverified until parser-owned exact
selectors and quota/termination race tests are available.

* Lean audit

The executable model is:

- =packages/proofs/ASPProof/MultiRoleLifecycleAuthority.lean=

It proves:

- generic role claim admission;
- per-role and total quota rejection;
- the legacy no-quota predicate admits a resource leak;
- different roles produce distinct instance keys;
- claim commit advances generation, revision, and both counts;
- dispatch and termination are admissible on the old snapshot;
- termination linearization invalidates old dispatch;
- completion releases quota;
- replacement cannot reuse the old target;
- a fresh replacement target is admissible;
- the spawned frontier path is safe and graph-shortest; and
- frontier recovery strictly reduces rounds and token exposure.

* Architectural defects exposed

** Generic lifecycle without quotas is incomplete

Exactly-once materialization prevents duplicate winners for one head. It does
not prevent an unbounded sequence of valid new residents.

** Termination is an authority transaction

Killing a process first and updating registry state later leaves a window where
dispatch remains authorized to a dying child.

** Quota release cannot follow intent

Releasing capacity at termination start permits a replacement before the old
child and target are durably retired.

** Restart loops discard durable progress

Returning to bootstrap or materialization after =spawned= repeats completed
work, increases graph distance and token cost, and can duplicate side effects.

* Rust implementation audit boundary

Parser-owned Rust discovery remains blocked by:

- invalid activation field =workspaceScope=;
- unreachable workspace-owner endpoint; and
- missing active provider generation.

After recovery, exact audit targets are generic configured-role lookup,
per-role/total quota enforcement, termination CAS, quota release timing,
message-target replacement, and phase-aware recovery routing.

* Next proof boundary

The next refinement should model resident-tree hierarchy, parent termination
cascades, orphan adoption, subtree quotas, and DAG-wide dispatch cancellation.
