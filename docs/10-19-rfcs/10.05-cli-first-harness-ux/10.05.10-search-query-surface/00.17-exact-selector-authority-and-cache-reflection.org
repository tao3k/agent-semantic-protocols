#+title: Exact Selector Authority and Cache Reflection

* Status

This clause defines the non-legacy exact-selector execution boundary for the
10.05 search and query surface.

* Authority

An explicit owner path plus structural selector is a complete parser-owned
request.  The live language provider is the authority for resolving and
projecting that request.  The CLI MUST resolve the verified global provider
catalog leaf and dispatch the typed stdin request before workspace activation,
source-index lookup, or database access.

The provider request MUST bind the language, provider, parser identity,
query-pack identity, owner digest, generation digest, projection kind, and
source bytes.  The provider response MUST be rejected when any of those
identities drift.

* Cache reflection

A resident generation or persistent index is an optional projection of live
provider authority.  It is not an alternative authority and MUST NOT veto a
live exact request.

Cache handling has only these admissible outcomes:

1. =typed-hit=: the cached projection has complete identity and live owner
   digest equality.
2. =typed-miss=: no complete matching projection exists; the cache contributes
   no answer.
3. =typed-failure=: transport, schema, identity, or persistence validation
   failed; the failure remains observable and MUST NOT be reflected into a
   generic fallback.

Implementations MUST NOT catch arbitrary errors and reinterpret them as
unavailability.  Any cache optimization must expose a closed typed state model
and tests for every state before it may precede the live provider path.

* Legacy removal

=--code= and =--names-only= are not aliases for exact projections.  Exact
queries accept only =--projection source= or
=--projection callable-skeleton=.  Removed resident DB owners, checkpoint
helpers, multiprocess writers, and their tests MUST NOT remain as dormant
fallback paths.

* Performance contract

The explicit exact path MUST avoid workspace project-resolution and activation.
Its hot work is limited to catalog leaf validation, one bounded owner read, one
typed provider request, and response validation.  Receipts MUST separately
measure catalog validation, owner read, provider execution, and output write so
that a cache or daemon optimization cannot hide latency by changing authority.
