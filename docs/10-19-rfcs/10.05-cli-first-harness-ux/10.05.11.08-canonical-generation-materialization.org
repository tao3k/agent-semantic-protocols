#+title: Runtime Server Canonical Generation Materialization
#+startup: overview

* Status

This RFC defines the v1 publication boundary between the durable Turso source
index and the Runtime Server query data plane.

* Ownership

- Turso is the durable canonical generation and MVCC authority.
- The global Tokio Runtime Server owns one workspace entry and one writer lane
  per workspace identity.
- MemoryBackend is the primary search/query data plane for the admitted active
  generation.
- memmap2 publishes an immutable generation snapshot and atomically switches
  the active epoch pointer after validation.
- A live or untracked owner is an overlay on an admitted canonical generation.
  It is never evidence of a complete generation by itself.

* Canonical materialization contract

=runtime-server-workspace-canonical-materialization.v1= is required when
=CommitSourceIndexGeneration= crosses the Runtime Server data-plane transport.
The envelope binds:

- the canonical workspace identity;
- the complete source snapshot root digest;
- the complete source-index import digest;
- exact file count;
- =rootDepth=[1,0]=;
- every owner byte sequence and every exact selector byte range.

The Runtime Server validates the complete envelope before durable publication.
An owner count different from the committed file count, a snapshot/import
digest drift, an invalid selector range, or a workspace identity mismatch is a
terminal admission failure.

* Atomic publication

The workspace writer lane performs the following ordered transition:

1. validate and build the next immutable MemoryBackend without changing the
   active epoch;
2. commit the matching source-index generation through the workspace's Turso
   write transaction;
3. serialize and validate the next mmap generation segment;
4. atomically switch the active-generation pointer;
5. publish the new in-process lease.

Readers holding the old =Arc= or mmap lease continue reading the old
generation. No reader observes a partially built generation. If steps 2-4
fail, the old generation remains active and the operation returns a typed
failure receipt.

* Overlay admission

=PublishRuntimeOwner= requires an active canonical generation with the same
workspace identity. Missing canonical state fails closed. The Runtime Server
must not synthesize =Ready=, =rootDepth=[1,0]=, or epoch 1 from one provider
owner.

* Performance gates

Fixtures must cover multiple workspaces, sessions, and concurrent readers while
one writer publishes the next generation. Warm exact projection requires zero:

- workspace canonicalizations;
- Turso opens;
- schema bootstraps;
- provider process spawns;
- manifest or activation reads;
- file-lock probes;
- control-socket round trips.

The gate also proves that old readers retain their old epoch and bytes after
the active pointer changes.

* Global daemon reconciliation

There is exactly one installed global daemon:
=dev.tao3k.agent-semantic-protocols.asp-runtime-server=. The former
=dev.tao3k.agent-semantic-protocols.asp-resident= LaunchAgent is Legacy and
must be retired by Global reconciliation. It must not be restarted, repaired,
or installed alongside Runtime Server.

Reconciliation fails its performance gate if a removed service enters a
keepalive restart loop. The installed receipt records the retired service
labels and proves that Runtime Server status remains responsive after
retirement. Agent-session routing is a Runtime Server namespace keyed by
workspace/session identity, not a second daemon process.
