#+TITLE: 10.05.68 Language Projection Generation Transaction v1
#+STATUS: Draft

* Purpose

Define the single language-neutral path from parser-owned language projection
facts to =asp.active-workspace-generation.v1=.  This contract applies to every
provider registered in the Global provider catalog; Rust is not a special
execution path.

* Responsibility boundary

A language harness parses one owner and publishes =semantic-language-projection.v1=.
For each source it publishes the content digest.  For each canonical item it
publishes one or more typed projections containing:

- canonical selector;
- projection kind (=source= or =callable-skeleton=);
- inclusive source byte bounds;
- normalized parser-facts digest;
- projection digest and UTF-8 projection payload.

The harness MUST NOT invent the workspace Merkle root, owner inclusion path, or
active generation digest.  Those identities do not exist until ASP admits the
complete provider-owned source envelope.

ASP Search owns the second phase.  Inside one generation transaction it:

1. validates every provider projection against the shared v1 schema;
2. verifies source digests and projection byte bounds against the captured
   source snapshot;
3. computes the provider workspace root and owner inclusion proofs;
4. materializes =ExactSelectorMaterializationProofV1= records;
5. publishes the source envelope, topology, exact-selector fixture, and active
   generation record atomically;
6. swaps the resident generation only after every committed leaf verifies.

No importer may require a final =materializationProof= in raw harness output.
No query may fabricate parser, query-pack, workspace, or generation digests.

* Registry-wide contract

The acceptance matrix is derived from the Provider Registry.  Every registered
language that declares structural selectors must pass the same projection and
generation gates.  The current registry includes Rust, TypeScript, Python,
Julia, Gerbil Scheme, Org, and Markdown.

Provider-private native exact execution may serve a cold live-overlay miss only
when the Registry explicitly declares that capability.  It is not a substitute
for generation publication and is never the warm query path.

* Cold and warm execution

Cold search may perform parser work and one atomic generation publication.  It
must not call =asp sync=, repair activation, reopen the same workspace database
per owner, or acquire a cross-workspace global lock.

Warm search and exact query resolve:

#+begin_example
workspace identity
  -> resident workspace session
  -> active generation
  -> load-once exact fixture
  -> selector projection bytes + typed receipt
#+end_example

The warm receipt must report zero provider subprocesses, zero database opens,
zero manifest writes, zero activation writes, and zero source scans.

* Concurrency

One workspace owns a concurrent read lease pool and one serialized writer lane.
Concurrent cold callers share one generation cell and observe the same committed
generation.  Different workspaces never share a database lock or writer lane.
Failed or incomplete generations are never installed as active.

* Required gates

- Registry-driven schema validation for every registered language.
- Missing source digest, projection, or parser fact fails before publication.
- Owner count, selector count, leaf count, and root digest commit together.
- Moved owners commit the new path and old-path tombstone in one transaction.
- Concurrent first readers publish exactly one generation.
- Warm exact resolution stays within the configured sub-millisecond fixture
  budget and performs no provider or persistence work.
- A fresh workspace with no active generation can complete =search prime= and
  owner discovery without entering an active-generation bootstrap cycle.
