#+title: Provider Runtime Self-Repair

* Status

Required runtime contract.

* Problem

A managed hook activation can become unreadable after the ASP runtime and an
installed language provider move to a new shared contract at different times.
Fail-closed enforcement remains mandatory, but an unreadable generated
activation must not permanently prevent the runtime from repairing its owning
provider artifact.

Treating an old provider response as a second accepted wire shape is not
self-repair.  It is an unbounded compatibility fallback and is forbidden.

* Owner

ASP owns recovery admission and atomic publication.  A language harness owns
its package-manager parser and build artifact.  The provider install receipt
must bind:

- language and provider identity;
- provider source checkout identity;
- source revision and dirty-tree digest;
- build recipe identity and digest;
- expected binary basename;
- installed artifact and metadata digests;
- provider manifest digest;
- shared contract closure digest.

No project activation, PATH probe, or guessed repository layout may replace
that receipt.

* State machine

#+begin_src text
activation-load
  -> valid: continue
  -> invalid-generated-artifact:
       hold fail-closed enforcement
       -> verify provider install receipt
       -> verify source/build identity
       -> execute receipt-owned rebuild
       -> validate provider contract probe
       -> atomically switch runtime artifact
       -> regenerate activation
       -> validate activation and policy coverage
       -> continue
#+end_src

Any failed transition leaves the previous runtime artifact untouched and emits
a typed failure receipt.  The hook must not admit ordinary tool execution
until a complete repaired activation validates.

* Recovery admission

The recovery lane is internal to pre-tool activation loading.  It is not a
general shell exception and exposes no arbitrary command string.  Only the
exact build recipe committed by the provider install receipt may execute.

The runtime must reject recovery when:

- the source checkout identity differs from the receipt;
- the build recipe or manifest digest differs;
- the source tree contains an uncommitted delta not covered by the receipt;
- the rebuilt artifact fails its provider contract probe;
- the rebuilt artifact still emits a legacy project-resolution shape;
- activation policy coverage becomes smaller without an explicit policy
  receipt.

* Reflection receipt

Every attempt emits =asp.provider-runtime-self-repair-receipt.v1= with the
trigger, verified identities, artifact transition, contract probe, activation
publication result, enforcement state, timings, and failure details.

The invariants are:

- =enforcementState= is always =fail-closed= during repair;
- =directSourceReads= is zero;
- =legacyAdapters= is zero;
- =atomicSwitch= is true for a successful repair;
- =activationRegenerated= and =policyCoverageValidated= are true before the
  hook resumes ordinary tool execution.

* Performance

The unchanged path performs only receipt and digest-generation checks and must
remain millisecond-class.  Rebuild work runs only after verified artifact or
contract drift.  Concurrent sessions for the same workspace join one repair
operation; they do not start duplicate provider builds.
