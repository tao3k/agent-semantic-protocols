#+title: RFC 10.15.02.02 — Agent Session Lifecycle Crash Recovery

* Status
Focused formal verification is complete. This RFC refines [[file:10.15.02.01-agent-session-transactional-generation-lifecycle.org][RFC 10.15.02.01]]. The Lean source, compiled module, direct audit, and runner pass; all 23 theorem declarations are axiom-free. No Rust implementation is authorized in this session.

* Problem
A durable lifecycle intent crosses a non-transactional host boundary. The host may accept retirement, path release, typed spawn, binding, or command execution before the local receipt and delivered CAS become durable. Retrying with a new key can duplicate a child or command effect. Treating absence of a local receipt as host rejection is unsound.

Recovery therefore preserves the original intent identity and distinguishes five facts: intent durable, host acceptance observed, receipt indexed, local state committed, and terminal command receipt present.

* Intent-indexed host receipt
A receipt is admissible only when slot, generation, intent key, kind, payload digest, and accepted state match the durable intent. Host idempotence means two accepted receipts for the same intent identify the same effect.

* Crash-window recovery law
Recovery never invents a second intent. Accepted-without-receipt persists the indexed receipt. Receipt-without-CAS commits the kind-specific CAS. Already committed state is idempotent. Missing durable intent blocks rather than inferring authority.

#+name: agent-session-crash-window-recovery
#+begin_src typst
#let Recover(k, s) = $upright("classifyRecovery")(k, s)$
$
  Recover(upright("retire"), upright("AcceptedNoReceipt"))
    = upright("PersistIndexedReceipt").
$
$
  Recover(upright("release"), upright("ReceiptNoCAS"))
    = upright("CommitReleasedCAS").
$
$
  Recover(upright("spawn"), upright("StartReceiptNoBinding"))
    = upright("CommitBindingCAS").
$
#+end_src

* Bounded uncertainty law
When host acceptance is unknown, recovery polls by the same stable intent key. Each poll consumes budget. Exhaustion yields =BlockedPollBudget=, not another unbounded repair loop.

#+name: agent-session-crash-bounded-poll
#+begin_src typst
#let Poll(b, n) = $upright("PollStep")(b, n)$
#let Recover(s) = $upright("classifyRecovery")(s)$
$ forall b, n, Poll(b, n) => n < b. $
$ not exists b, Poll(b, b). $
$ Recover(upright("UnknownAcceptanceBudgetZero")) = upright("BlockedPollBudget"). $
#+end_src

* Dispatch completion law
Dispatch identity belongs to the logical slot, not the delivery generation. A terminal completion from the old generation wins even if replacement binding has completed. Only an orphan with no terminal receipt may replay under the new verified binding, using the same stable dispatch key.

#+name: agent-session-crash-dispatch-completion
#+begin_src typst
#let Complete(d, r) = $upright("ValidDispatchCompletion")(d, r)$
#let Key(x) = $upright("dispatchKey")(x)$
#let Digest(x) = $upright("commandDigest")(x)$
$
  forall d, r,
  Complete(d, r) => Key(r) = Key(d) and Digest(r) = Digest(d).
$
$
  upright("TerminalExists") => upright("ReturnStoredTerminal")
  and not upright("ReplayDispatch").
$
#+end_src

* Lean-discovered corrections
1. Receipt absence is not host rejection.
2. Recovery must bind intent key, generation, kind, and payload digest.
3. Two receipts for one idempotent host intent must identify one effect.
4. Missing durable intent is a hard authority failure.
5. Polling is safe only with a decreasing budget and explicit blocked outcome.
6. Committed recovery transitions admit neither self-loops nor two-cycles.
7. Terminal command completion outranks replacement replay regardless of delivery generation.
