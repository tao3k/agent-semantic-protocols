* One-sentence summary

The ASP Hook is a local, compiled, platform-adapted policy evaluator: it
normalizes a Host invocation, classifies it against one immutable policy and
provider-projection bundle, and emits one typed decision without resolving or
executing providers and without contacting the Runtime Server.

* Normative ownership

The Hook boundary is split into four source-owned layers:

#+begin_example
Host event
  -> installed Host adapter and fixed Plugin payload
  -> Hook Action IR normalization
  -> compiled policy + provider projection
  -> one typed Hook decision
#+end_example

- The Host owns whether and how an invocation is delivered.
- The installed Plugin owns its fixed =hooks.json= and executable adapter.
- =agent-semantic-hook= owns normalization, matching, and decision rendering.
- =config.toml= owns declarative rules and language/document projections.
- the ASP Runtime owns provider activation, execution, Search/Query data, and
  generation publication.

Hook policy compilation and provider execution are deliberately disjoint.
Provider manifests, per-workspace Hook activation documents, provider route
tables, static provider command templates, and Runtime executables MUST NOT be
loaded by Hook classification. A Hook decision may name a registered
=languageId= and =providerId=, but those values are policy identities rather
than proof that a provider process is installed or active.

The prior =HookRoutes=, =HookRouteBindings=, =HookActivation=,
=ActivatedProvider=, and =materialize_provider_routes= Rust surfaces are
removed. The versioned JSON schemas that described historical wire artifacts
remain immutable archive contracts; they are not current Hook runtime inputs
and MUST NOT be used to reconstruct a compatibility path.

* Executable surfaces

Production Host events enter the standalone executable:

#+begin_src text
asp-hook pre-tool --client codex
asp-hook pre-tool --client claude
#+end_src

The public =asp= Client owns control-plane administration. The installed
=asp-hook-exec= adapter resolves the active Runtime artifact slot for
=runtime/bin/asp-hook= and performs one =exec=. It MUST NOT insert an =asp hook=
subcommand, infer a socket, start a Runtime Server, or repair project policy.

The production Codex transport is exactly one enabled Plugin Hook bundle.
Native inline =~/.codex/config.toml= Hook injection is an explicit debug/test
mode and MUST NOT coexist with the production Plugin mode. Rebuilding the ASP
binary, provider binaries, or Runtime Server does not authorize rewriting
Plugin trust or reinstalling an unchanged Plugin payload.

* Compiled policy projection

The managed Hook configuration is compiled into immutable decision shards.
Each provider projection contains only policy-classification facts:

#+begin_src text
languageId
providerId
packageRoots[]
sourceExtensions[]
configFiles[]
policy.directSourceRead
policy.bulkSourceDump
policy.rawSourceSearch
policy.agentSearchJson
#+end_src

There is one in-memory collection: =HookRuntime.policy_providers=. There is no
secondary activated-provider collection and no fallback from policy projection
to static routes. Config compilation validates every projection identity
against the registered language/provider catalog before publication.

The catalog establishes identity only. It does not expose a provider method
invocation, provider kind fallback, or a materialized route. Runtime provider
capability DTOs belong to =agent-semantic-provider-protocol=, not to Hook.

* Normalized invocation

Hook adapters normalize platform payloads into one Action IR before policy
matching. The IR keeps independent axes for:

- =HostInvocation=: the Host tool identity and envelope category;
- =SemanticCapability=: read, edit, search, enumerate, execute, or lifecycle;
- subjects: exact paths, path patterns, selectors, structured documents, and
  workspace mutation targets;
- parsed shell stages and wrapper depth;
- platform event and agent/session facts.

Semantic capability MUST NOT be copied from the Host tool name. A shell, MCP,
nested-tool, or native-read envelope may express the same semantic read. An
unobserved Host event produces no Action IR and no decision receipt; it is not
a synthetic allow or deny.

Shell input is parsed into stages. Quoting, wrappers, assignments, pipelines,
and nested command envelopes are parser-owned facts. Substring matching MUST
NOT authorize a protected route. Structured-document tools are classified by
their argv grammar before generic path projection.

The normative Action IR and Host-boundary refinement are specified by
[[file:10.15.02.10-hook-execution-plane.org][RFC 10.15.02.10]]. Wrapper snapshot
ownership is specified by
[[file:10.15-agent-hook-interception-protocol/10.15.40-parser-owned-wrapper-match-snapshots.org][RFC 10.15.40]].

* Source enforcement

Direct reads, bulk dumps, raw source searches, and agent-facing JSON search
are classified from the normalized action and provider projection. Obvious
source access remains fail-closed when optional state or diagnostic projection
is unavailable.

The Hook denies or allows the attempted action. It does not perform the
replacement Search/Query itself. Canonical source-search guidance names only
the public root operations:

#+begin_src text
asp search playbook '<one (search ...) Scheme expression>'
asp query playbook --language <producer|...> --selector <exact-selector> --projection <source|callable-skeleton>
#+end_src

Language-first =asp <language> search|query= aliases and provider-owned
playbook routes are not Hook protocol operations. Provider installation is not
a normal repair suggested by classification. Runtime admission preserves its
typed failure when the provider or transport is unavailable.

Raw-source enforcement is refined by
[[file:10.15.01-hook-raw-source-enforcement.org][RFC 10.15.01]]. Structured lazy
projection is refined by
[[file:10.15.02.08-hook-lazy-loader-capability.org][RFC 10.15.02.08]]. Exact
selector projection is refined by
[[file:10.15.03-merkle-exact-selector-warm-path.org][RFC 10.15.03]] and
[[file:10.15.04-exact-selector-projection-packet-v1.org][RFC 10.15.04]].

* Search and Query handoff

When a registered root Search/Query command is observed, Hook matching derives
the language/provider identity from =policy_providers=. The decision receipt
may contain:

#+begin_src text
registeredLanguageId
providerId
#+end_src

It MUST NOT emit =providerMaterialization=, =providerActivationRefresh=,
=providerLazyLoadCommand=, a static route, or an alternate provider command.
Provider readiness is evaluated later by the public Client/Runtime transaction.

Search/Query execution, Tokio concurrency, graph evidence, and performance
budgets are owned by RFC 10.05 and RFC 10.06.15. Hook only proves that the Host
action was normalized and classified against the published policy bundle.

* Decision transaction

Every observed Hook event produces exactly one authoritative decision. The
decision contains:

#+begin_src text
schemaId
schemaVersion
protocolId
protocolVersion
platform
event
decision
reasonKind
languageIds[]
subject
routes[]
message
fields
#+end_src

Normal Host rendering emits the platform response. =--emit decision= exposes
the typed packet for conformance and receipts. Rendered prose is not an
orchestration protocol and MUST NOT be parsed to infer recovery.

The local decode, projection, policy, and response-decision path has the strict
exclusive budget =elapsedMicros < 1000=. It performs no Runtime RPC, provider
execution, socket discovery, or blocking state repair. Diagnostic event logging
is best-effort after the decision and cannot alter it. The single-writer rules
are refined by
[[file:10.15.02.11-hook-decision-single-writer-transaction.org][RFC 10.15.02.11]].

* Stateful agent workflow

Agent/session lifecycle, subagent receipts, edit-before-search evidence, and
stop checks remain Hook policy facts where configured. They do not authorize
Hook to become the owner of provider lifecycle or Runtime execution.

The managed search child output contract is one Org =gql= source block with
=:profile search-evidence.v1 :eval never=. It contains graph evidence and no
source dump or prescribed next action. Lifecycle ownership is refined by
[[file:10.15-agent-hook-interception-protocol/10.15.30-asp-managed-subagent-management.org][RFC 10.15.30]]
and [[file:10.15.02.06-codex-multi-agent-v2-state-lifecycle.org][RFC 10.15.02.06]].

* Bootstrap and publication

Hook matcher publication is a control-plane transaction. Classification only
consumes a previously validated immutable artifact. A missing or stale artifact
selects the typed bootstrap/repair lane; it does not authorize a source-tree
fallback, in-memory config rebuild, Runtime restart, socket guess, or Plugin
reinstall.

Bootstrap, artifact identity, and publication are refined by:

- [[file:10.15.02.09-hook-bootstrap-repair-and-server-warm-path.org][RFC 10.15.02.09]];
- [[file:10.15.02.16-hook-matcher-publication-separation.org][RFC 10.15.02.16]];
- [[file:10.15.05-active-asp-artifact-merkle-receipt.org][RFC 10.15.05]].

Runtime Server readiness is a distinct transaction. A ready Hook artifact does
not prove a reachable Runtime endpoint, active provider generation, or usable
Search/Query data plane.

* Conformance

Acceptance requires all of the following:

1. schema-validated black/white matrices derive cases from the installed Host
   matcher and canonical policy/profile catalog;
2. a freshly linked =asp-hook= replay proves the real entry point classifies
   Host envelopes without contacting Runtime;
3. generated language/document cases cover every configured projection and
   both positive and negative subject mutations;
4. dependency gates prove Runtime Server and Client Core do not depend on
   =agent-semantic-hook=;
5. source gates reject reintroduction of route-bearing Hook activation DTOs or
   provider-route materializers;
6. latency evidence proves every covered decision is strictly below 1 ms;
7. a fresh Host task proves the installed Plugin actually intercepts the
   target action.

Zero tests, an unregistered test file, stale binary evidence, a source-only
inspection, or a partial matrix is not acceptance.

* Formal correspondence

The executable-plane proof is =ASPProof.HookExecutionPlane=. Its central
refinement is:

#+begin_example
classify(hostInvocation, compiledPolicy, providerProjection)
  = decision
#+end_example

Provider execution state and Runtime readiness are absent from the classifier
input. Any theorem or Rust path that introduces them below this boundary is an
architecture violation, not an optimization.

* Closure state

The compiled-policy Hook boundary is implemented. The remaining closure work
is evidence work: keep the full Hook matrix green, preserve the strict latency
budget, verify the installed Host transport in a fresh task, and reject any
future dependency or DTO change that recreates manifest/activation routing.
