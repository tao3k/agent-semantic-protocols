#+TITLE: RFC 10.07 — ASP State Home Project Identity
#+STATUS: Draft

* Problem

=ASP_STATE_HOME= currently contains two independent project hierarchies:

#+begin_example
projects/by-id/<repo-id>/workspaces/<workspace-id>/...
hooks/projects/<repo-id>/workspaces/<workspace-id>/...
#+end_example

The two roots do not share one registry or lifecycle owner.  A live audit found
2246 =projects/by-id= repository namespaces and 2916 =hooks/projects=
namespaces, with only 324 identifiers present in both trees.

Of 2217 readable =project.json= receipts:

- 2028 use =git-common-dir= identity
- 187 use path identity
- 2 use remote identity
- 1972 recorded Git top-level paths no longer exist

The stale receipts are dominated by test-created repositories below the
operating-system temporary directory.  Tests and benchmarks therefore write
ephemeral project identities into the user's durable global state.

* V1 Identity Contract

There MUST be one project registry and one workspace registry under
=ASP_STATE_HOME=.

#+begin_example
state/
  repositories/<repository-id>/repository.json
  workspaces/<workspace-id>/workspace.json
  ephemeral/<run-id>/<workspace-id>/
  runtime/
  org/
#+end_example

=hooks=, =client=, =artifacts=, =activation=, and receipts are consumers below
the same canonical workspace entry.  They MUST NOT create independent
repository or workspace namespaces.

* Repository Identity

Durable global repository identity is the normalized canonical Git remote
identity.  The configured canonical remote wins; otherwise the remote named
=origin= is canonical.  Additional remotes are alias evidence and do not
participate in =repository-id=.  If there is no configured canonical remote or
=origin= and more than one remote exists, resolution fails closed.

Equivalent SSH, SCP-like, and HTTPS spellings normalize to the same
=host/path= identity.  There is no implicit =git-common-dir= or path fallback
in the global repository registry.

A repository without a remote uses checkout-local state unless the caller
supplies an explicit state home and durable identity.  Temporary repositories
therefore cannot create global repository entries.

A checkout path, current working directory, Git worktree directory, symlink,
snapshot root, process id, timestamp, or activation digest MUST NOT affect
=repository-id=.

* Workspace Identity

Workspace identity represents a checkout or package workspace below one
repository identity.  It is derived from:

- canonical repository identity
- registered language-harness workspace/package anchor
- canonical checkout/worktree identity when the workspace is checkout-local

Changing cwd inside the same workspace MUST NOT create a new workspace
identity.

* Ephemeral State

Tests, benchmarks, sandtables, and temporary repositories MUST use an explicit
ephemeral state scope.  The shared test harness owns the temporary state root;
individual tests MUST NOT synthesize global project identifiers.

A root contained by the operating-system temporary directory is rejected from
durable global registration unless the caller supplies an explicit durable
identity.  It is routed to =state/ephemeral/<run-id>= and removed with the
owning run.

* Breaking Migration

The migration is one-way and does not retain legacy read compatibility.

1. Read every legacy =project.json= receipt.
2. Validate its recorded root and typed identity evidence.
3. Recompute the v1 canonical repository and workspace identities.
4. Move live state to the canonical workspace with digest and receipt checks.
5. Merge only identical immutable artifacts.
6. Keep the newest valid activation and active artifact receipt for each
   canonical workspace.
7. Delete legacy =hooks/projects= and =projects/by-id= namespaces after the
   migration receipt is durable.
8. Delete entries whose roots no longer exist and whose receipts have no live
   lease.

Missing or ambiguous identity evidence is a typed migration failure; it does
not authorize keeping another legacy namespace.

* Atomicity

Repository registry, workspace registry, activation, and active artifact
receipt are committed as one generation.  Healthcheck reads one generation
and MUST never observe an activation from one generation with receipt metadata
from another.

* Gates

The state identity gate covers:

- multiple cwd values inside one workspace
- symlink and canonical path
- Git worktree and main checkout
- two clones of one canonical remote
- local-only durable repository
- registered nested package workspace
- temporary test repository
- interrupted migration and replay

For every durable scenario the repository count is stable after repeated
resolution.  Temporary scenarios leave the durable repository count
unchanged.

Warm path resolution performs no subprocess, database open, manifest write, or
binary read and is measured in milliseconds.
