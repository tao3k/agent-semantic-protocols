#+title: RFC 10.15.02.04 — Agent Session Lifecycle Fencing Epoch

* Status
Focused formal verification is complete. This RFC refines [[file:10.15.02.03-agent-session-lifecycle-concurrent-linearizability.org][RFC 10.15.02.03]]. The Lean source, compiled module, direct audit, and runner pass; all 24 theorem declarations are axiom-free. No Rust implementation is authorized in this session.

* Problem
A controller may win an intent claim, pause, and resume after a newer controller has advanced the resident generation and fencing epoch. Revision CAS prevents simultaneous winners at one instant, but it does not stop an old winner from acting later with cached authority.

Every state-changing operation therefore carries an authority token. Admission compares the token with the current durable authority tuple, not with process identity or a previously successful claim.

* Authority tuple
The token binds logical slot, generation, fencing epoch, revision, state digest, capability digest, controller identity, and expiry. Controller identity is diagnostic; the other fields and lease time determine current authority.

#+name: agent-session-fencing-authority-tuple
#+begin_src typst
#let Current(c, t) = $upright("TokenCurrent")(c, t)$
#let Slot(x) = $upright("slot")(x)$
#let Gen(x) = $upright("generation")(x)$

#let State(x) = $upright("stateDigest")(x)$

$
  forall c, t,
  Current(c, t) => Slot(t) = Slot(c) and Gen(t) = Gen(c) and
  Epoch(t) = Epoch(c) and Rev(t) = Rev(c) and
  State(t) = State(c) and Cap(t) = Cap(c).
$
#+end_src

* Stale-authority exclusion
Generation, epoch, revision, state digest, capability digest, and expiry are independent rejection dimensions. Failure of any dimension rejects every lifecycle effect.

#+name: agent-session-fencing-stale-exclusion
#+begin_src typst
#let Current(c, t) = $upright("TokenCurrent")(c, t)$
#let Auth(c, t, a) = $upright("Authorized")(c, t, a)$
$
  forall c, t,
  not Current(c, t) =>
  forall a in (
    upright("retire"), upright("release"), upright("bind"),
    upright("dispatch"), upright("commitTerminal")
  ), not Auth(c, t, a).
$
#+end_src

* Fence monotonicity
A fence advance preserves the logical slot and strictly increases epoch. It has neither self-loops nor two-cycles. A token bound to the old epoch is invalid under the new authority.

#+name: agent-session-fencing-monotonicity
#+begin_src typst
#let Advance(x, y) = $upright("FenceAdvance")(x, y)$
#let Epoch(x) = $upright("fencingEpoch")(x)$
$ forall x, y, Advance(x, y) => Epoch(x) < Epoch(y). $
$ not exists x, Advance(x, x). $
$ not exists x, y, Advance(x, y) and Advance(y, x). $
#+end_src

* Actor authority versus receipt validity
Fencing rejects stale actors; it does not erase already produced host facts. A current controller may ingest a valid terminal receipt emitted by an old delivery generation because dispatch identity is logical-slot scoped. The stale controller itself may not commit that receipt.

#+name: agent-session-fencing-old-generation-receipt
#+begin_src typst
#let Valid(d, r) = $upright("ValidDispatchCompletion")(d, r)$
#let Key(x) = $upright("dispatchKey")(x)$
#let Ingest(c, r) = $upright("CurrentControllerIngests")(c, r)$
$
  forall d, r, c,
  Valid(d, r) and upright("TokenCurrent")(c)
  => Key(r) = Key(d) and Ingest(c, r).
$
$ upright("StaleController") !=> upright("CommitTerminal"). $
#+end_src

* Lean-discovered corrections
1. Revision CAS alone does not fence a paused old winner.
2. Authority must bind generation, epoch, revision, state digest, and capability digest.
3. Lease expiry is an independent rejection condition.
4. One stale field invalidates every lifecycle effect.
5. Fence epochs strictly increase and cannot form cycles.
6. Stale actor authority and old-generation receipt validity are distinct.
7. Only a current controller may commit an otherwise valid old-generation terminal receipt.
