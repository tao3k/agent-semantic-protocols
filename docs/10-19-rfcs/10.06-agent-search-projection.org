#+title: RFC 10.06 — Agent Search Playbook Projection
#+startup: overview

* Status

Current.  This file is the only agent-facing Search projection contract.
Git history owns every retired provider-local Search protocol; none is a
compatibility surface.

* Request admission and provider syntax identity

Research on optional structural evidence, redundancy, and replay is recorded in
[[file:10.06-agent-search-projection/10.06.14-search-evidence-output-reflection.org][10.06.14 Search Evidence Output Reflection]].
It does not change this contract's current grammar, default, or admission rules.

The empty form and every incomplete form fail
request parsing before Runtime dispatch.  They do not return an example,
grammar, guide, recovery command, or any other second agent-facing projection.

Tree-sitter Query remains the language-neutral structural query grammar.  ASP
extends only its existing predicate/directive slot with the namespaced
=#asp-*= family; it does not add a =(where ...)= wrapper or a second Agent-facing
query language.  The MRR Gerbil declaration
=mrr.enhanced-tree-sitter-query.v1= owns the extension operator table, operand
domains, result projection names, lowering rules, and typed recovery codes.
Each provider registers a capability table that binds its native parser facts
and Tree-sitter-compatible node/field vocabulary to that declaration. Provider
rows own concrete node kinds, field paths, relation kinds, projections, and
their publication state:
=runtime=, =provider-local=, or =not-materialized=. Runtime binds the selected
provider, parser, declaration digest, capability-table digest, active
generation, and compiled Search Layout internally. A syntactically valid query
that asks for a non-=runtime= row fails capability admission; it never invokes
a request-time source parser or silently weakens the predicate.

* Single request — layout-bound native inputs

#+begin_src sh
asp search playbook '<one (search ...) Scheme expression>'
#+end_src

=graph gql= and =graph pgql= leaves compile through the V1 relation IR and apply
to the generation-bound candidate graph.  This does not imply persistent
storage: durable PGQ storage is a separate registry-owned backend used only
for admitted low-volatility facts.  The public CLI accepts native arguments in
this shape. Native rg argv carries filename, path, glob, type, and exact-content
scope:

#+begin_src sh
asp search playbook '
  (search
    (producers (language rust python) (documents org md))
    (chain
      (intersect
        (rg "-n" "-g" "*.rs" "-g" "*.py" "-g" "*.org" "-g" "*.md"
            "-e" "ASP_RUNTIME_CLIENT_FD|transport-unavailable|ClientFrame"
            "crates" "languages" "docs")
        (tantivy "title:\"surface failure\"^2 OR body:transport"))
      (syntax rust
        "((_) @item
          (#asp-eq? @item \"kind\" \"function\")
          (#asp-any-match? @item \"queryKeys\"
                           \"RuntimeServingEndpoint|ClientFrame\")
          (#asp-select! @item \"kind\" \"name\" \"selector\"
                             \"byte-range\" \"scopes\" \"queryKeys\"
                             \"projections\" \"relations\"))")
      (graph gql "MATCH (a:Owner)-[:CALLS]->(b:Item) RETURN a, b")))'
#+end_src

Native leaves may repeat and their source order is preserved; no separate
priority field exists. The admitted compiled Search Layout, not an unrelated
flag order, owns execution edges and fusion. Graph is optional and forms a
barrier after the structural-scope stage. Retrieval input after the first Graph
leaf is invalid.

The MRR-owned Scheme reader admits exactly one datum and the Search Playbook
macro owns composition semantics. Each decoded Scheme string is one native argv
token for string-native leaves: rg argv goes to rg, the Tantivy string to its
query parser, native-syntax to canonical-selector admission, and the Graph
string to the admitted GQL parser. Syntax is different: its second value is one
Tree-sitter Query source string. Its ordinary pattern, field, capture,
alternation, quantifier, predicate, and directive syntax is retained; the
namespaced =#asp-*= forms are compiled against the Gerbil-owned extension table
and the selected provider's generation-bound capability table. No layer
converts it into a =(where ...)= dialect. When explicit structural inputs are absent, the
automatic native-parser fallback derives the owning registered parser from each
file in the layout's fused candidates.
=producers (language ...)= selects registered programming-language producers and
=producers (documents ...)= selects registered document producers for that derived scope;
at least one producer axis is required and both may be present. No layer may stringify
and split a native string into additional argv, reparse it as a different
grammar, interpolate it, or call a shell evaluator.

=chain= and =intersect= are the V1 reasoning-composition forms. Producer sets
are explicit symbol lists. A =|= inside a Scheme string retains the selected
native parser's meaning and never becomes a shell pipe. Search records branch digests, producer bindings, budgets,
evidence ids, and marginal verified gain without wrapping or translating the
native grammar. Alternatives within one native block share that block's
priority. Repeated leaves remain distinct layout inputs. Shared-scope stages
may fan out against one generation; serial scope-transform stages consume their
predecessor only when the compiled layout declares that edge. The former flag
matrix and an unquoted shell-token =|= are rejected before request admission.

The single request satisfies =SP-REQUEST-002= and =SP-GRAMMAR-003=.

* Request completeness and typed rejection

Every complete request carries one =(search ...)= expression with at least one
producer axis and a paired rg/Tantivy acquisition composition.
Host and Runtime bind the current =ProjectId=,
=WorkspaceId=, source generation, and compiled layout identity; they are receipt
fields, not Agent-authored executable code. The default layout is exactly
=intersect(rg-owner-set, tantivy-owner-set) -> structural-scope-facts -> graph?=: rg and
Tantivy consume one immutable generation owner universe, their intersection is
the file-context scope. The structural-scope node then selects either the union
of admitted explicit syntax/native-syntax matches or, when neither explicit
input is present, automatic parser grounding. Both paths derive selectors and
syntax/content facts inside that fused scope. Other
registered layouts may declare serial =scope-transform= edges. Graph consumes
only structurally grounded candidates and is not an independent vote
(=SP-LAYOUT-004=).

An incomplete request is rejected by the top-level parser with a typed
=search-playbook-request-incomplete= failure.  A provider-native parse failure
retains the provider's typed failure and exact argv.  Neither case returns a
successful projection, GQL block, example, grammar, or prescribed repair
command (=SP-RECOVERY-005=).

The active stable V1 request and result contracts are completed in place as one
hard cut; no V2 or compatibility route is introduced. Syntax and
native-syntax inputs establish a structural-selector scope and extract its
facts inside the fused file-context scope; every success binds an admitted
Search Layout receipt. The Search package owns
the shared layout model and execution; Rust owns schema
admission, scheduling, execution, and receipts. No Scheme evaluator or
provider-local planner enters the Search hot path.

* Fan-in, progressive delta, and freshness
** Provider-ranked Top-K projection

Top-K belongs to the Rust Search/Runtime implementation and its shared wire
contract.  It is the broad-search result, not an instruction encoded in an
Explorer prompt and not a post-hoc output-compression policy.  The agent
projection MUST preserve the provider-ranked candidate set without re-ranking,
trimming, or synthesizing candidates.

The wire result is =candidates= when the ranked set is non-empty, =empty= only
when execution succeeded with zero candidates, and =unavailable= with =stage=
and =reasonKind= when an execution boundary failed.  =no-output= is forbidden:
absence of assistant text is neither a search result nor a typed failure.

The Graph projection consumes the current structurally grounded candidates. It is a
fan-in relation-reasoning projection, not another independent lexical vote.
Acquisition may retain up to 4096 generation-bound candidate identities for
this internal frontier; those identities are not rendered.  Graph relates,
filters, and ranks that frontier before the formal Top-30 result is built.
For volatile code search, GQL/PGQL relation expressions are evaluated against an
ephemeral Python Graphs projection rebuilt from current selectors and mappings.
Persistent graph storage is used only for explicitly low-volatility Workspace
facts such as dependency topology.

The Explorer prompt owns only command-use responsibilities: compose the public
=asp search playbook= axes, preserve the returned selectors and relations, avoid
source payload, and leave subsequent Query selection to the parent Agent.  It
MUST NOT define K, ranking, truncation, or the result-state machine.


Each clause receipt binds the shared identity, exact input/output token digests,
elapsed time, truncation, and work counters.  Deterministic fan-in synthesizes
the evidence graph and returns exactly one explicit result:
=exact-selector-ready=, =disambiguation-required=,
=relationship-supported=, =no-match=, =contradiction=,
=refinement-required=, or =provider-contract-failure=.  A next delta cannot
replace that result.  The Agent reasons again and submits a fresh complete
request when refinement is required; no query-set round is stored or
resumed.  A generation mismatch invalidates context and selectors before
evidence is read (=SP-PROGRESS-006=).

=no-match= additionally requires an untruncated complete-coverage witness bound
to the admitted owner universe and every requested clause.  Every receipt binds the
same query-set/predicate and owner-universe digests, covers the full admitted
owner count, and reports zero matches.  A result enum, an empty top-K projection,
or a truncated receipt cannot prove absence.

Every public Syntax item is total and functional with respect to exact Query:
it carries one parser-owned structural identity and exactly one
generation-current selector in the GQL graph, but no embedded Query request or
command grammar. Independently materializing that selector through Query
Playbook round-trips to the same parser node. An ungrounded capture is
=provider-contract-failure= rather than a
display-only candidate (=SP-RESULT-007=).
The selector identity binds source-root, provider, parser identity/version, and
selector-grammar version in addition to node and generation identity.

Syntax Search and Query share one native contract (=SP-SYNTAX-007A=). Each
=(syntax <registered-producer> "<enhanced Tree-sitter Query>")= leaf carries
the familiar Tree-sitter Query surface. The selected provider interprets
concrete kinds and fields against its native parser facts, but cannot replace
that surface with a provider-private query language. Tree-sitter and ast-grep
may contribute adapter-produced facts only after a registry-bound resident
adapter is admitted; neither is an automatic request-time fallback.
=--native-syntax <canonical-exact-selector>= is a separate repeatable axis that
admits an already-known current selector; it never accepts a Tree-sitter query
or provider argv.
Org, Markdown, compiler, and future document parsers retain their own fact and
selector vocabularies through capability rows while accepting the same shared
enhanced Tree-sitter Query structure.

The shared envelope uses LSP-compatible document-selector, text-document,
position, range, selection-range, and location-link shapes.  ASP adds grammar,
parser, source, capture, native-fact, and structural-selector identities.  LSP
does not standardize an AST query language; no provider-native expression is
misrepresented as LSP grammar. Search settlement, Query materialization
request, and Query source result must round-trip to the same parser node without
a hidden Search handle.

* Volatility planes, persistent graph query, and logical inference

=(graph ...)= requires a registry-admitted =graphLanguage= family and version.
The admitted persistent property-graph families are =pgql= and =sql-pgq=.
Their compiler/lowering receipts bind source language/version, compiler or
lowerer identity/version, source token digest, GraphRelationalIR digest, and
provenance.

Evidence is a typed join of three volatility planes (=SP-EVIDENCE-008=):

- =DurableWorkspacePropertyGraph= stores low-volatility package, dependency,
  lockfile, build/test target, owner, and provider topology.  PGQL/SQL-PGQ query
  this plane only while owner/manifest digests and validator versions are
  current.
- =SnapshotSourceGraph= contains current fd, rg, Tantivy, parser, Tree-sitter,
  and Python Graph facts.  It is generation-bound and never promoted into the
  persistent database.
- =DerivedReasoningOverlay= contains facts with complete parent lineage.  A
  derived fact remains valid exactly while all parents remain valid.

Graph retrieval follows =SP-GRAPH-010=:

#+begin_example
PersistentGraphQuery(PGQL | SQL/PGQ)
  -> GraphRelationalIR
  -> owner-digest-bound DurableRelationFacts
SnapshotSourceGraph(sourceSnapshotDigest)
  -> snapshot-bound SourceRelationFacts
DurableRelationFacts + SourceRelationFacts
  -> LogicReasoning(Ascent rules)
  -> DerivedRelationFacts + derivation lineage
  -> EvidenceGraph synthesis
#+end_example

PGQL/SQL-PGQ property-graph reasoning and Ascent logical programming are the two
Meta Reasoning cores.  Ascent is not a sixth retrieval axis.  Its rule grammar,
registry entry, admission version, and bounded closure budget are separate from
PGQL/SQL-PGQ.  An absent or mismatched engine fails closed.  Every derived fact
carries =FactId=, =DerivationId=, and typed references to admitted parent facts
rather than detached identifier and validity lists.  It also binds the admitted
base-fact registry digest, Workspace binding, Ascent engine digest, and ruleset
digest.  Registry admission binds the complete ordered base =FactId= set to
QueryIdentity and a nonempty authority receipt; digest equality alone is not
admission.
Ascent cannot mint source/base facts.  A derived relation cannot become an
exact selector; materialization returns through a generation-current
provider/parser selector (=SP-GRAPH-010=).

Validated Root 0/Root 1 durable evidence may warm-start later reasoning only
after freshness admission.  It may alter owner routing, query priority, and
budget allocation, but cannot prune fresh axes or establish closure.  An
ExTS-inspired value-of-information policy decides whether to deepen an existing
reasoning branch or expand a new one.  Every branch receives one evidence
validation before quality gating; scores, depth, and historical success affect
scheduling only and never replace a typed witness (=SP-META-009=).
The scheduler may change physical completion order and per-branch budget, but
it MUST preserve Agent-authored semantic priority.  The semantic result,
QueryIdentity, and ordered clause receipts remain unchanged.

The formal Search result is the Graph-filtered Top-30 candidate set
(=SP-PROJECTION-011=), not a larger result later compressed for display.
Rendering MUST NOT apply a second K or token-budget truncation.  Internal work
budgets may bound acquisition and Graph evaluation, and truncation prevents an
absence claim; they do not redefine the returned ranking.  Per-item affordability
does not establish global diversity feasibility.  Utility measures
obligation discharge, selector readiness, provenance, freshness, diversity,
and token cost.  A stable EvidenceId breaks ties.  Output never contains an item
outside the admitted current-generation evidence set.

The compact receipt reports selected/admitted counts, exact token cost,
=truncated=, and an omitted-identity digest.  A truncated projection cannot
establish complete coverage or absence.  If the budget cannot carry a required
witness, the result remains =refinement-required= or
=provider-contract-failure= rather than silently dropping the witness or
changing semantic closure.

* Evidence mapping and round trajectory

Fan-in retains each backend result as a separately provenanced =EvidenceAtom=.
It may emit typed =same-source=, =grounds=, =supports=, =contradicts=, and
=derives-from= mappings when canonical source identity or parser grounding
supports them.  Mapping does not merge receipts, manufacture a selector, or
move snapshot evidence into the persistent Workspace graph (=SP-MAPPING-012=).
Only =same-source= requires source-identity equality; other typed relations may
cross source nodes when their grounding receipt is admitted.

When the current round is comparable with the immediately referenced prior
round, projection emits only bounded identity deltas:

#+begin_example
newEvidenceIds
retainedEvidenceIds
strengthenedEvidenceIds
weakenedEvidenceIds
contradictedEvidenceIds
disappearedEvidenceIds
relationAdds
relationRemoves
invalidatedEvidenceIds
trajectoryDigest
#+end_example

Evidence bodies already named by a retained EvidenceId are not repeated.
=disappearedEvidenceIds= is diagnostic only unless the current round also
carries the complete untruncated coverage witness required for =no-match=.
Generation drift requires explicit selector/evidence relocation; otherwise the
old snapshot atoms and their derived forward closure are invalidated
(=SP-TRAJECTORY-013=).

After delta admission, Ascent derives unresolved obligations, contradictions,
and impact relations.  The Meta Reasoning planner may use those facts plus
durable PGQL/SQL-PGQ owner/dependency relations to rank the next complete Layer
Two action set.  Expected utility affects scheduling only; the closure
validator remains independent (=SP-PLANNER-014=).

When a formal scenario participates in reasoning, the bounded projection also
names the immutable reference-model digest, scenario-projection digest,
invariant EvidenceIds, model-action/code mappings, trace-validation outcome,
model-checking counterexample identity, and reproduction/adjudication state.
These identities let the model request WHY, WHY-NOT, IMPACT, or exact trace
materialization without receiving the entire TLA+ model or source trace.
A counterexample without model-code conformance and reproduction remains
=unresolved= rather than a code-bug result (=SP-CONFORMANCE-015=).

These graph/reasoning fields are extension obligations only.  This RFC does not
claim that MRR Meta Reasoning, Relation Reasoning, PGQL/SQL-PGQ lowering,
or Ascent execution is currently implemented.

* Generation construction and accelerator authority

One immutable content generation is constructed and admitted in this order:

1. =sourceByteAcquisition= establishes parser-independent byte/path membership
   and binds the source snapshot; it MUST NOT be reported as ripgrep execution.
2. =nativeSyntax= commits the complete provider parser accounting for every
   admitted owner.  Each owner contributes exactly one of two mutually
   exclusive records: a usable parser projection (canonical selector, byte
   range, query keys, derived projections, module facts, and relations), or a
   typed =source-syntax-unavailable= diagnostic bound to the same owner and
   content digest.  It is one internal native-syntax playbook stage, not an
   owner-only command.
The two content-stage receipts carry the same generation identity. A missing,
failed, reordered, or identity-drifting acquisition or syntax stage rejects the
content candidate before publication. =rustResidentGraph= is independently
derived and attached to that exact published content identity; its absence or
construction cannot delay cold Search/Query. Tantivy is likewise a separately committed accelerator
for that exact identity. Before it is ready, one bounded cold =rg= route may
search only the admitted inventory and must content/native-syntax verify every
hit. After it is ready, query-time code never launches rg, Tantivy construction,
a provider, a durable database read, or a fallback process. The optional
=asp-python-graphs= session is selected only by an admitted graph
block and must be bound to the exact Project/Workspace/Generation/root identity.

* Projection contract

=compact= returns the bounded evidence needed for the next decision:

- generation and source-snapshot identity;
- matched owner paths and content digests;
- matched lexical terms and graph-derived rank;
- parser-owned structural selectors when available;
- bounded =nativeSyntax.projections[]= records containing each selected
  owner identity, content digest, canonical selectors, byte ranges, normalized
  query keys, derived projection digests, and owner-bound relation digests;
- typed work counters and elapsed time.

=full= may add explanations and traversed relations, but it does not expose an
alternate command grammar.  Both modes are projections of the same admitted
generation and ranked result.

The Agent-facing Search projection is one Org-bound GQL graph.  Ranked native
nodes carry their exact selectors and retrieval projection inside that graph;
direct, declared, derived, and proposed relations remain graph edges with their
authority and witness identity.  There is no parallel result header, evidence
row table, Query Grammar line, recommended command, or prose summary.
Generation, producer/parser, artifact, context, and evidence digests remain
Runtime validation data; they are not repeated into the Agent context unless a
separate diagnostic operation explicitly requests them.  Search GQL MUST NOT
contain source bytes, snippets, excerpts, display line ranges, fenced source,
prose that paraphrases source content, or an open extension map.  A full
machine receipt may retain integrity and audit data without making those fields
part of the default Agent projection.

=rootDigest= in every public Search/Query terminal denotes the source snapshot
root admitted for that ProjectId/WorkspaceId/generation.  A resident owner
directory or lexical/graph attachment may maintain its own Merkle root, but
that derived root is never substituted into the public field and is never a
compatibility alias.  This rule applies equally to Ready and Failed terminals,
so an owner-missing response cannot silently cross identity domains.

An =ownerPath= without either a valid parser projection or a typed diagnostic
is unaccounted and MUST fail closed.  A diagnostic is evidence about parser
availability, never a selector and never permission to synthesize one.  A
single diagnostic MUST NOT erase independently valid rg acquisition, Tantivy
lexical, byte, or Python/resident graph evidence.  The native-syntax stage is
complete only when the disjoint union of projected and diagnosed owners equals
the selected owner set.  The stage artifact digest binds both collections in
canonical owner order.  The public receipt is rendered by the Runtime search
handler from the resident generation; a schema-only fixture or an owner-count
summary is not an implementation of this contract.

The projection must never call internal construction inputs “seeds”.  Source
construction inputs are =source documents=; exact byte inputs are =byte
coverage inputs=; graph entry nodes are graph-internal mathematical values.

* GQL Search and direct Query materialization

Search locates and relates evidence.  Its only successful Agent-facing shape
is the single GQL block defined by RFC 10.06.15 and RFC 10.06.17:

#+begin_example
#+begin_src gql :profile search-evidence.v1 :eval never
(refresh:RustMethod {selector:"rust://src/registry.rs#item/method/refresh/scope/implementation-owner/type/Registry"})-[:CALLS]->(publish:RustMethod {selector:"rust://src/registry.rs#item/method/publish/scope/implementation-owner/type/Registry"})
#+end_src
#+end_example

The =matchedBy= sequence is itself evidence: acquisition clause references are
preserved in Agent-authored priority order and Graph references are appended as
the final fan-in suffix.  A renderer or Explorer Hook MUST reject a Graph
reference followed by a new acquisition reference because that would claim a
transition the Playbook planner forbids.

The Agent decides whether to query and which graph-bound selector to use.
Search never emits a selected command or preferred projection.  Query is a
distinct exact structural materialization operation:

#+begin_src sh
asp query playbook --language '<producer|...>' --selector <exact-selector> \
  --projection <callable-skeleton|source> --workspace <root>
#+end_src

Search display ranges and owner paths are not executable selectors.  A
successful Query returns direct native code, with the admitted GQL relationship keyword
immediately before the source block and no detached relation appendix:

#+begin_example
#+gql: Registry::refresh --calls--> Registry::publish
#+begin_src rust :query "rust://src/registry.rs#item/implementation/type/Registry" :filename "src/registry.rs"
impl Registry {
    pub fn refresh(&mut self) -> Result<Receipt, Error> {
        let artifact = self.store.load()?;
        self.publish(artifact)
    }

    fn publish(&mut self, artifact: Artifact) -> Result<Receipt, Error> {
        self.publisher.publish(artifact)
    }
}
#+end_src
#+end_example

The =#+gql:= relationship keyword is Runtime-produced from the admitted Project
Topology for the exact selector set; the Client renderer must not infer it from
source text or synthesize it from selector spelling.  Query preflights the
complete selector and relationship set before exposing any source bytes.

When Search has grounded current selectors, ASP Explorer emits the single GQL
evidence graph and stops.  The parent or another authorized reader reasons over
the evidence and independently
decides whether to materialize one selector, refine Search, compare evidence,
or stop.  A SubAgent MUST NOT pre-read or summarize source, because doing so
duplicates transport and model-context cost without adding evidence.

Invalid request recovery follows the same projection boundary: it is a typed
failure, never an alternate successful renderer.  Normal =asp search playbook=
execution renders only its admitted GQL graph.  Provider/parser identities and
digests remain internal admission facts and are not rendered as reasoning
evidence.

* Removed surfaces

The following inputs must fail closed and must not be translated:

- the single Runtime-owned Search Playbook operation;
- language-first public routes =asp <language> search= and
  =asp <language> query=;
- opaque =--query-set <string>= and =--from-hook=;
- invalid or uncovered =clauseOrder=, acquisition after the Graph barrier, and
  standalone shell-pipe tokens;
- northbound =search.owner= methods and ASP Client owner-search DTOs;
- prompt-output/search-packet replay of the retired compact grammar;
- graph construction that bypasses the admitted Rust generation, an unregistered
  graph language, or a cross-generation/unbound graph session.

The hard cut applies to every adapter, not only the ASP client parser.  Hook
activation and durable Hook policy expose one =playbook= route kind and one
=playbookRoute= provider projection.  Any other provider-local Search route
field or route-kind enum value is invalid input; Hook must not retain recovery
aliases.  A source-read denial may request a
fresh complete query set and hands exact source materialization to
=query --selector= only after parser-owned selector grounding.

Language providers expose parser/projection facts to ASP Server, but they do
not own a second public search workflow.  Provider-local Search renderers are
absent from public CLI dispatch.  The Search package owns acquisition, Tantivy indexing, graph
admission, planning, ranking, and agent projection; provider packages own only
language-specific parsing and fact production.

* Language provider minimal contract

The engineering boundary is dependency inversion, not a duplicated Playbook
facade in every language package.  A Language provider may publish only:

- canonical native-parser facts bound to source and provider identity;
- selector resolution and exact typed projections;
- language/document-owned native syntax contract schemas and fact/schema
  registrations;
- provider readiness and typed evidence transport.

Tree-sitter Query owns the base pattern/capture grammar. The Gerbil-owned
=mrr.enhanced-tree-sitter-query.v1= declaration is the sole authority for
=#asp-*= operators, operand domains, projections, lowering, and recovery codes.
The provider-owned capability table is the sole authority for that producer's
concrete node kinds, fields, relations, projection availability, publication
state, and parser granularity. ASP Server's
=asp.workspace.query.syntax-plan-context= read returns only the already
resident generation digest and immutable provider capability. It performs no
Query parse, regular-expression compile, provider call, filesystem read, or
generation work. The Client source plane combines that context with the
Gerbil operator declaration and Agent-authored Tree-sitter Query, then forwards
the compiled resident plan unchanged. Search Playbook maps the result into the
shared Query/evidence envelope. Shared schemas contain no copied Rust, Python,
Org, Markdown, or future-language node enums. The Agent never supplies a
contract digest. Runtime revalidates every syntax contract and generation
identity internally; the
default Agent projection returns canonical selectors and relations, not those
identity fields.

A Language registry MUST NOT contain any =search/*= method.  Its provider
manifest MUST NOT contain a Playbook route.  =search playbook= is registered,
parsed, planned, rendered, and terminated only by ASP Rust/Runtime.  Language
packages therefore do not own search plans, rg acquisition, lexical ranking,
graph composition, reasoning profiles, search caches, search benchmarks,
recommended-next search commands, or search CLI compatibility stubs beyond a
typed hard rejection at the provider binary boundary.

Parser indexes named =search_index= in older providers are not automatically
Search authority.  The reusable portion is renamed or projected as native
facts; ranking, candidate selection, query planning, and agent-facing rendering
are removed or moved into =agent-semantic-search=.  Tests must distinguish
parser-fact completeness from Search orchestration and must reject any provider
registry containing =search/*=.

* Required evidence

Closure requires all of the following:

- schema tests for request and Python graph receipt identity;
- Rust parser rejection tests for every removed public surface;
- ordered base-generation admission and drift tests;
- resident Tantivy/byte/graph execution tests with zero query-time processes;
- truthful executed/skipped receipts proving that resident byte evidence is not
  mislabeled as ripgrep and that skipped Python Graph starts no worker;
- Runtime ClientFrame integration for workspace and owner scopes;
- Lean proofs that base stage reordering cannot commit, optional Python absence
  preserves base identity, and graph-required intent fails on absent/stale
  Python session identity;
- a representative real-project playbook receipt with timing and work counts.

** Large-workspace performance evidence

Performance evidence is a projection of the real generation and query
architecture, not a separate benchmark-only algorithm.  Generation
publication phases may be ordered, while query axes remain an independent
fan-out/fan-in set.  Evidence MUST measure the following phases independently:

1. complete content-generation publication: =fd= inventory, repository
   admission intersection, native parser facts, and one immutable Rust graph;
2. cold lexical query before accelerator readiness: bounded =rg= over the
   admitted inventory plus content/native-syntax verification;
3. bootstrap and delta accelerator publication: content-addressed lexical
   shard reuse/rebuild/retirement, Tantivy attach/commit, rg/Tantivy result
   equivalence, atomic pointer publication, and first reader open;
4. warm candidate query: Tantivy lookup plus bounded Rust graph rank over the
   already-admitted generation;
5. relationship query: the same warm base path plus one exact-generation
   Python Graph evaluation receipt;
6. concurrent warm query: independent queries share the immutable generation
   and may observe only that generation.

A large-workspace gate uses at least 4,096 admitted owners, at least 32 cold
generation samples, at least 512 warm query samples, and a 32-query concurrent
burst.  It reports actual sample count and p50/p95/p99/max nanoseconds for each
measured phase.  A duration is the direct monotonic-clock observation; tests
MUST NOT replace a zero observation with a hard-coded positive counter.

The gate also proves result quality: every known lexical cohort is recalled,
Rust graph expansion is bounded and generation-local, non-relationship intent
starts no Python worker, and relationship intent accepts Python Graph evidence
