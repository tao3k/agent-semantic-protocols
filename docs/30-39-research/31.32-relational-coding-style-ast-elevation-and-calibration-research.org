* Abstract & Central Thesis

Large Language Models (LLMs) already produce syntactically well-formed code for
isolated tasks 90–98% of the time. Consequently, the bottleneck in AI-assisted
software engineering has shifted away from "can the model emit compiling syntax?"
toward *two sharper frontier problems*:

1. *Frontier 1 — Higher-Level Code Elevation via Machine-Native Relational Style Theories*:
   LLMs default to verbose, imperative, redundant code that passes unit tests
   yet violates repository architecture, idiom density, and maintainability
   contracts. We argue that *natural-language coding style documents are the
   wrong representation for LLMs*: prose is designed for human cognition,
   suffers from attention dilution and polysemy, and cannot execute as a formal
   verifier. Instead, Coding Style should be formalized as an *executable
   relational and algebraic theory* ($\mathcal{T} = \langle \mathcal{R}_{\text{ded}},
   \mathcal{R}_{\text{choice}}, \preceq_{\text{style}}, \mathcal{W}_{\text{elev}} \rangle$)
   authored in *:gerbil-ascent* (Datalog + lattices + Dusa finite-choice) over
   AST facts projected by *two complementary syntax-parsing DSLs*:
   (i) *:gerbil-parser* (full-strength declarative grammars -> lossless CST), and
   (ii) ASP's *external native language providers* (~asp-rust~ ~syn~,
   ~asp-typescript~ ~tsc~, ~asp-python~ ~ast~, ~AspJulia.jl~ ~JuliaSyntax~,
   ~asp-gerbil-scheme~ over HTTP-JSON). The *same* mathematical/relational
   theory both drives deterministic AST elevation/verification *and* projects
   compact, high-entropy symbolic contracts ($\forall$, $\neg\exists$, Horn
   predicates, algebraic rewrite schemas $\text{LHS} \leadsto \text{RHS}$) into
   the LLM context — eliminating human-prose ambiguity.
2. *Frontier 2 — Sound Zero-Round-Trip Automatic Syntax Calibration*:
   In the residual 2–10% of edits or tool calls where an LLM drops or duplicates
   delimiters (~)~, ~}~, ~]~), omits a semicolon/comma, or emits an unmatched
   punctuation token, forcing a full LLM retry loop wastes seconds and thousands
   of tokens while risking cascading drift. We formulate *Dual-Track Sound
   Calibration* inside ASP's pure-Rust AST engine (~crates/agent-semantic-ast~):
   - *Track A*: Bounded *CPCT+ minimum-cost LR recovery* (Diekmann & Tratt,
     ECOOP 2020) over ~:gerbil-parser~'s compiled ~LRFailureFrontier~.
   - *Track B*: *Oracle-Verified Bounded Calibration* over *Source-Backed
     Span-Indexed Lossless Overlays*, enabling even non-recovering,
     trivia-dropping native parsers (~syn~, Python ~ast~) to serve as 100% sound
     oracles for lossless editing and bounded delimiter calibration without
     introducing Tree-sitter or duplicate language parsers.

* 1. Empirical Problem Statement: Why Current AI Coding Architectures Plateau

** 1.1 The Natural-Language Coding Style Bottleneck

Empirical studies on SWE-bench (2024–2026) and agentic coding evaluations reveal
three structural pathologies when coding style is conveyed solely as prose:

1. *The Verifier Gap (Passing Tests != Acceptable Engineering)*:
   Audits of SWE-bench trajectories show that roughly half of test-passing
   agent patches are rejected by human maintainers due to verbosity, duplicated
   helpers, violated module boundaries, poor idiomaticity, or technical debt.
2. *Attention Dilution & Rule Interference*:
   Real engineering codebases enforce dozens of interlocking structural rules
   (for example, ASP's ~asp-rust-rules.md~ specifies 74 distinct module, API,
   iterator, complexity, async, and ABI invariants; Marlin's ~CODING-STYLE.org~
   specifies POO lexical-capture, composition, and functional-boundary
   conventions). Injecting prose rulebooks into prompts degrades adherence as
   context length grows; rules compete probabilistically in attention rather
   than composing deductively.
3. *"Solve Early, Stop Late" & Post-Mortem Linter Loops*:
   Agent trajectories frequently reach functional correctness early, then burn
   additional turns fighting post-mortem linter text output — often introducing
   fresh regressions during text rewrites.

** 1.2 The Text-Plane Edit Format Bottleneck

Studies of Aider's edit-format benchmarks and OpenAI Codex ~apply_patch~ show
that a large fraction of end-to-end failures stem from *edit representation
friction* rather than algorithmic misunderstanding:
- Unified diffs fail on shifted line numbers and indentation drift.
- ~SEARCH/REPLACE~ blocks impose a heavy context-copying token tax and break
  whenever compact code outlines omit braces or boilerplate (documented in ASP
  [31.13-ast-apply-patch-direction-report.org](file:31.13-ast-apply-patch-direction-report.org)).
- Aider uses Tree-sitter only as a *read-only* heuristic syntax summary
  (~RepoMap~) and reverts to raw text matching for every write.
- A single missing ~}~ or ~)~ triggers a full rejection and an expensive extra
  LLM turn.

* 3. Frontier 1 Formalization: Machine-Native Relational Coding Style

** 3.1 Why Mathematical & Relational Specifications Outperform Prose for LLMs

Natural language optimizes for *human narrative compression* at the cost of
ambiguity: a sentence such as "replace manual iterator loops with adapters
unless early exit complicates ownership" hides quantifiers, scope boundaries,
negated exceptions, and exact AST shapes.

By contrast, an LLM trained on formal mathematics, type theory, compiler IR,
and logic programming exhibits three structural advantages when given a
*machine-native relational specification* (corroborated empirically by
*Logic-LM* and *SymbCoT*):

1. *Zero Semantic Ambiguity*: Universal/existential quantifiers ($\forall$,
   $\neg\exists$), typed predicates (`ast_loop`, `ast_call`, `in_scope_type`),
   and algebraic rewrite schemas (`LHS ⇝ RHS`) leave zero interpretive slack.
2. *Higher Information Density per Token*: A 4-line symbolic style contract
   conveys the exact structural invariants of 40 lines of prose while anchoring
   every identifier to real symbols in the active Open EDB.
3. *1:1 Specification–Verifier Isomorphism (Single Source of Truth)*:
   The *exact same* `:gerbil-ascent` relation object that projects the compact
   symbolic contract to the LLM *also executes deterministically* on the
   resulting AST! Drift between "what the prompt asked for" and "what the gate
   enforces" becomes impossible by construction.

** 3.3 Formal Mathematical Specification of a Style Theory $\mathcal{T}$

Let $G_{\text{AST}} = (V, E_{\text{child}}, E_{\text{cfg}}, E_{\text{call}}, \tau, \sigma)$
denote the relational projection of a file's native AST and workspace Open EDB,
where each node $v \in V$ carries universal kind $\tau(v)$, native language
kind, and exact UTF-8 byte span $\sigma(v) = [b_0, b_1) \subseteq [0, |B|)$.

A *Coding Style Theory* in ~:gerbil-ascent~ is a 4-tuple
$\mathcal{T} = \langle \mathcal{R}_{\text{ded}}, \mathcal{R}_{\text{choice}},
\preceq_{\text{style}}, \mathcal{W}_{\text{elev}} \rangle$:

1. *Deductive Structural Rules* ($\mathcal{R}_{\text{ded}}$):
   Stratified Datalog clauses over $G_{\text{AST}}$ deriving typed predicates:
   - $\text{violation}(r, v, w)$: rule $r$ is violated at AST node $v$ with
     derivation witness $w$.
   - $\text{elevatable}(r, v, \theta)$: node $v$ matches an idiomatic
     elevation template $r$ under substitution $\theta$.
2. *Style Cost Lattice* ($\mathcal{L}, \preceq_{\text{style}}$):
   Assigns every candidate subtree $e$ a multi-objective cost tuple:
   $$
   \text{Cost}(e) = \bigl(\, \text{Violations}(e),\; \text{LinearScansInLoops}(e),\;
   \text{MutAccumulators}(e),\; \text{NestingDepth}(e),\; \text{AstNodeCount}(e) \,\bigr)
   $$
   ordered lexicographically (or via per-repository weighted lattice in POO).
3. *Semantics-Preserving Elevation Schemas* ($\mathcal{W}_{\text{elev}}$):
   Each Class-1 rule $w = (\text{LHS} \leadsto \text{RHS} \mid \Phi)$ carries a
   logical side-condition $\Phi$ proved in $\mathcal{R}_{\text{ded}}$ (e.g., no
   early ~break~/~return~, accumulator never escapes loop, pure predicate).
   An automatic elevation $e \leadsto e'$ is admitted *iff*:
   $$
   \Phi(e) \;\wedge\; \text{Cost}(e') \prec_{\text{style}} \text{Cost}(e)
   \;\wedge\; \text{NativeOracle}(\text{Splice}(B, \sigma(e), e')) = \text{accepted}
   $$
4. *Finite-Choice Refactoring Planner* ($\mathcal{R}_{\text{choice}}$, Dusa POPL 2025):
   When multiple Class-2 architectural actions interact (e.g., two functions
   share a primitive ~provider_id: &str~ and live in an oversized module
   violating both ~RUST-AGENT-API-TYPE-012~ and ~RUST-MOD-R002~), Dusa choice
   rules select a *single mutually consistent refactoring plan* without
   conflicting byte-span edits.

* 4. Frontier 2 Formalization: Source-Backed Lossless Overlay & Dual-Track Calibration

** 4.1 Source-Backed Span-Indexed Lossless Overlay Theorem

Let $B \in \Sigma^N$ be the immutable UTF-8 byte sequence of a source file with
digest $h_0 = \text{BLAKE3}(B)$. Let an authoritative native parser
$P_{\text{nat}}$ return an AST node span table where every target node $u$ has
byte interval $\sigma(u) = [s_u, e_u)$ satisfying $0 \le s_u \le e_u \le N$.

Given a non-overlapping sorted edit set
$\Delta = \{(s_1, e_1, r_1), \dots, (s_m, e_m, r_m)\}$ with
$0 \le s_1 \le e_1 \le s_2 \le \dots \le e_m \le N$, define:
$$
\text{Splice}(B, \Delta) = B[0..s_1) \mathbin{\|} r_1 \mathbin{\|} B[e_1..s_2) \mathbin{\|} r_2 \mathbin{\|} \dots \mathbin{\|} r_m \mathbin{\|} B[e_m..N)
$$

*Lossless Preservation Property*: Every byte index $i \notin \bigcup_{k=1}^m [s_k, e_k)$
(all untouched comments, doc-comments, whitespace, blank lines, and sibling
AST items) is preserved *bit-for-bit identically* in $\text{Splice}(B, \Delta)$,
*independently of whether $P_{\text{nat}}$ retains trivia in its internal AST
structs* (such as Rust ~syn~ or Python ~ast~).

** 4.2 Dual-Track Sound Syntax Calibration

Let $S_0 = \text{Splice}(B, \Delta_{\text{raw}})$ be the spliced candidate
buffer.

1. *Fast Path*: Query authoritative parser oracle $P_{\text{nat}}(S_0)$. If
   $\text{accepted}(P_{\text{nat}}(S_0))$, emit $S_0$ with zero calibration
   overhead.
2. *Track A — Bounded CPCT+ LR Recovery (~:gerbil-parser~ Grammars)*:
   When $P_{\text{nat}}$ is a ~:gerbil-parser~ compiled LR machine (Scheme or
   Rust AOT ~gerbil-parser-runtime~), capture the exact failure checkpoint
   $F = \text{LRFailureFrontier}(S_0)$. Perform breadth-first cost-ordered
   search up to cost budget $K = 3$ over grammar-admissible operations:
   - $\text{MISSING}(t)$ for $t \in \text{ExpectedLiterals}(F)$ (cost 1)
   - $\text{SKIPPED}(\text{tok})$ (cost 1)
   - $\text{ERROR}(\text{tok} \to t)$ for $t \in \text{ExpectedLiterals}(F)$ (cost 2)
   Let $\mathcal{C}_A(S_0, K)$ be all edit sequences of cost $\le K$ whose
   resumed parse reaches ~ParseArtifact(status = accepted)~.
3. *Track B — Oracle-Verified Bounded Calibration (External Native HTTP-JSON Providers)*:
   When $P_{\text{nat}}$ is an external native provider (~asp-rust~ ~syn~,
   ~asp-typescript~ ~tsc~, ~asp-python~ ~ast~, ~AspJulia.jl~ ~JuliaSyntax~,
   ~asp-gerbil-scheme~) reporting error span $[e_0, e_1)$ and diagnostic $d$:
   - Run the parameterized token-aware *Lexical Delimiter Skeleton* (respecting
     strings, raw strings, char literals, comments, indentation; *zero*
     duplicated language grammar) strictly around $[e_0, e_1)$ and the edited
     hole span $[s_k, e_k)$ to propose a bounded set $\mathcal{P}$ ($|\mathcal{P}| \le 8$,
     cost $\le 2$) of pure delimiter/punctuation repairs (~)~, ~}~, ~]~, ~;~,
     ~,~, fence strip).
   - Send $\mathcal{P}$ in *one batched HTTP-JSON ~ast-verify~ frame* to
     $P_{\text{nat}}$, retaining $\mathcal{C}_B = \{ r \in \mathcal{P} \mid \text{accepted}(P_{\text{nat}}(r(S_0))) \}$.

** 4.3 Soundness & Uniqueness Admission Rule (Fail-Closed)

Let $\mathcal{C} \in \{\mathcal{C}_A, \mathcal{C}_B\}$ and
$c^* = \min_{r \in \mathcal{C}} \text{cost}(r)$, with minimal repair set
$\mathcal{M} = \{ r \in \mathcal{C} \mid \text{cost}(r) = c^* \}$.

$$
\text{Admit}(S_0) =
\begin{cases}
  \text{Calibrated}(r^*(S_0),\; \text{Receipt}(r^*, c^*)) & \text{if } |\mathcal{M}| = 1 \text{ with } \mathcal{M} = \{r^*\} \\
  \text{RejectTypedHole}(\text{ambiguous-tie},\; \mathcal{M}) & \text{if } |\mathcal{M}| \ge 2 \\
  \text{RejectTypedHole}(\text{uncalibrated-error},\; d) & \text{if } \mathcal{M} = \emptyset
\end{cases}
$$

This guarantees:
- *Zero unsound repairs* (every admitted repair passes the real compiler parser
  with 0 syntax errors on the full file).
- *Zero silent guessing* (ambiguous minimal ties and semantic omissions always
  fail closed into a structured *Typed Hole* diagnostic).
- *Zero wasted LLM retries* on the overwhelming majority of delimiter slips.

** Explicit Non-Claims (Honesty Boundaries)

- Automated syntax calibration does *not* solve semantic logic bugs, missing
  type definitions, or borrow-checker architecture errors (those belong to
  Typed Hole feedback and Frontier 1 style/refactoring guidance).
- Local Class-1 ~AutoElevate~ does *not* attempt arbitrary whole-program
  rewriting; cross-function API/ownership changes remain Class-2 proposals.
- External HTTP-JSON provider latency (~ast-verify~) depends on loopback round
  trips and must be measured separately from in-process Rust and
  ~:gerbil-parser~ AOT timings.
