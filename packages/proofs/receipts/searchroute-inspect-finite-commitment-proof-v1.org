* Lean-discovered protocol corrections

- Exclusion completeness is invalid for an arbitrary digest.  It requires a
  root that opens to a valid canonical manifest.
- Canonical ordering is part of the commitment, not an output-format detail.
- Universe and frontier commitments require distinct domain tags.
- Membership and exclusion verifiers must both bind the supplied root.
- A verified opening materializes the manifest used by this baseline
  construction, so its proof bytes are linear in manifest size.
- Verified membership and exclusion cannot coexist for one root and candidate.

* Remaining boundary

The finite full-manifest construction is a correctness baseline, not the final
online search representation.  A production construction still needs a
canonical JSON byte contract, algorithm identity, collision-resistance
assumptions weaker than ideal digest injectivity, and logarithmic membership
and non-membership openings such as a domain-separated Merkle structure.
