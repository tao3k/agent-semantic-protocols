* Status

This receipt records the first executable proof bundle for the Clause-first
SearchLoop model.  It proves the named local theorems under the model encoded in
Lean.  It does not establish full RFC closure, runtime conformance, or
equivalence between the Org RFC and an AXLE-generated declaration bundle.

* Axiom audit

The following theorems do not depend on any axioms:

- =snapshot_drift_changes_action_identity=
- =selector_drift_blocks_materialization=
- =rank_cannot_disable_mandatory_escalation=
- =provider_drift_changes_cache_identity=

The other sixteen named theorems depend only on Lean's standard =propext=
axiom.  No theorem reports =sorryAx=.  This receipt does not interpret
=propext= as an RFC assumption; it records the kernel dependency separately so
that a future constructive-proof policy can tighten it explicitly.

* Formal findings fed back into the RFC

The executable model rejects or repairs nine underspecified formulations:

1. endpoint overlap is not fact identity;
2. overlapping clause-state predicates require ordered classification;
3. fairness at zero budget requires a typed =needs-budget= terminal state;
4. action identity must include snapshot identity;
5. no-hit cannot prove absence without complete scope and freshness;
6. rank cannot substitute for closure evidence;
7. selector drift blocks materialization;
8. mandatory graph escalation is independent of rank;
9. cache identity must include provider identity.

These findings are recorded normatively in the RFC risk and proof-plan modules.

* Open proof obligations

- AXLE must emit a versioned declaration bundle from stable RFC clause IDs.
- The Lean model must consume or be mechanically checked against that bundle.
- Transition-system safety and liveness must be proved over complete traces,
  not only the current local decision lemmas and finite witnesses.
- Clause merge algebra, cache invalidation, graph-escalation completeness, and
  bounded-progress theorem families remain open.
- ASP currently exposes no Lean language facade; Lean source identity and exact
  materialization are therefore not yet parser-owned by ASP.
