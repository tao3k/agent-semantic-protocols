* Adversarial Review
:PROPERTIES:
:REVIEW_SUBJECT: RFC 10.06.14 Search Evidence Output Reflection
:REVIEW_MODE: adversarial-reflection
:END:

** Challenge

Does a compact structural output preserve enough verified knowledge for an
Agent to select an exact Query, distinguish unknown from absent, and revisit
evidence after context or source changes?

Subject: [[file:../../../docs/10-19-rfcs/10.06-agent-search-projection/10.06.14-search-evidence-output-reflection.org][English RFC]].

** Criteria

- redundancy: remove repeated presentation only if required answers and
  source-occurrence provenance remain recoverable.
- out of scope: do not claim a new production grammar, live acceptance, or
  better Agent reasoning from finite proof examples.
- command clarity: replay commands use the package-pinned Lean toolchain;
  proposed Query flags remain explicitly undecided.
- mechanism clarity: exact admission, projection, and historical replay have
  different obligations.
- structure: use the existing SDD, adversarial-review, and reflection-answers
  Org contracts without changing materialized contracts.

** Findings

The independent review identified configuration-sensitive structure, ambiguous
coverage, and cross-snapshot witness deduplication as pressure points. The
model now distinguishes raw and active structure, carries a soundness proof
for certified views, and tests identical occurrences under different bindings.

Two suggestions were narrowed rather than adopted wholesale. Raw parser
membership need not depend on every implementation-body edit or resolver
change. Certified complete coverage can justify exclusion, but an attempted
query or an arbitrary coverage field cannot. The model now states and proves
that distinction.

The model's finite instance identifiers do not prove real selector uniqueness.
Its abstract Org delimiter reader is not the product parser. Its declared
costs are not tokenizer measurements. Production refinement and Agent-task
evaluation remain required.

** Reflection Questions
:PROPERTIES:
:CONTRACT_ORG: [[../../../org/contracts/agent.reflection-answers.v1.org][agent.reflection-answers.v1]]
:END:

| Question | Value |
|----------+-------|
| R01 Does equal topology prove fresh implementation evidence? | No. Body and resolver changes are separate countermodels; structurally validated membership may still be reusable. See [[#E1][E1 model and audit]]. |
| R02 Are type names or member discovery paths canonical owners? | No. Same-named impl instances differ; raw syntax and active cfg membership have different dependencies. See [[#E1][E1]]. |
| R03 Can a skeleton preserve arbitrary future answers? | No. Indistinguishable worlds defeat every decoder for an omitted independent fact. Declared-question preservation is proved instead. See [[#E1][E1]]. |
| R04 Does a missing hit prove absence? | Only a sound complete coverage certificate can justify ruledOut; partial or merely attempted coverage is unknown. See [[#E1][E1]]. |
| R05 Do two collectors imply two independent supports? | No. Deduplicate equal witnesses while preserving collector attribution, distinct occurrences, and distinct bindings. See [[#E2][E2 executable checks]]. |
| R06 Is deletion-minimal output globally cheapest or best for reasoning? | No. A cheaper sufficient alternative exists in the countermodel; real token and reasoning costs remain unmeasured. See [[#E1][E1]]. |
| R07 Is previously sent evidence usable after compaction or edits? | Only with retained or retrievable validated evidence. Historical replay is distinct from current admission. See [[#E2][E2]]. |
| R08 Can reachability replace direct-call evidence? | No. Transitive reduction preserves reachability but can remove a required direct edge. See [[#E1][E1]]. |
| R09 Is raw native source safe inside an unescaped Org block? | Not in the abstract framing countermodel. Actual Org renderer round-trip and metadata attachment remain open integration gates. See [[#E1][E1]]. |
| R10 Must an Agent request a skeleton before exact Query? | No. Admission depends on the selected target and binding, not earlier flag use; a member cannot silently expand to its owner. See [[#E2][E2]]. |
| R11 Can same-snapshot premises be composed unconditionally? | No. Individually possible edges may require mutually exclusive configurations. Joint-behavior conclusions need a compatible witness. See [[#E6][E6]]. |
| R12 Does a valid positive clause prove the full query? | No. A true A witness does not satisfy A AND NOT B when B is true. Explanations retain the full retrieval decision as a separate premise. See [[#E6][E6]]. |
| R13 Does a truncated skeleton establish absence? | No. Negative answers require a sound scoped completeness certificate from the facts' authority. Source-window budgets and member coverage remain separate. See [[#E6][E6]]. |
| R14 Can compact aliases or duplicate rows change support? | No. Support depends on canonical witnesses, while collector attribution and replay references remain available. See [[#E6][E6]]. |
| R15 Must every queryable reachable node be queried again? | No. Eligibility is distinct from scheduling within a question-bound episode and fixed binding. New questions may begin new episodes. See [[#E6][E6]]. |
| R16 Can a candidate path or URI mint a native selector? | A candidate path cannot. A registered provider projection may mint a selector under the same binding. Explicit native syntax accepts a validated canonical item selector as a graph anchor; a bare file URI or stale selector is rejected. See [[#E6][E6]]. |
| R17 Can a flat top-k hit list support the next Agent decision? | No. Core rank must remain distinct from the bounded witness closure that preserves owners, edges, and evidence. Omitted candidates remain unknown, and the frontier exposes both Query-eligible and Search-eligible nodes. See [[#E6][E6]]. |
| R18 May Ascent become a second Agent-facing result language? | No. Logical inference executes internally; Runtime settles novel topology conclusions and frontiers into the single GQL result with modality and proof references. See [[#E6][E6]]. |
| R19 May one provider's dense hits dominate the frontier? | Not by input order or hit volume. Selection uses relevance-threshold marginal graph coverage across heterogeneous provider/evidence clusters, without fixed language quotas. See [[#E6][E6]]. |
| R20 May fired Ascent rules be rendered because they are explanatory? | No. They duplicate the graph and expose engine syntax. The typed receipt retains fixed-point and proof artifacts while GQL carries the topology settlement. See [[#E6][E6]]. |
| R21 Does a body-only edit invalidate every topology fact? | No. Declaration skeleton identity may remain reusable, while body-derived CALLS, RETURNS, EMITS, and REFERENCES bind content and must be invalidated. See [[#E6][E6]]. |
| R22 Does an absent edge in a bounded slice establish missing? | No. Partial coverage yields unknown. Only certified complete coverage for the relation and target kind may yield certified missing. See [[#E6][E6]]. |
| R23 May Python rank select a node without its proof path? | No. A post-rank topology-proof certification closes all transitive proof dependencies and rejects disconnected selections. See [[#E6][E6]]. |
| R24 Does semi-naive delta support cross-generation deletion automatically? | No. Addition-only completeness accepts a deletion counterexample. Generation replacement must apply removals and invalidate derived descendants. See [[#E6][E6]]. |
| R25 Should the result emit Query 1, Query 2, and Search 1? | No. One MaterializationSet feeds one Query Playbook; graph frontier edges express unresolved Search obligations. See [[#E6][E6]]. |
| R26 Can an LLM summary enter factual closure directly? | No. A premise-bound proposed annotation may guide ranking or frontier expansion but cannot prove behavior before authorized admission. See [[#E6][E6]]. |
| R27 Should natural-language reasoning stay outside topology? | No. It belongs in GQL as a typed SemanticAnnotation with premises, producer, and admission state, never as unbound prose or parser fact. See [[#E6][E6]]. |

*** Design Disposition

The design is now split by owner. RFC 10.06.14 retains only reflection and
counterexamples; RFC 10.06.15 owns Search/Query grammar and materialization;
RFC 10.06.16 owns the topology reasoning library; RFC 10.06.17 owns the typed
topology-inference bridge and GQL settlement. Future fixes update the responsible RFC
instead of extending one cumulative document.

The accepted boundary is selector-first and language-neutral: every admitted
native parser node, including document and structured-data nodes, carries its
provider-minted exact Query selector. A typed jq program may refine a selected
JSON node but cannot mint or repair selector authority. A format with no
applicable native parser may expose a bounded =SourceExcerpt=; this is a
separate evidence type and never selector-failure recovery. GQL carries admitted
facts, settled derivations, direct Query mappings, frontier boundaries, and
premise-bound semantic annotations. Ascent executes internally as versioned
logical inference; its proof receipt is machine-readable but its source and fired rules
are not a second default projection. One GQL graph is the successful
=search playbook= output; no =--evidence-skeleton= switch remains.
This is design and formal-model closure, not a production Search/Query gate.
Shared-schema, renderer, provider round-trip, and controlled Agent-task evidence
remain required before live acceptance.
