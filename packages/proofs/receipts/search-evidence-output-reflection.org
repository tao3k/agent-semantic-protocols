* Adversarial Review

:REVIEW_MODE: adversarial-reflection

** Challenge

Does a compact structural output preserve enough verified knowledge for an
Agent to select an exact Query, distinguish unknown from absent, and revisit
evidence after context or source changes?

Subject: [[file:../../../docs/10-19-rfcs/10.06-agent-search-projection/10.06.14-search-evidence-output-reflection.org][English RFC]].

** Criteria

- redundancy: remove repeated presentation only if required answers and
  source-occurrence provenance remain recoverable.
- out of scope: do not claim a new production grammar, live acceptance, or
  better Agent reasoning from finite proof examples.
- command clarity: replay commands use the package-pinned Lean toolchain;
  proposed Query flags remain explicitly undecided.
- mechanism clarity: exact admission, projection, and historical replay have
  different obligations.
- structure: use the existing SDD, adversarial-review, and reflection-answers
  Org contracts without changing materialized contracts.

** Findings

The independent review identified configuration-sensitive structure, ambiguous
coverage, and cross-snapshot witness deduplication as pressure points. The
model now distinguishes raw and active structure, carries a soundness proof
for certified views, and tests identical occurrences under different bindings.

Two suggestions were narrowed rather than adopted wholesale. Raw parser
membership need not depend on every implementation-body edit or resolver
change. Certified complete coverage can justify exclusion, but an attempted
query or an arbitrary coverage field cannot. The model now states and proves
that distinction.

The model's finite instance identifiers do not prove real selector uniqueness.
Its abstract Org delimiter reader is not the product parser. Its declared
costs are not tokenizer measurements. Production refinement and Agent-task
evaluation remain required.

** Reflection Questions
:PROPERTIES:
:CONTRACT_ORG: [[../../../org/contracts/agent.reflection-answers.v1.org][agent.reflection-answers.v1]]
:END:

| Question | Value |
|----------+-------|
| R01 Does equal topology prove fresh implementation evidence? | No. Body and resolver changes are separate countermodels; structurally validated membership may still be reusable. See [[#E1][E1 model and audit]]. |
| R02 Are type names or member discovery paths canonical owners? | No. Same-named impl instances differ; raw syntax and active cfg membership have different dependencies. See [[#E1][E1]]. |
| R03 Can a skeleton preserve arbitrary future answers? | No. Indistinguishable worlds defeat every decoder for an omitted independent fact. Declared-question preservation is proved instead. See [[#E1][E1]]. |
| R04 Does a missing hit prove absence? | Only a sound complete coverage certificate can justify ruledOut; partial or merely attempted coverage is unknown. See [[#E1][E1]]. |
| R05 Do two collectors imply two independent supports? | No. Deduplicate equal witnesses while preserving collector attribution, distinct occurrences, and distinct bindings. See [[#E2][E2 executable checks]]. |
| R06 Is deletion-minimal output globally cheapest or best for reasoning? | No. A cheaper sufficient alternative exists in the countermodel; real token and reasoning costs remain unmeasured. See [[#E1][E1]]. |
| R07 Is previously sent evidence usable after compaction or edits? | Only with retained or retrievable validated evidence. Historical replay is distinct from current admission. See [[#E2][E2]]. |
| R08 Can reachability replace direct-call evidence? | No. Transitive reduction preserves reachability but can remove a required direct edge. See [[#E1][E1]]. |
| R09 Is raw native source safe inside an unescaped Org block? | Not in the abstract framing countermodel. Actual Org renderer round-trip and metadata attachment remain open integration gates. See [[#E1][E1]]. |
| R10 Must an Agent request a skeleton before exact Query? | No. Admission depends on the selected target and binding, not earlier flag use; a member cannot silently expand to its owner. See [[#E2][E2]]. |

*** Design Disposition

The user accepted the minimal native Org Query envelope and the Search/Query
semantic boundaries recorded in the RFC's Accepted Output Boundary section.
Evidence grouping, optional flag namespace, relation grammar, and coverage
encoding remain open. This is design approval, not a new implementation gate.
The research gate establishes abstract constraints, not product behavior. Advance to a
shared-schema/rendering candidate only after the RFC's unresolved affiliation,
scope, coverage, and replay questions are addressed. Then use real parser
round-trip tests and controlled Agent-task evaluation to compare A/B/C.
