* Search Closure Receipt v1 draft

This draft records the docs-level contract for the calibrated search loop. It is
not yet a generated JSON Schema artifact.

=search= is the reasoning plane. =query= is the exact evidence materialization
plane. A search loop closes by returning a =SearchClosureReceipt=; it does not
return public =search --choice read:*= actions.

** Top-level packet

#+end_src

** EvidenceScope

#+begin_src text
EvidenceScope
  scopeId
  intentDigest
  obligationSetDigest
  sourceSnapshotRef
  evidenceGraphRoot
  obligations[]
  evidenceChain
#+end_src

Obligations are claim-specific closure targets:

- =identity=: unique canonical selector plus owner snapshot proof.
- =existential=: at least one exact support path.
- =enumeration=: admitted scope fully enumerated, untruncated, with snapshot and provider proof.
- =absence=: complete negative proof over the admitted scope; ordinary no-hit is not enough.
- =causal-flow=: continuous typed evidence edges with exact pivots where required.
- =handoff=: provider or language admission proof plus downstream scope receipt.

- =all-required=
- =first-exact=

=best-supported= is ranking evidence only. It cannot by itself authorize
terminal closure.

** Search intent and intent coverage

=SearchIntentPacket= is the admitted statement of what the search run is
trying to establish.  =IntentCoverage= is a separate proof that every
normalized intent claim is represented by one or more obligations.  Execution
coverage cannot substitute for intent coverage: running every node in a route
program does not prove that the obligation set captured the user's request.

#+begin_src text
SearchIntentPacket
  schemaId: asp.search-intent-packet
  schemaVersion: 1
  runId
  intentDigest
  normalizedIntentClaims[]
    claimId
    claimClass: identity|existential|enumeration|absence|causal-flow|handoff
    requestedScope
  obligationSetDigest
  obligations[]
  intentCoverage: IntentCoverage

IntentCoverage
  verdict: complete|partial|unknown
  coveredClaims[]
    claimId
    obligationIds[]
  uncoveredClaimIds[]
  normalizerDigest
  evaluatorDigest
  proofRefs[]
#+end_src

A terminal =answer= requires =IntentCoverage.verdict= to be =complete=.  A
=partial= or =unknown= verdict may produce a partial, clarification, or handoff
receipt, but it cannot be promoted to closed search merely because all admitted
actions completed.  This proves closure relative to an admitted intent packet;
it does not claim empirical precision or recall, which remains a benchmark
property.

** Graph route evaluation

=GraphRouteEvaluation= is a deterministic evaluation over the current
authoritative state.  =closure-candidate= means that closure validation should
run; it is not itself closure authority.

not proof that no competing edge exists.

** Route proposal

=SearchReasoningRouter= may emit a =RouteProposal=.  A proposal has no provider
authority, cannot mutate the evidence graph, cannot spend budget, and cannot
close an obligation.  Natural-language goals are explanatory metadata only;
they are never executable actions.

** Admitted route program

=GraphRouter= validates a proposal or constructs a deterministic route and
admits an immutable, finite, typed DAG as =RouteProgram=.  Admission validates
the whole DAG; every node is then validated again immediately before execution.

#+end_src

Serial and parallel execution are derived from dependency edges and runtime
policy.  Batch is a transport optimization and must retain the individual
action keys, receipts, and budget entries.  =bypass-reasoning=, =plan-once=,
and =checkpointed-reasoning= are observed execution profiles, not separate
state machines.  In particular:

#+begin_quote
PlanOnce means reason once, validate each node.
#+end_quote

A plan is invalidated or checkpointed when its snapshot, intent, obligation
set, policy, provider/parser/schema binding, relevant graph precondition, guard,
or authorized budget no longer holds.

** Just-in-time execution grant

=SearchRouter= executes only a typed node carrying a fresh =ExecutionGrant=.
The grant is scoped to the current graph and control state; plan admission is
not a reusable provider capability.

#+begin_src text

  runId
  planId
  planDigest
  nodeId
  typedActionDigest
  resolvedInputsDigest
  expectedEvidenceGraphRoot
  sourceSnapshotRef
  providerActivationDigest

  schemaDigest
  policyDigest
  controlEpoch

  budgetReservationId

  issuedAtMs
  expiresAtMs
#+end_src

=actionKey= is stable across retries of the same resolved action.  Every graph
admission and budget charge is deduplicated by this key.  A result produced
under a different snapshot, control epoch, lease fence, or resolved input is a
different action and cannot be admitted through the old grant.

** Reasoning checkpoint and ChoicePanel projection

=GraphRouter= issues a =ReasoningCheckpoint= only when continuation requires a
semantic decision, clarification, or budget priority that deterministic guards
cannot resolve.

#+begin_src text

=ChoicePanel= is an optional bounded projection of a checkpoint.  Resolving a
choice selects a proposal or semantic decision; it does not issue an
=ExecutionGrant= and does not authorize a provider action.  =GraphRouter= must
validate and admit the selected result against live state.

** Durable advisory reasoning frame

=ReasoningFrame= persists the conclusions needed to resume reasoning without
persisting chain-of-thought.  It is advisory: resident memory, a frame, or a
=contextEpoch= cannot establish source freshness, graph truth, action authority,
or closure.

#+begin_src text

  runId

  controlEpoch

On handoff or model replacement, a new planner consumes a fresh frame bound to
the current graph.  Lease fencing rejects late choices and proposals from the
previous holder.  Reusing the same resident context is a performance
observation, never a correctness prerequisite.

** Search and query boundary

=search= owns intent normalization, obligation routing, proposal/program
coordination, evidence-graph growth, and closure proof.  =query= materializes a
parser-owned exact selector requested by an admitted typed action or
=QueryHandoff=.  A reasoning frame or =RouteProposal= cannot invoke =query=
directly, and exact materialization cannot by itself close enumeration,
absence, causal-flow, or handoff claims.

** Event requirements

The replay log must prove plan admission, just-in-time authority, exactly-once
state admission, budget accounting, cancellation, handoff fencing, and closure.
These are event kinds carried by the shared event envelope, not independent
backend row formats.

#+begin_src text
RouteProposalObserved
RouteProgramAdmitted
RouteProgramInvalidated
ActionAdmitted
ExecutionGrantIssued
ActionStarted
ActionResultObserved
ActionCompleted
GraphDeltaCommitted
GraphDeltaRejected
JoinEvaluated
BudgetReserved
BudgetConsumed
BudgetReleased
CancellationRequested
LateResultQuarantined
CheckpointIssued
CheckpointResolved
QualityGateEvaluated
ClosureFinalized
#+end_src

=RouteProposalObserved= records an untrusted proposal and grants no provider,
graph, budget, or closure authority.  =RouteProgramAdmitted= records only that
the finite typed DAG and its static bindings passed structural admission;
it is not reusable execution authority.  =RouteProgramInvalidated= terminates
that admission when a bound precondition no longer holds.

=ActionAdmitted= records the per-node live validation against the current
evidence graph, snapshot, control epoch, policy, dependencies, and budget.
=ExecutionGrantIssued= is the separate just-in-time capability that permits
=SearchRouter= to invoke the admitted action.

=ActionStarted=, =ActionResultObserved=, and =ActionCompleted= are provider
invocation observations.  They may occur more than once for one =actionKey=
after an outcome-unknown crash or retry; none of them is graph admission.
=GraphDeltaCommitted= and =GraphDeltaRejected= are the authoritative graph
admission outcomes.  A graph delta and the corresponding =BudgetConsumed=
entry are admitted at most once per =actionKey=; reservations and unused
amounts are represented by =BudgetReserved= and =BudgetReleased=.

=CancellationRequested= revokes future authority but cannot erase an invocation
already in progress.  A result observed after cancellation is emitted as
=LateResultQuarantined= by default and cannot mutate the active graph without a
new admission decision.  =JoinEvaluated= consumes admitted branch outcomes,
while =CheckpointIssued= and =CheckpointResolved= record the remaining
reasoning boundaries.  =QualityGateEvaluated= records a recomputable gate
verdict and its proof references; it is not terminal authority.  Only
=ClosureFinalized= can terminate the search run.

An action may be invoked again after an outcome-unknown crash unless the
provider supports =actionKey= deduplication.  The portable guarantee is
at-least-once provider invocation with exactly-once graph admission and
exactly-once budget accounting.  Exactly-once provider invocation may be
reported only when the provider receipt proves deduplication for the same
action key.

Search closure events use a typed event envelope stored as backend-neutral
session events. The payload is schema-validated before write. The envelope
includes =causes[]=, =sequence=, =previousEventDigest=, =eventDigest=, optional
graph roots, and optional batch/branch identities for execution DAG joins.

** Obligation object

#+begin_src text
Obligation
  id
  claimClass: identity|existential|enumeration|absence|causal-flow|handoff
  expectedCardinality: one|one-or-more|all|none|unknown
  admittedScope
    languageIds[]
    providerIds[]
    ownerRoots[]
    workspaceSnapshotRoot
  state: open|partial|closed|failed|waived
  supportPaths[]
  completenessProofRef?
  negativeCompletenessProofRef?
  reason?
#+end_src

Closure is per-obligation. A receipt may be terminal only when every mandatory
obligation is =closed=, or when =resultKind= explicitly records a non-terminal
outcome such as =partial=, =clarification=, or =handoff=.

Rules:

- =identity= requires one canonical structural selector and owner snapshot proof.
- =existential= requires at least one exact support path.
- =enumeration= requires complete admitted-scope enumeration with =truncated=false=.
- =absence= requires negative-complete proof; no-hit without scope proof is partial.
- =causal-flow= requires a connected typed edge path.
- =handoff= requires language/provider admission proof and downstream scope receipt.

Validation outcomes:

- =accepted=: execute the planned bundle once.
- =stale-panel=: reissue current panel; no provider action.
- =unknown-choice=: record invalid attempt; no provider action.
- =graph-root-mismatch=: no provider action.
- =source-snapshot-mismatch=: invalidate the proposal; no provider action.
- =control-epoch-mismatch=: reject the resolution; no provider action.
- =lease-fence-mismatch=: reject the stale holder; no provider action.

A valid choice resolves only the checkpoint.  Provider execution still requires
an admitted =RouteProgram= and a separately issued fresh =ExecutionGrant=.
- =language-mismatch=: fail closed or handoff.
- =expired=: reissue panel or close partial.

** Execution plan

This is the executor projection of an admitted =RouteProgram=, not an
independent planner authority.  Parallel branches are staged from one common
evidence root and source snapshot.  =all-required= requires every mandatory
branch to succeed and have its receipt admitted; failed, timed-out, or cancelled
is terminal operational state but not join satisfaction.  =first-exact= is
valid only for identity or existential claims and is forbidden for enumeration,
absence, causal-flow, handoff, and competing cross-language ownership.

  routeProgramId
  routeProgramDigest
  schedulerMode: single|serial|parallel-all|parallel-first-proof|parallel-disambiguate|hybrid

  branches[]
  maxParallel
  budgetReservationIds[]

Branch

  targets[]
  maySatisfy[]
  dependsOn[]
  actionKind
  executionGrantRefs[]
  expectedOutput
#+end_src

Default mode is =serial=. Parallel branches require runtime proof of
independence and shared immutable authority. =best-supported= may rank evidence
but cannot close terminal by itself.

Terminality requires:

- no stale or invalid accepted choice;
- no freshness mismatch;
- no open mandatory obligation;
- no truncated enumeration for =enumeration= claims;
- no ordinary no-hit standing in for =absence=;
- no unresolved cross-language ownership ambiguity;
- no =best-supported= join standing alone as closure.
